**Emportez vos conversations de code avec l'IA sur n'importe quel PC, et d'un outil d'IA à un autre.**

ChatRelay synchronise l'historique des conversations des assistants de code IA (**Claude Code** et **OpenAI Codex** aujourd'hui) entre vos ordinateurs. Commencez une conversation sur le PC du bureau, puis ouvrez la même conversation sur l'ordinateur portable de la maison : mêmes messages, mêmes appels d'outils, et chaque chemin de fichier est adapté aux chemins de la nouvelle machine. ChatRelay écrit aussi un court résumé de l'historique d'un projet dans le fichier d'instructions que lit un autre outil (`CLAUDE.md`, `AGENTS.md`, `GEMINI.md`), pour que vous puissiez poursuivre le travail dans un autre outil d'IA.

## Ce que fait ChatRelay

- **Déplace l'historique des conversations entre PC.** Chaque conversation de Claude Code (CLI dans le terminal et extension VS Code) et de Codex (CLI, extension VS Code et application de bureau) est copiée vers un espace de stockage qui vous appartient, puis de là vers vos autres PC. Sur l'autre PC, elle apparaît dans la liste d'historique de l'outil lui-même : `claude --resume`, le panneau Claude Code dans VS Code, `codex resume` ou la barre latérale de Codex.
- **Corrige les chemins de fichiers.** Votre projet peut se trouver dans `C:\Users\me\shop` sur un PC et dans `D:\work\shop` sur un autre, ou dans `/home/me/shop` sous Linux. ChatRelay réécrit chaque chemin présent dans la conversation (dossier de travail, entrées et sorties des outils, liens vers des fichiers, texte des messages) pour qu'il corresponde au chemin sur le PC qui reçoit.
- **N'envoie que ce qui a changé.** Après le premier envoi, seules les nouvelles lignes d'une conversation sont transférées : quelques Ko au lieu du fichier entier.
- **Ne perd jamais votre travail.** Il ne modifie jamais vos originaux lors de l'envoi. Il sauvegarde chaque fichier avant de le modifier, montre d'abord un aperçu (simulation, « dry run »), et n'écrase jamais une conversation qui a changé sur les deux PC : il garde les deux.
- **Fonctionne tout seul.** Avec la synchronisation automatique activée, les conversations Claude Code sont envoyées à la fin d'une session et téléchargées au début d'une session. Les conversations Codex sont envoyées et téléchargées toutes les 15 minutes en arrière-plan.
- **Résume.** Il transforme tout l'historique d'un projet (de tous les outils) en un fichier `HANDOFF.md` : ce qui est fait, les décisions, les bugs ouverts, les prochaines étapes, les fichiers modifiés. Il peut aussi placer une version courte dans `CLAUDE.md`, `AGENTS.md` ou `GEMINI.md`, pour que l'outil suivant démarre avec le contexte.
- **Lisible partout.** Une page web en lecture seule et une application Android affichent toutes vos conversations depuis le stockage GitHub, sur n'importe quel appareil.
- **Ressemble à VS Code.** Application de bureau en noir et blanc, dans le style de VS Code, avec des thèmes sombre et clair, une vue simple pour l'usage quotidien et une vue avancée avec tous les détails.

## Outils IA pris en charge

| Outil | Où il fonctionne | Voir les conversations | Synchroniser entre PC | Restaurer dans l'outil | Fichier de contexte |
|---|---|---|---|---|---|
| **Claude Code** | CLI dans le terminal, extension VS Code | ✅ | ✅ (avec les hooks de synchronisation automatique) | ✅ `claude --resume`, historique VS Code | `CLAUDE.md` |
| **OpenAI Codex** | Codex CLI, extension VS Code, application de bureau Codex | ✅ | ✅ (en arrière-plan, toutes les 15 min) | ✅ `codex resume`, barre latérale de Codex | `AGENTS.md` |
| Gemini CLI | Terminal | prévu | prévu | prévu | `GEMINI.md` (déjà disponible comme destination des résumés) |
| Kiro (IDE et CLI), Cursor, Antigravity | | prévu | prévu | prévu | |

Chaque outil conserve son historique dans son propre format non documenté, et ces formats changent d'une version à l'autre. ChatRelay vérifie donc le format qu'il trouve sur votre PC. S'il voit une version qu'il ne connaît pas, il affiche quand même les conversations, mais **désactive l'écriture** pour cet outil et vous explique pourquoi dans **Settings → AI tools** (Paramètres → Outils IA). Il ne devine jamais.

Versions vérifiées : Claude Code 2.1.x ; Codex 0.144 à 0.160 (base de données d'index `state_5.sqlite`, migration de schéma 58).

## Téléchargement et installation

### Windows

1. Téléchargez `ChatRelay_<version>_x64-setup.exe` depuis la [dernière version publiée](https://github.com/Abh1shxkk/claude-sync-releases/releases/latest). (Les versions jusqu'à v0.5.0 s'appellent `ClaudeSync_…`.)
2. Lancez-le. L'installateur n'est pas signé numériquement, donc Windows SmartScreen peut afficher « Windows a protégé votre ordinateur » : cliquez sur **More info → Run anyway** (Informations complémentaires → Exécuter quand même).
3. Vous n'installez qu'une seule fois. Les versions suivantes arrivent toutes seules (voir [Mises à jour](#mises-à-jour)).

L'application s'installe pour l'utilisateur courant dans `%LOCALAPPDATA%\Claude Sync\` (le dossier garde son ancien nom ; voir [À propos du changement de nom](#à-propos-du-changement-de-nom)). Elle démarre dans la zone de notification. Fermer la fenêtre la laisse tourner là ; utilisez **Quit** (Quitter) dans le menu de la zone de notification pour l'arrêter.

### Android (visionneuse)

Téléchargez `ChatRelay_<version>.apk` depuis la même page de versions et ouvrez-le sur votre téléphone (autorisez « installer des applications inconnues » pour votre navigateur ou votre gestionnaire de fichiers quand on vous le demande). L'application Android est une **visionneuse en lecture seule** de votre stockage GitHub ; un téléphone n'a pas d'historique d'outil d'IA à lui.

### macOS et Linux

Le moteur Rust et l'application se compilent sous macOS et Linux (voir [Compilation depuis les sources](#compilation-depuis-les-sources-et-développement)), mais aucun installateur n'est encore publié pour eux et ils n'ont pas été testés.

### Web

La visionneuse web est une page statique que vous pouvez héberger vous-même (GitHub Pages, Cloudflare Pages, Netlify…) ou lancer en local. Voir [Visionneuse web et téléphone](#visionneuse-web-et-téléphone).

## Première configuration

Quand ChatRelay s'ouvre pour la première fois, un assistant de configuration vous guide à travers ces étapes. Vous pouvez le relancer à tout moment depuis la palette de commandes (**Ctrl+Shift+P → Run First-time Setup Again** (Relancer la première configuration)).

1. **Votre historique.** ChatRelay trouve l'historique de Claude Code dans `%USERPROFILE%\.claude\projects` (ou dans le dossier indiqué par `CLAUDE_CONFIG_DIR`) et celui de Codex dans `%USERPROFILE%\.codex` (ou `CODEX_HOME`). Il affiche le nombre de conversations trouvées pour chaque outil.
2. **La suppression après 30 jours de Claude Code.** Par défaut, Claude Code supprime les conversations de plus de 30 jours (`cleanupPeriodDays`). ChatRelay vous le montre et propose d'augmenter cette durée. Il sauvegarde `settings.json` avant de le modifier.
3. **Nom de la machine.** Par exemple `OFFICE-PC` ou `HOME-LAPTOP`. Il est affiché à côté de chaque conversation, pour que vous sachiez de quel PC elle vient.
4. **Stockage (backend).** Un dossier (Google Drive, OneDrive, Dropbox, lecteur réseau) ou un dépôt GitHub privé. Voir la section suivante.
5. **Clé API Anthropic (facultative).** Nécessaire uniquement pour les résumés. Elle est stockée dans le Gestionnaire d'identification Windows (le trousseau du système), jamais dans un fichier.
6. **Synchronisation automatique.** Active l'envoi et le téléchargement automatiques (hooks Claude Code plus minuterie en arrière-plan).
7. **Tout envoyer.** Envoie, si vous le souhaitez, tout votre historique existant tout de suite, avec une barre de progression.

## Choisir où votre historique est stocké (backend)

Votre historique va dans un endroit que **vous** contrôlez. ChatRelay n'a aucun serveur à lui.

### Option A : un dossier

N'importe quel dossier que vos autres PC peuvent aussi voir :

- Google Drive pour ordinateur, par ex. `G:\My Drive\chatrelay`
- OneDrive, par ex. `%OneDrive%\chatrelay`
- Dropbox, un NAS ou un partage réseau, ou une clé USB que vous emportez

Seules des copies compressées y sont placées. Vos dossiers `~/.claude` et `~/.codex` en cours d'utilisation ne sont jamais déplacés dans un dossier cloud. Le backend dossier conserve aussi les versions précédentes de chaque fichier (**Settings → What to sync → Versions kept (folder backend)** (Paramètres → Quoi synchroniser → Versions conservées (backend dossier)), 2 par défaut).

### Option B : un dépôt GitHub privé

Le meilleur choix si vous voulez aussi la visionneuse web ou téléphone.

1. **Sign in with GitHub** (Se connecter avec GitHub) (recommandé). ChatRelay affiche un code court ; vous le saisissez sur github.com et vous approuvez. L'application GitHub ChatRelay n'a accès qu'aux dépôts que vous choisissez (normalement uniquement votre dépôt d'historique), avec la permission de lire et d'écrire leur contenu. Aucun mot de passe n'est stocké, et aucun serveur n'intervient.
2. Ou collez un **personal access token** (jeton d'accès personnel) : un jeton classique avec la portée `repo`, ou un jeton à granularité fine avec *Contents: Read and write* sur ce seul dépôt. Si vous êtes connecté avec la GitHub CLI (`gh auth login`), ChatRelay peut utiliser ce jeton.
3. Choisissez un dépôt **privé** existant ou cliquez sur **Create private repo** (Créer un dépôt privé). Les dépôts publics sont refusés, car l'historique des conversations peut contenir du code privé et des secrets.

Sur GitHub, chaque envoi est **un commit**. Les fichiers de plus de 40 Mo (compressés) sont découpés automatiquement en plusieurs parties, car GitHub refuse les fichiers individuels de plus de 100 Mo.

Le jeton est conservé uniquement dans le trousseau du système (service `claude-sync`).

## Configurer votre deuxième PC

Sur le **PC 1** (celui qui a déjà l'historique) :

1. Installez ChatRelay et choisissez un backend.
2. Envoyez : cliquez sur **Upload now** (Envoyer maintenant) dans la vue simple (ou sur **Upload everything** (Tout envoyer) à la fin de la configuration), ou sur **Push** (Envoyer) sur un projet dans la vue avancée. Un aperçu montre chaque conversation et les secrets éventuellement trouvés ; vous pouvez choisir de les masquer (caviarder) dans la copie envoyée.

Sur le **PC 2** :

1. Installez ChatRelay et choisissez **le même backend** (le même dossier synchronisé, ou le même dépôt GitHub).
2. Placez le dossier du projet sur le PC 2 (par exemple avec `git clone`). Le chemin peut être différent, par exemple `D:\work\shop` au lieu de `C:\Users\me\shop`.
3. Cliquez sur **Bring history to this PC** (Ramener l'historique sur ce PC) dans la vue simple, ou ouvrez la vue **Sync** (Synchronisation) dans la vue avancée. ChatRelay liste chaque projet présent dans le backend et l'endroit où il irait sur ce PC :
   - Les **projets Git** sont associés automatiquement grâce à leur URL distante (remote).
   - **Autres projets** : cliquez sur **Import into…** (Importer dans…) / **Link** (Lier) et choisissez une fois le dossier local. Ce lien est mémorisé.
4. Vérifiez la **simulation (dry run)** : quels fichiers seront écrits et chaque changement de chemin (par exemple `×166  C:\Users\me\shop → D:\work\shop`). Puis confirmez.
5. Ouvrez la conversation dans l'outil : `claude --resume` ou le panneau Claude de VS Code ; `codex resume` ou la barre latérale de Codex.

Pour Codex : **fermez d'abord Codex** (CLI, extension VS Code et application de bureau). ChatRelay n'écrit jamais dans les fichiers de Codex pendant qu'il tourne ; la conversation concernée est ignorée avec le motif « Codex is running » (Codex est en cours d'exécution), et elle arrivera la prochaine fois.

Activez **Auto-sync** (Synchronisation automatique) sur les deux PC et vous n'aurez plus besoin de faire tout cela à la main.

## Utilisation au quotidien

### Vue simple et vue avancée

- **Simple view** (Vue simple, par défaut) : vos projets avec un point d'état, deux grands boutons (**Upload now** / **Bring history to this PC**), l'interrupteur de synchronisation automatique et la vérification des mises à jour.
- **Advanced view** (Vue avancée) : une disposition proche de VS Code avec une barre d'activité (Projects **Ctrl+Shift+E**, Sync **Ctrl+Shift+Y**, Summaries, Logs, Backups, Settings — c'est-à-dire Projets, Synchronisation, Résumés, Journaux, Sauvegardes, Paramètres), des onglets, une barre d'état et une palette de commandes (**Ctrl+Shift+P**) qui contient toutes les actions.

Passez de l'une à l'autre avec **Ctrl+Shift+P → Switch to Simple/Advanced View** (Passer à la vue simple/avancée).

### Points d'état

| Point | Signification | Que faire |
|---|---|---|
| Vert | Synchronisé | Rien |
| Jaune / orange | Des modifications sur ce PC ne sont pas encore envoyées | Faites un Push, ou attendez la synchronisation automatique |
| Rouge | La dernière synchronisation a échoué | Ouvrez **Logs** (Journaux) pour voir la raison |
| Gris | Jamais synchronisé | Faites un Push une fois |
| Cercle vide | Pas encore d'identité de projet (non lié) | Faites un Push (un lien est créé) ou utilisez **Link** pour le lier au projet venant de l'autre PC |

### Conversations de plusieurs outils

Chaque conversation porte un petit badge indiquant son outil (**Claude** ou **Codex**). Les projets dans lesquels vous avez utilisé plus d'un outil affichent un **filtre** (All / Claude Code / Codex, c'est-à-dire Tous / Claude Code / Codex). Ouvrir une conversation affiche la transcription complète : vos messages, les réponses de l'assistant, les appels d'outils (commandes exécutées, fichiers modifiés) et la liste des fichiers modifiés.

### Push et pull (envoyer et récupérer)

- **Push** envoie les conversations d'un projet qui ont changé depuis la dernière synchronisation. **Push all** (Tout envoyer) le fait pour tous les projets.
- **Pull** (Récupérer) télécharge ce qui est nouveau. Il commence toujours par une **simulation (dry run)** qui liste chaque fichier qu'il écrirait et chaque réécriture de chemin. Rien n'est écrit tant que vous n'avez pas confirmé.

### Synchronisation automatique

Quand **Auto-sync** est activé :

- **Claude Code** : des hooks dans `~/.claude/settings.json` lancent ChatRelay quand une session Claude Code **commence** (pull) et **se termine** (push).
- **Codex** : Codex n'a pas ce genre de hook, donc l'application de bureau vérifie toutes les 15 minutes (en commençant 20 secondes après le lancement). Elle envoie les projets dont les conversations Codex ont changé et télécharge les nouvelles (rien n'est fait tant que Codex tourne).
- Les envois qui ont échoué parce que vous étiez hors ligne sont mis en file d'attente et réessayés.

Vous pouvez activer ou désactiver la synchronisation automatique dans les paramètres, dans le menu de la zone de notification, ou avec `claude-sync hooks install|uninstall`.

### Menu de la zone de notification

Push now · Pull now · Auto-sync on/off · Last sync status · Open · Quit (Envoyer maintenant · Récupérer maintenant · Synchronisation automatique activée/désactivée · État de la dernière synchronisation · Ouvrir · Quitter).

### Sauvegardes

Chaque écriture est précédée d'une sauvegarde dans `~/.claude-sync/backups/<timestamp>-<what>/`. Ouvrez **Backups** (Sauvegardes) (ou `claude-sync backups`) pour les voir, et utilisez **Restore** (Restaurer) sur l'une d'elles pour remettre chaque fichier exactement comme il était. Une restauration supprime aussi les fichiers que la modification avait créés.

### Journaux

**Logs** (Journaux) affiche tout ce que ChatRelay a fait, avec les erreurs mises en évidence, et un bouton qui copie un rapport d'erreur.

## Prise en charge de Codex en détail

Ce qui voyage avec chaque conversation Codex :

| Élément | Où Codex le conserve | Ce que fait ChatRelay |
|---|---|---|
| La conversation (« rollout ») | `~/.codex/sessions/YYYY/MM/DD/rollout-<time>-<id>.jsonl` (certaines versions écrivent `.jsonl.zst`, compressé) | Copiée, chaque chemin réécrit |
| La ligne d'index du fil | `~/.codex/state_5.sqlite`, table `threads` | Ajoutée ou mise à jour pour que la conversation apparaisse dans `codex resume` et dans la barre latérale |
| Le nom du fil | `~/.codex/session_index.jsonl` | Ajouté |
| La mémoire Codex de ce fil | `~/.codex/memories_1.sqlite`, table `stage1_outputs` | Ajoutée si ce PC n'en a pas pour ce fil ; chemins réécrits |
| Les objectifs (goals) de ce fil | `~/.codex/goals_1.sqlite`, tables `thread_goals`, `thread_goal_continuation_deferrals` | Ajoutés si ce PC n'en a pas pour ce fil |

Les détails qui comptent :

- **Codex doit être fermé** pendant que ChatRelay écrit. ChatRelay recherche les processus `codex` en cours (CLI, extension VS Code, application de bureau). Il ne vous demande de rien fermer pendant la synchronisation en arrière-plan ; il réessaie simplement plus tard.
- **Le mode d'historique est conservé.** Les versions récentes de Codex stockent un historique « paginé » ; Codex reconstruit sa base de données de pages (`thread_history_*.sqlite`) à partir du fichier de conversation la première fois que vous l'ouvrez, donc ChatRelay n'écrit jamais dans cette base.
- **Vos propres réglages pour un fil restent les vôtres.** Lors d'une mise à jour, l'état épinglé, le nom personnalisé, l'état d'archivage et le compte définis sur ce PC sont conservés. Les dossiers et sections qui n'existent que sur l'autre PC sont retirés.
- **Compte.** Un fil importé est attribué au compte Codex qui possède le plus de fils sur ce PC.
- **Préfixe de chemin Windows.** Sous Windows, Codex stocke les dossiers de travail sous la forme `\\?\D:\project`. ChatRelay ajoute ce préfixe uniquement aux chemins Windows, sur un PC dont le Codex l'utilise, et jamais aux chemins macOS ou Linux.
- **Les conversations compressées** (`.jsonl.zst`) peuvent être lues et mises à jour. Lors d'une mise à jour, le fichier est remplacé par un `.jsonl` normal (l'original compressé est sauvegardé d'abord).
- **Les données de suivi de la mémoire** qui appartiennent à l'autre PC (combien de fois une mémoire a été utilisée, si elle a été choisie pour la consolidation) ne sont pas copiées.
- **Versions inconnues.** Si l'index de Codex utilise une base de données que ChatRelay ne connaît pas (par exemple un futur `state_6.sqlite`), ou ajoute un champ obligatoire qu'il ne sait pas remplir, l'écriture est désactivée pour Codex avec un avertissement clair. La lecture fonctionne toujours.

## Résumés et "Continuer dans un autre outil"

> 🔒 **Les secrets n'atteignent jamais l'IA.** Avant d'envoyer quoi que ce soit au modèle, ChatRelay remplace les clés, jetons et mots de passe trouvés dans les conversations (clés d'API Anthropic, OpenAI, OpenRouter, GitHub, AWS, Google, Slack, Stripe, Hugging Face, npm, SendGrid, bots Telegram ; JWT ; clés privées ; lignes du type `PASSWORD=…` ; mots de passe dans les URL) par `[REDACTED:kind]`. Cela se fait toujours et ne peut pas être désactivé ; l'écran indique combien ont été masqués. Votre code et le reste de la conversation sont tout de même envoyés : pour du code privé ou client, préférez un modèle payant dont le fournisseur ne conserve pas les données.

Ouvrez **Summaries** (Résumés) dans la vue avancée, choisissez un projet, cochez les conversations (de n'importe quel outil) et un modèle, puis cliquez sur **Generate handoff** (Générer le document de passation).

- Modèles : **Claude Opus 5.5** (par défaut), Claude Sonnet 5.5 (plus rapide, moins cher), Claude Haiku 5.5 (le moins cher), Claude Fable 5.1 (le plus performant). Il vous faut une clé API Anthropic (**Settings → Summaries**, Paramètres → Résumés).
- L'historique est d'abord condensé : vos demandes, la réponse finale de l'assistant à chaque tour, et les fichiers modifiés. Les longues sorties d'outils et le raisonnement interne sont retirés. Les conversations de tous les outils sont fusionnées par ordre chronologique et étiquetées avec leur outil.
- Les longs historiques sont résumés par morceaux d'environ 100k tokens, puis fusionnés.
- Le résultat contient ces sections : Project overview, What's done, Key decisions, Open bugs / known issues, Next steps, Files touched (Vue d'ensemble du projet, Ce qui est fait, Décisions clés, Bugs ouverts / problèmes connus, Prochaines étapes, Fichiers modifiés).

Ensuite vous pouvez :

- **Save HANDOFF.md** (Enregistrer HANDOFF.md) dans le dossier du projet, ou
- **Continue in…** (Continuer dans…) un outil : choisissez Claude Code (`CLAUDE.md`), Codex (`AGENTS.md`) ou Gemini CLI (`GEMINI.md`). La liste montre les outils installés sur ce PC. ChatRelay ajoute à ce fichier une courte section « Previous context » (Contexte précédent : vue d'ensemble, ce qui est fait, prochaines étapes). Le relancer remplace uniquement sa propre section ; le reste du fichier n'est pas touché.
- Ou **copy** (copier) le texte.

En ligne de commande : `claude-sync summarize --target handoff|claude-md|agents-md|gemini-md|none`.

## Sécurité et confidentialité

- **Les originaux ne sont jamais modifiés lors de l'envoi.** L'envoi ne fait que lire vos fichiers d'historique.
- **Rien n'est écrit pendant que l'outil tourne** (Codex). La session Claude Code ouverte (celle qui a déclenché le hook) n'est jamais touchée.
- **Une sauvegarde avant chaque écriture**, y compris pour le `settings.json` de Claude Code, les bases de données de Codex (avec leurs fichiers `-wal` et `-shm`) et `session_index.jsonl`.
- **Une simulation (dry run) pour chaque import.** Vous voyez chaque fichier et chaque réécriture de chemin avant que quoi que ce soit ne se produise.
- **Les deux versions sont conservées en cas de conflit**, rien n'est jamais écrasé.
- **Recherche de secrets.** Avant l'envoi, ChatRelay cherche des clés API et des mots de passe : clés Anthropic, OpenAI, GitHub, AWS, Google, Slack et Stripe, JWT, clés privées, lignes du type `.env` comme `SECRET=…`, et identifiants contenus dans des URL. Vous choisissez : **warn** (avertir), **redact** (caviarder : remplacé par `[REDACTED:kind]` uniquement dans la copie envoyée) ou **off** (désactivé).
- **Les secrets restent dans le trousseau du système.** Votre jeton GitHub et votre clé Anthropic ne sont jamais écrits dans un fichier.
- **Vos connexions ne sont jamais touchées.** ChatRelay ne lit, ne copie et ne modifie pas les fichiers de connexion de Claude Code ou de Codex (`~/.claude/.credentials.json`, `~/.codex/auth.json`, …). Synchroniser l'historique ne peut pas vous déconnecter. Si vous êtes déconnecté, cela vient de l'outil lui-même (par exemple une session expirée, ou une connexion avec un autre compte sur un autre PC).
- **Stockage privé uniquement.** Les dépôts GitHub publics sont refusés.
- **Aucun serveur ChatRelay.** Les données circulent uniquement entre vos PC, votre dossier ou GitHub, et (seulement quand vous créez un résumé) l'API Anthropic.

Volontairement non synchronisés : `~/.claude/history.jsonl` (l'historique des invites rappelées avec la flèche haut, pour tous les projets), `~/.claude/file-history/` (instantanés de retour en arrière) et tous les identifiants.

## Fonctionnement (technique)

### Où Claude Code conserve l'historique

| Chemin | Contenu |
|---|---|
| `~/.claude/projects/<encoded-path>/<session-uuid>.jsonl` | Un fichier par session, un objet JSON par ligne |
| `~/.claude/projects/<encoded-path>/<session-uuid>/subagents/*.jsonl` + `*.meta.json` | Transcriptions des sous-agents (synchronisées comme « sidecar », fichiers annexes) |
| `~/.claude/projects/<encoded-path>/<session-uuid>/tool-results/*` | Grosses sorties d'outils enregistrées sur le disque (sidecar) |
| `~/.claude/projects/<encoded-path>/memory/` | Mémoire automatique du projet (`MEMORY.md` + notes) |

Points qui diffèrent de ce qu'on suppose habituellement, tous pris en charge :

- **La casse de la lettre de lecteur dépend du client.** L'extension VS Code enregistre `c:\Users\…` (dossier `c--Users-…`), la CLI enregistre `C:\Users\…` (dossier `C--Users-…`), et une même session peut contenir les deux. Sous Windows, les chemins sont comparés sans tenir compte de la casse.
- **Les noms de dossiers ne peuvent pas être décodés de façon fiable.** `C:\Users\me\my project` et `C:\Users\me\my-project` sont tous deux encodés en `C--Users-me-my-project`. Le vrai chemin provient du `cwd` enregistré dans les sessions ; décoder le nom n'est qu'une solution de secours, signalée comme telle.
- **Les sessions peuvent être énormes** (plus de 200 Mo avec des images ou PDF intégrés), donc tout est lu en flux (streaming). Les résultats d'analyse sont mis en cache selon la taille et la date de modification, donc une nouvelle analyse prend environ 100 ms.
- **Une seule réponse de l'assistant s'étend sur plusieurs lignes** (une par bloc de contenu, même `message.id`) ; le décompte des messages élimine ces doublons. Les titres viennent de la première vraie invite (les balises d'encapsulation de l'IDE sont retirées) ; le `ai-title` propre à Claude Code est affiché à côté.
- **Beaucoup de types de lignes en plus de user/assistant** (`attachment`, `file-history-snapshot`, `queue-operation`, `ai-title`, `last-prompt`, `permission-mode`, …). Les types et champs inconnus sont conservés tels quels.

### Où Codex conserve l'historique

Voir [Prise en charge de Codex en détail](#prise-en-charge-de-codex-en-détail). Chaque ligne d'un rollout est de la forme `{timestamp, type, payload}` ; la première est `session_meta`, avec l'identifiant de session et le `cwd`. Codex a écrit les conversations selon trois générations de format (éléments `event_msg/item_completed` dans les versions ≥0.15x, événements `user_message`/`agent_message` avant cela, simples messages `response_item` dans les plus anciennes) ; la visionneuse utilise la plus riche qui est présente.

### Adaptateurs

Chaque outil d'IA est un **adaptateur** (`crates/core/src/providers/`) derrière une interface unique (`ProviderAdapter`) : détecter l'outil et son format, lister les projets et les sessions, lire une session dans une forme indépendante de l'outil (`UniversalSession`), l'exporter sans perte (`SessionBundle` : les fichiers originaux plus les métadonnées de l'outil, comme la ligne d'index de Codex), l'importer sur un autre PC (réécrire les chemins, vérifier que l'outil ne tourne pas, sauvegarder, simuler) et ajouter de nouvelles lignes. Voir [Ajouter un autre outil IA](#ajouter-un-autre-outil-ia-guide-des-adaptateurs).

### Identité du projet

Le même projet a un chemin différent sur chaque PC, il est donc identifié, dans cet ordre, par :

1. Un **lien manuel** (bouton Link / `claude-sync link <dir> <id>`), stocké dans la configuration de ChatRelay
2. Le **remote git**, normalisé : `git@github.com:Me/Repo.git` et `https://github.com/me/repo` deviennent tous deux `git:github.com/me/repo`
3. Un fichier **`.claude-sync.json`** à la racine du projet, contenant un UUID, créé au premier push pour les projets sans git (committez-le, ou faites le lien à la main sur l'autre PC). « Upload everything » et la synchronisation en arrière-plan créent plutôt un lien dans la configuration de ChatRelay, de sorte que rien n'est écrit dans vos dossiers de projet.

### Organisation du stockage (dans le dossier ou le dépôt)

```
<projectId-slug>/
  manifest.json                          machines, original paths, hashes, timestamps, revision
  <sessionId>.jsonl.gz                   Claude Code session (whole, or its start when deltas exist)
  <sessionId>.d<N>.jsonl.gz              lines appended after that, one blob per push
  <sessionId>.sidecar.json.gz            subagents/ + tool-results/ (if any)
  memory.json.gz                         Claude Code project memory (if any)
  <provider>-<sessionId>.bundle.json.gz  another tool's session (e.g. codex-…): files + metadata
  <provider>-<sessionId>.d<N>.jsonl.gz   lines appended to it later
  .versions/<file>/<timestamp>           previous versions (folder backend)
```

Les sessions des autres outils sont listées sous `providerSessions` dans le manifeste (clé `<provider>:<id>`). Les anciennes versions de l'application ignorent cette liste et la laissent intacte.

### Push

- Les sessions sont comparées par SHA-256 ; seules les nouvelles ou celles qui ont changé sont envoyées. Les originaux sont uniquement lus.
- **Seules les nouvelles lignes sont envoyées.** Les outils d'IA ne font qu'ajouter des lignes à la fin d'un fichier de conversation, donc après le premier envoi d'une session, un push n'enregistre que les lignes ajoutées depuis la dernière synchronisation, sous forme de partie « delta ». Chaque partie enregistre les chemins de la machine qui l'a envoyée. Les empreintes des sessions sont chaînées (`hash = sha256(previous : sha256(part))`). Après 40 parties, le push suivant renvoie la session entière. Quand ce raccourci ne s'applique pas (le fichier a changé d'une autre manière, un conflit, un état provenant d'une ancienne version), le fichier entier est envoyé.
- Si le backend contient une version que vous n'avez pas encore vue et qui contient des messages que vous n'avez pas, le push de cette session est refusé avec « pull first » (faites d'abord un pull), pour que rien ne soit perdu.
- **Hors ligne ?** (GitHub injoignable, le lecteur cloud n'est pas monté.) Le push est mis en file d'attente dans `~/.claude-sync/queue.json` et réessayé à la prochaine exécution, ainsi que toutes les 15 minutes par l'application de bureau.

### Pull

- Les chemins sont réécrits à l'intérieur du JSON analysé (valeurs texte **et** clés d'objets), donc l'échappement JSON ne pose jamais de problème. Formes prises en charge : chemins Windows sous la forme `C:\…`, `c:/…`, Git-Bash `/c/…` et WSL `/mnt/c/…` (sans tenir compte de la casse) ; chemins POSIX (en tenant compte de la casse) ; URL `file:///`, y compris les espaces encodés en `%20` ; les séparateurs après la racine du projet sont convertis lors du passage d'un système d'exploitation à un autre ; le dossier personnel de l'outil (`~/.claude`, `~/.codex`) et le nom de dossier encodé de Claude Code sont aussi réécrits. Les dossiers voisins comme `shop-old` ne sont jamais touchés.
- **Chemin rapide :** un PC qui possède exactement ce qu'il a synchronisé la dernière fois ne télécharge que les parties manquantes et les ajoute à la fin.
- **Divergence** (les conversations ne font que s'allonger ; elles sont comparées par identifiants de ligne pour Claude Code et par début de texte commun pour les autres outils) :
  - la version distante contient la version locale → mise à jour
  - la version locale contient la version distante → la vôtre est plus récente et elle est conservée (envoyée au prochain push)
  - les deux ont changé → **conflit** : votre copie reste telle quelle, et l'autre version est enregistrée comme une **nouvelle conversation avec un nouvel identifiant** (Codex : nommée « <name> (from <PC>) »). Les deux apparaissent alors dans l'outil et se synchronisent vers vos autres PC.

### Hooks de synchronisation automatique (Claude Code)

« Enable auto-sync » (Activer la synchronisation automatique) fusionne ceci dans `~/.claude/settings.json` ; vos autres paramètres et hooks sont conservés, et une sauvegarde est faite d'abord :

```jsonc
"hooks": {
  "SessionStart": [{ "hooks": [{ "type": "command", "command": "\"…/Claude Sync/claude-sync.exe\" pull --hook --quiet --claude-sync-hook", "timeout": 60 }] }],
  "SessionEnd":   [{ "hooks": [{ "type": "command", "command": "\"…/Claude Sync/claude-sync.exe\" push --hook --quiet --claude-sync-hook", "timeout": 60 }] }]
}
```

- `--hook` lit le JSON du hook de Claude Code depuis stdin (`cwd`, `session_id`), et à défaut utilise `CLAUDE_PROJECT_DIR`, puis le dossier de travail. Les hooks **se terminent toujours avec le code 0**, ils ne peuvent donc jamais casser une session ; les erreurs vont dans le panneau Logs.
- Le hook lance l'exécutable natif `claude-sync` installé à côté de l'application. Node.js n'est pas nécessaire.
- « Disable auto-sync » (Désactiver la synchronisation automatique) retire uniquement les hooks qui contiennent le marqueur `claude-sync-hook`.

## Mises à jour

- L'application de bureau vérifie s'il existe une nouvelle version au démarrage, chaque fois que sa fenêtre est ouverte, toutes les heures, quand vous revenez à sa fenêtre après au moins 5 minutes, et quand vous cliquez sur **Check for updates** (Rechercher des mises à jour) dans Settings → About, dans la vue simple ou dans la palette de commandes. Elle affiche un indicateur de chargement pendant la vérification.
- Quand une mise à jour est disponible, vous voyez **A new version is available → Update now** (Une nouvelle version est disponible → Mettre à jour maintenant). L'application la télécharge, vérifie sa signature (les applications n'acceptent que les mises à jour signées avec la clé du projet), l'installe sur place et redémarre. L'historique et les paramètres sont conservés.
- L'application Android affiche un avis avec un lien vers le nouvel APK.

## Dépannage et FAQ

**SmartScreen bloque l'installateur.** L'installateur n'est pas signé numériquement. Cliquez sur **More info → Run anyway** (Informations complémentaires → Exécuter quand même).

**Un projet affiche un point jaune.** Il contient sur ce PC des conversations qui ne sont pas encore envoyées. Faites un push, ou activez la synchronisation automatique.

**Un projet de mon autre PC n'apparaît pas / apparaît sous un autre nom.** Les projets sont associés grâce au remote git, à un fichier `.claude-sync.json` ou à un lien. Si les dossiers ont des noms différents et pas de remote git, utilisez une fois **Link** (ou **Import into…**) et choisissez le bon dossier local.

**Une conversation Codex a été ignorée : « Codex is running ».** Fermez la Codex CLI, le panneau Codex de l'extension VS Code (ou VS Code) et l'application de bureau Codex, puis refaites un pull. La synchronisation en arrière-plan réessaie toute seule.

**L'import Codex est désactivé : « Unknown Codex index database » / « new required fields » (base d'index Codex inconnue / nouveaux champs obligatoires).** Votre Codex est plus récent que ce que connaît cette version de ChatRelay. Mettez ChatRelay à jour. Vos conversations restent visibles.

**Je vois une conversation en double, dont l'une se termine par « (from OFFICE-PC) ».** Elle a été poursuivie sur les deux PC avant qu'ils ne se synchronisent. Les deux versions sont conservées ; supprimez dans l'outil celle dont vous n'avez pas besoin.

**Mes anciennes conversations Claude Code ont disparu.** Claude Code supprime les conversations plus anciennes que `cleanupPeriodDays` (30 par défaut). Augmentez cette valeur dans les paramètres (ou avec `claude-sync cleanup-days 3650`). Les conversations déjà envoyées peuvent être récupérées depuis le backend avec un pull.

**La synchronisation m'a-t-elle déconnecté de Claude ?** Non. ChatRelay ne lit et n'écrit jamais les fichiers de connexion. Voir [Sécurité et confidentialité](#sécurité-et-confidentialité).

**Le premier envoi est lent.** Le premier envoi transmet tout (compressé). Ensuite, seules les nouvelles lignes sont envoyées.

**« Pull first » lors d'un push.** Un autre PC a envoyé une version plus récente que la vôtre ne contient pas. Faites un pull, puis un push.

**Hors ligne.** Les push sont mis en file d'attente et réessayés automatiquement ; `claude-sync queue` les réessaie tout de suite.

**Quelque chose s'est mal passé après un pull.** Ouvrez **Backups** (Sauvegardes) et restaurez la sauvegarde faite juste avant.

**Où trouver les erreurs ?** Dans la vue **Logs** (Journaux) (vous pouvez y copier un rapport d'erreur), ou dans `~/.claude-sync/logs/claude-sync.log`.

## Compilation depuis les sources et développement

Prérequis : Node.js 20+, Rust (stable) et, sous Windows, la chaîne d'outils MSVC (Visual Studio « Desktop development with C++ », Développement Desktop en C++).

```bash
git clone https://github.com/Abh1shxkk/chatrelay.git
cd chatrelay
npm install
npm run tauri:dev      # run the desktop app with hot reload
npm run test:rust      # cargo test --workspace: engine, adapters, push/pull, GitHub backend
npm test               # UI helper tests (vitest)
npm run typecheck      # TypeScript
npm run tauri:build    # installer in target/release/bundle/nsis/
```

Organisation du projet :

```
crates/core/       Rust engine: scanner, JSONL, path rewriting, sync, backends, hooks, summaries
crates/core/src/providers/   AI tool adapters: claude_code.rs, codex.rs (+ codex_format.rs, browser-safe parsing)
crates/core/src/provider_sync.rs   other tools' sessions in push/pull (bundles, deltas, conflict copies)
crates/core/tests/  integration tests with fixture files (tests/fixtures/codex, tests/fixtures/claude-code)
crates/cli/        the `claude-sync` CLI (also what the Claude Code hooks run)
crates/wasm/       the engine compiled to WebAssembly for the web and phone viewers
src-tauri/         desktop app: window, tray, background sync, the API behind window.claudeSync
src/renderer/      React + TypeScript + Tailwind UI (shared by desktop, web and phone)
src/shared/        TypeScript types and helpers
mobile/            Android / iOS shell around the web version (Tauri)
scripts/           release, CLI staging, WASM build
tests/             vitest tests; tests/web/mock-github.mjs for testing the web version
```

Lancer une copie de développement à côté d'une version installée : définissez un identifiant et un dossier de données séparés, pour qu'elle ne touche jamais à vos vrais paramètres :

```powershell
$env:TAURI_CONFIG='{"identifier":"com.claudesync.dev","productName":"ChatRelay Dev"}'
$env:CLAUDE_SYNC_HOME='D:\tmp\chatrelay-dev'
npm run tauri:dev
```

### Version web

```bash
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.129   # must match wasm-bindgen in Cargo.lock
npm run web:wasm     # rebuild the WebAssembly engine
npm run web:dev      # http://localhost:5175/web.html
npm run web:build    # static site in out/web/ (host on GitHub Pages, Cloudflare Pages, Netlify…)
```

`node tests/web/mock-github.mjs <folder-backend>` sert un backend dossier sous la forme d'une fausse API GitHub (uniquement dans les builds de développement : définissez `localStorage['claude-sync-web:apiBase'] = 'http://localhost:5176'` et utilisez le jeton `test-token-123456`).

### Application mobile (Android, iOS)

**Android** nécessite le JDK 17, le SDK Android (plateforme 36, build-tools 36, NDK r27) et les cibles Rust pour Android (`tauri android init` les installe) :

```powershell
$env:JAVA_HOME = "<jdk-17>"; $env:ANDROID_HOME = "<android-sdk>"; $env:NDK_HOME = "$env:ANDROID_HOME\ndk\<version>"
npm run mobile:android:init      # once: generates mobile/gen/android
npm run mobile:android:apk       # debug APK for a phone (arm64)
adb install -r <that apk>
npm run mobile:android:release   # release APK/AAB, signed when CLAUDE_SYNC_KEYSTORE_PROPERTIES is set
```

La signature des versions publiées lit un fichier de propriétés conservé **en dehors du dépôt**, dont le chemin est donné par `CLAUDE_SYNC_KEYSTORE_PROPERTIES` :

```properties
storeFile=D:/dev/android-keys/claude-sync-release.jks
storePassword=…
keyAlias=claude-sync
keyPassword=…
```

Créez la clé une seule fois avec `keytool -genkeypair -keystore claude-sync-release.jks -alias claude-sync -keyalg RSA -keysize 4096 -validity 10000` et sauvegardez-la : les mises à jour d'une application installée doivent être signées avec la même clé.

**iOS** nécessite un Mac avec Xcode et `rustup target add aarch64-apple-ios aarch64-apple-ios-sim` :

```bash
npm install && npm run web:wasm
npm run mobile:ios:init
npm run mobile:ios:dev
npm run mobile:ios:build
```

## Ajouter un autre outil IA (guide des adaptateurs)

1. **Vérifiez d'abord le format de stockage sur une vraie machine** : où se trouvent les sessions, le format des lignes/enregistrements, l'éventuelle base de données d'index et son schéma, la façon dont l'outil liste les sessions, la façon dont il stocke les chemins, quels processus signifient « en cours d'exécution ». Notez tout cela en haut du fichier de l'adaptateur.
2. Ajoutez un `ProviderId` dans `crates/core/src/providers/mod.rs` et un fichier `providers/<tool>.rs` qui implémente `ProviderAdapter` : `detect`, `list_projects`, `list_sessions`, `read_session`, `export_session`, `import_session` et, si besoin, `append_session`, `context_file_name`, `process_names`.
3. Règles que chaque adaptateur respecte : refuser d'écrire pendant que l'outil tourne (`ensure_not_running`), sauvegarder chaque fichier avant d'écrire (`ImportOptions.backups`), respecter `dry_run`, respecter `keep_both` (enregistrer une session entrante divergente sous un nouvel identifiant), et désactiver l'import (avec un avertissement dans `ProviderStatus`) pour tout format qu'il ne reconnaît pas.
4. Placez l'analyse pure (parsing) dans un fichier sans accès au système de fichiers (comme `codex_format.rs`) pour que la visionneuse web puisse l'utiliser, et ajoutez-la à `messages_from_bundle`.
5. Ajoutez des fichiers d'exemple (fixtures) dans `crates/core/tests/fixtures/<tool>/` et des tests : détection, liste, lecture, export → import sur une deuxième machine simulée (chemins réécrits), mise à jour, version locale en avance, conflit, refus quand le processus tourne, format inconnu.
6. Ajoutez le libellé dans `src/shared/types.ts` (`PROVIDER_LABELS`). Les badges, les filtres, le push/pull, les résumés et la visionneuse le récupèrent à partir de là.

## Publier une version

Les applications installées consultent `latest.json` sur [Abh1shxkk/claude-sync-releases](https://github.com/Abh1shxkk/claude-sync-releases).

1. Augmentez `version` dans `package.json`, `src-tauri/tauri.conf.json`, `mobile/tauri.conf.json` et `Cargo.toml`.
2. `npm run release -- --notes "What changed"`

Cela compile l'installateur Windows signé avec la clé de mise à jour (`TAURI_SIGNING_PRIVATE_KEY`, ou `D:\dev\tauri-keys\claude-sync-updater.key` avec son fichier `.password`) et l'APK signé, écrit `latest.json` et envoie le tout comme version `v<version>`. Options : `--no-apk`, `--skip-build`, `--dry-run`, `--notes-file <file>`. La connexion à GitHub provient de `git credential fill` (ou de `GITHUB_TOKEN`).

Gardez une sauvegarde de la clé de mise à jour. Les applications n'acceptent que les mises à jour signées avec elle ; sa partie publique se trouve dans `src-tauri/tauri.conf.json`.

## Limitations connues

- L'installateur Windows n'est pas signé numériquement (avertissement SmartScreen).
- Seul Windows est testé. macOS et Linux se compilent mais n'ont pas d'installateurs publiés.
- Une conversation ouverte sur deux PC en même temps ne peut pas être fusionnée en direct ; elle devient une copie de conflit.
- Codex n'a pas de hook « fin de session », donc la synchronisation de Codex a lieu toutes les 15 minutes plutôt qu'instantanément.
- Pour les chemins de plus de 200 caractères, l'empreinte exacte que Claude Code utilise dans le nom de dossier n'est pas documentée ; ChatRelay préfère un dossier existant dont les sessions enregistrent le même `cwd`, et sinon utilise son propre suffixe `-<hash>`.
- Les visionneuses web et téléphone sont en lecture seule et nécessitent le backend GitHub.

## À propos du changement de nom

ChatRelay s'appelait **Claude Sync** jusqu'à la v0.5.0. Pour que les installations existantes continuent de se mettre à jour et que rien ne soit perdu, ces noms internes n'ont **pas** changé :

| Conservé | Pourquoi |
|---|---|
| Dossier d'installation et entrée du menu Démarrer « Claude Sync » | Windows identifie l'application installée grâce à eux ; les changer installerait une deuxième copie au lieu de mettre à jour |
| Identifiant de l'application `com.claudesync.app` / `com.claudesync.mobile` | Les mises à jour et les installations Android en dépendent |
| Dossier de données `~/.claude-sync/`, `CLAUDE_SYNC_HOME` | Vos paramètres, l'état de synchronisation et les sauvegardes |
| CLI `claude-sync` | Les hooks de Claude Code l'appellent par son chemin |
| Fichiers de projet `.claude-sync.json`, marqueur `claude-sync-hook` | Les projets et hooks existants continuent de fonctionner |
| Dépôt des versions `claude-sync-releases` | Les applications installées y téléchargent leurs mises à jour |
| Application GitHub « claude-sync-abh1shxkk » | Les connexions existantes continuent de fonctionner |
