**अपनी AI coding chats को किसी भी PC पर ले जाएँ, और एक AI tool से दूसरे AI tool में भी।**

ChatRelay आपके computers के बीच AI coding assistants (अभी **Claude Code** और **OpenAI Codex**) की chat history sync करता है। Office PC पर कोई बातचीत शुरू करें, फिर वही बातचीत घर के laptop पर खोलें: वही messages, वही tool calls, और हर file path नई machine के paths में बदला हुआ। यह किसी project की history का एक छोटा summary उस instructions file में भी लिख देता है जिसे दूसरा tool पढ़ता है (`CLAUDE.md`, `AGENTS.md`, `GEMINI.md`), ताकि आप काम किसी दूसरे AI tool में आगे जारी रख सकें।

## यह क्या करता है

- **Chat history को एक PC से दूसरे PC पर ले जाता है।** Claude Code (terminal CLI और VS Code extension) और Codex (CLI, VS Code extension और desktop app) की हर बातचीत एक ऐसी storage जगह पर copy होती है जो आपकी अपनी है, और वहाँ से आपके दूसरे PCs पर। दूसरे PC पर वह उस tool की अपनी history list में दिखती है: `claude --resume`, VS Code में Claude Code panel, `codex resume`, या Codex sidebar।
- **File paths ठीक करता है।** हो सकता है आपका project एक PC पर `C:\Users\me\shop` हो और दूसरे पर `D:\work\shop`, या Linux पर `/home/me/shop`। ChatRelay chat के अंदर का हर path (working folder, tool के inputs और outputs, file links, message का text) बदलकर लेने वाले PC का path कर देता है।
- **सिर्फ़ बदला हुआ हिस्सा भेजता है।** पहली बार upload होने के बाद, बातचीत की सिर्फ़ नई lines जाती हैं: पूरी file की जगह कुछ KB।
- **काम कभी नहीं खोता।** Upload करते समय यह आपकी original files को कभी नहीं बदलता। किसी file को बदलने से पहले उसका backup लेता है, पहले preview (dry run) दिखाता है, और ऐसी बातचीत को कभी overwrite नहीं करता जो दोनों PCs पर बदली हो: दोनों को रख लेता है।
- **अपने आप चलता है।** Auto-sync चालू हो तो Claude Code की बातचीत session ख़त्म होने पर upload होती है और session शुरू होने पर download होती है। Codex की बातचीत background में हर 15 मिनट पर upload और download होती है।
- **Summary बनाता है।** यह किसी project की पूरी history (हर tool की) को एक `HANDOFF.md` में बदल देता है: क्या हो चुका है, कौन-से फ़ैसले लिए गए, कौन-से bugs बाक़ी हैं, आगे क्या करना है, किन files को छुआ गया। यह एक छोटा version `CLAUDE.md`, `AGENTS.md` या `GEMINI.md` में भी डाल सकता है, ताकि अगला tool पूरे context के साथ शुरू हो।
- **कहीं भी पढ़ें।** एक read-only web page और एक Android app आपकी GitHub storage से आपकी सारी बातचीत किसी भी device पर दिखाते हैं।
- **VS Code जैसा दिखता है।** Black-and-white, VS Code जैसा desktop app, dark और light themes के साथ, रोज़ के काम के लिए एक simple view और हर detail वाला एक advanced view।

## कौन-से AI tools चलते हैं

| Tool | कहाँ चलता है | Chats देखना | PCs के बीच sync | Tool में वापस लाना | Context file |
|---|---|---|---|---|---|
| **Claude Code** | Terminal CLI, VS Code extension | ✅ | ✅ (auto-sync hooks के साथ) | ✅ `claude --resume`, VS Code history | `CLAUDE.md` |
| **OpenAI Codex** | Codex CLI, VS Code extension, Codex desktop app | ✅ | ✅ (background में, हर 15 मिनट) | ✅ `codex resume`, Codex sidebar | `AGENTS.md` |
| Gemini CLI | Terminal | योजना में | योजना में | योजना में | `GEMINI.md` (summary target अभी से उपलब्ध) |
| Kiro (IDE और CLI), Cursor, Antigravity | | योजना में | योजना में | योजना में | |

हर tool अपनी history अपने ही बिना-documented format में रखता है, और ये formats versions के बीच बदलते रहते हैं। इसलिए ChatRelay आपके PC पर मिले format को जाँचता है। अगर उसे कोई ऐसा version दिखता है जिसे वह नहीं जानता, तो वह बातचीत फिर भी दिखाता है, लेकिन उस tool के लिए **writing बंद कर देता है** और इसकी वजह **Settings → AI tools** में बताता है। यह कभी अंदाज़ा नहीं लगाता।

जाँचे गए versions: Claude Code 2.1.x; Codex 0.144 से 0.160 तक (index database `state_5.sqlite`, schema migration 58)।

## Download और install

### Windows

1. [latest release](https://github.com/Abh1shxkk/claude-sync-releases/releases/latest) से `ChatRelay_<version>_x64-setup.exe` download करें। (v0.5.0 तक के releases का नाम `ClaudeSync_…` है।)
2. इसे चलाएँ। Installer code-signed नहीं है, इसलिए Windows SmartScreen कह सकता है "Windows protected your PC": **More info → Run anyway** (और जानकारी → फिर भी चलाएँ) पर click करें।
3. Install सिर्फ़ एक बार करना है। आगे के versions अपने आप आ जाते हैं (देखें [Updates](#updates))।

App हर user के लिए अलग `%LOCALAPPDATA%\Claude Sync\` में install होता है (folder का नाम पुराना ही है; देखें [नाम बदलने के बारे में](#नाम-बदलने-के-बारे-में))। यह system tray में शुरू होता है। Window बंद करने पर भी यह वहाँ चलता रहता है; इसे बंद करने के लिए tray menu में **Quit** (बंद करें) इस्तेमाल करें।

### Android (viewer)

उसी release page से `ChatRelay_<version>.apk` download करें और अपने phone पर खोलें (पूछे जाने पर अपने browser या file manager के लिए "install unknown apps" की इजाज़त दें)। Android app आपकी GitHub storage का सिर्फ़ **read-only viewer** है; phone की अपनी कोई AI tool history नहीं होती।

### macOS और Linux

Rust engine और app macOS और Linux पर build हो जाते हैं (देखें [Source से build करना](#source-से-build-करना-और-development)), लेकिन उनके लिए अभी कोई installer publish नहीं हुआ है और उन्हें test नहीं किया गया है।

### Web

Web viewer एक static page है जिसे आप खुद host कर सकते हैं (GitHub Pages, Cloudflare Pages, Netlify…) या अपने PC पर चला सकते हैं। देखें [Web और phone viewer](#web-और-phone-viewer)।

## पहली बार setup

ChatRelay पहली बार खुलने पर एक setup wizard आपको इन steps से गुज़ारता है। आप इसे command palette से कभी भी दोबारा चला सकते हैं (**Ctrl+Shift+P → Run First-time Setup Again**, यानी पहली बार वाला setup फिर से चलाएँ)।

1. **आपकी history।** ChatRelay, Claude Code की history `%USERPROFILE%\.claude\projects` में (या `CLAUDE_CONFIG_DIR` वाले folder में) और Codex की history `%USERPROFILE%\.codex` में (या `CODEX_HOME` में) ढूँढता है। यह दिखाता है कि हर tool की कितनी बातचीत मिली।
2. **Claude Code का 30 दिन वाला delete।** Default रूप से Claude Code 30 दिन से पुरानी बातचीत delete कर देता है (`cleanupPeriodDays`)। ChatRelay यह दिखाता है और इसे बढ़ाने का option देता है। बदलने से पहले यह `settings.json` का backup लेता है।
3. **Machine का नाम।** जैसे `OFFICE-PC` या `HOME-LAPTOP`। यह हर बातचीत के साथ दिखता है, ताकि आपको पता रहे कि वह किस PC से आई।
4. **Storage (backend)।** एक folder (Google Drive, OneDrive, Dropbox, network drive) या एक private GitHub repository। अगला section देखें।
5. **Anthropic API key (optional)।** सिर्फ़ summaries के लिए चाहिए। यह Windows Credential Manager (OS keychain) में रखी जाती है, कभी किसी file में नहीं।
6. **Auto-sync।** अपने आप upload/download चालू करता है (Claude Code hooks और background timer)।
7. **Upload everything** (सब कुछ upload करें)। चाहें तो आपकी पूरी मौजूदा history उसी समय progress bar के साथ upload कर देता है।

## History कहाँ रखी जाए (backend)

आपकी history ऐसी जगह जाती है जिसे **आप** control करते हैं। ChatRelay का अपना कोई server नहीं है।

### Option A: एक folder

कोई भी folder जो आपके दूसरे PCs को भी दिखता हो:

- Google Drive for desktop, जैसे `G:\My Drive\chatrelay`
- OneDrive, जैसे `%OneDrive%\chatrelay`
- Dropbox, NAS या network share, या साथ रखी जाने वाली USB drive

वहाँ सिर्फ़ compressed copies जाती हैं। आपके चालू `~/.claude` और `~/.codex` folders कभी cloud folder में नहीं ले जाए जाते। Folder backend हर file के पिछले versions भी रखता है (**Settings → What to sync → Versions kept (folder backend)**, यानी कितने पुराने versions रखे जाएँ; default 2)।

### Option B: एक private GitHub repository

अगर आपको web या phone viewer भी चाहिए, तो यह सबसे अच्छा है।

1. **Sign in with GitHub** (GitHub से sign in करें; recommended)। ChatRelay एक छोटा code दिखाता है; आप उसे github.com पर डालते हैं और approve करते हैं। ChatRelay GitHub App को सिर्फ़ उन्हीं repositories का access मिलता है जो आप चुनते हैं (आम तौर पर सिर्फ़ आपकी history repository), उनके contents पढ़ने और लिखने की permission के साथ। कोई password save नहीं होता, और बीच में कोई server नहीं होता।
2. या एक **personal access token** paste करें (`repo` scope वाला classic token, या सिर्फ़ उस एक repo पर *Contents: Read and write* वाला fine-grained token)। अगर आप GitHub CLI से logged in हैं (`gh auth login`), तो ChatRelay वह token इस्तेमाल कर सकता है।
3. कोई मौजूदा **private** repository चुनें या **Create private repo** (private repo बनाएँ) पर click करें। Public repositories मना कर दी जाती हैं, क्योंकि chat history में private code और secrets हो सकते हैं।

GitHub पर हर upload **एक commit** होता है। 40 MB (compressed) से बड़ी files अपने आप हिस्सों में बँट जाती हैं, क्योंकि GitHub 100 MB से बड़ी अकेली file नहीं लेता।

Token सिर्फ़ OS keychain में रहता है (service `claude-sync`)।

## दूसरे PC पर setup

**PC 1** पर (जिस पर पहले से history है):

1. ChatRelay install करें और एक backend चुनें।
2. Upload करें: Simple view में **Upload now** (अभी upload करें) पर click करें (या setup के आख़िर में **Upload everything**), या Advanced view में किसी project पर **Push**। एक preview हर बातचीत और मिले हुए secrets दिखाता है; आप चाहें तो upload होने वाली copy में उन्हें छिपा (redact) सकते हैं।

**PC 2** पर:

1. ChatRelay install करें और **वही backend** चुनें (वही synced folder, या वही GitHub repo)।
2. Project folder को PC 2 पर रखें (जैसे `git clone` से)। Path अलग हो सकता है, जैसे `C:\Users\me\shop` की जगह `D:\work\shop`।
3. **Bring history to this PC** (history इस PC पर लाएँ; Simple view) पर click करें, या **Sync** view खोलें (Advanced view)। ChatRelay backend का हर project दिखाता है और बताता है कि वह इस PC पर कहाँ जाएगा:
   - **Git projects** अपने remote URL से अपने आप match हो जाते हैं।
   - **बाक़ी projects**: **Import into…** (इसमें import करें) / **Link** पर click करें और एक बार local folder चुनें। यह link याद रखा जाता है।
4. **Dry run** जाँचें: कौन-सी files लिखी जाएँगी और हर path का बदलाव (जैसे `×166  C:\Users\me\shop → D:\work\shop`)। फिर confirm करें।
5. Tool में बातचीत खोलें: `claude --resume` या VS Code का Claude panel; `codex resume` या Codex sidebar।

Codex के लिए: **पहले Codex बंद करें** (CLI, VS Code extension और desktop app)। Codex चलते समय ChatRelay उसकी files में कभी नहीं लिखता; वह बातचीत "Codex is running" (Codex चल रहा है) वजह के साथ छोड़ दी जाती है, और अगली बार आ जाती है।

दोनों PCs पर **Auto-sync** चालू कर दें, फिर यह सब दोबारा हाथ से करने की ज़रूरत नहीं।

## रोज़ का इस्तेमाल

### Simple view और Advanced view

- **Simple view** (default): status dot के साथ आपके projects, दो बड़े buttons (**Upload now** / **Bring history to this PC**), auto-sync switch और update check।
- **Advanced view**: VS Code जैसा layout, जिसमें activity bar (Projects **Ctrl+Shift+E**, Sync **Ctrl+Shift+Y**, Summaries, Logs, Backups, Settings), tabs, status bar और हर action वाला command palette (**Ctrl+Shift+P**) है।

दोनों के बीच **Ctrl+Shift+P → Switch to Simple/Advanced View** से बदलें।

### Status dots

| Dot | मतलब | क्या करें |
|---|---|---|
| हरा | Synced है | कुछ नहीं |
| पीला / नारंगी | इस PC के बदलाव अभी upload नहीं हुए | Push करें, या auto-sync का इंतज़ार करें |
| लाल | पिछला sync fail हुआ | वजह के लिए **Logs** खोलें |
| स्लेटी (grey) | कभी sync नहीं हुआ | एक बार Push करें |
| खोखला गोला | अभी कोई project identity नहीं (link नहीं है) | Push करें (link बन जाएगा) या दूसरे PC वाले project से **Link** करें |

### कई tools की बातचीत

हर बातचीत पर उसके tool का एक छोटा badge होता है (**Claude** या **Codex**)। जिन projects में आपने एक से ज़्यादा tool इस्तेमाल किए, उनमें एक **filter** दिखता है (All / Claude Code / Codex)। बातचीत खोलने पर पूरा transcript दिखता है: आपके messages, assistant के जवाब, tool calls (चलाए गए commands, edit की गई files) और बदली गई files की list।

### Push और pull

- **Push** किसी project की वे बातचीत upload करता है जो पिछले sync के बाद बदली हैं। **Push all** हर project के लिए यही करता है।
- **Pull** नई चीज़ें download करता है। यह हमेशा एक **dry run** से शुरू होता है जो हर वह file दिखाता है जिसे यह लिखेगा और हर path का बदलाव। आपके confirm करने तक कुछ नहीं लिखा जाता।

### Auto-sync

जब **Auto-sync** चालू हो:

- **Claude Code**: `~/.claude/settings.json` में लगे hooks, Claude Code session **शुरू** होने पर (pull) और **ख़त्म** होने पर (push) ChatRelay चलाते हैं।
- **Codex**: Codex में ऐसा कोई hook नहीं है, इसलिए desktop app हर 15 मिनट पर जाँच करता है (app खुलने के 20 सेकंड बाद से)। यह उन projects को upload करता है जिनकी Codex बातचीत बदली है और नई बातचीत download करता है (Codex चलते समय यह छोड़ दिया जाता है)।
- जो uploads offline होने की वजह से fail हुए, वे queue में रखे जाते हैं और फिर से कोशिश की जाती है।

Auto-sync को आप Settings में, tray menu में, या `claude-sync hooks install|uninstall` से चालू या बंद कर सकते हैं।

### Tray menu

Push now · Pull now · Auto-sync on/off · Last sync status · Open · Quit (अभी push · अभी pull · auto-sync चालू/बंद · पिछले sync का status · खोलें · बंद करें)।

### Backups

हर write से पहले `~/.claude-sync/backups/<timestamp>-<what>/` में एक backup बनता है। उन्हें देखने के लिए **Backups** खोलें (या `claude-sync backups`), और किसी एक को **Restore** (वापस लाएँ) करके हर file बिल्कुल पहले जैसी कर दें। Restore उन files को भी हटा देता है जो उस बदलाव ने बनाई थीं।

### Logs

**Logs** में ChatRelay का किया हुआ सब कुछ दिखता है, errors highlight होकर, और एक button जो error report copy कर देता है।

## Codex support विस्तार से

हर Codex बातचीत के साथ क्या-क्या जाता है:

| चीज़ | Codex इसे कहाँ रखता है | ChatRelay क्या करता है |
|---|---|---|
| बातचीत ("rollout") | `~/.codex/sessions/YYYY/MM/DD/rollout-<time>-<id>.jsonl` (कुछ versions `.jsonl.zst`, यानी compressed, लिखते हैं) | Copy होती है, हर path बदला जाता है |
| Thread की index row | `~/.codex/state_5.sqlite`, table `threads` | जोड़ी या update की जाती है ताकि बातचीत `codex resume` और sidebar में दिखे |
| Thread का नाम | `~/.codex/session_index.jsonl` | जोड़ा जाता है |
| उस thread की Codex memory | `~/.codex/memories_1.sqlite`, table `stage1_outputs` | अगर इस PC पर उस thread की memory नहीं है तो जोड़ी जाती है; paths बदले जाते हैं |
| उस thread के goals | `~/.codex/goals_1.sqlite`, tables `thread_goals`, `thread_goal_continuation_deferrals` | अगर इस PC पर उस thread के goals नहीं हैं तो जोड़े जाते हैं |

ज़रूरी बातें:

- ChatRelay के लिखते समय **Codex बंद होना चाहिए**। ChatRelay चल रहे `codex` processes (CLI, VS Code extension, desktop app) जाँचता है। Background sync के दौरान यह आपसे कुछ बंद करने को नहीं कहता; बस बाद में फिर कोशिश करता है।
- **History mode वैसा ही रहता है।** Codex के नए versions "paginated" history रखते हैं; जब आप बातचीत पहली बार खोलते हैं तो Codex अपना page database (`thread_history_*.sqlite`) बातचीत की file से दोबारा बना लेता है, इसलिए ChatRelay उस database में कभी नहीं लिखता।
- **किसी thread की आपकी अपनी settings आपकी ही रहती हैं।** Update पर इस PC की pinned state, custom नाम, archive state और account वैसे ही रहते हैं। जो folders और sections सिर्फ़ दूसरे PC पर हैं, वे हटा दिए जाते हैं।
- **Account।** Import किया गया thread उस Codex account को दिया जाता है जिसके पास इस PC पर सबसे ज़्यादा threads हैं।
- **Windows path prefix।** Windows पर Codex working folders को `\\?\D:\project` की तरह रखता है। ChatRelay यह prefix सिर्फ़ Windows paths में और सिर्फ़ उस PC पर जोड़ता है जिसका Codex इसे इस्तेमाल करता है, macOS या Linux paths में कभी नहीं।
- **Compressed बातचीत** (`.jsonl.zst`) पढ़ी और update की जा सकती है। Update पर file की जगह एक सादी `.jsonl` आ जाती है (compressed original का backup पहले ले लिया जाता है)।
- **Memory का हिसाब-किताब** जो दूसरे PC का है (कोई memory कितनी बार इस्तेमाल हुई, क्या उसे consolidation के लिए चुना गया था), copy नहीं होता।
- **अनजान versions।** अगर Codex का index कोई ऐसा database इस्तेमाल करता है जिसे ChatRelay नहीं जानता (जैसे आगे आने वाला `state_6.sqlite`), या कोई ऐसा ज़रूरी field जोड़ता है जिसे वह भर नहीं सकता, तो Codex के लिए writing साफ़ warning के साथ बंद कर दी जाती है। पढ़ना फिर भी चलता है।

## Summaries और "Continue in another tool"

> 🔒 **Secrets कभी AI तक नहीं पहुँचते।** Model को कुछ भी भेजने से पहले ChatRelay chats में मिली keys, tokens और passwords (Anthropic, OpenAI, OpenRouter, GitHub, AWS, Google, Slack, Stripe, Hugging Face, npm, SendGrid, Telegram bot की API keys; JWT; private keys; `PASSWORD=…` जैसी lines; URL के अंदर के passwords) को `[REDACTED:kind]` से बदल देता है। यह हमेशा होता है, बंद नहीं किया जा सकता; screen पर दिखता है कि कितने छुपाए गए। आपका code और बाकी बातचीत फिर भी भेजी जाती है, इसलिए private या client code के लिए ऐसा paid model चुनें जिसका provider data नहीं रखता।

**Summaries** खोलें (Advanced view), एक project चुनें, बातचीत (किसी भी tool की) और एक model पर tick करें, फिर **Generate handoff** (handoff बनाएँ) पर click करें।

- Models: **Claude Opus 5.5** (default), Claude Sonnet 5.5 (तेज़, सस्ता), Claude Haiku 5.5 (सबसे सस्ता), Claude Fable 5.1 (सबसे ज़्यादा capable)। आपको एक Anthropic API key चाहिए (**Settings → Summaries**)।
- पहले history छोटी की जाती है: आपकी requests, हर turn में assistant का आख़िरी जवाब, और बदली गई files। लंबा tool output और thinking हटा दिए जाते हैं। सभी tools की बातचीत समय के क्रम में मिला दी जाती है और हर एक पर उसके tool का label लगता है।
- लंबी histories का summary लगभग 100k-token के हिस्सों में बनता है और फिर उन्हें मिला दिया जाता है।
- नतीजे में ये sections होते हैं: Project overview, What's done, Key decisions, Open bugs / known issues, Next steps, Files touched (project का परिचय, क्या हो चुका है, मुख्य फ़ैसले, बाक़ी bugs / मालूम दिक्कतें, अगले steps, छुई गई files)।

फिर आप:

- Project folder में **Save HANDOFF.md** (HANDOFF.md save करें) कर सकते हैं, या
- किसी tool में **Continue in…** (…में जारी रखें): Claude Code (`CLAUDE.md`), Codex (`AGENTS.md`) या Gemini CLI (`GEMINI.md`) चुनें। List में वही tools दिखते हैं जो इस PC पर installed हैं। ChatRelay उस file में एक छोटा "Previous context" section (overview, क्या हो चुका है, अगले steps) जोड़ता है। दोबारा चलाने पर सिर्फ़ उसका अपना section बदला जाता है; बाक़ी file को छुआ नहीं जाता।
- या text को **copy** कर सकते हैं।

Command line से: `claude-sync summarize --target handoff|claude-md|agents-md|gemini-md|none`।

## Web और phone viewer

**🌐 लाइव वेब व्यूअर:** <https://abh1shxkk.github.io/claude-sync-web/>

App का एक read-only version जो आपके **GitHub** backend की history किसी भी browser से या Android app से खोलता है: projects, हर tool की बातचीत, और पूरे transcripts। यह वही Rust engine इस्तेमाल करता है, WebAssembly में compile किया हुआ, इसलिए यह बिल्कुल वही दिखाता है जो desktop app दिखाता है। Upload, download, auto-sync और summaries desktop app में ही रहते हैं, क्योंकि उन्हें local history folders चाहिए।

- GitHub से sign in करें, या अपने repo के नाम और एक **fine-grained token से जो सिर्फ़ उसी repo तक, Contents: Read-only के साथ, सीमित हो**।
- Token सिर्फ़ उसी browser में रखा जाता है (अगर आप "remember" पर tick करें तो localStorage में, वरना sessionStorage में)।
- Page सिर्फ़ `api.github.com` से बात करता है और कोई third-party script load नहीं करता।
- पहली बार खोलने पर यह messages गिनने के लिए हर बातचीत को एक बार पढ़ता है; नतीजे content hash के हिसाब से cache हो जाते हैं।
- Phone जितनी छोटी screen पर layout एक pane में बदल जाता है: list → project → transcript, back button और नीचे एक bar के साथ।

## सुरक्षा और privacy

- **Upload पर originals कभी नहीं बदले जाते।** Upload सिर्फ़ आपकी history files को पढ़ता है।
- **Tool चलते समय कुछ नहीं लिखा जाता** (Codex)। Claude Code का खुला session (जिसने hook चलाया) कभी छुआ नहीं जाता।
- **हर write से पहले backup**, जिसमें Claude Code की `settings.json`, Codex के databases (उनकी `-wal` और `-shm` files के साथ) और `session_index.jsonl` भी शामिल हैं।
- **हर import के लिए dry run।** कुछ भी होने से पहले आप हर file और हर path का बदलाव देख लेते हैं।
- **Conflict पर दोनों versions रखे जाते हैं**, कभी overwrite नहीं होते।
- **Secret scan।** Upload से पहले ChatRelay API keys और passwords ढूँढता है: Anthropic, OpenAI, GitHub, AWS, Google, Slack और Stripe keys, JWTs, private keys, `.env` जैसी `SECRET=…` lines, और URLs के अंदर के credentials। आप चुनते हैं: **warn** (चेतावनी), **redact** (सिर्फ़ upload होने वाली copy में `[REDACTED:kind]` से बदल देना), या **off** (बंद)।
- **Secrets OS keychain में रहते हैं।** आपका GitHub token और Anthropic key कभी किसी file में नहीं लिखे जाते।
- **आपके logins को कभी छुआ नहीं जाता।** ChatRelay, Claude Code या Codex की login files (`~/.claude/.credentials.json`, `~/.codex/auth.json`, …) को न पढ़ता है, न copy करता है, न बदलता है। History sync करने से आप log out नहीं हो सकते। अगर आप log out होते हैं, तो वह tool की अपनी वजह से होता है (जैसे session expire होना या किसी दूसरे PC पर दूसरे account से sign in करना)।
- **सिर्फ़ private storage।** Public GitHub repositories मना कर दी जाती हैं।
- **ChatRelay का कोई server नहीं।** Data सिर्फ़ आपके PCs, आपके folder या GitHub, और (सिर्फ़ जब आप summary बनाते हैं) Anthropic API के बीच जाता है।

जान-बूझकर sync नहीं होता: `~/.claude/history.jsonl` (सभी projects में आपकी up-arrow वाली prompt history), `~/.claude/file-history/` (rewind snapshots), और सारे credentials।

| AI tools | (status) | हर tool: installed है या नहीं, version, पहचाना गया format, restore चालू/बंद, warnings, बातचीत की गिनती, context file |

| What to sync | Subagent transcripts (sidecars) | Claude Code के हर session के `subagents/` और `tool-results/` folders |
| What to sync | Project memory | Claude Code का हर project वाला memory folder (`memory/`) |
| What to sync | Secret scan before upload | Off / Warn / Auto-redact |

| Secrets | GitHub token, Anthropic API key | OS keychain में रखे जाते हैं (**Remove from keychain** किसी एक को delete करता है) |

| Appearance | Theme | Dark / light |

यही settings command line से: `claude-sync config [key] [value]`, जैसे `config machineName DESK-1`, `config backend.folder "G:\My Drive\chatrelay"`, `config backend.github me/my-history`, `config secretScan redact`।

## Command-line tool (CLI)

Installer, app के पास ही `claude-sync.exe` रखता है (`%LOCALAPPDATA%\Claude Sync\`)। Claude Code hooks यही चलाते हैं। इसे कहीं से भी इस्तेमाल करने के लिए उस folder को अपने `PATH` में जोड़ें। Source से: `cargo run -p claude-sync-cli -- …`।

```
claude-sync scan [--json]                 List projects & sessions
claude-sync status [--json]               Backend, last sync, hooks, queue, cleanupPeriodDays
claude-sync push [--cwd <dir>] [--all] [--dry-run] [--redact]
claude-sync pull [--cwd <dir>] [--project <id>] [--all] [--dry-run]
claude-sync summarize [--cwd <dir>] [--model <id>] [--target handoff|claude-md|agents-md|gemini-md|none]
claude-sync remote                        List projects stored in the backend
claude-sync link <dir> <projectId>        Link a local folder to a remote project ID (--remove to unlink)
claude-sync config [key] [value]          Show or set config (machineName, backend.folder, backend.github, secretScan, ...)
claude-sync secret set github-token|anthropic-api-key <value>
claude-sync hooks install|uninstall       Add/remove the SessionStart/SessionEnd hooks
claude-sync cleanup-days <n>              Set Claude Code's cleanupPeriodDays (backs up settings.json)
claude-sync backups [restore <id>]        List or restore backups
claude-sync queue                         Retry queued (offline) pushes

Other AI coding tools (provider = claude-code | codex):
claude-sync providers [--json]            Which tools are installed, their version/format, import on/off
claude-sync providers sessions <provider> [--cwd <dir>] [--json]
claude-sync providers show <provider> <id> [--json]      Read a session in the tool-neutral format
claude-sync providers export <provider> <id> --out <file.json.gz>
claude-sync providers import <file.json.gz> --to <dir> [--dry-run]

Flags: --hook (read Claude Code hook JSON from stdin; never fails), --quiet, --json, --verbose
```

Commands का हिन्दी में मतलब:

- `scan` — projects और sessions की list; `status` — backend, पिछला sync, hooks, queue, cleanupPeriodDays।
- `push` / `pull` — upload / download (`--dry-run` से सिर्फ़ preview)।
- `summarize` — summary बनाना; `remote` — backend में रखे projects की list।
- `link` — किसी local folder को remote project ID से जोड़ना (`--remove` से link हटाना)।
- `config` — config देखना या बदलना; `secret set` — token या API key keychain में रखना।
- `hooks install|uninstall` — SessionStart/SessionEnd hooks जोड़ना/हटाना।
- `cleanup-days <n>` — Claude Code का cleanupPeriodDays सेट करना (settings.json का backup लेकर)।
- `backups [restore <id>]` — backups की list या restore; `queue` — queue में रुके (offline) pushes फिर से चलाना।
- `providers …` — दूसरे AI coding tools: कौन-से tools installed हैं, उनका version/format, import चालू/बंद; किसी tool के sessions की list; किसी session को tool-neutral format में पढ़ना; export और import।
- Flags: `--hook` (stdin से Claude Code का hook JSON पढ़ता है; कभी fail नहीं होता), `--quiet`, `--json`, `--verbose`।

Exit codes: `0` OK, `1` error, `2` push में conflicts थे (पहले pull करें)।

## यह कैसे काम करता है (technical)

### Claude Code history कहाँ रखता है

| Path | क्या है |
|---|---|
| `~/.claude/projects/<encoded-path>/<session-uuid>.jsonl` | हर session की एक file, हर line में एक JSON object |
| `~/.claude/projects/<encoded-path>/<session-uuid>/subagents/*.jsonl` + `*.meta.json` | Subagent transcripts ("sidecar" के रूप में sync होते हैं) |
| `~/.claude/projects/<encoded-path>/<session-uuid>/tool-results/*` | Disk पर save हुए बड़े tool outputs (sidecar) |
| `~/.claude/projects/<encoded-path>/memory/` | Project की auto-memory (`MEMORY.md` + notes) |

आम धारणाओं से अलग बातें, जो सब संभाली जाती हैं:

- **Drive-letter का case client के हिसाब से अलग होता है।** VS Code extension `c:\Users\…` लिखता है (folder `c--Users-…`), CLI `C:\Users\…` लिखता है (folder `C--Users-…`), और एक ही session में दोनों हो सकते हैं। Windows पर paths की तुलना case-insensitive होती है।
- **Folder के नाम भरोसे से decode नहीं हो सकते।** `C:\Users\me\my project` और `C:\Users\me\my-project` दोनों `C--Users-me-my-project` बनते हैं। असली path sessions में दर्ज `cwd` से आता है; नाम को decode करना सिर्फ़ एक label वाला fallback है।
- **Sessions बहुत बड़े हो सकते हैं** (embedded images/PDFs के साथ 200+ MB), इसलिए सब कुछ stream होता है। Scan के नतीजे size और modification time के हिसाब से cache होते हैं, इसलिए दोबारा scan करने में लगभग 100 ms लगते हैं।
- **Assistant का एक जवाब कई lines में फैला होता है** (हर content block की एक line, एक ही `message.id`); message गिनती में इन्हें एक ही गिना जाता है। Titles पहले असली prompt से आते हैं (IDE के wrapper tags हटाकर); Claude Code का अपना `ai-title` उसके पास दिखता है।
- **User/assistant के अलावा कई तरह की lines** (`attachment`, `file-history-snapshot`, `queue-operation`, `ai-title`, `last-prompt`, `permission-mode`, …)। अनजान types और fields बिना छुए रखे जाते हैं।

### Codex history कहाँ रखता है

देखें [Codex support विस्तार से](#codex-support-विस्तार-से)। Rollout की हर line `{timestamp, type, payload}` होती है; पहली line `session_meta` होती है जिसमें session id और `cwd` होते हैं। Codex ने बातचीत तीन पीढ़ियों (generations) में लिखी है (≥0.15x में `event_msg/item_completed` items, उससे पहले `user_message`/`agent_message` events, सबसे पुराने में सादे `response_item` messages); viewer मौजूद सबसे ज़्यादा जानकारी वाला रूप इस्तेमाल करता है।

### Adapters

हर AI tool एक **adapter** है (`crates/core/src/providers/`), जो एक ही interface (`ProviderAdapter`) के पीछे है: tool और उसका format पहचानना, projects और sessions की list बनाना, किसी session को tool-neutral रूप (`UniversalSession`) में पढ़ना, उसे बिना कुछ खोए export करना (`SessionBundle`: original files और tool का metadata, जैसे Codex की index row), उसे दूसरे PC पर import करना (paths बदलना, जाँचना कि tool चल तो नहीं रहा, backup, dry run), और नई lines जोड़ना। देखें [नया AI tool जोड़ना](#नया-ai-tool-जोड़ना-adapter-guide)।

### Project identity

एक ही project का path हर PC पर अलग होता है, इसलिए उसकी पहचान इस क्रम में होती है:

1. एक **manual link** (Link button / `claude-sync link <dir> <id>`), जो ChatRelay के config में रखा जाता है
2. **git remote**, एक जैसे रूप में बदलकर: `git@github.com:Me/Repo.git` और `https://github.com/me/repo` दोनों `git:github.com/me/repo` बन जाते हैं
3. Project root में एक **`.claude-sync.json`** जिसमें एक UUID होता है; non-git projects के लिए यह पहले push पर बनता है (इसे commit करें, या दूसरे PC पर हाथ से link करें)। "Upload everything" और background sync इसकी जगह ChatRelay के config में link बनाते हैं, ताकि आपके project folders में कुछ न लिखा जाए।

### Storage layout (folder या repo में)

```
<projectId-slug>/
  manifest.json                          machines, original paths, hashes, timestamps, revision
  <sessionId>.jsonl.gz                   Claude Code session (whole, or its start when deltas exist)
  <sessionId>.d<N>.jsonl.gz              lines appended after that, one blob per push
  <sessionId>.sidecar.json.gz            subagents/ + tool-results/ (if any)
  memory.json.gz                         Claude Code project memory (if any)
  <provider>-<sessionId>.bundle.json.gz  another tool's session (e.g. codex-…): files + metadata
  <provider>-<sessionId>.d<N>.jsonl.gz   lines appended to it later
  .versions/<file>/<timestamp>           previous versions (folder backend)
```

इन files का हिन्दी में मतलब:

- `manifest.json` — machines, original paths, hashes, timestamps, revision।
- `<sessionId>.jsonl.gz` — Claude Code session (पूरा, या deltas होने पर उसकी शुरुआत)।
- `<sessionId>.d<N>.jsonl.gz` — उसके बाद जोड़ी गई lines, हर push का एक blob।
- `<sessionId>.sidecar.json.gz` — `subagents/` + `tool-results/` (अगर हों)।
- `memory.json.gz` — Claude Code की project memory (अगर हो)।
- `<provider>-<sessionId>.bundle.json.gz` — किसी दूसरे tool का session (जैसे `codex-…`): files + metadata।
- `<provider>-<sessionId>.d<N>.jsonl.gz` — उसमें बाद में जोड़ी गई lines।
- `.versions/<file>/<timestamp>` — पिछले versions (folder backend)।

दूसरे tools के sessions manifest में `providerSessions` के नीचे लिखे होते हैं (key `<provider>:<id>`)। App के पुराने versions उस list को नज़रअंदाज़ करते हैं और उसे जैसा है वैसा रहने देते हैं।

### Push

- Sessions की तुलना SHA-256 से होती है; सिर्फ़ नए या बदले हुए sessions upload होते हैं। Originals को सिर्फ़ पढ़ा जाता है।
- **सिर्फ़ नई lines भेजी जाती हैं।** AI tools बातचीत की file के आख़िर में सिर्फ़ जोड़ते हैं, इसलिए किसी session के पहले upload के बाद push सिर्फ़ पिछले sync के बाद जुड़ी lines को एक "delta" हिस्से के रूप में रखता है। हर हिस्सा उस machine के paths दर्ज करता है जिसने उसे push किया। Session hashes एक chain में जुड़े होते हैं (`hash = sha256(previous : sha256(part))`)। 40 हिस्सों के बाद अगला push पूरा session फिर से upload करता है। जब यह shortcut लागू नहीं होता (file किसी और तरीके से बदली, conflict हुआ, किसी पुराने version की state है), तो पूरी file upload होती है।
- अगर backend में कोई ऐसा version है जो आपने नहीं देखा और जिसमें ऐसे messages हैं जो आपके पास नहीं हैं, तो उस session का push "pull first" (पहले pull करें) कहकर मना कर दिया जाता है, ताकि कुछ न खोए।
- **Offline हैं?** (GitHub तक पहुँच नहीं, या cloud drive mount नहीं है।) Push `~/.claude-sync/queue.json` में queue हो जाता है और अगली बार चलने पर, और desktop app द्वारा हर 15 मिनट पर, फिर से कोशिश होती है।

### Pull

- Paths parsed JSON के अंदर बदले जाते हैं (string values **और** object keys दोनों), इसलिए JSON escaping से कभी दिक्कत नहीं होती। संभाले जाने वाले रूप: Windows paths `C:\…`, `c:/…`, Git-Bash `/c/…` और WSL `/mnt/c/…` के रूप में (case-insensitive); POSIX paths (case-sensitive); `file:///` URLs, `%20`-encoded spaces समेत; एक operating system से दूसरे पर जाते समय project root के बाद के separators बदल दिए जाते हैं; tool का अपना home folder (`~/.claude`, `~/.codex`) और Claude Code का encoded folder नाम भी बदले जाते हैं। `shop-old` जैसे पास वाले (sibling) folders को कभी छुआ नहीं जाता।
- **Fast path:** जिस PC पर बिल्कुल वही है जो उसने पिछली बार sync किया था, वह सिर्फ़ ग़ायब हिस्से download करके जोड़ देता है।
- **अलग-अलग बदलाव (divergence)** (बातचीत में सिर्फ़ जोड़ा जाता है; Claude Code के लिए line ids से और दूसरे tools के लिए text की शुरुआत (prefix) से तुलना होती है):
  - remote में local पूरा शामिल है → update
  - local में remote पूरा शामिल है → आपका version नया है और रखा जाता है (अगले push पर upload होगा)
  - दोनों बदले → **conflict**: आपकी copy जैसी है वैसी रहती है, और दूसरा version एक **नई बातचीत के रूप में नई id के साथ** save होता है (Codex में नाम "<name> (from <PC>)")। फिर दोनों tool में दिखती हैं और आपके दूसरे PCs पर sync होती हैं।

### Auto-sync hooks (Claude Code)

"Enable auto-sync" (auto-sync चालू करें) इसे `~/.claude/settings.json` में मिला देता है; आपकी बाक़ी settings और hooks वैसे ही रहते हैं, और पहले एक backup बनता है:

```jsonc
"hooks": {
  "SessionStart": [{ "hooks": [{ "type": "command", "command": "\"…/Claude Sync/claude-sync.exe\" pull --hook --quiet --claude-sync-hook", "timeout": 60 }] }],
  "SessionEnd":   [{ "hooks": [{ "type": "command", "command": "\"…/Claude Sync/claude-sync.exe\" push --hook --quiet --claude-sync-hook", "timeout": 60 }] }]
}
```

- `--hook` stdin से Claude Code का hook JSON (`cwd`, `session_id`) पढ़ता है; वह न मिले तो `CLAUDE_PROJECT_DIR` और फिर working directory इस्तेमाल करता है। Hooks **हमेशा 0 पर exit** करते हैं, इसलिए वे कभी कोई session नहीं बिगाड़ सकते; errors Logs panel में जाते हैं।
- Hook, app के पास install हुआ native `claude-sync` executable चलाता है। Node.js की ज़रूरत नहीं।
- "Disable auto-sync" (auto-sync बंद करें) सिर्फ़ वही hooks हटाता है जिनमें `claude-sync-hook` marker है।

## Updates

- Desktop app नया version तब जाँचता है जब वह शुरू होता है, हर बार जब उसकी window खोली जाती है, हर घंटे, जब आप 5 मिनट या ज़्यादा बाद window पर वापस आते हैं, और जब आप **Check for updates** (updates जाँचें) पर click करते हैं (Settings → About, Simple view, या command palette)। जाँच के दौरान एक spinner दिखता है।
- जब नया version उपलब्ध हो, तो आपको **A new version is available → Update now** (नया version उपलब्ध है → अभी update करें) दिखता है। App उसे download करता है, उसका signature जाँचता है (apps सिर्फ़ project की key से signed updates ही लेते हैं), उसे अपनी जगह पर install करता है और restart होता है। History और settings वैसी ही रहती हैं।
- Android app नए APK के link के साथ एक notice दिखाता है।

## समस्या-समाधान और FAQ

**SmartScreen installer को रोक देता है।** Installer code-signed नहीं है। **More info → Run anyway** पर click करें।

**किसी project पर पीला dot दिखता है।** उसकी कुछ बातचीत इस PC पर है जो अभी upload नहीं हुई। उसे Push करें, या auto-sync चालू करें।

**मेरे दूसरे PC का project नहीं दिखता / किसी और नाम से दिखता है।** Projects git remote, `.claude-sync.json`, या link से match होते हैं। अगर folders के नाम अलग हैं और कोई git remote नहीं है, तो एक बार **Link** (या **Import into…**) इस्तेमाल करें और सही local folder चुनें।

**एक Codex बातचीत छोड़ दी गई: "Codex is running"।** Codex CLI, VS Code extension का Codex panel (या VS Code) और Codex desktop app बंद करें, फिर दोबारा pull करें। Background sync अपने आप फिर कोशिश करता है।

**Codex import बंद है: "Unknown Codex index database" / "new required fields"।** आपका Codex उससे नया है जितना यह ChatRelay version जानता है। ChatRelay update करें। आपकी बातचीत फिर भी दिखती रहेगी।

**मुझे एक बातचीत दो बार दिखती है, एक के आख़िर में "(from OFFICE-PC)"।** Sync होने से पहले उसे दोनों PCs पर आगे बढ़ाया गया था। दोनों versions रखे गए हैं; जो नहीं चाहिए उसे tool में delete कर दें।

**मेरी पुरानी Claude Code बातचीत ग़ायब हो गई।** Claude Code, `cleanupPeriodDays` (default 30) से पुरानी बातचीत delete कर देता है। इसे Settings में बढ़ाएँ (या `claude-sync cleanup-days 3650`)। जो बातचीत पहले से upload हो चुकी है, उसे backend से वापस pull किया जा सकता है।

**क्या sync करने से मैं Claude से log out हो गया?** नहीं। ChatRelay login files को कभी नहीं पढ़ता या लिखता। देखें [सुरक्षा और privacy](#सुरक्षा-और-privacy)।

**पहली बार upload धीमा है।** पहला upload सब कुछ (compressed) भेजता है। उसके बाद सिर्फ़ नई lines भेजी जाती हैं।

**Push करते समय "Pull first"।** किसी दूसरे PC ने एक नया version upload किया है जो आपके पास नहीं है। Pull करें, फिर push करें।

**Offline।** Pushes queue में रखे जाते हैं और अपने आप फिर से कोशिश होती है; `claude-sync queue` अभी तुरंत फिर से कोशिश करता है।

**Pull के बाद कुछ गड़बड़ हो गई।** **Backups** खोलें और उससे ठीक पहले बना backup restore करें।

**Errors कहाँ मिलेंगे?** **Logs** view में (वहाँ से error report copy करें), या `~/.claude-sync/logs/claude-sync.log` में।

## Source से build करना और development

ज़रूरतें: Node.js 20+, Rust (stable), और Windows पर MSVC toolchain (Visual Studio "Desktop development with C++")।

```bash
git clone https://github.com/Abh1shxkk/chatrelay.git
cd chatrelay
npm install
npm run tauri:dev      # run the desktop app with hot reload
npm run test:rust      # cargo test --workspace: engine, adapters, push/pull, GitHub backend
npm test               # UI helper tests (vitest)
npm run typecheck      # TypeScript
npm run tauri:build    # installer in target/release/bundle/nsis/
```

ऊपर के commands: `tauri:dev` desktop app को hot reload के साथ चलाता है; `test:rust` engine, adapters, push/pull और GitHub backend के tests चलाता है; `npm test` UI helper tests (vitest) चलाता है; `typecheck` TypeScript जाँचता है; `tauri:build` installer को `target/release/bundle/nsis/` में बनाता है।

Project की बनावट:

```
crates/core/       Rust engine: scanner, JSONL, path rewriting, sync, backends, hooks, summaries
crates/core/src/providers/   AI tool adapters: claude_code.rs, codex.rs (+ codex_format.rs, browser-safe parsing)
crates/core/src/provider_sync.rs   other tools' sessions in push/pull (bundles, deltas, conflict copies)
crates/core/tests/  integration tests with fixture files (tests/fixtures/codex, tests/fixtures/claude-code)
crates/cli/        the `claude-sync` CLI (also what the Claude Code hooks run)
crates/wasm/       the engine compiled to WebAssembly for the web and phone viewers
src-tauri/         desktop app: window, tray, background sync, the API behind window.claudeSync
src/renderer/      React + TypeScript + Tailwind UI (shared by desktop, web and phone)
src/shared/        TypeScript types and helpers
mobile/            Android / iOS shell around the web version (Tauri)
scripts/           release, CLI staging, WASM build
tests/             vitest tests; tests/web/mock-github.mjs for testing the web version
```

हिन्दी में:

- `crates/core/` — Rust engine: scanner, JSONL, path बदलना, sync, backends, hooks, summaries।
- `crates/core/src/providers/` — AI tool adapters: `claude_code.rs`, `codex.rs` (+ `codex_format.rs`, browser में चलने लायक parsing)।
- `crates/core/src/provider_sync.rs` — push/pull में दूसरे tools के sessions (bundles, deltas, conflict copies)।
- `crates/core/tests/` — fixture files के साथ integration tests (`tests/fixtures/codex`, `tests/fixtures/claude-code`)।
- `crates/cli/` — `claude-sync` CLI (Claude Code hooks भी यही चलाते हैं)।
- `crates/wasm/` — web और phone viewers के लिए WebAssembly में compile किया हुआ engine।
- `src-tauri/` — desktop app: window, tray, background sync, `window.claudeSync` के पीछे की API।
- `src/renderer/` — React + TypeScript + Tailwind UI (desktop, web और phone में साझा)।
- `src/shared/` — TypeScript types और helpers।
- `mobile/` — web version के चारों ओर Android / iOS shell (Tauri)।
- `scripts/` — release, CLI staging, WASM build।
- `tests/` — vitest tests; web version test करने के लिए `tests/web/mock-github.mjs`।

Installed app के साथ-साथ एक development copy चलाना: एक अलग identifier और data folder सेट करें, ताकि यह आपकी असली settings को कभी न छुए:


(`wasm-bindgen-cli` का version `Cargo.lock` में मौजूद `wasm-bindgen` से मेल खाना चाहिए; `web:wasm` WebAssembly engine दोबारा build करता है; `web:dev` इसे `http://localhost:5175/web.html` पर चलाता है; `web:build` `out/web/` में static site बनाता है, जिसे GitHub Pages, Cloudflare Pages, Netlify… पर host किया जा सकता है।)

`node tests/web/mock-github.mjs <folder-backend>` किसी folder backend को नकली GitHub API की तरह चलाता है (सिर्फ़ dev builds में: `localStorage['claude-sync-web:apiBase'] = 'http://localhost:5176'` सेट करें और token `test-token-123456` इस्तेमाल करें)।

### Mobile app (Android, iOS)

**Android** के लिए JDK 17, Android SDK (platform 36, build-tools 36, NDK r27) और Rust के Android targets चाहिए (`tauri android init` इन्हें install कर देता है):

```powershell
$env:JAVA_HOME = "<jdk-17>"; $env:ANDROID_HOME = "<android-sdk>"; $env:NDK_HOME = "$env:ANDROID_HOME\ndk\<version>"
npm run mobile:android:init      # once: generates mobile/gen/android
npm run mobile:android:apk       # debug APK for a phone (arm64)
adb install -r <that apk>
npm run mobile:android:release   # release APK/AAB, signed when CLAUDE_SYNC_KEYSTORE_PROPERTIES is set
```

(`mobile:android:init` सिर्फ़ एक बार चलाना है: यह `mobile/gen/android` बनाता है; `mobile:android:apk` phone (arm64) के लिए debug APK बनाता है; `mobile:android:release` release APK/AAB बनाता है, जो `CLAUDE_SYNC_KEYSTORE_PROPERTIES` सेट होने पर signed होता है।)

Release signing एक properties file पढ़ता है जो **repo के बाहर** रखी जाती है, और जिसका नाम `CLAUDE_SYNC_KEYSTORE_PROPERTIES` में दिया जाता है:

```properties
storeFile=D:/dev/android-keys/claude-sync-release.jks
storePassword=…
keyAlias=claude-sync
keyPassword=…
```

Key एक बार `keytool -genkeypair -keystore claude-sync-release.jks -alias claude-sync -keyalg RSA -keysize 4096 -validity 10000` से बनाएँ और उसका backup रखें: installed app के updates उसी key से signed होने चाहिए।

**iOS** के लिए Xcode वाला Mac और `rustup target add aarch64-apple-ios aarch64-apple-ios-sim` चाहिए:

```bash
npm install && npm run web:wasm
npm run mobile:ios:init
npm run mobile:ios:dev
npm run mobile:ios:build
```

## नया AI tool जोड़ना (adapter guide)

1. **पहले किसी असली machine पर storage format जाँचें**: sessions कहाँ रहते हैं, line/record का format, कोई index database और उसका schema, tool sessions की list कैसे बनाता है, paths कैसे रखता है, कौन-से processes का मतलब है कि tool "चल रहा है"। यह सब adapter file के ऊपर लिख दें।
2. `crates/core/src/providers/mod.rs` में एक `ProviderId` जोड़ें और एक file `providers/<tool>.rs` बनाएँ जो `ProviderAdapter` implement करे: `detect`, `list_projects`, `list_sessions`, `read_session`, `export_session`, `import_session`, और चाहें तो `append_session`, `context_file_name`, `process_names`।
3. हर adapter इन नियमों को मानता है: tool चलते समय लिखने से मना करना (`ensure_not_running`), लिखने से पहले हर file का backup लेना (`ImportOptions.backups`), `dry_run` का पालन करना, `keep_both` का पालन करना (अलग राह पर गया आने वाला session नई id के साथ save करना), और कोई भी अनजान format दिखने पर import बंद कर देना (`ProviderStatus` में warning के साथ)।
4. शुद्ध parsing को ऐसी file में रखें जिसमें file-system access न हो (जैसे `codex_format.rs`), ताकि web viewer उसे इस्तेमाल कर सके, और उसे `messages_from_bundle` में जोड़ें।
5. `crates/core/tests/fixtures/<tool>/` में fixture files जोड़ें और tests लिखें: detect, list, read, export → दूसरी नकली machine पर import (paths बदले हुए), update, local-ahead (local आगे है), conflict, चल रहे process पर मना करना, अनजान format।
6. `src/shared/types.ts` (`PROVIDER_LABELS`) में label जोड़ें। Badges, filters, push/pull, summaries और viewer इसे वहीं से ले लेते हैं।

## Release publish करना

Installed apps [Abh1shxkk/claude-sync-releases](https://github.com/Abh1shxkk/claude-sync-releases) पर `latest.json` जाँचते हैं।

1. `package.json`, `src-tauri/tauri.conf.json`, `mobile/tauri.conf.json` और `Cargo.toml` में `version` बढ़ाएँ।
2. `npm run release -- --notes "What changed"`

यह updater key (`TAURI_SIGNING_PRIVATE_KEY`, या `D:\dev\tauri-keys\claude-sync-updater.key` अपनी `.password` file के साथ) से signed Windows installer और signed APK build करता है, `latest.json` लिखता है और सब कुछ release `v<version>` के रूप में upload कर देता है। Flags: `--no-apk`, `--skip-build`, `--dry-run`, `--notes-file <file>`। GitHub login `git credential fill` (या `GITHUB_TOKEN`) से आता है।

Updater key का backup रखें। Apps सिर्फ़ उसी key से signed updates लेते हैं; उसका public हिस्सा `src-tauri/tauri.conf.json` में है।

## मालूम कमियाँ

- Windows installer code-signed नहीं है (SmartScreen warning)।
- सिर्फ़ Windows पर test हुआ है। macOS और Linux पर build होता है लेकिन उनके installers publish नहीं हुए हैं।
- एक ही समय पर दो PCs पर खुली बातचीत को live merge नहीं किया जा सकता; वह conflict copy बन जाती है।
- Codex में "session ended" hook नहीं है, इसलिए Codex sync तुरंत नहीं, हर 15 मिनट पर चलता है।
- 200 characters से लंबे paths के लिए Claude Code का सही folder-name hash documented नहीं है; ChatRelay पहले ऐसे मौजूदा folder को चुनता है जिसके sessions में वही `cwd` दर्ज हो, वरना अपना `-<hash>` suffix इस्तेमाल करता है।
- Web और phone viewers read-only हैं और उन्हें GitHub backend चाहिए।

| Releases repo `claude-sync-releases` | Installed apps इसी से updates download करते हैं |
| GitHub App "claude-sync-abh1shxkk" | मौजूदा sign-ins चलते रहते हैं |
