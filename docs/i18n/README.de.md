**Nehmen Sie Ihre KI-Coding-Chats auf jeden PC mit – und von einem KI-Tool zum nächsten.**

ChatRelay synchronisiert den Chatverlauf von KI-Coding-Assistenten (derzeit **Claude Code** und **OpenAI Codex**) zwischen Ihren Computern. Beginnen Sie ein Gespräch auf Ihrem Büro-PC und öffnen Sie dasselbe Gespräch später auf Ihrem Laptop zu Hause: dieselben Nachrichten, dieselben Tool-Aufrufe, wobei jeder Dateipfad an die Pfade des neuen Rechners angepasst wird. Außerdem schreibt ChatRelay eine kurze Zusammenfassung des Projektverlaufs in die Anweisungsdatei, die ein anderes Tool liest (`CLAUDE.md`, `AGENTS.md`, `GEMINI.md`). So können Sie die Arbeit in einem anderen KI-Tool fortsetzen.

## Was ChatRelay macht

- **Überträgt den Chatverlauf zwischen PCs.** Jedes Gespräch aus Claude Code (Terminal-CLI und VS-Code-Erweiterung) und Codex (CLI, VS-Code-Erweiterung und Desktop-App) wird an einen Speicherort kopiert, der Ihnen gehört, und von dort auf Ihre anderen PCs. Auf dem anderen PC erscheint es in der Verlaufsliste des jeweiligen Tools: `claude --resume`, das Claude-Code-Panel in VS Code, `codex resume` oder die Codex-Seitenleiste.
- **Korrigiert Dateipfade.** Ihr Projekt liegt vielleicht auf einem PC unter `C:\Users\me\shop` und auf einem anderen unter `D:\work\shop`, oder unter Linux unter `/home/me/shop`. ChatRelay schreibt jeden Pfad im Chat (Arbeitsordner, Ein- und Ausgaben von Tools, Dateilinks, Nachrichtentext) auf den Pfad des empfangenden PCs um.
- **Sendet nur, was sich geändert hat.** Nach dem ersten Hochladen werden nur die neuen Zeilen eines Gesprächs übertragen: ein paar KB statt der ganzen Datei.
- **Geht nie Arbeit verloren.** Beim Hochladen werden Ihre Originale nie verändert. Vor jeder Änderung an einer Datei wird eine Sicherung angelegt, zuerst wird eine Vorschau (Probelauf, „dry run“) gezeigt, und ein Gespräch, das auf beiden PCs geändert wurde, wird nie überschrieben: Beide Versionen bleiben erhalten.
- **Läuft von selbst.** Mit eingeschalteter automatischer Synchronisierung werden Claude-Code-Gespräche hochgeladen, wenn eine Sitzung endet, und heruntergeladen, wenn eine Sitzung beginnt. Codex-Gespräche werden alle 15 Minuten im Hintergrund hoch- und heruntergeladen.
- **Fasst zusammen.** ChatRelay macht aus dem gesamten Verlauf eines Projekts (aus allen Tools) eine `HANDOFF.md`: was erledigt ist, Entscheidungen, offene Fehler, nächste Schritte, bearbeitete Dateien. Eine Kurzfassung kann es auch in `CLAUDE.md`, `AGENTS.md` oder `GEMINI.md` schreiben, damit das nächste Tool den Zusammenhang gleich kennt.
- **Überall lesbar.** Eine schreibgeschützte Webseite und eine Android-App zeigen alle Ihre Gespräche aus dem GitHub-Speicher an, auf jedem Gerät.
- **Sieht aus wie VS Code.** Schwarz-weiße Desktop-App im Stil von VS Code, mit dunklem und hellem Design, einer einfachen Ansicht für den Alltag und einer erweiterten Ansicht mit allen Details.

## Unterstützte KI-Tools

| Tool | Wo es läuft | Chats ansehen | Zwischen PCs synchronisieren | Im Tool wiederherstellen | Kontextdatei |
|---|---|---|---|---|---|
| **Claude Code** | Terminal-CLI, VS-Code-Erweiterung | ✅ | ✅ (mit Auto-Sync-Hooks) | ✅ `claude --resume`, VS-Code-Verlauf | `CLAUDE.md` |
| **OpenAI Codex** | Codex CLI, VS-Code-Erweiterung, Codex-Desktop-App | ✅ | ✅ (im Hintergrund, alle 15 Min.) | ✅ `codex resume`, Codex-Seitenleiste | `AGENTS.md` |
| Gemini CLI | Terminal | geplant | geplant | geplant | `GEMINI.md` (als Ziel für Zusammenfassungen bereits verfügbar) |
| Kiro (IDE und CLI), Cursor, Antigravity | | geplant | geplant | geplant | |

Jedes Tool speichert seinen Verlauf in einem eigenen, nicht dokumentierten Format, und diese Formate ändern sich von Version zu Version. Deshalb prüft ChatRelay das Format, das es auf Ihrem PC vorfindet. Erkennt es eine Version, die es nicht kennt, zeigt es die Gespräche trotzdem an, **schaltet aber das Schreiben** für dieses Tool **ab** und erklärt Ihnen den Grund unter **Settings → AI tools** (Einstellungen → KI-Tools). Es rät nie.

Geprüfte Versionen: Claude Code 2.1.x; Codex 0.144 bis 0.160 (Index-Datenbank `state_5.sqlite`, Schema-Migration 58).

## Herunterladen und installieren

### Windows

1. Laden Sie `ChatRelay_<version>_x64-setup.exe` aus dem [neuesten Release](https://github.com/Abh1shxkk/claude-sync-releases/releases/latest) herunter. (Releases bis v0.5.0 heißen `ClaudeSync_…`.)
2. Führen Sie die Datei aus. Das Installationsprogramm ist nicht code-signiert, daher meldet Windows SmartScreen eventuell „Der Computer wurde durch Windows geschützt“: Klicken Sie auf **More info → Run anyway** (Weitere Informationen → Trotzdem ausführen).
3. Sie installieren nur einmal. Spätere Versionen kommen von selbst (siehe [Updates](#updates)).

Die App wird pro Benutzer in `%LOCALAPPDATA%\Claude Sync\` installiert (der Ordner behält seinen alten Namen; siehe [Zur Umbenennung](#zur-umbenennung)). Sie startet im Infobereich der Taskleiste (System-Tray). Wenn Sie das Fenster schließen, läuft sie dort weiter; zum Beenden verwenden Sie **Quit** (Beenden) im Tray-Menü.

### Android (Viewer)

Laden Sie `ChatRelay_<version>.apk` von derselben Release-Seite herunter und öffnen Sie die Datei auf Ihrem Smartphone (erlauben Sie bei Nachfrage „Unbekannte Apps installieren“ für Ihren Browser oder Dateimanager). Die Android-App ist ein **schreibgeschützter Viewer** für Ihren GitHub-Speicher; ein Smartphone hat keinen eigenen KI-Tool-Verlauf.

### macOS und Linux

Die Rust-Engine und die App lassen sich unter macOS und Linux bauen (siehe [Aus dem Quellcode bauen](#aus-dem-quellcode-bauen-und-entwicklung)), aber es werden dafür noch keine Installationsprogramme veröffentlicht, und sie wurden noch nicht getestet.

### Web

Der Web-Viewer ist eine statische Seite, die Sie selbst hosten (GitHub Pages, Cloudflare Pages, Netlify…) oder lokal ausführen können. Siehe [Viewer für Web und Smartphone](#viewer-für-web-und-smartphone).

## Ersteinrichtung

Wenn ChatRelay zum ersten Mal geöffnet wird, führt Sie ein Einrichtungsassistent durch diese Schritte. Sie können ihn jederzeit über die Befehlspalette erneut starten (**Ctrl+Shift+P → Run First-time Setup Again** – Ersteinrichtung erneut ausführen).

1. **Ihr Verlauf.** ChatRelay findet den Verlauf von Claude Code in `%USERPROFILE%\.claude\projects` (oder im Ordner aus `CLAUDE_CONFIG_DIR`) und den von Codex in `%USERPROFILE%\.codex` (oder `CODEX_HOME`). Es zeigt an, wie viele Gespräche es pro Tool gefunden hat.
2. **Die 30-Tage-Löschung von Claude Code.** Standardmäßig löscht Claude Code Gespräche, die älter als 30 Tage sind (`cleanupPeriodDays`). ChatRelay zeigt das an und bietet an, den Wert zu erhöhen. Vor der Änderung wird `settings.json` gesichert.
3. **Rechnername.** Zum Beispiel `OFFICE-PC` oder `HOME-LAPTOP`. Er wird neben jedem Gespräch angezeigt, damit Sie wissen, von welchem PC es stammt.
4. **Speicherort (Backend).** Ein Ordner (Google Drive, OneDrive, Dropbox, Netzlaufwerk) oder ein privates GitHub-Repository. Siehe den nächsten Abschnitt.
5. **Anthropic-API-Schlüssel (optional).** Wird nur für Zusammenfassungen benötigt. Er wird in der Windows-Anmeldeinformationsverwaltung (Schlüsselbund des Betriebssystems) gespeichert, nie in einer Datei.
6. **Auto-Sync.** Schaltet das automatische Hoch- und Herunterladen ein (Claude-Code-Hooks plus den Hintergrund-Timer).
7. **Alles hochladen.** Lädt auf Wunsch sofort Ihren gesamten vorhandenen Verlauf hoch, mit Fortschrittsbalken.

## Wo Ihr Verlauf gespeichert wird (Backend)

Ihr Verlauf landet an einem Ort, den **Sie** kontrollieren. ChatRelay hat keinen eigenen Server.

### Option A: ein Ordner

Jeder Ordner, den auch Ihre anderen PCs sehen können:

- Google Drive für den Desktop, z. B. `G:\My Drive\chatrelay`
- OneDrive, z. B. `%OneDrive%\chatrelay`
- Dropbox, ein NAS oder eine Netzwerkfreigabe oder ein USB-Laufwerk, das Sie mitnehmen

Dort landen nur komprimierte Kopien. Ihre aktiven Ordner `~/.claude` und `~/.codex` werden nie in einen Cloud-Ordner verschoben. Das Ordner-Backend bewahrt außerdem frühere Versionen jeder Datei auf (**Settings → What to sync → Versions kept (folder backend)** – Einstellungen → Was synchronisiert wird → Aufbewahrte Versionen (Ordner-Backend), Standard 2).

### Option B: ein privates GitHub-Repository

Am besten, wenn Sie auch den Web- oder Smartphone-Viewer nutzen möchten.

1. **Sign in with GitHub** (Mit GitHub anmelden, empfohlen). ChatRelay zeigt einen kurzen Code an; Sie geben ihn auf github.com ein und bestätigen. Die ChatRelay-GitHub-App erhält nur Zugriff auf die Repositories, die Sie auswählen (normalerweise nur Ihr Verlaufs-Repository), mit der Berechtigung, deren Inhalte zu lesen und zu schreiben. Es wird kein Passwort gespeichert, und es ist kein Server beteiligt.
2. Oder fügen Sie ein **Personal Access Token** ein (klassisches Token mit dem Scope `repo` oder ein fein abgestuftes Token mit *Contents: Read and write* für genau dieses eine Repository). Wenn Sie in der GitHub CLI angemeldet sind (`gh auth login`), kann ChatRelay dieses Token verwenden.
3. Wählen Sie ein bestehendes **privates** Repository oder klicken Sie auf **Create private repo** (Privates Repository erstellen). Öffentliche Repositories werden abgelehnt, weil der Chatverlauf privaten Code und Geheimnisse enthalten kann.

Auf GitHub ist jedes Hochladen **ein Commit**. Dateien, die (komprimiert) größer als 40 MB sind, werden automatisch in Teile aufgeteilt, weil GitHub einzelne Dateien über 100 MB ablehnt.

Das Token liegt nur im Schlüsselbund des Betriebssystems (Dienst `claude-sync`).

## Den zweiten PC einrichten

Auf **PC 1** (dem, auf dem der Verlauf bereits liegt):

1. Installieren Sie ChatRelay und wählen Sie ein Backend.
2. Hochladen: Klicken Sie in der einfachen Ansicht auf **Upload now** (Jetzt hochladen) (oder am Ende der Einrichtung auf **Upload everything** – Alles hochladen) oder in der erweiterten Ansicht bei einem Projekt auf **Push** (Hochladen). Eine Vorschau zeigt jedes Gespräch und alle gefundenen Geheimnisse; Sie können wählen, diese in der hochgeladenen Kopie zu verbergen (schwärzen).

Auf **PC 2**:

1. Installieren Sie ChatRelay und wählen Sie **dasselbe Backend** (denselben synchronisierten Ordner oder dasselbe GitHub-Repository).
2. Legen Sie den Projektordner auf PC 2 ab (zum Beispiel mit `git clone`). Der Pfad darf anders sein, zum Beispiel `D:\work\shop` statt `C:\Users\me\shop`.
3. Klicken Sie auf **Bring history to this PC** (Verlauf auf diesen PC holen, einfache Ansicht) oder öffnen Sie die Ansicht **Sync** (Synchronisierung, erweiterte Ansicht). ChatRelay listet jedes Projekt im Backend auf und zeigt, wohin es auf diesem PC kommen würde:
   - **Git-Projekte** werden automatisch über ihre Remote-URL zugeordnet.
   - **Andere Projekte**: Klicken Sie auf **Import into…** (Importieren nach…) / **Link** (Verknüpfen) und wählen Sie einmalig den lokalen Ordner. Die Verknüpfung wird gespeichert.
4. Prüfen Sie den **Probelauf** (dry run): welche Dateien geschrieben werden und jede Pfadänderung (zum Beispiel `×166  C:\Users\me\shop → D:\work\shop`). Bestätigen Sie dann.
5. Öffnen Sie das Gespräch im Tool: `claude --resume` oder das Claude-Panel in VS Code; `codex resume` oder die Codex-Seitenleiste.

Für Codex: **Schließen Sie zuerst Codex** (CLI, VS-Code-Erweiterung und Desktop-App). ChatRelay schreibt nie in die Dateien von Codex, solange es läuft; das betreffende Gespräch wird mit dem Grund „Codex is running“ (Codex läuft) übersprungen und kommt beim nächsten Mal an.

Schalten Sie **Auto-sync** (automatische Synchronisierung) auf beiden PCs ein, dann müssen Sie nichts davon mehr von Hand erledigen.

## Alltägliche Nutzung

### Einfache Ansicht und erweiterte Ansicht

- **Simple view** (einfache Ansicht, Standard): Ihre Projekte mit einem Statuspunkt, zwei große Schaltflächen (**Upload now** / **Bring history to this PC**), der Auto-Sync-Schalter und die Update-Prüfung.
- **Advanced view** (erweiterte Ansicht): ein Layout wie in VS Code mit einer Aktivitätsleiste (Projects **Ctrl+Shift+E**, Sync **Ctrl+Shift+Y**, Summaries, Logs, Backups, Settings – Projekte, Synchronisierung, Zusammenfassungen, Protokolle, Sicherungen, Einstellungen), Tabs, einer Statusleiste und einer Befehlspalette (**Ctrl+Shift+P**) mit allen Aktionen.

Wechseln Sie zwischen beiden mit **Ctrl+Shift+P → Switch to Simple/Advanced View** (zur einfachen/erweiterten Ansicht wechseln).

### Statuspunkte

| Punkt | Bedeutung | Was zu tun ist |
|---|---|---|
| Grün | Synchronisiert | Nichts |
| Gelb / orange | Änderungen auf diesem PC noch nicht hochgeladen | Hochladen (Push) oder auf Auto-Sync warten |
| Rot | Letzte Synchronisierung fehlgeschlagen | Den Grund unter **Logs** (Protokolle) nachsehen |
| Grau | Nie synchronisiert | Einmal hochladen (Push) |
| Leerer Kreis | Noch keine Projektidentität (nicht verknüpft) | Hochladen (dabei wird eine Verknüpfung angelegt) oder per **Link** mit dem Projekt vom anderen PC verknüpfen |

### Gespräche aus mehreren Tools

Jedes Gespräch trägt ein kleines Abzeichen mit seinem Tool (**Claude** oder **Codex**). Bei Projekten, in denen Sie mehr als ein Tool verwendet haben, gibt es einen **Filter** (All / Claude Code / Codex – Alle / Claude Code / Codex). Wenn Sie ein Gespräch öffnen, sehen Sie das vollständige Transkript: Ihre Nachrichten, die Antworten des Assistenten, Tool-Aufrufe (ausgeführte Befehle, bearbeitete Dateien) und die Liste der geänderten Dateien.

### Push und Pull

- **Push** lädt die Gespräche eines Projekts hoch, die sich seit der letzten Synchronisierung geändert haben. **Push all** (alle hochladen) erledigt das für jedes Projekt.
- **Pull** lädt herunter, was neu ist. Es beginnt immer mit einem **Probelauf** (dry run), der jede Datei auflistet, die geschrieben würde, und jede Pfadumschreibung. Nichts wird geschrieben, bevor Sie bestätigen.

### Auto-Sync

Wenn **Auto-sync** eingeschaltet ist:

- **Claude Code**: Hooks in `~/.claude/settings.json` starten ChatRelay, wenn eine Claude-Code-Sitzung **beginnt** (Pull) und **endet** (Push).
- **Codex**: Codex hat keinen solchen Hook, daher prüft die Desktop-App alle 15 Minuten (beginnend 20 Sekunden nach dem Start). Sie lädt Projekte hoch, deren Codex-Gespräche sich geändert haben, und lädt neue herunter (wird übersprungen, solange Codex läuft).
- Uploads, die fehlgeschlagen sind, weil Sie offline waren, werden in eine Warteschlange gestellt und erneut versucht.

Sie können Auto-Sync in den Einstellungen, im Tray-Menü oder mit `claude-sync hooks install|uninstall` ein- und ausschalten.

### Tray-Menü

Push now · Pull now · Auto-sync on/off · Last sync status · Open · Quit (Jetzt hochladen · Jetzt herunterladen · Auto-Sync ein/aus · Status der letzten Synchronisierung · Öffnen · Beenden).

### Sicherungen

Vor jedem Schreibvorgang wird eine Sicherung in `~/.claude-sync/backups/<timestamp>-<what>/` angelegt. Öffnen Sie **Backups** (Sicherungen) (oder `claude-sync backups`), um sie anzusehen, und stellen Sie eine mit **Restore** (Wiederherstellen) wieder her, um jede Datei genau so zurückzusetzen, wie sie war. Eine Wiederherstellung entfernt auch Dateien, die durch die Änderung neu angelegt wurden.

### Protokolle

**Logs** (Protokolle) zeigt alles, was ChatRelay getan hat, mit hervorgehobenen Fehlern, und eine Schaltfläche, die einen Fehlerbericht kopiert.

## Codex-Unterstützung im Detail

Was mit jedem Codex-Gespräch übertragen wird:

| Element | Wo Codex es speichert | Was ChatRelay tut |
|---|---|---|
| Das Gespräch („Rollout“) | `~/.codex/sessions/YYYY/MM/DD/rollout-<time>-<id>.jsonl` (manche Versionen schreiben komprimiert `.jsonl.zst`) | Wird kopiert, jeder Pfad wird umgeschrieben |
| Die Indexzeile des Threads | `~/.codex/state_5.sqlite`, Tabelle `threads` | Wird hinzugefügt oder aktualisiert, damit das Gespräch in `codex resume` und der Seitenleiste erscheint |
| Der Name des Threads | `~/.codex/session_index.jsonl` | Wird hinzugefügt |
| Codex-Gedächtnis (Memory) für diesen Thread | `~/.codex/memories_1.sqlite`, Tabelle `stage1_outputs` | Wird hinzugefügt, wenn dieser PC noch keines für den Thread hat; Pfade werden umgeschrieben |
| Ziele (Goals) dieses Threads | `~/.codex/goals_1.sqlite`, Tabellen `thread_goals`, `thread_goal_continuation_deferrals` | Werden hinzugefügt, wenn dieser PC noch keine für den Thread hat |

Wichtige Details:

- **Codex muss geschlossen sein**, während ChatRelay schreibt. ChatRelay prüft, ob `codex`-Prozesse laufen (CLI, VS-Code-Erweiterung, Desktop-App). Bei der Hintergrund-Synchronisierung bittet es Sie nicht, etwas zu schließen; es versucht es einfach später noch einmal.
- **Der Verlaufsmodus bleibt erhalten.** Neuere Codex-Versionen speichern den Verlauf „seitenweise“ (paginated); Codex baut seine Seiten-Datenbank (`thread_history_*.sqlite`) beim ersten Öffnen aus der Gesprächsdatei neu auf, daher schreibt ChatRelay diese Datenbank nie.
- **Ihre eigenen Einstellungen für einen Thread bleiben Ihre.** Bei einer Aktualisierung bleiben der Anheft-Status, der eigene Name, der Archiv-Status und das Konto dieses PCs erhalten. Ordner und Bereiche, die nur auf dem anderen PC existieren, werden entfernt.
- **Konto.** Ein importierter Thread wird dem Codex-Konto zugeordnet, dem auf diesem PC die meisten Threads gehören.
- **Windows-Pfadpräfix.** Codex unter Windows speichert Arbeitsordner als `\\?\D:\project`. ChatRelay fügt dieses Präfix nur bei Windows-Pfaden auf einem PC hinzu, dessen Codex es verwendet, und nie bei macOS- oder Linux-Pfaden.
- **Komprimierte Gespräche** (`.jsonl.zst`) können gelesen und aktualisiert werden. Bei einer Aktualisierung wird die Datei durch eine normale `.jsonl` ersetzt (das komprimierte Original wird vorher gesichert).
- **Gedächtnis-Buchhaltung**, die zum anderen PC gehört (wie oft ein Gedächtniseintrag verwendet wurde, ob er für die Konsolidierung ausgewählt wurde), wird nicht kopiert.
- **Unbekannte Versionen.** Wenn der Index von Codex eine Datenbank verwendet, die ChatRelay nicht kennt (zum Beispiel ein künftiges `state_6.sqlite`), oder ein Pflichtfeld hinzukommt, das es nicht füllen kann, wird das Schreiben für Codex mit einer klaren Warnung abgeschaltet. Lesen funktioniert weiterhin.

## Sicherheit und Datenschutz

- **Originale werden beim Hochladen nie verändert.** Beim Hochladen werden Ihre Verlaufsdateien nur gelesen.
- **Nichts wird geschrieben, solange das Tool läuft** (Codex). Die offene Claude-Code-Sitzung (diejenige, die den Hook ausgelöst hat) wird nie angefasst.
- **Sicherung vor jedem Schreibvorgang**, auch für die `settings.json` von Claude Code, die Datenbanken von Codex (mit ihren `-wal`- und `-shm`-Dateien) und `session_index.jsonl`.
- **Probelauf bei jedem Import.** Sie sehen jede Datei und jede Pfadumschreibung, bevor irgendetwas passiert.
- **Bei Konflikten bleiben beide Versionen erhalten**, nichts wird überschrieben.
- **Suche nach Geheimnissen.** Vor dem Hochladen sucht ChatRelay nach API-Schlüsseln und Passwörtern: Schlüssel von Anthropic, OpenAI, GitHub, AWS, Google, Slack und Stripe, JWTs, private Schlüssel, Zeilen im `.env`-Stil wie `SECRET=…` und Zugangsdaten in URLs. Sie wählen: **warn** (warnen), **redact** (schwärzen – nur in der hochgeladenen Kopie durch `[REDACTED:kind]` ersetzt) oder **off** (aus).
- **Geheimnisse bleiben im Schlüsselbund des Betriebssystems.** Ihr GitHub-Token und Ihr Anthropic-Schlüssel werden nie in eine Datei geschrieben.
- **Ihre Anmeldungen werden nie angefasst.** ChatRelay liest, kopiert oder ändert die Anmeldedateien von Claude Code oder Codex nicht (`~/.claude/.credentials.json`, `~/.codex/auth.json`, …). Das Synchronisieren des Verlaufs kann Sie nicht abmelden. Wenn Sie abgemeldet werden, liegt das am Tool selbst (zum Beispiel an einer abgelaufenen Sitzung oder an der Anmeldung mit einem anderen Konto auf einem anderen PC).
- **Nur privater Speicher.** Öffentliche GitHub-Repositories werden abgelehnt.
- **Kein ChatRelay-Server.** Daten fließen nur zwischen Ihren PCs, Ihrem Ordner oder GitHub und (nur wenn Sie eine Zusammenfassung erstellen) der Anthropic-API.

Bewusst nicht synchronisiert: `~/.claude/history.jsonl` (Ihr Eingabeverlauf über die Pfeil-nach-oben-Taste, projektübergreifend), `~/.claude/file-history/` (Snapshots zum Zurückspulen) und alle Zugangsdaten.

## Wie es funktioniert (technisch)

### Wo Claude Code den Verlauf speichert

| Pfad | Was |
|---|---|
| `~/.claude/projects/<encoded-path>/<session-uuid>.jsonl` | Eine Datei pro Sitzung, ein JSON-Objekt pro Zeile |
| `~/.claude/projects/<encoded-path>/<session-uuid>/subagents/*.jsonl` + `*.meta.json` | Subagent-Transkripte (als „Sidecar“ synchronisiert) |
| `~/.claude/projects/<encoded-path>/<session-uuid>/tool-results/*` | Große Tool-Ausgaben, die auf der Festplatte gespeichert sind (Sidecar) |
| `~/.claude/projects/<encoded-path>/memory/` | Automatisches Projektgedächtnis (`MEMORY.md` + Notizen) |

Dinge, die von den üblichen Annahmen abweichen – alle werden berücksichtigt:

- **Die Groß-/Kleinschreibung des Laufwerksbuchstabens hängt vom Client ab.** Die VS-Code-Erweiterung speichert `c:\Users\…` (Ordner `c--Users-…`), die CLI speichert `C:\Users\…` (Ordner `C--Users-…`), und eine Sitzung kann beides enthalten. Unter Windows werden Pfade ohne Beachtung der Groß-/Kleinschreibung verglichen.
- **Ordnernamen lassen sich nicht zuverlässig zurückübersetzen.** `C:\Users\me\my project` und `C:\Users\me\my-project` werden beide zu `C--Users-me-my-project` kodiert. Der echte Pfad stammt aus dem in den Sitzungen gespeicherten `cwd`; das Dekodieren des Namens ist nur ein gekennzeichneter Notbehelf.
- **Sitzungen können riesig sein** (über 200 MB mit eingebetteten Bildern/PDFs), deshalb wird alles gestreamt. Scan-Ergebnisse werden anhand von Größe und Änderungszeit zwischengespeichert, sodass ein erneuter Scan etwa 100 ms dauert.
- **Eine Antwort des Assistenten erstreckt sich über mehrere Zeilen** (eine pro Inhaltsblock, gleiche `message.id`); bei der Nachrichtenzählung werden sie zusammengefasst. Titel stammen aus der ersten echten Eingabe (IDE-Wrapper-Tags werden entfernt); der eigene `ai-title` von Claude Code wird daneben angezeigt.
- **Viele Zeilentypen außer user/assistant** (`attachment`, `file-history-snapshot`, `queue-operation`, `ai-title`, `last-prompt`, `permission-mode`, …). Unbekannte Typen und Felder bleiben unverändert erhalten.

### Wo Codex den Verlauf speichert

Siehe [Codex-Unterstützung im Detail](#codex-unterstützung-im-detail). Jede Zeile eines Rollouts ist `{timestamp, type, payload}`; die erste ist `session_meta` mit der Sitzungs-ID und `cwd`. Codex hat Gespräche in drei Generationen geschrieben (`event_msg/item_completed`-Elemente ab ≥0.15x, davor `user_message`/`agent_message`-Ereignisse, in den ältesten Versionen einfache `response_item`-Nachrichten); der Viewer verwendet die reichhaltigste vorhandene Form.

### Adapter

Jedes KI-Tool ist ein **Adapter** (`crates/core/src/providers/`) hinter einer gemeinsamen Schnittstelle (`ProviderAdapter`): das Tool und sein Format erkennen, Projekte und Sitzungen auflisten, eine Sitzung in eine tool-neutrale Form (`UniversalSession`) einlesen, sie verlustfrei exportieren (`SessionBundle`: die Originaldateien plus Tool-Metadaten wie die Codex-Indexzeile), sie auf einem anderen PC importieren (Pfade umschreiben, prüfen, dass das Tool nicht läuft, sichern, Probelauf) und neue Zeilen anhängen. Siehe [Ein weiteres KI-Tool hinzufügen](#ein-weiteres-ki-tool-hinzufügen-adapter-anleitung).

### Projektidentität

Dasselbe Projekt hat auf jedem PC einen anderen Pfad, deshalb wird es in dieser Reihenfolge identifiziert über:

1. Eine **manuelle Verknüpfung** (Schaltfläche Link / `claude-sync link <dir> <id>`), gespeichert in der Konfiguration von ChatRelay
2. Das **Git-Remote**, vereinheitlicht: `git@github.com:Me/Repo.git` und `https://github.com/me/repo` werden beide zu `git:github.com/me/repo`
3. Eine Datei **`.claude-sync.json`** im Projektstamm mit einer UUID, die beim ersten Push für Projekte ohne Git angelegt wird (committen Sie sie oder verknüpfen Sie auf dem anderen PC manuell). „Upload everything“ und die Hintergrund-Synchronisierung legen stattdessen eine Verknüpfung in der Konfiguration von ChatRelay an, sodass nichts in Ihre Projektordner geschrieben wird.

### Speicheraufbau (im Ordner oder Repository)

```
<projectId-slug>/
  manifest.json                          machines, original paths, hashes, timestamps, revision
  <sessionId>.jsonl.gz                   Claude Code session (whole, or its start when deltas exist)
  <sessionId>.d<N>.jsonl.gz              lines appended after that, one blob per push
  <sessionId>.sidecar.json.gz            subagents/ + tool-results/ (if any)
  memory.json.gz                         Claude Code project memory (if any)
  <provider>-<sessionId>.bundle.json.gz  another tool's session (e.g. codex-…): files + metadata
  <provider>-<sessionId>.d<N>.jsonl.gz   lines appended to it later
  .versions/<file>/<timestamp>           previous versions (folder backend)
```

Sitzungen anderer Tools werden im Manifest unter `providerSessions` aufgeführt (Schlüssel `<provider>:<id>`). Ältere Versionen der App ignorieren diese Liste und lassen sie unverändert.

### Push

- Sitzungen werden per SHA-256 verglichen; nur neue oder geänderte werden hochgeladen. Originale werden immer nur gelesen.
- **Nur neue Zeilen werden gesendet.** KI-Tools hängen an eine Gesprächsdatei immer nur etwas an. Deshalb speichert ein Push nach dem ersten Hochladen einer Sitzung nur die seit der letzten Synchronisierung hinzugekommenen Zeilen als „Delta“-Teil. Jeder Teil vermerkt die Pfade des Rechners, der ihn hochgeladen hat. Die Hashes einer Sitzung werden verkettet (`hash = sha256(previous : sha256(part))`). Nach 40 Teilen lädt der nächste Push wieder die ganze Sitzung hoch. Wenn die Abkürzung nicht greift (die Datei wurde auf andere Weise geändert, ein Konflikt, ein Zustand aus einer älteren Version), wird die ganze Datei hochgeladen.
- Wenn das Backend eine Version hat, die Sie noch nicht gesehen haben und die Nachrichten enthält, die Ihnen fehlen, wird der Push dieser Sitzung mit „pull first“ (zuerst herunterladen) abgelehnt, damit nichts verloren geht.
- **Offline?** (GitHub nicht erreichbar, Cloud-Laufwerk nicht eingebunden.) Der Push wird in `~/.claude-sync/queue.json` in die Warteschlange gestellt und beim nächsten Lauf sowie von der Desktop-App alle 15 Minuten erneut versucht.

### Pull

- Pfade werden innerhalb des geparsten JSON umgeschrieben (in String-Werten **und** in Objektschlüsseln), daher ist das Escaping von JSON nie ein Problem. Unterstützte Formen: Windows-Pfade als `C:\…`, `c:/…`, Git-Bash `/c/…` und WSL `/mnt/c/…` (ohne Beachtung der Groß-/Kleinschreibung); POSIX-Pfade (mit Beachtung der Groß-/Kleinschreibung); `file:///`-URLs einschließlich `%20`-kodierter Leerzeichen; Trennzeichen nach dem Projektstamm werden beim Wechsel zwischen Betriebssystemen umgewandelt; der eigene Home-Ordner des Tools (`~/.claude`, `~/.codex`) und der kodierte Ordnername von Claude Code werden ebenfalls umgeschrieben. Benachbarte Ordner wie `shop-old` werden nie angefasst.
- **Schneller Weg:** Ein PC, der genau das hat, was er zuletzt synchronisiert hat, lädt nur die fehlenden Teile herunter und hängt sie an.
- **Abweichungen** (Gespräche werden nur ergänzt; verglichen wird bei Claude Code über Zeilen-IDs und bei anderen Tools über den Textanfang):
  - Remote enthält Lokal → Aktualisierung
  - Lokal enthält Remote → Ihre Version ist neuer und bleibt erhalten (wird beim nächsten Push hochgeladen)
  - Beide geändert → **Konflikt**: Ihre Kopie bleibt, wie sie ist, und die andere Version wird als **neues Gespräch mit neuer ID** gespeichert (Codex: benannt „<name> (from <PC>)“). Beide erscheinen dann im Tool und werden auf Ihre anderen PCs synchronisiert.

### Auto-Sync-Hooks (Claude Code)

„Enable auto-sync“ (Auto-Sync aktivieren) fügt Folgendes in `~/.claude/settings.json` ein; Ihre anderen Einstellungen und Hooks bleiben erhalten, und vorher wird eine Sicherung angelegt:

```jsonc
"hooks": {
  "SessionStart": [{ "hooks": [{ "type": "command", "command": "\"…/Claude Sync/claude-sync.exe\" pull --hook --quiet --claude-sync-hook", "timeout": 60 }] }],
  "SessionEnd":   [{ "hooks": [{ "type": "command", "command": "\"…/Claude Sync/claude-sync.exe\" push --hook --quiet --claude-sync-hook", "timeout": 60 }] }]
}
```

- `--hook` liest das Hook-JSON von Claude Code von stdin (`cwd`, `session_id`), ersatzweise `CLAUDE_PROJECT_DIR` und danach das Arbeitsverzeichnis. Hooks **beenden sich immer mit 0**, damit sie nie eine Sitzung stören können; Fehler landen im Logs-Panel.
- Der Hook führt die native ausführbare Datei `claude-sync` aus, die neben der App installiert ist. Node.js wird nicht benötigt.
- „Disable auto-sync“ (Auto-Sync deaktivieren) entfernt nur die Hooks, die die Markierung `claude-sync-hook` enthalten.

| `~/.claude-sync/queue.json` | Pushes, die auf das Backend warten |
| `~/.claude-sync/scan-cache.json` | Scan-Cache (Größen, Zeiten, Titel) |
| Schlüsselbund des Betriebssystems, Dienst `claude-sync` | `github-token`, `anthropic-api-key` |
| `~/.claude/projects/…` | Claude-Code-Gespräche (gelesen; beim Pull geschrieben) |
| `~/.claude/settings.json` | Nur für Auto-Sync-Hooks und `cleanupPeriodDays` (vorher gesichert) |
| `~/.codex/sessions/…`, `state_5.sqlite`, `session_index.jsonl`, `memories_1.sqlite`, `goals_1.sqlite` | Codex-Gespräche und ihr Index (gelesen; beim Pull geschrieben, nur bei geschlossenem Codex, vorher gesichert) |
| `<project>/.claude-sync.json` | Nur für Projekte ohne Git, die über eine Projektansicht hochgeladen wurden |
| `<project>/HANDOFF.md`, `CLAUDE.md`, `AGENTS.md`, `GEMINI.md` | Nur wenn Sie dort eine Zusammenfassung speichern |

## Updates

- Die Desktop-App sucht nach einer neuen Version, wenn sie startet, jedes Mal, wenn ihr Fenster geöffnet wird, jede Stunde, wenn Sie nach mindestens 5 Minuten zum Fenster zurückkehren und wenn Sie auf **Check for updates** (Nach Updates suchen) klicken (Settings → About, in der einfachen Ansicht oder in der Befehlspalette). Während der Prüfung wird ein Ladesymbol angezeigt.
- Wenn ein Update verfügbar ist, sehen Sie **A new version is available → Update now** (Eine neue Version ist verfügbar → Jetzt aktualisieren). Die App lädt es herunter, prüft seine Signatur (Apps akzeptieren nur Updates, die mit dem Schlüssel des Projekts signiert sind), installiert es an Ort und Stelle und startet neu. Verlauf und Einstellungen bleiben erhalten.
- Die Android-App zeigt einen Hinweis mit einem Link zur neuen APK.

## Fehlerbehebung und FAQ

**SmartScreen blockiert das Installationsprogramm.** Das Installationsprogramm ist nicht code-signiert. Klicken Sie auf **More info → Run anyway**.

**Ein Projekt zeigt einen gelben Punkt.** Es hat Gespräche auf diesem PC, die noch nicht hochgeladen sind. Laden Sie es hoch (Push) oder schalten Sie Auto-Sync ein.

**Ein Projekt von meinem anderen PC erscheint nicht / erscheint unter einem anderen Namen.** Projekte werden über das Git-Remote, eine `.claude-sync.json` oder eine Verknüpfung zugeordnet. Wenn die Ordner unterschiedlich heißen und es kein Git-Remote gibt, verwenden Sie einmalig **Link** (oder **Import into…**) und wählen Sie den richtigen lokalen Ordner.

**Ein Codex-Gespräch wurde übersprungen: „Codex is running“.** Schließen Sie die Codex CLI, das Codex-Panel der VS-Code-Erweiterung (oder VS Code) und die Codex-Desktop-App und führen Sie dann erneut einen Pull aus. Die Hintergrund-Synchronisierung versucht es von selbst erneut.

**Der Codex-Import ist abgeschaltet: „Unknown Codex index database“ / „new required fields“.** (Unbekannte Codex-Index-Datenbank / neue Pflichtfelder.) Ihr Codex ist neuer, als diese ChatRelay-Version kennt. Aktualisieren Sie ChatRelay. Ihre Gespräche sind weiterhin sichtbar.

**Ich sehe ein Gespräch doppelt, eines davon endet mit „(from OFFICE-PC)“.** Es wurde auf beiden PCs fortgesetzt, bevor diese synchronisiert wurden. Beide Versionen bleiben erhalten; löschen Sie im Tool diejenige, die Sie nicht brauchen.

**Meine alten Claude-Code-Gespräche sind verschwunden.** Claude Code löscht Gespräche, die älter als `cleanupPeriodDays` sind (Standard 30). Erhöhen Sie den Wert in den Einstellungen (oder mit `claude-sync cleanup-days 3650`). Bereits hochgeladene Gespräche können aus dem Backend zurückgeholt werden (Pull).

**Hat mich die Synchronisierung bei Claude abgemeldet?** Nein. ChatRelay liest oder schreibt nie Anmeldedateien. Siehe [Sicherheit und Datenschutz](#sicherheit-und-datenschutz).

**Das Hochladen ist beim ersten Mal langsam.** Beim ersten Hochladen wird alles (komprimiert) gesendet. Danach werden nur neue Zeilen gesendet.

**„Pull first“ beim Push.** Ein anderer PC hat eine neuere Version hochgeladen, die Ihre nicht enthält. Führen Sie erst einen Pull und dann einen Push aus.

**Offline.** Pushes werden in die Warteschlange gestellt und automatisch erneut versucht; `claude-sync queue` versucht es sofort erneut.

**Nach einem Pull ist etwas schiefgegangen.** Öffnen Sie **Backups** und stellen Sie die Sicherung wieder her, die direkt davor angelegt wurde.

**Wo finde ich Fehler?** In der Ansicht **Logs** (dort können Sie einen Fehlerbericht kopieren) oder in `~/.claude-sync/logs/claude-sync.log`.

## Aus dem Quellcode bauen und Entwicklung

Voraussetzungen: Node.js 20+, Rust (stable) und unter Windows die MSVC-Toolchain (Visual Studio „Desktop development with C++“ – Desktopentwicklung mit C++).

```bash
git clone https://github.com/Abh1shxkk/chatrelay.git
cd chatrelay
npm install
npm run tauri:dev      # run the desktop app with hot reload
npm run test:rust      # cargo test --workspace: engine, adapters, push/pull, GitHub backend
npm test               # UI helper tests (vitest)
npm run typecheck      # TypeScript
npm run tauri:build    # installer in target/release/bundle/nsis/
```

Projektaufbau:

```
crates/core/       Rust engine: scanner, JSONL, path rewriting, sync, backends, hooks, summaries
crates/core/src/providers/   AI tool adapters: claude_code.rs, codex.rs (+ codex_format.rs, browser-safe parsing)
crates/core/src/provider_sync.rs   other tools' sessions in push/pull (bundles, deltas, conflict copies)
crates/core/tests/  integration tests with fixture files (tests/fixtures/codex, tests/fixtures/claude-code)
crates/cli/        the `claude-sync` CLI (also what the Claude Code hooks run)
crates/wasm/       the engine compiled to WebAssembly for the web and phone viewers
src-tauri/         desktop app: window, tray, background sync, the API behind window.claudeSync
src/renderer/      React + TypeScript + Tailwind UI (shared by desktop, web and phone)
src/shared/        TypeScript types and helpers
mobile/            Android / iOS shell around the web version (Tauri)
scripts/           release, CLI staging, WASM build
tests/             vitest tests; tests/web/mock-github.mjs for testing the web version
```

Eine Entwicklungskopie neben einer installierten Version ausführen: Legen Sie eine eigene Kennung und einen eigenen Datenordner fest, damit Ihre echten Einstellungen nie berührt werden:

```powershell
$env:TAURI_CONFIG='{"identifier":"com.claudesync.dev","productName":"ChatRelay Dev"}'
$env:CLAUDE_SYNC_HOME='D:\tmp\chatrelay-dev'
npm run tauri:dev
```

### Mobile App (Android, iOS)

**Android** benötigt JDK 17, das Android SDK (Plattform 36, Build-Tools 36, NDK r27) und die Rust-Android-Targets (`tauri android init` installiert diese):

```powershell
$env:JAVA_HOME = "<jdk-17>"; $env:ANDROID_HOME = "<android-sdk>"; $env:NDK_HOME = "$env:ANDROID_HOME\ndk\<version>"
npm run mobile:android:init      # once: generates mobile/gen/android
npm run mobile:android:apk       # debug APK for a phone (arm64)
adb install -r <that apk>
npm run mobile:android:release   # release APK/AAB, signed when CLAUDE_SYNC_KEYSTORE_PROPERTIES is set
```

Die Release-Signierung liest eine Properties-Datei, die **außerhalb des Repositorys** liegt und durch `CLAUDE_SYNC_KEYSTORE_PROPERTIES` angegeben wird:

```properties
storeFile=D:/dev/android-keys/claude-sync-release.jks
storePassword=…
keyAlias=claude-sync
keyPassword=…
```

Erstellen Sie den Schlüssel einmalig mit `keytool -genkeypair -keystore claude-sync-release.jks -alias claude-sync -keyalg RSA -keysize 4096 -validity 10000` und sichern Sie ihn: Updates für eine installierte App müssen mit demselben Schlüssel signiert sein.

**iOS** benötigt einen Mac mit Xcode und `rustup target add aarch64-apple-ios aarch64-apple-ios-sim`:

```bash
npm install && npm run web:wasm
npm run mobile:ios:init
npm run mobile:ios:dev
npm run mobile:ios:build
```

## Ein weiteres KI-Tool hinzufügen (Adapter-Anleitung)

1. **Prüfen Sie das Speicherformat zuerst auf einem echten Rechner**: wo die Sitzungen liegen, das Zeilen-/Datensatzformat, eine eventuelle Index-Datenbank und deren Schema, wie das Tool Sitzungen auflistet, wie es Pfade speichert, welche Prozesse „läuft“ bedeuten. Notieren Sie das oben in der Adapter-Datei.
2. Fügen Sie in `crates/core/src/providers/mod.rs` eine `ProviderId` hinzu und eine Datei `providers/<tool>.rs`, die `ProviderAdapter` implementiert: `detect`, `list_projects`, `list_sessions`, `read_session`, `export_session`, `import_session`, optional `append_session`, `context_file_name`, `process_names`.
3. Regeln, an die sich jeder Adapter hält: das Schreiben verweigern, solange das Tool läuft (`ensure_not_running`), jede Datei vor dem Schreiben sichern (`ImportOptions.backups`), `dry_run` beachten, `keep_both` beachten (eine abweichende eingehende Sitzung unter einer neuen ID speichern) und den Import (mit einer Warnung in `ProviderStatus`) bei jedem nicht erkannten Format abschalten.
4. Legen Sie das reine Parsen in eine Datei ohne Dateisystemzugriff (wie `codex_format.rs`), damit der Web-Viewer es nutzen kann, und fügen Sie es zu `messages_from_bundle` hinzu.
5. Legen Sie Fixture-Dateien unter `crates/core/tests/fixtures/<tool>/` an und schreiben Sie Tests: Erkennen, Auflisten, Lesen, Export → Import auf einem zweiten simulierten Rechner (Pfade umgeschrieben), Aktualisierung, lokal neuer, Konflikt, Verweigerung bei laufendem Prozess, unbekanntes Format.
6. Fügen Sie die Bezeichnung in `src/shared/types.ts` (`PROVIDER_LABELS`) hinzu. Abzeichen, Filter, Push/Pull, Zusammenfassungen und der Viewer übernehmen sie von dort.

## Ein Release veröffentlichen

Installierte Apps prüfen `latest.json` auf [Abh1shxkk/claude-sync-releases](https://github.com/Abh1shxkk/claude-sync-releases).

1. Erhöhen Sie `version` in `package.json`, `src-tauri/tauri.conf.json`, `mobile/tauri.conf.json` und `Cargo.toml`.
2. `npm run release -- --notes "What changed"`

Das baut das Windows-Installationsprogramm, signiert mit dem Updater-Schlüssel (`TAURI_SIGNING_PRIVATE_KEY` oder `D:\dev\tauri-keys\claude-sync-updater.key` mit seiner `.password`-Datei), und die signierte APK, schreibt `latest.json` und lädt alles als Release `v<version>` hoch. Flags: `--no-apk`, `--skip-build`, `--dry-run`, `--notes-file <file>`. Die GitHub-Anmeldung kommt aus `git credential fill` (oder `GITHUB_TOKEN`).

Bewahren Sie eine Sicherung des Updater-Schlüssels auf. Apps akzeptieren nur Updates, die damit signiert sind; sein öffentlicher Teil steht in `src-tauri/tauri.conf.json`.

## Bekannte Einschränkungen

- Das Windows-Installationsprogramm ist nicht code-signiert (SmartScreen-Warnung).
- Nur Windows ist getestet. macOS und Linux lassen sich bauen, haben aber keine veröffentlichten Installationsprogramme.
- Ein Gespräch, das gleichzeitig auf zwei PCs geöffnet ist, kann nicht live zusammengeführt werden; es wird zu einer Konfliktkopie.
- Codex hat keinen Hook für „Sitzung beendet“, daher läuft die Codex-Synchronisierung alle 15 Minuten statt sofort.
- Für Pfade mit mehr als 200 Zeichen ist der genaue Ordnernamen-Hash von Claude Code nicht dokumentiert; ChatRelay bevorzugt einen vorhandenen Ordner, dessen Sitzungen dasselbe `cwd` vermerken, und verwendet andernfalls ein eigenes `-<hash>`-Suffix.
- Die Viewer für Web und Smartphone sind schreibgeschützt und benötigen das GitHub-Backend.
