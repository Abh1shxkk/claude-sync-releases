**把你的 AI 编程对话带到任何一台电脑上，也能从一个 AI 工具带到另一个 AI 工具。**

ChatRelay 会在你的多台电脑之间同步 AI 编程助手的聊天记录（目前支持 **Claude Code** 和 **OpenAI Codex**）。你可以在办公室的电脑上开始一段对话，然后回家在笔记本上打开同一段对话：消息一样、工具调用一样，而且里面所有的文件路径都会自动换成新电脑上的路径。它还能把一个项目的历史写成简短摘要，放进另一个工具会读取的说明文件里（`CLAUDE.md`、`AGENTS.md`、`GEMINI.md`），这样你就可以换一个 AI 工具接着干活。

## 功能简介

- **在电脑之间搬运聊天记录。** Claude Code（终端 CLI 和 VS Code 扩展）以及 Codex（CLI、VS Code 扩展和桌面应用）里的每一段对话，都会被复制到一个由你自己掌控的存储位置，再从那里同步到你的其他电脑。在另一台电脑上，这些对话会直接出现在工具自己的历史列表里：`claude --resume`、VS Code 中的 Claude Code 面板、`codex resume`，或者 Codex 侧边栏。
- **自动修正文件路径。** 你的项目在一台电脑上可能是 `C:\Users\me\shop`，在另一台上是 `D:\work\shop`，在 Linux 上又是 `/home/me/shop`。ChatRelay 会把对话里的每一个路径（工作目录、工具的输入和输出、文件链接、消息正文）都改写成接收电脑上的路径。
- **只发送有变化的部分。** 第一次上传之后，每次只传对话中新增的几行：几 KB，而不是整个文件。
- **绝不丢失你的工作。** 上传时从不修改你的原始文件。每次修改文件之前都会先备份，先给你看预览（试运行），而且如果一段对话在两台电脑上都有改动，它绝不会互相覆盖，而是两份都保留。
- **自动运行。** 打开自动同步后，Claude Code 的对话会在会话结束时自动上传、在会话开始时自动下载。Codex 的对话则每 15 分钟在后台上传和下载一次。
- **生成摘要。** 它能把一个项目的全部历史（来自所有工具）整理成一份 `HANDOFF.md`：做完了什么、做过哪些决定、还有哪些未解决的 bug、下一步做什么、改动过哪些文件。它还可以把简短版本写进 `CLAUDE.md`、`AGENTS.md` 或 `GEMINI.md`，让下一个工具一开始就了解上下文。
- **随处查看。** 一个只读网页和一个 Android 应用，可以在任何设备上查看你存放在 GitHub 中的全部对话。
- **外观像 VS Code。** 黑白配色、VS Code 风格的桌面应用，有深色和浅色主题，还有日常使用的简洁视图，以及显示所有细节的高级视图。

## 支持的 AI 工具

| 工具 | 运行环境 | 查看对话 | 电脑间同步 | 恢复到工具中 | 上下文文件 |
|---|---|---|---|---|---|
| **Claude Code** | 终端 CLI、VS Code 扩展 | ✅ | ✅（通过自动同步钩子） | ✅ `claude --resume`、VS Code 历史记录 | `CLAUDE.md` |
| **OpenAI Codex** | Codex CLI、VS Code 扩展、Codex 桌面应用 | ✅ | ✅（后台运行，每 15 分钟一次） | ✅ `codex resume`、Codex 侧边栏 | `AGENTS.md` |
| Gemini CLI | 终端 | 计划中 | 计划中 | 计划中 | `GEMINI.md`（已可作为摘要的写入目标） |
| Kiro（IDE 和 CLI）、Cursor、Antigravity | | 计划中 | 计划中 | 计划中 | |

每个工具都用自己的、没有公开文档的格式保存历史记录，而且这些格式会随版本变化。所以 ChatRelay 会检查它在你电脑上找到的格式。如果遇到不认识的版本，它仍然会显示对话，但会**关闭对该工具的写入**，并在 **Settings → AI tools**（设置 → AI 工具）里告诉你原因。它从不靠猜。

已验证的版本：Claude Code 2.1.x；Codex 0.144 到 0.160（索引数据库 `state_5.sqlite`，数据库结构迁移版本 58）。

## 下载与安装

### Windows

1. 从[最新发布页](https://github.com/Abh1shxkk/claude-sync-releases/releases/latest)下载 `ChatRelay_<version>_x64-setup.exe`。（v0.5.0 及更早的版本文件名是 `ClaudeSync_…`。）
2. 运行它。安装程序没有代码签名，所以 Windows SmartScreen 可能会提示 “Windows 已保护你的电脑”：点击 **More info → Run anyway**（更多信息 → 仍要运行）。
3. 只需要安装一次。之后的新版本会自动送达（见[更新](#更新)）。

应用按用户安装在 `%LOCALAPPDATA%\Claude Sync\`（这个文件夹保留了旧名字，见[关于改名](#关于改名)）。它会在系统托盘中启动。关闭窗口后它仍在托盘里运行；要真正退出，请在托盘菜单中选择 **Quit**（退出）。

### Android（查看器）

在同一个发布页下载 `ChatRelay_<version>.apk`，然后在手机上打开它（如果系统询问，请允许你的浏览器或文件管理器“安装未知应用”）。Android 应用是你 GitHub 存储的**只读查看器**；手机本身没有 AI 工具的历史记录。

### macOS 和 Linux

Rust 引擎和应用本身可以在 macOS 和 Linux 上构建（见[从源码构建](#从源码构建与开发)），但目前还没有发布这两个平台的安装包，也还没有经过测试。

### 网页版

网页查看器是一个静态网页，你可以自己托管（GitHub Pages、Cloudflare Pages、Netlify……），也可以在本地运行。见[网页版与手机查看器](#网页版与手机查看器)。

## 首次设置

第一次打开 ChatRelay 时，设置向导会带你完成以下步骤。之后随时可以从命令面板再次运行它（**Ctrl+Shift+P → Run First-time Setup Again**（再次运行首次设置））。

1. **你的历史记录。** ChatRelay 会在 `%USERPROFILE%\.claude\projects`（或 `CLAUDE_CONFIG_DIR` 指定的文件夹）中找到 Claude Code 的历史记录，在 `%USERPROFILE%\.codex`（或 `CODEX_HOME`）中找到 Codex 的历史记录，并显示每个工具找到了多少段对话。
2. **Claude Code 的 30 天自动删除。** 默认情况下，Claude Code 会删除超过 30 天的对话（`cleanupPeriodDays`）。ChatRelay 会提示这一点，并建议你把这个天数调大。修改前它会先备份 `settings.json`。
3. **电脑名称。** 例如 `OFFICE-PC` 或 `HOME-LAPTOP`。它会显示在每段对话旁边，让你知道这段对话来自哪台电脑。
4. **存储位置（后端）。** 一个文件夹（Google Drive、OneDrive、Dropbox、网络驱动器），或者一个私有 GitHub 仓库。见下一节。
5. **Anthropic API 密钥（可选）。** 只有生成摘要时才需要。它保存在 Windows 凭据管理器（系统钥匙串）中，从不写入任何文件。
6. **自动同步。** 打开自动上传/下载（Claude Code 钩子加上后台定时器）。
7. **全部上传。** 可选：立即上传你现有的全部历史记录，并显示进度条。

## 选择历史记录的存放位置（后端）

你的历史记录会存放在一个由**你自己**掌控的地方。ChatRelay 没有自己的服务器。

### 方案 A：一个文件夹

任何一个你的其他电脑也能访问的文件夹都可以：

- Google Drive 桌面版，例如 `G:\My Drive\chatrelay`
- OneDrive，例如 `%OneDrive%\chatrelay`
- Dropbox、NAS 或网络共享，或者你随身携带的 U 盘

存进去的只有压缩副本。你正在使用的 `~/.claude` 和 `~/.codex` 文件夹永远不会被移进云端文件夹。文件夹后端还会保留每个文件的旧版本（**Settings → What to sync → Versions kept (folder backend)**（设置 → 同步内容 → 保留的版本数（文件夹后端）），默认 2 个）。

### 方案 B：一个私有 GitHub 仓库

如果你还想用网页版或手机查看器，这是最佳选择。

1. **Sign in with GitHub**（使用 GitHub 登录，推荐）。ChatRelay 会显示一个短代码；你在 github.com 上输入它并批准即可。ChatRelay GitHub App 只能访问你选定的仓库（通常只有你的历史记录仓库），权限是读写这些仓库的内容。不保存任何密码，也不经过任何服务器。
2. 或者粘贴一个 **personal access token**（个人访问令牌）：带 `repo` 权限范围的经典令牌，或者对那一个仓库拥有 *Contents: Read and write*（内容：读写）权限的细粒度令牌。如果你已经用 GitHub CLI 登录过（`gh auth login`），ChatRelay 可以直接使用那个令牌。
3. 选择一个已有的**私有**仓库，或者点击 **Create private repo**（创建私有仓库）。公开仓库会被拒绝，因为聊天记录里可能包含私有代码和密钥。

在 GitHub 上，每次上传就是**一次提交（commit）**。压缩后超过 40 MB 的文件会自动拆分成多个部分，因为 GitHub 不接受超过 100 MB 的单个文件。

令牌只保存在系统钥匙串中（服务名 `claude-sync`）。

## 设置第二台电脑

在 **电脑 1**（已经有历史记录的那台）上：

1. 安装 ChatRelay 并选择一个后端。
2. 上传：在简洁视图中点击 **Upload now**（立即上传）（或者在设置结束时点击 **Upload everything**（全部上传）），或者在高级视图中对某个项目点击 **Push**（推送）。预览中会列出每段对话以及发现的所有密钥；你可以选择在上传的副本中把它们隐藏（脱敏）。

在 **电脑 2** 上：

1. 安装 ChatRelay，并选择**同一个后端**（同一个同步文件夹，或同一个 GitHub 仓库）。
2. 把项目文件夹放到电脑 2 上（例如用 `git clone`）。路径可以不同，比如是 `D:\work\shop` 而不是 `C:\Users\me\shop`。
3. 点击 **Bring history to this PC**（把历史记录带到这台电脑，简洁视图），或者打开 **Sync**（同步）视图（高级视图）。ChatRelay 会列出后端中的每个项目，以及它在这台电脑上会放到哪里：
   - **Git 项目**会通过远程仓库地址自动匹配。
   - **其他项目**：点击 **Import into…**（导入到…）/ **Link**（关联），选一次本地文件夹即可。这个关联会被记住。
4. 检查**试运行**结果：会写入哪些文件，以及每一处路径变化（例如 `×166  C:\Users\me\shop → D:\work\shop`）。然后确认。
5. 在工具中打开这段对话：`claude --resume` 或 VS Code 的 Claude 面板；`codex resume` 或 Codex 侧边栏。

对于 Codex：**请先关闭 Codex**（CLI、VS Code 扩展和桌面应用）。Codex 运行时，ChatRelay 绝不会写入 Codex 的文件；这段对话会被跳过，原因显示为 “Codex is running”（Codex 正在运行），下次再导入。

在两台电脑上都打开 **Auto-sync**（自动同步），以后就再也不用手动做这些了。

## 日常使用

### 简洁视图和高级视图

- **Simple view**（简洁视图，默认）：显示你的项目和状态圆点、两个大按钮（**Upload now** / **Bring history to this PC**）、自动同步开关和检查更新。
- **Advanced view**（高级视图）：类似 VS Code 的布局，有活动栏（Projects 项目 **Ctrl+Shift+E**、Sync 同步 **Ctrl+Shift+Y**、Summaries 摘要、Logs 日志、Backups 备份、Settings 设置）、标签页、状态栏，以及包含所有操作的命令面板（**Ctrl+Shift+P**）。

用 **Ctrl+Shift+P → Switch to Simple/Advanced View**（切换到简洁/高级视图）在两者之间切换。

### 状态圆点

| 圆点 | 含义 | 该怎么做 |
|---|---|---|
| 绿色 | 已同步 | 无需操作 |
| 黄色 / 橙色 | 这台电脑上有尚未上传的改动 | 推送，或等待自动同步 |
| 红色 | 上次同步失败 | 打开 **Logs**（日志）查看原因 |
| 灰色 | 从未同步过 | 推送一次 |
| 空心圆 | 还没有项目身份（未关联） | 推送它（会自动创建关联），或者用 **Link** 把它关联到另一台电脑上的项目 |

### 来自多个工具的对话

每段对话都有一个小标签，标明它来自哪个工具（**Claude** 或 **Codex**）。如果某个项目用过不止一个工具，会显示一个**筛选器**（All 全部 / Claude Code / Codex）。打开一段对话会显示完整记录：你的消息、助手的回答、工具调用（运行过的命令、编辑过的文件），以及改动过的文件列表。

### 推送和拉取

- **Push**（推送）会上传一个项目中自上次同步以来有改动的对话。**Push all**（全部推送）会处理所有项目。
- **Pull**（拉取）会下载新内容。它总是先进行一次**试运行**，列出它将写入的每个文件和每一处路径改写。在你确认之前，什么都不会写入。

### 自动同步

当 **Auto-sync** 打开时：

- **Claude Code**：`~/.claude/settings.json` 中的钩子会在 Claude Code 会话**开始**时（拉取）和**结束**时（推送）运行 ChatRelay。
- **Codex**：Codex 没有这样的钩子，所以桌面应用每 15 分钟检查一次（启动后 20 秒开始第一次）。它会上传 Codex 对话有改动的项目，并下载新对话（Codex 运行时跳过）。
- 因为离线而失败的上传会进入队列，稍后重试。

你可以在设置里、托盘菜单里，或者用 `claude-sync hooks install|uninstall` 打开或关闭自动同步。

### 托盘菜单

Push now（立即推送）· Pull now（立即拉取）· Auto-sync on/off（自动同步开/关）· Last sync status（上次同步状态）· Open（打开）· Quit（退出）。

### 备份

每次写入之前，都会先在 `~/.claude-sync/backups/<timestamp>-<what>/` 中做一次备份。打开 **Backups**（备份）（或运行 `claude-sync backups`）可以查看它们；对某个备份点击 **Restore**（恢复），就能把每个文件原样还原。恢复时还会删除那次改动新建的文件。

### 日志

**Logs**（日志）会显示 ChatRelay 做过的所有事情，错误会高亮显示，还有一个按钮可以复制错误报告。

## Codex 支持详解

每段 Codex 对话会一起同步的内容：

| 内容 | Codex 存放位置 | ChatRelay 的处理方式 |
|---|---|---|
| 对话本身（“rollout”） | `~/.codex/sessions/YYYY/MM/DD/rollout-<time>-<id>.jsonl`（有些版本写成压缩的 `.jsonl.zst`） | 复制过去，所有路径都会改写 |
| 该对话线程的索引行 | `~/.codex/state_5.sqlite`，表 `threads` | 新增或更新，使对话出现在 `codex resume` 和侧边栏中 |
| 该对话线程的名称 | `~/.codex/session_index.jsonl` | 新增 |
| 该线程的 Codex 记忆 | `~/.codex/memories_1.sqlite`，表 `stage1_outputs` | 如果这台电脑上该线程还没有记忆，则新增；路径会改写 |
| 该线程的目标（goals） | `~/.codex/goals_1.sqlite`，表 `thread_goals`、`thread_goal_continuation_deferrals` | 如果这台电脑上该线程还没有目标，则新增 |

需要注意的细节：

- ChatRelay 写入时 **Codex 必须处于关闭状态**。ChatRelay 会检查是否有正在运行的 `codex` 进程（CLI、VS Code 扩展、桌面应用）。后台同步时它不会要求你关闭任何东西，只是稍后再试。
- **保留历史记录模式。** 较新版本的 Codex 使用“分页”方式保存历史；第一次打开对话时，Codex 会根据对话文件重建它的分页数据库（`thread_history_*.sqlite`），所以 ChatRelay 从不写入这个数据库。
- **你对某个线程的个人设置仍归你所有。** 更新时，这台电脑上的置顶状态、自定义名称、归档状态和账户都会保留。只存在于另一台电脑上的文件夹和分组会被清空。
- **账户。** 导入的线程会分配给这台电脑上拥有最多线程的那个 Codex 账户。
- **Windows 路径前缀。** Windows 上的 Codex 会把工作目录存成 `\\?\D:\project` 的形式。只有当这台电脑上的 Codex 使用这种前缀时，ChatRelay 才会给 Windows 路径加上它，而且从不给 macOS 或 Linux 路径加。
- **压缩的对话**（`.jsonl.zst`）可以读取和更新。更新时，文件会被替换成普通的 `.jsonl`（压缩的原文件会先备份）。
- 属于另一台电脑的**记忆统计信息**（某条记忆被使用的次数、是否被选中进行整合）不会被复制。
- **未知版本。** 如果 Codex 的索引使用了 ChatRelay 不认识的数据库（例如将来的 `state_6.sqlite`），或者新增了一个它无法填写的必填字段，就会关闭对 Codex 的写入，并给出明确警告。读取仍然可以正常使用。

## 摘要与“在另一个工具中继续”

> 🔒 **密钥永远不会发给 AI。** 在把任何内容发送给模型之前，ChatRelay 会把聊天里发现的密钥、令牌和密码（Anthropic、OpenAI、OpenRouter、GitHub、AWS、Google、Slack、Stripe、Hugging Face、npm、SendGrid、Telegram 机器人的 API 密钥；JWT；私钥；`PASSWORD=…` 这类行；URL 里的密码）替换成 `[REDACTED:kind]`。这一步总是执行，无法关闭；界面会显示隐藏了多少个。代码和其余对话内容仍会发送，所以私有代码或客户代码请优先选择不保留数据的付费模型。

打开 **Summaries**（摘要，高级视图），选择一个项目，勾选要包含的对话（可以来自任何工具）并选择一个模型，然后点击 **Generate handoff**（生成交接文档）。

- 模型：**Claude Opus 5.5**（默认）、Claude Sonnet 5.5（更快、更便宜）、Claude Haiku 5.5（最便宜）、Claude Fable 5.1（能力最强）。你需要一个 Anthropic API 密钥（**Settings → Summaries**（设置 → 摘要））。
- 历史记录会先被精简：保留你的请求、每一轮中助手的最终回答，以及改动过的文件。冗长的工具输出和思考过程会被去掉。来自所有工具的对话按时间顺序合并，并标注各自的工具。
- 很长的历史记录会按大约 10 万 token 一段分别总结，然后再合并。
- 结果包含以下几个部分：Project overview（项目概览）、What's done（已完成的工作）、Key decisions（关键决定）、Open bugs / known issues（未解决的 bug / 已知问题）、Next steps（下一步）、Files touched（改动过的文件）。

然后你可以：

- **Save HANDOFF.md**（保存 HANDOFF.md）到项目文件夹中，或者
- **Continue in…**（在…中继续）某个工具：选择 Claude Code（`CLAUDE.md`）、Codex（`AGENTS.md`）或 Gemini CLI（`GEMINI.md`）。列表中显示的是这台电脑上已安装的工具。ChatRelay 会在那个文件里加入一个简短的 “Previous context”（之前的上下文）部分（概览、已完成的工作、下一步）。再次运行时，只会替换它自己的那一部分；文件的其余内容不会被改动。
- 或者 **copy**（复制）这段文字。

命令行用法：`claude-sync summarize --target handoff|claude-md|agents-md|gemini-md|none`。

## 安全与隐私

- **上传时绝不修改原始文件。** 上传只会读取你的历史记录文件。
- **工具运行时不写入任何东西**（Codex）。Claude Code 当前打开的会话（触发钩子的那个）永远不会被改动。
- **每次写入前都会备份**，包括 Claude Code 的 `settings.json`、Codex 的数据库（连同它们的 `-wal` 和 `-shm` 文件）以及 `session_index.jsonl`。
- **每次导入都有试运行。** 在真正执行之前，你能看到每个文件和每一处路径改写。
- **发生冲突时两个版本都会保留**，绝不会互相覆盖。
- **密钥扫描。** 上传前，ChatRelay 会查找 API 密钥和密码：Anthropic、OpenAI、GitHub、AWS、Google、Slack 和 Stripe 的密钥，JWT，私钥，`.env` 风格的 `SECRET=…` 行，以及 URL 中包含的登录凭据。你可以选择：**warn**（警告）、**redact**（脱敏，只在上传的副本中替换为 `[REDACTED:kind]`）或 **off**（关闭）。
- **密钥保存在系统钥匙串中。** 你的 GitHub 令牌和 Anthropic 密钥从不写入任何文件。
- **绝不碰你的登录信息。** ChatRelay 不会读取、复制或修改 Claude Code 或 Codex 的登录文件（`~/.claude/.credentials.json`、`~/.codex/auth.json`……）。同步历史记录不可能让你退出登录。如果你被登出了，那是工具本身造成的（例如会话过期，或者在另一台电脑上用另一个账户登录）。
- **只使用私有存储。** 公开的 GitHub 仓库会被拒绝。
- **没有 ChatRelay 服务器。** 数据只在你的电脑、你的文件夹或 GitHub 之间传输，以及（仅在你生成摘要时）发送给 Anthropic API。

以下内容按设计不会同步：`~/.claude/history.jsonl`（你在所有项目中按上方向键调出的提示词历史）、`~/.claude/file-history/`（回退快照），以及所有登录凭据。

## 工作原理（技术细节）

### Claude Code 把历史记录存在哪里

| 路径 | 内容 |
|---|---|
| `~/.claude/projects/<encoded-path>/<session-uuid>.jsonl` | 每个会话一个文件，每行一个 JSON 对象 |
| `~/.claude/projects/<encoded-path>/<session-uuid>/subagents/*.jsonl` + `*.meta.json` | 子代理的对话记录（作为“附属文件（sidecar）”同步） |
| `~/.claude/projects/<encoded-path>/<session-uuid>/tool-results/*` | 保存到磁盘的大型工具输出（附属文件） |
| `~/.claude/projects/<encoded-path>/memory/` | 项目自动记忆（`MEMORY.md` + 笔记） |

以下几点与通常的假设不同，ChatRelay 都已处理：

- **不同客户端的盘符大小写不同。** VS Code 扩展记录的是 `c:\Users\…`（文件夹 `c--Users-…`），CLI 记录的是 `C:\Users\…`（文件夹 `C--Users-…`），同一个会话里甚至可能两种都有。在 Windows 上，路径比较时不区分大小写。
- **文件夹名无法可靠地还原成路径。** `C:\Users\me\my project` 和 `C:\Users\me\my-project` 编码后都是 `C--Users-me-my-project`。真实路径来自会话中记录的 `cwd`；解码文件夹名只是一个带标注的后备方案。
- **会话可能非常大**（嵌入图片/PDF 时可达 200 MB 以上），所以所有处理都是流式进行的。扫描结果按文件大小和修改时间缓存，所以重新扫描大约只需 100 毫秒。
- **助手的一次回复会占用好几行**（每个内容块一行，`message.id` 相同）；统计消息数时会去重。标题取自第一条真正的提示词（会去掉 IDE 包装标签）；Claude Code 自己生成的 `ai-title` 显示在旁边。
- **除了 user/assistant，还有很多其他类型的行**（`attachment`、`file-history-snapshot`、`queue-operation`、`ai-title`、`last-prompt`、`permission-mode`……）。不认识的类型和字段会原样保留。

### Codex 把历史记录存在哪里

见 [Codex 支持详解](#codex-支持详解)。rollout 文件的每一行都是 `{timestamp, type, payload}`；第一行是 `session_meta`，包含会话 id 和 `cwd`。Codex 先后用过三代格式来写对话（≥0.15x 版本中的 `event_msg/item_completed` 条目，更早版本中的 `user_message`/`agent_message` 事件，最老版本中的普通 `response_item` 消息）；查看器会使用其中信息最丰富的那一种。

### 适配器

每个 AI 工具都是一个**适配器**（`crates/core/src/providers/`），实现同一个接口（`ProviderAdapter`）：检测工具及其格式、列出项目和会话、把会话读成与工具无关的通用结构（`UniversalSession`）、无损导出（`SessionBundle`：原始文件加上工具元数据，例如 Codex 的索引行）、在另一台电脑上导入（改写路径、确认工具没有在运行、备份、试运行），以及追加新行。见[添加其他 AI 工具](#添加其他-ai-工具适配器指南)。

### 项目身份

同一个项目在每台电脑上的路径都不同，所以按以下顺序识别项目：

1. **手动关联**（Link 按钮 / `claude-sync link <dir> <id>`），保存在 ChatRelay 的配置中
2. **git 远程地址**，经过规范化处理：`git@github.com:Me/Repo.git` 和 `https://github.com/me/repo` 都会变成 `git:github.com/me/repo`
3. 项目根目录中的一个 **`.claude-sync.json`** 文件，里面保存一个 UUID，非 git 项目第一次推送时创建（请把它提交到仓库，或者在另一台电脑上手动关联）。“Upload everything”（全部上传）和后台同步则改为在 ChatRelay 的配置中创建关联，所以不会往你的项目文件夹里写任何东西。

### 存储结构（在文件夹或仓库中）

```
<projectId-slug>/
  manifest.json                          machines, original paths, hashes, timestamps, revision
  <sessionId>.jsonl.gz                   Claude Code session (whole, or its start when deltas exist)
  <sessionId>.d<N>.jsonl.gz              lines appended after that, one blob per push
  <sessionId>.sidecar.json.gz            subagents/ + tool-results/ (if any)
  memory.json.gz                         Claude Code project memory (if any)
  <provider>-<sessionId>.bundle.json.gz  another tool's session (e.g. codex-…): files + metadata
  <provider>-<sessionId>.d<N>.jsonl.gz   lines appended to it later
  .versions/<file>/<timestamp>           previous versions (folder backend)
```

各文件说明（对应上面代码块中的英文注释）：`manifest.json` 记录电脑、原始路径、哈希、时间戳和修订号；`<sessionId>.jsonl.gz` 是 Claude Code 会话（完整内容，或者存在增量时的开头部分）；`<sessionId>.d<N>.jsonl.gz` 是之后追加的行，每次推送一个数据块；`<sessionId>.sidecar.json.gz` 是 `subagents/` + `tool-results/`（如果有）；`memory.json.gz` 是 Claude Code 的项目记忆（如果有）；`<provider>-<sessionId>.bundle.json.gz` 是其他工具的会话（例如 `codex-…`）：文件 + 元数据；`<provider>-<sessionId>.d<N>.jsonl.gz` 是之后追加到它上面的行；`.versions/<file>/<timestamp>` 是旧版本（文件夹后端）。

其他工具的会话列在 manifest 的 `providerSessions` 中（键为 `<provider>:<id>`）。旧版本的应用会忽略这个列表，并保持它原样不动。

### 推送（Push）

- 会话通过 SHA-256 进行比较；只上传新的或有改动的会话。原始文件永远只被读取。
- **只发送新增的行。** AI 工具只会往对话文件末尾追加内容，所以一个会话第一次上传之后，推送时只把自上次同步以来新增的行存成一个“增量（delta）”部分。每个部分都会记录推送它的那台电脑的路径。会话哈希是链式的（`hash = sha256(previous : sha256(part))`）。累计 40 个部分之后，下一次推送会重新上传整个会话。如果这条捷径不适用（文件以其他方式被修改、发生冲突、状态来自旧版本），就会上传整个文件。
- 如果后端有一个你还没见过的版本，其中包含你没有的消息，那么这个会话的推送会被拒绝，并提示 “pull first”（请先拉取），这样就不会丢失任何内容。
- **离线了？**（GitHub 无法访问、云盘没有挂载。）推送会被放进 `~/.claude-sync/queue.json` 队列，在下次运行时重试，桌面应用也会每 15 分钟重试一次。

### 拉取（Pull）

- 路径是在解析后的 JSON 内部改写的（字符串值**和**对象键都会处理），所以 JSON 转义永远不会出问题。支持的形式：Windows 路径 `C:\…`、`c:/…`、Git-Bash 的 `/c/…` 和 WSL 的 `/mnt/c/…`（不区分大小写）；POSIX 路径（区分大小写）；`file:///` URL，包括用 `%20` 编码的空格；在不同操作系统之间迁移时，项目根目录之后的路径分隔符会被转换；工具自己的主文件夹（`~/.claude`、`~/.codex`）和 Claude Code 的编码文件夹名也会被改写。像 `shop-old` 这样的同级文件夹永远不会被改动。
- **快速路径：** 如果一台电脑上的内容和它上次同步时完全一样，它只会下载缺少的部分并追加上去。
- **分歧处理**（对话只会追加内容；Claude Code 按行 id 比较，其他工具按文本前缀比较）：
  - 远程包含本地 → 更新
  - 本地包含远程 → 你的版本更新，予以保留（下次推送时上传）
  - 两边都有改动 → **冲突**：你的副本保持原样，另一个版本会被保存为**一段使用新 id 的新对话**（Codex：命名为 “<name> (from <PC>)”）。之后两者都会出现在工具中，并同步到你的其他电脑。

### 自动同步钩子（Claude Code）

“Enable auto-sync”（启用自动同步）会把以下内容合并进 `~/.claude/settings.json`；你的其他设置和钩子都会保留，并且会先做备份：

```jsonc
"hooks": {
  "SessionStart": [{ "hooks": [{ "type": "command", "command": "\"…/Claude Sync/claude-sync.exe\" pull --hook --quiet --claude-sync-hook", "timeout": 60 }] }],
  "SessionEnd":   [{ "hooks": [{ "type": "command", "command": "\"…/Claude Sync/claude-sync.exe\" push --hook --quiet --claude-sync-hook", "timeout": 60 }] }]
}
```

- `--hook` 从 stdin 读取 Claude Code 钩子的 JSON（`cwd`、`session_id`），读不到时依次退回到 `CLAUDE_PROJECT_DIR` 和当前工作目录。钩子**总是以 0 退出**，所以永远不会破坏会话；错误会记录到日志面板。
- 钩子运行的是安装在应用旁边的原生 `claude-sync` 可执行文件。不需要 Node.js。
- “Disable auto-sync”（停用自动同步）只会移除包含 `claude-sync-hook` 标记的钩子。

## 更新

- 桌面应用会在以下时机检查新版本：启动时、每次打开窗口时、每小时一次、离开 5 分钟以上后回到窗口时，以及你点击 **Check for updates**（检查更新）时（在 Settings → About（设置 → 关于）、简洁视图或命令面板中）。检查期间会显示一个加载动画。
- 有新版本时，你会看到 **A new version is available → Update now**（有新版本可用 → 立即更新）。应用会下载新版本、验证签名（应用只接受用本项目密钥签名的更新）、原地安装并重启。历史记录和设置都会保留。
- Android 应用会显示一条通知，附带新 APK 的下载链接。

## 故障排查与常见问题

**SmartScreen 拦截了安装程序。** 安装程序没有代码签名。点击 **More info → Run anyway**（更多信息 → 仍要运行）。

**某个项目显示黄色圆点。** 这台电脑上有尚未上传的对话。推送它，或者打开自动同步。

**另一台电脑上的项目没有出现 / 以不同的名字出现。** 项目是通过 git 远程地址、`.claude-sync.json` 文件或关联来匹配的。如果两边文件夹名字不同、又没有 git 远程地址，就用一次 **Link**（关联）（或 **Import into…**（导入到…）），选择正确的本地文件夹。

**一段 Codex 对话被跳过了：“Codex is running”（Codex 正在运行）。** 关闭 Codex CLI、VS Code 扩展里的 Codex 面板（或直接关闭 VS Code）以及 Codex 桌面应用，然后再拉取一次。后台同步会自己重试。

**Codex 导入被关闭了：“Unknown Codex index database”（未知的 Codex 索引数据库）/ “new required fields”（新的必填字段）。** 你的 Codex 比当前 ChatRelay 版本所认识的更新。请更新 ChatRelay。你的对话仍然可以查看。

**我看到同一段对话出现了两次，其中一个以 “(from OFFICE-PC)” 结尾。** 这段对话在两台电脑同步之前，分别在两台电脑上都继续聊过。两个版本都会保留；在工具中删掉你不需要的那个即可。

**我以前的 Claude Code 对话不见了。** Claude Code 会删除超过 `cleanupPeriodDays`（默认 30 天）的对话。在设置中把它调大（或运行 `claude-sync cleanup-days 3650`）。已经上传过的对话可以从后端重新拉取回来。

**同步会不会让我退出 Claude 登录？** 不会。ChatRelay 从不读取或写入登录文件。见[安全与隐私](#安全与隐私)。

**第一次上传很慢。** 第一次上传会发送全部内容（压缩后）。之后只发送新增的行。

**推送时提示 “Pull first”（请先拉取）。** 另一台电脑上传了一个更新的版本，而你这边没有。先拉取，再推送。

**离线。** 推送会进入队列并自动重试；运行 `claude-sync queue` 可以立即重试。

**拉取后出了问题。** 打开 **Backups**（备份），恢复拉取之前刚做的那个备份。

**在哪里查看错误？** **Logs**（日志）视图（可以在那里复制错误报告），或者 `~/.claude-sync/logs/claude-sync.log`。

## 从源码构建与开发

环境要求：Node.js 20+、Rust（stable 稳定版），在 Windows 上还需要 MSVC 工具链（Visual Studio 的 “Desktop development with C++”（使用 C++ 的桌面开发）工作负载）。

```bash
git clone https://github.com/Abh1shxkk/chatrelay.git
cd chatrelay
npm install
npm run tauri:dev      # run the desktop app with hot reload
npm run test:rust      # cargo test --workspace: engine, adapters, push/pull, GitHub backend
npm test               # UI helper tests (vitest)
npm run typecheck      # TypeScript
npm run tauri:build    # installer in target/release/bundle/nsis/
```

上面各命令的作用：`tauri:dev` 以热重载方式运行桌面应用；`test:rust` 运行 `cargo test --workspace`（引擎、适配器、推送/拉取、GitHub 后端）；`npm test` 运行界面辅助函数的测试（vitest）；`typecheck` 做 TypeScript 类型检查；`tauri:build` 生成安装程序，位于 `target/release/bundle/nsis/`。

项目结构：

```
crates/core/       Rust engine: scanner, JSONL, path rewriting, sync, backends, hooks, summaries
crates/core/src/providers/   AI tool adapters: claude_code.rs, codex.rs (+ codex_format.rs, browser-safe parsing)
crates/core/src/provider_sync.rs   other tools' sessions in push/pull (bundles, deltas, conflict copies)
crates/core/tests/  integration tests with fixture files (tests/fixtures/codex, tests/fixtures/claude-code)
crates/cli/        the `claude-sync` CLI (also what the Claude Code hooks run)
crates/wasm/       the engine compiled to WebAssembly for the web and phone viewers
src-tauri/         desktop app: window, tray, background sync, the API behind window.claudeSync
src/renderer/      React + TypeScript + Tailwind UI (shared by desktop, web and phone)
src/shared/        TypeScript types and helpers
mobile/            Android / iOS shell around the web version (Tauri)
scripts/           release, CLI staging, WASM build
tests/             vitest tests; tests/web/mock-github.mjs for testing the web version
```

各目录说明（对应上面代码块中的英文注释）：

- `crates/core/`：Rust 引擎：扫描器、JSONL、路径改写、同步、后端、钩子、摘要
- `crates/core/src/providers/`：AI 工具适配器：`claude_code.rs`、`codex.rs`（以及 `codex_format.rs`，可在浏览器中安全使用的解析代码）
- `crates/core/src/provider_sync.rs`：推送/拉取中其他工具的会话（数据包、增量、冲突副本）
- `crates/core/tests/`：使用测试数据文件的集成测试（`tests/fixtures/codex`、`tests/fixtures/claude-code`）
- `crates/cli/`：`claude-sync` CLI（也是 Claude Code 钩子运行的程序）
- `crates/wasm/`：编译成 WebAssembly 的引擎，供网页版和手机查看器使用
- `src-tauri/`：桌面应用：窗口、托盘、后台同步、`window.claudeSync` 背后的 API
- `src/renderer/`：React + TypeScript + Tailwind 界面（桌面、网页和手机共用）
- `src/shared/`：TypeScript 类型和辅助函数
- `mobile/`：包裹网页版的 Android / iOS 外壳（Tauri）
- `scripts/`：发布、CLI 打包准备、WASM 构建
- `tests/`：vitest 测试；`tests/web/mock-github.mjs` 用于测试网页版

在已安装版本旁边运行一个开发副本：设置单独的应用标识和数据文件夹，这样它永远不会碰到你真正的设置：

```powershell
$env:TAURI_CONFIG='{"identifier":"com.claudesync.dev","productName":"ChatRelay Dev"}'
$env:CLAUDE_SYNC_HOME='D:\tmp\chatrelay-dev'
npm run tauri:dev
```

### 网页版构建

```bash
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.129   # must match wasm-bindgen in Cargo.lock
npm run web:wasm     # rebuild the WebAssembly engine
npm run web:dev      # http://localhost:5175/web.html
npm run web:build    # static site in out/web/ (host on GitHub Pages, Cloudflare Pages, Netlify…)
```

说明：`wasm-bindgen-cli` 的版本必须与 `Cargo.lock` 中的 `wasm-bindgen` 一致；`web:wasm` 重新构建 WebAssembly 引擎；`web:dev` 启动开发服务器，地址是 http://localhost:5175/web.html；`web:build` 在 `out/web/` 中生成静态网站（可托管在 GitHub Pages、Cloudflare Pages、Netlify……上）。

`node tests/web/mock-github.mjs <folder-backend>` 会把一个文件夹后端模拟成假的 GitHub API 来提供服务（仅限开发版本：设置 `localStorage['claude-sync-web:apiBase'] = 'http://localhost:5176'`，并使用令牌 `test-token-123456`）。

### 手机应用（Android、iOS）

**Android** 需要 JDK 17、Android SDK（platform 36、build-tools 36、NDK r27）以及 Rust 的 Android 编译目标（`tauri android init` 会安装这些）：

```powershell
$env:JAVA_HOME = "<jdk-17>"; $env:ANDROID_HOME = "<android-sdk>"; $env:NDK_HOME = "$env:ANDROID_HOME\ndk\<version>"
npm run mobile:android:init      # once: generates mobile/gen/android
npm run mobile:android:apk       # debug APK for a phone (arm64)
adb install -r <that apk>
npm run mobile:android:release   # release APK/AAB, signed when CLAUDE_SYNC_KEYSTORE_PROPERTIES is set
```

说明：`mobile:android:init` 只需运行一次，会生成 `mobile/gen/android`；`mobile:android:apk` 生成用于手机的调试版 APK（arm64）；`mobile:android:release` 生成正式版 APK/AAB，设置了 `CLAUDE_SYNC_KEYSTORE_PROPERTIES` 时会自动签名。

正式版签名会读取一个保存在**仓库之外**的 properties 文件，文件路径由 `CLAUDE_SYNC_KEYSTORE_PROPERTIES` 指定：

```properties
storeFile=D:/dev/android-keys/claude-sync-release.jks
storePassword=…
keyAlias=claude-sync
keyPassword=…
```

用 `keytool -genkeypair -keystore claude-sync-release.jks -alias claude-sync -keyalg RSA -keysize 4096 -validity 10000` 创建一次密钥，并做好备份：已安装应用的更新必须用同一个密钥签名。

**iOS** 需要一台装有 Xcode 的 Mac，并运行 `rustup target add aarch64-apple-ios aarch64-apple-ios-sim`：

```bash
npm install && npm run web:wasm
npm run mobile:ios:init
npm run mobile:ios:dev
npm run mobile:ios:build
```

## 添加其他 AI 工具（适配器指南）

1. **先在真实电脑上核实存储格式**：会话存在哪里、行/记录的格式、有没有索引数据库及其结构、工具如何列出会话、如何保存路径、哪些进程表示工具“正在运行”。把这些写在适配器文件的开头。
2. 在 `crates/core/src/providers/mod.rs` 中添加一个 `ProviderId`，并新建文件 `providers/<tool>.rs` 实现 `ProviderAdapter`：`detect`、`list_projects`、`list_sessions`、`read_session`、`export_session`、`import_session`，以及可选的 `append_session`、`context_file_name`、`process_names`。
3. 每个适配器都必须遵守的规则：工具运行时拒绝写入（`ensure_not_running`），写入前备份每个文件（`ImportOptions.backups`），遵守 `dry_run`，遵守 `keep_both`（把出现分歧的传入会话以新 id 保存），遇到任何不认识的格式就关闭导入（并在 `ProviderStatus` 中给出警告）。
4. 把纯解析代码放在一个不访问文件系统的文件里（例如 `codex_format.rs`），这样网页查看器也能使用它，并把它加入 `messages_from_bundle`。
5. 在 `crates/core/tests/fixtures/<tool>/` 下添加测试数据文件和测试：检测、列出、读取、导出 → 在第二台模拟电脑上导入（路径被改写）、更新、本地领先、冲突、因进程运行而拒绝写入、未知格式。
6. 在 `src/shared/types.ts`（`PROVIDER_LABELS`）中添加显示名称。标签、筛选器、推送/拉取、摘要和查看器都会从那里自动获取。

## 发布新版本

已安装的应用会检查 [Abh1shxkk/claude-sync-releases](https://github.com/Abh1shxkk/claude-sync-releases) 上的 `latest.json`。

1. 在 `package.json`、`src-tauri/tauri.conf.json`、`mobile/tauri.conf.json` 和 `Cargo.toml` 中提升 `version`。
2. `npm run release -- --notes "What changed"`

这会构建用更新器密钥签名的 Windows 安装程序（密钥来自 `TAURI_SIGNING_PRIVATE_KEY`，或者 `D:\dev\tauri-keys\claude-sync-updater.key` 及其 `.password` 文件）和已签名的 APK，生成 `latest.json`，并把所有文件作为 `v<version>` 版本上传。可用参数：`--no-apk`、`--skip-build`、`--dry-run`、`--notes-file <file>`。GitHub 登录信息来自 `git credential fill`（或 `GITHUB_TOKEN`）。

请备份好更新器密钥。应用只接受用它签名的更新；它的公钥部分在 `src-tauri/tauri.conf.json` 中。

## 已知限制

- Windows 安装程序没有代码签名（会出现 SmartScreen 警告）。
- 只在 Windows 上测试过。macOS 和 Linux 可以构建，但没有发布安装包。
- 同一段对话如果同时在两台电脑上打开，无法实时合并；它会变成一个冲突副本。
- Codex 没有“会话结束”钩子，所以 Codex 同步是每 15 分钟运行一次，而不是即时同步。
- 对于超过 200 个字符的路径，Claude Code 文件夹名的确切哈希规则没有公开文档；ChatRelay 会优先使用一个已存在、且其中会话记录了相同 `cwd` 的文件夹，否则就使用它自己的 `-<hash>` 后缀。
- 网页版和手机查看器是只读的，并且需要使用 GitHub 后端。
