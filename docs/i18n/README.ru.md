**Переносите свои чаты с ИИ-помощниками для программирования на любой компьютер и из одного ИИ-инструмента в другой.**

ChatRelay синхронизирует историю чатов ИИ-помощников для программирования (сейчас это **Claude Code** и **OpenAI Codex**) между вашими компьютерами. Начните разговор на рабочем ПК, а потом откройте тот же разговор на домашнем ноутбуке: те же сообщения, те же вызовы инструментов, а все пути к файлам заменены на пути нового компьютера. Кроме того, ChatRelay записывает краткую сводку истории проекта в файл инструкций, который читает другой инструмент (`CLAUDE.md`, `AGENTS.md`, `GEMINI.md`), чтобы вы могли продолжить работу в другом ИИ-инструменте.

## Что умеет ChatRelay

- **Переносит историю чатов между компьютерами.** Каждый разговор из Claude Code (CLI в терминале и расширение для VS Code) и Codex (CLI, расширение для VS Code и настольное приложение) копируется в хранилище, которое принадлежит вам, а оттуда — на ваши другие компьютеры. На другом компьютере он появляется в собственном списке истории инструмента: `claude --resume`, панель Claude Code в VS Code, `codex resume` или боковая панель Codex.
- **Исправляет пути к файлам.** Ваш проект может лежать в `C:\Users\me\shop` на одном компьютере и в `D:\work\shop` на другом, или в `/home/me/shop` на Linux. ChatRelay переписывает каждый путь внутри чата (рабочая папка, входные и выходные данные инструментов, ссылки на файлы, текст сообщений) на путь принимающего компьютера.
- **Отправляет только изменения.** После первой загрузки передаются только новые строки разговора: несколько КБ вместо целого файла.
- **Никогда не теряет вашу работу.** При загрузке он никогда не изменяет ваши оригиналы. Перед изменением любого файла он делает его резервную копию, сначала показывает предварительный просмотр (пробный прогон) и никогда не перезаписывает разговор, который изменился на обоих компьютерах: он сохраняет обе версии.
- **Работает сам.** При включённой автосинхронизации разговоры Claude Code загружаются в хранилище, когда сеанс заканчивается, и скачиваются, когда сеанс начинается. Разговоры Codex загружаются и скачиваются каждые 15 минут в фоновом режиме.
- **Делает сводки.** Он превращает всю историю проекта (из всех инструментов) в файл `HANDOFF.md`: что сделано, принятые решения, открытые ошибки, следующие шаги, затронутые файлы. Он также может поместить краткую версию в `CLAUDE.md`, `AGENTS.md` или `GEMINI.md`, чтобы следующий инструмент начал работу уже с контекстом.
- **Читайте где угодно.** Веб-страница только для чтения и приложение для Android показывают все ваши разговоры из хранилища GitHub на любом устройстве.
- **Выглядит как VS Code.** Чёрно-белое настольное приложение в стиле VS Code с тёмной и светлой темами, простым режимом для повседневного использования и расширенным режимом со всеми подробностями.

## Поддерживаемые ИИ-инструменты

| Инструмент | Где работает | Просмотр чатов | Синхронизация между компьютерами | Восстановление в инструмент | Файл контекста |
|---|---|---|---|---|---|
| **Claude Code** | CLI в терминале, расширение для VS Code | ✅ | ✅ (с хуками автосинхронизации) | ✅ `claude --resume`, история VS Code | `CLAUDE.md` |
| **OpenAI Codex** | Codex CLI, расширение для VS Code, настольное приложение Codex | ✅ | ✅ (в фоне, каждые 15 мин) | ✅ `codex resume`, боковая панель Codex | `AGENTS.md` |
| Gemini CLI | Терминал | запланировано | запланировано | запланировано | `GEMINI.md` (запись сводки уже доступна) |
| Kiro (IDE и CLI), Cursor, Antigravity | | запланировано | запланировано | запланировано | |

Каждый инструмент хранит историю в своём собственном недокументированном формате, и эти форматы меняются от версии к версии. Поэтому ChatRelay проверяет формат, который находит на вашем компьютере. Если он видит незнакомую версию, он всё равно показывает разговоры, но **отключает запись** для этого инструмента и объясняет причину в **Settings → AI tools** (Настройки → ИИ-инструменты). Он никогда не действует наугад.

Проверенные версии: Claude Code 2.1.x; Codex от 0.144 до 0.160 (база данных индекса `state_5.sqlite`, миграция схемы 58).

## Скачивание и установка

### Windows

1. Скачайте `ChatRelay_<version>_x64-setup.exe` со страницы [последнего релиза](https://github.com/Abh1shxkk/claude-sync-releases/releases/latest). (Релизы до v0.5.0 называются `ClaudeSync_…`.)
2. Запустите его. Установщик не подписан цифровой подписью, поэтому Windows SmartScreen может сообщить «Система Windows защитила ваш компьютер»: нажмите **More info → Run anyway** (Подробнее → Выполнить в любом случае).
3. Устанавливать нужно только один раз. Следующие версии приходят сами (см. [Обновления](#обновления)).

Приложение устанавливается для текущего пользователя в `%LOCALAPPDATA%\Claude Sync\` (папка сохраняет старое имя; см. [О переименовании](#о-переименовании)). Оно запускается в области уведомлений (трее). Если закрыть окно, приложение продолжит работать там; чтобы остановить его, выберите **Quit** (Выход) в меню трея.

### Android (просмотрщик)

Скачайте `ChatRelay_<version>.apk` с той же страницы релиза и откройте его на телефоне (когда спросят, разрешите «установку неизвестных приложений» для вашего браузера или файлового менеджера). Приложение для Android — это **просмотрщик только для чтения** вашего хранилища GitHub; у телефона нет собственной истории ИИ-инструментов.

### macOS и Linux

Движок на Rust и приложение собираются на macOS и Linux (см. [Сборка из исходников](#сборка-из-исходников-и-разработка)), но установщики для них пока не публикуются, и они не тестировались.

### Веб

Веб-просмотрщик — это статическая страница, которую можно разместить самостоятельно (GitHub Pages, Cloudflare Pages, Netlify…) или запустить локально. См. [Веб-просмотрщик и приложение для телефона](#веб-просмотрщик-и-приложение-для-телефона).

## Первоначальная настройка

При первом запуске ChatRelay мастер настройки проведёт вас по этим шагам. Его можно запустить снова в любой момент из палитры команд (**Ctrl+Shift+P → Run First-time Setup Again** (Повторить первоначальную настройку)).

1. **Ваша история.** ChatRelay находит историю Claude Code в `%USERPROFILE%\.claude\projects` (или в папке из `CLAUDE_CONFIG_DIR`), а историю Codex — в `%USERPROFILE%\.codex` (или `CODEX_HOME`). Он показывает, сколько разговоров найдено для каждого инструмента.
2. **Удаление через 30 дней в Claude Code.** По умолчанию Claude Code удаляет разговоры старше 30 дней (`cleanupPeriodDays`). ChatRelay показывает это и предлагает увеличить срок. Перед изменением он делает резервную копию `settings.json`.
3. **Имя компьютера.** Например, `OFFICE-PC` или `HOME-LAPTOP`. Оно показывается рядом с каждым разговором, чтобы вы знали, с какого компьютера он пришёл.
4. **Хранилище (бэкенд).** Папка (Google Drive, OneDrive, Dropbox, сетевой диск) или приватный репозиторий GitHub. См. следующий раздел.
5. **API-ключ Anthropic (необязательно).** Нужен только для сводок. Он хранится в диспетчере учётных данных Windows (связке ключей ОС), а не в файле.
6. **Автосинхронизация.** Включает автоматическую загрузку и скачивание (хуки Claude Code плюс фоновый таймер).
7. **Загрузить всё.** При желании сразу загружает всю вашу существующую историю, с индикатором прогресса.

## Где хранить историю (бэкенд)

Ваша история попадает в место, которым управляете **вы**. У ChatRelay нет собственного сервера.

### Вариант A: папка

Любая папка, которую видят и ваши другие компьютеры:

- Google Drive для компьютера, например `G:\My Drive\chatrelay`
- OneDrive, например `%OneDrive%\chatrelay`
- Dropbox, NAS или сетевая папка, либо USB-накопитель, который вы носите с собой

Туда попадают только сжатые копии. Ваши рабочие папки `~/.claude` и `~/.codex` никогда не переносятся в облачную папку. Бэкенд-папка также хранит предыдущие версии каждого файла (**Settings → What to sync → Versions kept (folder backend)** (Настройки → Что синхронизировать → Сколько версий хранить (бэкенд-папка)), по умолчанию 2).

### Вариант B: приватный репозиторий GitHub

Лучший вариант, если вам также нужен веб-просмотрщик или приложение для телефона.

1. **Sign in with GitHub** (Войти через GitHub) — рекомендуется. ChatRelay показывает короткий код; вы вводите его на github.com и подтверждаете. GitHub App ChatRelay получает доступ только к выбранным вами репозиториям (обычно только к репозиторию с историей), с правом читать и записывать их содержимое. Пароль не хранится, и никакой сервер не участвует.
2. Или вставьте **personal access token** (персональный токен доступа): классический токен с областью `repo` или детализированный (fine-grained) токен с правом *Contents: Read and write* на этот один репозиторий. Если вы вошли в GitHub CLI (`gh auth login`), ChatRelay может использовать этот токен.
3. Выберите существующий **приватный** репозиторий или нажмите **Create private repo** (Создать приватный репозиторий). Публичные репозитории не принимаются, потому что история чатов может содержать закрытый код и секреты.

На GitHub каждая загрузка — это **один коммит**. Файлы больше 40 МБ (в сжатом виде) автоматически разбиваются на части, потому что GitHub не принимает отдельные файлы больше 100 МБ.

Токен хранится только в связке ключей ОС (служба `claude-sync`).

## Настройка второго компьютера

На **компьютере 1** (на котором уже есть история):

1. Установите ChatRelay и выберите бэкенд.
2. Загрузите историю: нажмите **Upload now** (Загрузить сейчас) в простом режиме (или **Upload everything** (Загрузить всё) в конце настройки) либо **Push** (Отправить) на проекте в расширенном режиме. Предварительный просмотр показывает каждый разговор и все найденные секреты; вы можете скрыть (замаскировать) их в загружаемой копии.

На **компьютере 2**:

1. Установите ChatRelay и выберите **тот же бэкенд** (ту же синхронизируемую папку или тот же репозиторий GitHub).
2. Поместите папку проекта на компьютер 2 (например, с помощью `git clone`). Путь может отличаться, например `D:\work\shop` вместо `C:\Users\me\shop`.
3. Нажмите **Bring history to this PC** (Перенести историю на этот компьютер) в простом режиме или откройте представление **Sync** (Синхронизация) в расширенном режиме. ChatRelay покажет все проекты в бэкенде и то, куда они попадут на этом компьютере:
   - **Git-проекты** сопоставляются автоматически по URL удалённого репозитория (remote).
   - **Остальные проекты**: нажмите **Import into…** (Импортировать в…) / **Link** (Связать) и один раз выберите локальную папку. Связь запоминается.
4. Проверьте **пробный прогон**: какие файлы будут записаны и каждое изменение путей (например, `×166  C:\Users\me\shop → D:\work\shop`). Затем подтвердите.
5. Откройте разговор в инструменте: `claude --resume` или панель Claude в VS Code; `codex resume` или боковая панель Codex.

Для Codex: **сначала закройте Codex** (CLI, расширение для VS Code и настольное приложение). ChatRelay никогда не записывает в файлы Codex, пока он запущен; такой разговор пропускается с причиной «Codex is running» (Codex запущен) и будет перенесён в следующий раз.

Включите **Auto-sync** (Автосинхронизация) на обоих компьютерах, и больше ничего из этого не придётся делать вручную.

## Повседневное использование

### Простой и расширенный режимы

- **Простой режим** (Simple view, по умолчанию): ваши проекты с цветной точкой состояния, две большие кнопки (**Upload now** / **Bring history to this PC**), переключатель автосинхронизации и проверка обновлений.
- **Расширенный режим** (Advanced view): интерфейс в стиле VS Code с панелью действий (Projects **Ctrl+Shift+E**, Sync **Ctrl+Shift+Y**, Summaries, Logs, Backups, Settings — проекты, синхронизация, сводки, журналы, резервные копии, настройки), вкладками, строкой состояния и палитрой команд (**Ctrl+Shift+P**) со всеми действиями.

Переключаться между ними можно через **Ctrl+Shift+P → Switch to Simple/Advanced View** (Перейти в простой/расширенный режим).

### Точки состояния

| Точка | Значение | Что делать |
|---|---|---|
| Зелёная | Синхронизировано | Ничего |
| Жёлтая / оранжевая | Изменения на этом компьютере ещё не загружены | Нажать Push или дождаться автосинхронизации |
| Красная | Последняя синхронизация не удалась | Открыть **Logs** (Журналы) и посмотреть причину |
| Серая | Ни разу не синхронизировалось | Один раз нажать Push |
| Пустой кружок | У проекта ещё нет идентификатора (не связан) | Нажать Push (связь будет создана) или **Link**, чтобы связать его с проектом с другого компьютера |

### Разговоры из нескольких инструментов

У каждого разговора есть маленький значок с названием инструмента (**Claude** или **Codex**). В проектах, где вы использовали больше одного инструмента, есть **фильтр** (All / Claude Code / Codex — все / Claude Code / Codex). Если открыть разговор, вы увидите полную расшифровку: ваши сообщения, ответы помощника, вызовы инструментов (выполненные команды, отредактированные файлы) и список изменённых файлов.

### Push и pull (отправка и получение)

- **Push** (Отправить) загружает разговоры проекта, изменившиеся с последней синхронизации. **Push all** (Отправить всё) делает это для всех проектов.
- **Pull** (Получить) скачивает новое. Он всегда начинается с **пробного прогона**, который показывает каждый файл, который будет записан, и каждую замену пути. Ничего не записывается, пока вы не подтвердите.

### Автосинхронизация

Когда включена **Auto-sync** (Автосинхронизация):

- **Claude Code**: хуки в `~/.claude/settings.json` запускают ChatRelay, когда сеанс Claude Code **начинается** (pull) и **заканчивается** (push).
- **Codex**: у Codex нет таких хуков, поэтому настольное приложение проверяет изменения каждые 15 минут (первый раз — через 20 секунд после запуска). Оно загружает проекты, в которых изменились разговоры Codex, и скачивает новые (пропускается, пока Codex запущен).
- Загрузки, которые не удались, потому что вы были без сети, ставятся в очередь и повторяются.

Включить или выключить автосинхронизацию можно в настройках, в меню трея или командой `claude-sync hooks install|uninstall`.

### Меню трея

Push now · Pull now · Auto-sync on/off · Last sync status · Open · Quit (Отправить сейчас · Получить сейчас · Автосинхронизация вкл/выкл · Состояние последней синхронизации · Открыть · Выход).

### Резервные копии

Перед каждой записью создаётся резервная копия в `~/.claude-sync/backups/<timestamp>-<what>/`. Откройте **Backups** (Резервные копии) (или выполните `claude-sync backups`), чтобы их увидеть, и нажмите **Restore** (Восстановить) на нужной, чтобы вернуть все файлы точно в прежнее состояние. Восстановление также удаляет файлы, которые были созданы этим изменением.

### Журналы

**Logs** (Журналы) показывает всё, что сделал ChatRelay, с выделенными ошибками, и кнопку, которая копирует отчёт об ошибке.

## Поддержка Codex подробно

Что переносится вместе с каждым разговором Codex:

| Элемент | Где его хранит Codex | Что делает ChatRelay |
|---|---|---|
| Сам разговор («rollout») | `~/.codex/sessions/YYYY/MM/DD/rollout-<time>-<id>.jsonl` (некоторые версии пишут сжатый `.jsonl.zst`) | Копирует, переписывая все пути |
| Строка индекса для треда | `~/.codex/state_5.sqlite`, таблица `threads` | Добавляет или обновляет, чтобы разговор появился в `codex resume` и в боковой панели |
| Название треда | `~/.codex/session_index.jsonl` | Добавляет |
| Память Codex для этого треда | `~/.codex/memories_1.sqlite`, таблица `stage1_outputs` | Добавляет, если на этом компьютере её для этого треда нет; пути переписываются |
| Цели этого треда | `~/.codex/goals_1.sqlite`, таблицы `thread_goals`, `thread_goal_continuation_deferrals` | Добавляет, если на этом компьютере их для этого треда нет |

Важные подробности:

- **Codex должен быть закрыт**, пока ChatRelay записывает данные. ChatRelay проверяет, есть ли запущенные процессы `codex` (CLI, расширение для VS Code, настольное приложение). Во время фоновой синхронизации он ничего не просит закрыть, а просто пробует позже ещё раз.
- **Режим истории сохраняется.** Новые версии Codex хранят историю «постранично»; Codex сам перестраивает свою базу страниц (`thread_history_*.sqlite`) из файла разговора при первом открытии, поэтому ChatRelay никогда не записывает в эту базу.
- **Ваши собственные настройки треда остаются вашими.** При обновлении сохраняются закрепление, собственное название, состояние архивации и учётная запись на этом компьютере. Папки и разделы, которые существуют только на другом компьютере, очищаются.
- **Учётная запись.** Импортированный тред назначается той учётной записи Codex, которой на этом компьютере принадлежит больше всего тредов.
- **Префикс путей Windows.** Codex в Windows хранит рабочие папки в виде `\\?\D:\project`. ChatRelay добавляет этот префикс только к путям Windows и только на компьютере, где Codex его использует, и никогда — к путям macOS или Linux.
- **Сжатые разговоры** (`.jsonl.zst`) можно читать и обновлять. При обновлении файл заменяется обычным `.jsonl` (сжатый оригинал перед этим сохраняется в резервную копию).
- **Служебный учёт памяти**, относящийся к другому компьютеру (как часто использовалась запись памяти, выбиралась ли она для объединения), не копируется.
- **Незнакомые версии.** Если индекс Codex использует базу данных, которую ChatRelay не знает (например, будущую `state_6.sqlite`), или в нём появилось обязательное поле, которое ChatRelay не может заполнить, запись для Codex отключается с понятным предупреждением. Чтение при этом продолжает работать.

## Сводки и «Продолжить в другом инструменте»

> 🔒 **Секреты никогда не попадают к ИИ.** Перед отправкой чего-либо модели ChatRelay заменяет найденные в чатах ключи, токены и пароли (API-ключи Anthropic, OpenAI, OpenRouter, GitHub, AWS, Google, Slack, Stripe, Hugging Face, npm, SendGrid, Telegram-ботов; JWT; приватные ключи; строки вида `PASSWORD=…`; пароли внутри URL) на `[REDACTED:kind]`. Это происходит всегда и не отключается; на экране видно, сколько скрыто. Код и остальная переписка всё равно отправляются, поэтому для закрытого или клиентского кода лучше выбрать платную модель, провайдер которой не хранит данные.

Откройте **Summaries** (Сводки) в расширенном режиме, выберите проект, отметьте разговоры (из любого инструмента) и модель, затем нажмите **Generate handoff** (Создать сводку для передачи).

- Модели: **Claude Opus 5.5** (по умолчанию), Claude Sonnet 5.5 (быстрее, дешевле), Claude Haiku 5.5 (самая дешёвая), Claude Fable 5.1 (самая мощная). Нужен API-ключ Anthropic (**Settings → Summaries** (Настройки → Сводки)).
- Сначала история сжимается: ваши запросы, итоговый ответ помощника на каждом шаге и изменённые файлы. Длинный вывод инструментов и «размышления» модели отбрасываются. Разговоры из всех инструментов объединяются в порядке времени и помечаются названием инструмента.
- Длинные истории сводятся по частям примерно по 100 тыс. токенов, а затем объединяются.
- В результате есть такие разделы: Project overview, What's done, Key decisions, Open bugs / known issues, Next steps, Files touched (обзор проекта, что сделано, ключевые решения, открытые ошибки / известные проблемы, следующие шаги, затронутые файлы).

Затем вы можете:

- **Save HANDOFF.md** (Сохранить HANDOFF.md) в папку проекта, или
- **Continue in…** (Продолжить в…) другом инструменте: выберите Claude Code (`CLAUDE.md`), Codex (`AGENTS.md`) или Gemini CLI (`GEMINI.md`). В списке показаны инструменты, установленные на этом компьютере. ChatRelay добавляет в этот файл короткий раздел «Previous context» (Предыдущий контекст: обзор, что сделано, следующие шаги). При повторном запуске заменяется только этот его собственный раздел; остальная часть файла не трогается.
- Или **скопировать** текст.

Из командной строки: `claude-sync summarize --target handoff|claude-md|agents-md|gemini-md|none`.

## Веб-просмотрщик и приложение для телефона

**🌐 Веб-просмотр онлайн:** <https://abh1shxkk.github.io/claude-sync-web/>

Версия приложения только для чтения, которая открывает историю из вашего бэкенда **GitHub** в любом браузере или в приложении для Android: проекты, разговоры из всех инструментов и полные расшифровки. Она использует тот же движок на Rust, скомпилированный в WebAssembly, поэтому показывает ровно то же, что и настольное приложение. Загрузка, скачивание, автосинхронизация и сводки остаются в настольном приложении, потому что им нужны локальные папки с историей.

- Войдите через GitHub или укажите имя репозитория и **детализированный (fine-grained) токен, ограниченный этим репозиторием, с правом Contents: Read-only**.
- Токен хранится только в этом браузере (в localStorage, если вы отметили «запомнить», иначе в sessionStorage).
- Страница обращается только к `api.github.com` и не загружает сторонние скрипты.
- При первом посещении каждый разговор читается один раз, чтобы посчитать сообщения; результаты кэшируются по хешу содержимого.
- На экранах размером с телефон интерфейс переключается на одну панель: список → проект → расшифровка, с кнопкой «назад» и нижней панелью.

## Безопасность и конфиденциальность

- **Оригиналы никогда не изменяются при загрузке.** Загрузка только читает ваши файлы истории.
- **Ничего не записывается, пока инструмент запущен** (Codex). Открытый сеанс Claude Code (тот, который запустил хук) никогда не трогается.
- **Резервная копия перед каждой записью**, включая `settings.json` Claude Code, базы данных Codex (вместе с их файлами `-wal` и `-shm`) и `session_index.jsonl`.
- **Пробный прогон для каждого импорта.** Вы видите каждый файл и каждую замену пути до того, как что-либо произойдёт.
- **При конфликте сохраняются обе версии**, ничего не перезаписывается.
- **Поиск секретов.** Перед загрузкой ChatRelay ищет API-ключи и пароли: ключи Anthropic, OpenAI, GitHub, AWS, Google, Slack и Stripe, JWT, закрытые ключи, строки вида `SECRET=…` как в `.env` и учётные данные внутри URL. Вы выбираете: **warn** (предупреждать), **redact** (маскировать — заменяется на `[REDACTED:kind]` только в загружаемой копии) или **off** (выключено).
- **Секреты остаются в связке ключей ОС.** Ваш токен GitHub и ключ Anthropic никогда не записываются в файл.
- **Ваши входы в аккаунты никогда не трогаются.** ChatRelay не читает, не копирует и не изменяет файлы входа Claude Code или Codex (`~/.claude/.credentials.json`, `~/.codex/auth.json`, …). Синхронизация истории не может разлогинить вас. Если вас всё же разлогинило, причина — в самом инструменте (например, истёк сеанс или вы вошли под другой учётной записью на другом компьютере).
- **Только приватное хранилище.** Публичные репозитории GitHub не принимаются.
- **Нет сервера ChatRelay.** Данные передаются только между вашими компьютерами, вашей папкой или GitHub и (только когда вы создаёте сводку) API Anthropic.

Намеренно не синхронизируются: `~/.claude/history.jsonl` (ваша история запросов по стрелке «вверх» во всех проектах), `~/.claude/file-history/` (снимки для отката) и все учётные данные.

## Инструмент командной строки (CLI)

Установщик помещает `claude-sync.exe` рядом с приложением (`%LOCALAPPDATA%\Claude Sync\`). Именно его запускают хуки Claude Code. Добавьте эту папку в `PATH`, чтобы пользоваться им откуда угодно. Из исходников: `cargo run -p claude-sync-cli -- …`.

```
claude-sync scan [--json]                 List projects & sessions
claude-sync status [--json]               Backend, last sync, hooks, queue, cleanupPeriodDays
claude-sync push [--cwd <dir>] [--all] [--dry-run] [--redact]
claude-sync pull [--cwd <dir>] [--project <id>] [--all] [--dry-run]
claude-sync summarize [--cwd <dir>] [--model <id>] [--target handoff|claude-md|agents-md|gemini-md|none]
claude-sync remote                        List projects stored in the backend
claude-sync link <dir> <projectId>        Link a local folder to a remote project ID (--remove to unlink)
claude-sync config [key] [value]          Show or set config (machineName, backend.folder, backend.github, secretScan, ...)
claude-sync secret set github-token|anthropic-api-key <value>
claude-sync hooks install|uninstall       Add/remove the SessionStart/SessionEnd hooks
claude-sync cleanup-days <n>              Set Claude Code's cleanupPeriodDays (backs up settings.json)
claude-sync backups [restore <id>]        List or restore backups
claude-sync queue                         Retry queued (offline) pushes

Other AI coding tools (provider = claude-code | codex):
claude-sync providers [--json]            Which tools are installed, their version/format, import on/off
claude-sync providers sessions <provider> [--cwd <dir>] [--json]
claude-sync providers show <provider> <id> [--json]      Read a session in the tool-neutral format
claude-sync providers export <provider> <id> --out <file.json.gz>
claude-sync providers import <file.json.gz> --to <dir> [--dry-run]

Flags: --hook (read Claude Code hook JSON from stdin; never fails), --quiet, --json, --verbose
```

Коды выхода: `0` — всё в порядке, `1` — ошибка, `2` — при push возникли конфликты (сначала выполните pull).

| `CLAUDE_CONFIG_DIR` | Папка Claude Code (по умолчанию `~/.claude`) |
| `CODEX_HOME` | Папка Codex (по умолчанию `~/.codex`) |

## Как это работает (технические детали)

### Где Claude Code хранит историю

| Путь | Что там |
|---|---|
| `~/.claude/projects/<encoded-path>/<session-uuid>.jsonl` | Один файл на сеанс, один JSON-объект на строку |
| `~/.claude/projects/<encoded-path>/<session-uuid>/subagents/*.jsonl` + `*.meta.json` | Расшифровки субагентов (синхронизируются как «sidecar» — сопутствующие файлы) |
| `~/.claude/projects/<encoded-path>/<session-uuid>/tool-results/*` | Большие результаты инструментов, сохранённые на диск (sidecar) |
| `~/.claude/projects/<encoded-path>/memory/` | Автоматическая память проекта (`MEMORY.md` + заметки) |

Что отличается от привычных предположений (всё это учтено):

- **Регистр буквы диска зависит от клиента.** Расширение для VS Code записывает `c:\Users\…` (папка `c--Users-…`), CLI записывает `C:\Users\…` (папка `C--Users-…`), и в одном сеансе могут встречаться оба варианта. В Windows пути сравниваются без учёта регистра.
- **Имена папок нельзя надёжно расшифровать.** `C:\Users\me\my project` и `C:\Users\me\my-project` оба кодируются как `C--Users-me-my-project`. Настоящий путь берётся из `cwd`, записанного в сеансах; расшифровка имени — лишь запасной вариант, помеченный соответствующим образом.
- **Сеансы бывают огромными** (200+ МБ со встроенными изображениями/PDF), поэтому всё обрабатывается потоково. Результаты сканирования кэшируются по размеру и времени изменения, так что повторное сканирование занимает около 100 мс.
- **Один ответ помощника занимает несколько строк** (по одной на каждый блок содержимого, с одинаковым `message.id`); при подсчёте сообщений повторы убираются. Заголовки берутся из первого настоящего запроса (служебные теги IDE удаляются); собственный `ai-title` Claude Code показывается рядом.
- **Помимо user/assistant есть много других типов строк** (`attachment`, `file-history-snapshot`, `queue-operation`, `ai-title`, `last-prompt`, `permission-mode`, …). Незнакомые типы и поля сохраняются без изменений.

### Где Codex хранит историю

См. [Поддержка Codex подробно](#поддержка-codex-подробно). Каждая строка rollout-файла имеет вид `{timestamp, type, payload}`; первая строка — `session_meta` с идентификатором сеанса и `cwd`. Codex записывал разговоры в трёх поколениях форматов (элементы `event_msg/item_completed` в ≥0.15x, события `user_message`/`agent_message` раньше, простые сообщения `response_item` в самых старых); просмотрщик использует самый подробный из имеющихся.

### Адаптеры

Каждый ИИ-инструмент — это **адаптер** (`crates/core/src/providers/`) за единым интерфейсом (`ProviderAdapter`): обнаружить инструмент и его формат, перечислить проекты и сеансы, прочитать сеанс в независимом от инструмента виде (`UniversalSession`), экспортировать его без потерь (`SessionBundle`: исходные файлы плюс метаданные инструмента, например строка индекса Codex), импортировать на другом компьютере (переписать пути, проверить, что инструмент не запущен, сделать резервную копию, пробный прогон) и дописать новые строки. См. [Добавление другого ИИ-инструмента](#добавление-другого-ии-инструмента-руководство-по-адаптерам).

### Идентификация проекта

У одного и того же проекта на каждом компьютере свой путь, поэтому он определяется (по порядку):

1. По **ручной связи** (кнопка Link / `claude-sync link <dir> <id>`), сохранённой в конфигурации ChatRelay
2. По **git remote** в нормализованном виде: `git@github.com:Me/Repo.git` и `https://github.com/me/repo` оба превращаются в `git:github.com/me/repo`
3. По файлу **`.claude-sync.json`** в корне проекта, содержащему UUID; он создаётся при первом push для проектов без git (закоммитьте его или свяжите проект вручную на другом компьютере). «Upload everything» и фоновая синхронизация вместо этого создают связь в конфигурации ChatRelay, поэтому в папки ваших проектов ничего не записывается.

### Структура хранилища (в папке или репозитории)

```
<projectId-slug>/
  manifest.json                          machines, original paths, hashes, timestamps, revision
  <sessionId>.jsonl.gz                   Claude Code session (whole, or its start when deltas exist)
  <sessionId>.d<N>.jsonl.gz              lines appended after that, one blob per push
  <sessionId>.sidecar.json.gz            subagents/ + tool-results/ (if any)
  memory.json.gz                         Claude Code project memory (if any)
  <provider>-<sessionId>.bundle.json.gz  another tool's session (e.g. codex-…): files + metadata
  <provider>-<sessionId>.d<N>.jsonl.gz   lines appended to it later
  .versions/<file>/<timestamp>           previous versions (folder backend)
```

Сеансы других инструментов перечислены в манифесте под ключом `providerSessions` (ключ `<provider>:<id>`). Старые версии приложения игнорируют этот список и оставляют его нетронутым.

### Push (отправка)

- Сеансы сравниваются по SHA-256; загружаются только новые или изменённые. Оригиналы только читаются.
- **Отправляются только новые строки.** ИИ-инструменты всегда только дописывают строки в файл разговора, поэтому после первой загрузки сеанса push сохраняет лишь строки, добавленные с последней синхронизации, в виде «дельта»-части. Каждая часть запоминает пути компьютера, который её отправил. Хеши сеанса связаны в цепочку (`hash = sha256(previous : sha256(part))`). После 40 частей следующий push снова загружает сеанс целиком. Когда такой быстрый путь неприменим (файл изменился другим способом, конфликт, состояние от более старой версии), загружается весь файл.
- Если в бэкенде есть не виденная вами версия, содержащая сообщения, которых у вас нет, push этого сеанса отклоняется с сообщением «pull first» (сначала выполните pull), так что ничего не теряется.
- **Нет сети?** (GitHub недоступен, облачный диск не подключён.) Push ставится в очередь в `~/.claude-sync/queue.json` и повторяется при следующем запуске, а настольное приложение повторяет его каждые 15 минут.

### Pull (получение)

- Пути переписываются внутри разобранного JSON (в строковых значениях **и** в ключах объектов), поэтому экранирование JSON никогда не становится проблемой. Поддерживаемые формы: пути Windows в виде `C:\…`, `c:/…`, Git-Bash `/c/…` и WSL `/mnt/c/…` (без учёта регистра); пути POSIX (с учётом регистра); URL `file:///`, включая пробелы, закодированные как `%20`; разделители после корня проекта преобразуются при переходе между операционными системами; домашняя папка самого инструмента (`~/.claude`, `~/.codex`) и закодированное имя папки Claude Code тоже переписываются. Соседние папки, например `shop-old`, никогда не затрагиваются.
- **Быстрый путь:** компьютер, у которого есть ровно то, что он синхронизировал в прошлый раз, скачивает только недостающие части и дописывает их.
- **Расхождение** (разговоры только дополняются; для Claude Code они сравниваются по идентификаторам строк, для других инструментов — по общему началу текста):
  - удалённая версия содержит локальную → обновление
  - локальная версия содержит удалённую → ваша новее и сохраняется (будет загружена при следующем push)
  - изменились обе → **конфликт**: ваша копия остаётся как есть, а другая версия сохраняется как **новый разговор с новым идентификатором** (в Codex — с названием «<name> (from <PC>)»). Обе версии затем появляются в инструменте и синхронизируются на ваши другие компьютеры.

### Хуки автосинхронизации (Claude Code)

«Enable auto-sync» (Включить автосинхронизацию) добавляет это в `~/.claude/settings.json`; ваши другие настройки и хуки сохраняются, а перед этим делается резервная копия:

```jsonc
"hooks": {
  "SessionStart": [{ "hooks": [{ "type": "command", "command": "\"…/Claude Sync/claude-sync.exe\" pull --hook --quiet --claude-sync-hook", "timeout": 60 }] }],
  "SessionEnd":   [{ "hooks": [{ "type": "command", "command": "\"…/Claude Sync/claude-sync.exe\" push --hook --quiet --claude-sync-hook", "timeout": 60 }] }]
}
```

- `--hook` читает JSON хука Claude Code из stdin (`cwd`, `session_id`), а если его нет — использует `CLAUDE_PROJECT_DIR`, а затем рабочую папку. Хуки **всегда завершаются с кодом 0**, поэтому никогда не могут сломать сеанс; ошибки попадают в панель Logs.
- Хук запускает родной исполняемый файл `claude-sync`, установленный рядом с приложением. Node.js не нужен.
- «Disable auto-sync» (Выключить автосинхронизацию) удаляет только хуки с меткой `claude-sync-hook`.

## Обновления

- Настольное приложение проверяет наличие новой версии при запуске, каждый раз при открытии окна, каждый час, при возвращении к окну спустя 5 минут или больше и когда вы нажимаете **Check for updates** (Проверить обновления) (Settings → About, простой режим или палитра команд). Во время проверки показывается индикатор загрузки.
- Когда обновление доступно, вы видите **A new version is available → Update now** (Доступна новая версия → Обновить сейчас). Приложение скачивает его, проверяет подпись (приложения принимают только обновления, подписанные ключом проекта), устанавливает на место и перезапускается. История и настройки сохраняются.
- Приложение для Android показывает уведомление со ссылкой на новый APK.

## Решение проблем и частые вопросы

**SmartScreen блокирует установщик.** Установщик не подписан цифровой подписью. Нажмите **More info → Run anyway** (Подробнее → Выполнить в любом случае).

**У проекта жёлтая точка.** На этом компьютере есть разговоры, которые ещё не загружены. Сделайте push или включите автосинхронизацию.

**Проект с другого компьютера не появляется / появляется под другим именем.** Проекты сопоставляются по git remote, файлу `.claude-sync.json` или связи. Если у папок разные имена и нет git remote, один раз воспользуйтесь **Link** (или **Import into…**) и выберите нужную локальную папку.

**Разговор Codex пропущен: «Codex is running».** Закройте Codex CLI, панель Codex в расширении для VS Code (или сам VS Code) и настольное приложение Codex, затем снова выполните pull. Фоновая синхронизация повторит попытку сама.

**Импорт Codex отключён: «Unknown Codex index database» / «new required fields».** Ваш Codex новее, чем известно этой версии ChatRelay. Обновите ChatRelay. Ваши разговоры по-прежнему видны.

**Я вижу разговор дважды, и один заканчивается на «(from OFFICE-PC)».** Его продолжили на обоих компьютерах до того, как они синхронизировались. Сохранены обе версии; удалите ненужную в самом инструменте.

**Мои старые разговоры Claude Code пропали.** Claude Code удаляет разговоры старше `cleanupPeriodDays` (по умолчанию 30). Увеличьте значение в настройках (или выполните `claude-sync cleanup-days 3650`). Уже загруженные разговоры можно вернуть из бэкенда с помощью pull.

**Синхронизация разлогинила меня из Claude?** Нет. ChatRelay никогда не читает и не записывает файлы входа. См. [Безопасность и конфиденциальность](#безопасность-и-конфиденциальность).

**Первая загрузка идёт медленно.** Первая загрузка отправляет всё (в сжатом виде). После этого отправляются только новые строки.

**«Pull first» при push.** Другой компьютер загрузил более новую версию, которой у вас нет. Сделайте pull, затем push.

**Нет сети.** Отправки ставятся в очередь и повторяются автоматически; `claude-sync queue` повторяет их сразу.

**Что-то пошло не так после pull.** Откройте **Backups** и восстановите резервную копию, сделанную прямо перед ним.

**Где искать ошибки?** В представлении **Logs** (оттуда можно скопировать отчёт об ошибке) или в `~/.claude-sync/logs/claude-sync.log`.

## Сборка из исходников и разработка

Требования: Node.js 20+, Rust (stable), а в Windows — набор инструментов MSVC (Visual Studio, компонент «Desktop development with C++» — «Разработка классических приложений на C++»).

```bash
git clone https://github.com/Abh1shxkk/chatrelay.git
cd chatrelay
npm install
npm run tauri:dev      # run the desktop app with hot reload
npm run test:rust      # cargo test --workspace: engine, adapters, push/pull, GitHub backend
npm test               # UI helper tests (vitest)
npm run typecheck      # TypeScript
npm run tauri:build    # installer in target/release/bundle/nsis/
```

Структура проекта:

```
crates/core/       Rust engine: scanner, JSONL, path rewriting, sync, backends, hooks, summaries
crates/core/src/providers/   AI tool adapters: claude_code.rs, codex.rs (+ codex_format.rs, browser-safe parsing)
crates/core/src/provider_sync.rs   other tools' sessions in push/pull (bundles, deltas, conflict copies)
crates/core/tests/  integration tests with fixture files (tests/fixtures/codex, tests/fixtures/claude-code)
crates/cli/        the `claude-sync` CLI (also what the Claude Code hooks run)
crates/wasm/       the engine compiled to WebAssembly for the web and phone viewers
src-tauri/         desktop app: window, tray, background sync, the API behind window.claudeSync
src/renderer/      React + TypeScript + Tailwind UI (shared by desktop, web and phone)
src/shared/        TypeScript types and helpers
mobile/            Android / iOS shell around the web version (Tauri)
scripts/           release, CLI staging, WASM build
tests/             vitest tests; tests/web/mock-github.mjs for testing the web version
```

Запуск копии для разработки рядом с установленной: задайте отдельный идентификатор и папку данных, чтобы она никогда не трогала ваши настоящие настройки:

```powershell
$env:TAURI_CONFIG='{"identifier":"com.claudesync.dev","productName":"ChatRelay Dev"}'
$env:CLAUDE_SYNC_HOME='D:\tmp\chatrelay-dev'
npm run tauri:dev
```

```bash
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.129   # must match wasm-bindgen in Cargo.lock
npm run web:wasm     # rebuild the WebAssembly engine
```

### Мобильное приложение (Android, iOS)

Для **Android** нужны JDK 17, Android SDK (platform 36, build-tools 36, NDK r27) и целевые платформы Rust для Android (их устанавливает `tauri android init`):

```powershell
$env:JAVA_HOME = "<jdk-17>"; $env:ANDROID_HOME = "<android-sdk>"; $env:NDK_HOME = "$env:ANDROID_HOME\ndk\<version>"
npm run mobile:android:init      # once: generates mobile/gen/android
npm run mobile:android:apk       # debug APK for a phone (arm64)
adb install -r <that apk>
npm run mobile:android:release   # release APK/AAB, signed when CLAUDE_SYNC_KEYSTORE_PROPERTIES is set
```

Подпись релиза читает файл свойств, который хранится **вне репозитория** и указывается в `CLAUDE_SYNC_KEYSTORE_PROPERTIES`:

```properties
storeFile=D:/dev/android-keys/claude-sync-release.jks
storePassword=…
keyAlias=claude-sync
keyPassword=…
```

Создайте ключ один раз командой `keytool -genkeypair -keystore claude-sync-release.jks -alias claude-sync -keyalg RSA -keysize 4096 -validity 10000` и сохраните его резервную копию: обновления установленного приложения должны быть подписаны тем же ключом.

Для **iOS** нужен Mac с Xcode и `rustup target add aarch64-apple-ios aarch64-apple-ios-sim`:

```bash
npm install && npm run web:wasm
npm run mobile:ios:init
npm run mobile:ios:dev
npm run mobile:ios:build
```

## Добавление другого ИИ-инструмента (руководство по адаптерам)

1. **Сначала проверьте формат хранения на реальном компьютере**: где лежат сеансы, формат строк/записей, есть ли база данных индекса и какова её схема, как инструмент показывает список сеансов, как он хранит пути, какие процессы означают, что он «запущен». Запишите это в начале файла адаптера.
2. Добавьте `ProviderId` в `crates/core/src/providers/mod.rs` и файл `providers/<tool>.rs`, реализующий `ProviderAdapter`: `detect`, `list_projects`, `list_sessions`, `read_session`, `export_session`, `import_session`, а при необходимости `append_session`, `context_file_name`, `process_names`.
3. Правила, которым следует каждый адаптер: отказываться от записи, пока инструмент запущен (`ensure_not_running`), делать резервную копию каждого файла перед записью (`ImportOptions.backups`), соблюдать `dry_run`, соблюдать `keep_both` (сохранять разошедшийся входящий сеанс под новым идентификатором) и отключать импорт (с предупреждением в `ProviderStatus`) при любом незнакомом формате.
4. Поместите чистый разбор данных в файл без доступа к файловой системе (как `codex_format.rs`), чтобы его мог использовать веб-просмотрщик, и добавьте его в `messages_from_bundle`.
5. Добавьте тестовые файлы (fixtures) в `crates/core/tests/fixtures/<tool>/` и тесты: обнаружение, список, чтение, экспорт → импорт на второй «поддельный» компьютер (с переписанными путями), обновление, случай «локальная версия впереди», конфликт, отказ при запущенном процессе, незнакомый формат.
6. Добавьте подпись в `src/shared/types.ts` (`PROVIDER_LABELS`). Значки, фильтры, push/pull, сводки и просмотрщик берут её оттуда.

## Публикация релиза

Установленные приложения проверяют `latest.json` в [Abh1shxkk/claude-sync-releases](https://github.com/Abh1shxkk/claude-sync-releases).

1. Увеличьте `version` в `package.json`, `src-tauri/tauri.conf.json`, `mobile/tauri.conf.json` и `Cargo.toml`.
2. `npm run release -- --notes "What changed"`

Эта команда собирает установщик для Windows, подписанный ключом обновлений (`TAURI_SIGNING_PRIVATE_KEY` или `D:\dev\tauri-keys\claude-sync-updater.key` вместе с файлом `.password`), и подписанный APK, записывает `latest.json` и загружает всё как релиз `v<version>`. Флаги: `--no-apk`, `--skip-build`, `--dry-run`, `--notes-file <file>`. Данные для входа в GitHub берутся из `git credential fill` (или `GITHUB_TOKEN`).

Храните резервную копию ключа обновлений. Приложения принимают только обновления, подписанные им; его открытая часть находится в `src-tauri/tauri.conf.json`.

## Известные ограничения

- Установщик для Windows не подписан цифровой подписью (предупреждение SmartScreen).
- Тестируется только Windows. macOS и Linux собираются, но опубликованных установщиков для них нет.
- Разговор, открытый на двух компьютерах одновременно, нельзя объединить «вживую»; он становится конфликтной копией.
- У Codex нет хука «сеанс завершён», поэтому синхронизация Codex выполняется раз в 15 минут, а не мгновенно.
- Для путей длиннее 200 символов точный хеш имени папки в Claude Code не задокументирован; ChatRelay предпочитает существующую папку, сеансы в которой записали тот же `cwd`, а иначе использует собственный суффикс `-<hash>`.
- Веб-просмотрщик и приложение для телефона работают только для чтения и требуют бэкенд GitHub.

## Планы

- Адаптеры для Gemini CLI, Kiro (IDE и CLI), Cursor и Antigravity — по одному, каждый сначала проверяется на реальном инструменте.
- Установщики с цифровой подписью; сборки для macOS и Linux.

## О переименовании

До v0.5.0 ChatRelay назывался **Claude Sync**. Чтобы существующие установки продолжали обновляться и ничего не потерялось, эти внутренние имена **не** менялись:

| Что сохранено | Почему |
|---|---|
| Папка установки и пункт меню «Пуск» «Claude Sync» | По ним Windows узнаёт установленное приложение; если их изменить, вместо обновления установится вторая копия |
| Идентификатор приложения `com.claudesync.app` / `com.claudesync.mobile` | От него зависят обновления и установки на Android |
| Папка данных `~/.claude-sync/`, `CLAUDE_SYNC_HOME` | Ваши настройки, состояние синхронизации и резервные копии |
| CLI `claude-sync` | Хуки Claude Code вызывают его по пути |
| Файлы проектов `.claude-sync.json`, метка `claude-sync-hook` | Существующие проекты и хуки продолжают работать |
| Репозиторий релизов `claude-sync-releases` | Из него установленные приложения скачивают обновления |
| GitHub App «claude-sync-abh1shxkk» | Существующие входы продолжают работать |
