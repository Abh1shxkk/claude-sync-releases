**AI 코딩 대화를 어느 PC로든, 그리고 한 AI 도구에서 다른 AI 도구로 가져가세요.**

ChatRelay는 AI 코딩 도우미(현재는 **Claude Code**와 **OpenAI Codex**)의 대화 기록을 여러 컴퓨터 사이에서 동기화합니다. 회사 PC에서 대화를 시작한 다음, 집 노트북에서 같은 대화를 열 수 있습니다. 메시지도 같고 도구 호출도 같으며, 모든 파일 경로는 새 컴퓨터의 경로로 바뀝니다. 또한 프로젝트 기록의 짧은 요약을 다른 도구가 읽는 지침 파일(`CLAUDE.md`, `AGENTS.md`, `GEMINI.md`)에 써 주므로, 다른 AI 도구에서 작업을 이어서 할 수 있습니다.

> **언어:** [English](../../README.md) · [简体中文](README.zh-CN.md) · [हिन्दी](README.hi.md) · [Español](README.es.md) · [Português](README.pt-BR.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [日本語](README.ja.md) · **한국어** · [Русский](README.ru.md)
>
> 기준이 되는 문서는 영어 파일입니다. 번역본은 같은 내용을 다루지만, 서로 다른 부분이 있다면 영어 파일이 우선합니다.

> **이전 이름은 "Claude Sync"입니다.** 이제 둘 이상의 AI 도구를 다루게 되어 v0.5.1에서 프로젝트 이름이 바뀌었습니다. 기존 사용자에게 달라지는 것은 없습니다. 앱은 그 자리에서 스스로 업데이트되고, 설정과 기록은 원래 있던 곳(`~/.claude-sync`)에 그대로 있으며, 명령줄 도구 이름도 여전히 `claude-sync`입니다. Windows 설치 폴더와 시작 메뉴 항목도 예전 이름을 유지하므로 업데이트가 계속 정상적으로 작동합니다. [이름 변경에 대하여](#이름-변경에-대하여)를 참고하세요.

## 하는 일

- **PC 사이에서 대화 기록을 옮겨 줍니다.** Claude Code(터미널 CLI와 VS Code 확장)와 Codex(CLI, VS Code 확장, 데스크톱 앱)의 모든 대화가 여러분이 소유한 저장 공간으로 복사되고, 거기서 다른 PC로 전달됩니다. 다른 PC에서는 그 도구 자체의 기록 목록에 나타납니다. `claude --resume`, VS Code의 Claude Code 패널, `codex resume`, 또는 Codex 사이드바입니다.
- **파일 경로를 고쳐 줍니다.** 프로젝트가 한 PC에서는 `C:\Users\me\shop`이고 다른 PC에서는 `D:\work\shop`이거나, Linux에서는 `/home/me/shop`일 수 있습니다. ChatRelay는 대화 안의 모든 경로(작업 폴더, 도구 입력과 출력, 파일 링크, 메시지 본문)를 받는 PC의 경로로 다시 씁니다.
- **바뀐 부분만 보냅니다.** 처음 업로드한 뒤에는 대화의 새 줄만 전송됩니다. 파일 전체 대신 몇 KB 정도입니다.
- **작업을 절대 잃지 않습니다.** 업로드할 때 원본을 수정하지 않습니다. 파일을 바꾸기 전에는 항상 백업하고, 먼저 미리보기(드라이 런)를 보여 주며, 두 PC에서 모두 바뀐 대화는 덮어쓰지 않고 둘 다 보관합니다.
- **알아서 작동합니다.** 자동 동기화를 켜면 Claude Code 대화는 세션이 끝날 때 업로드되고 세션이 시작될 때 다운로드됩니다. Codex 대화는 백그라운드에서 15분마다 업로드되고 다운로드됩니다.
- **요약해 줍니다.** 프로젝트의 전체 기록(모든 도구의 기록)을 `HANDOFF.md`로 정리합니다. 완료한 일, 결정 사항, 남은 버그, 다음 단계, 수정한 파일이 담깁니다. 짧은 버전을 `CLAUDE.md`, `AGENTS.md` 또는 `GEMINI.md`에 넣어 줄 수도 있어서, 다음 도구가 맥락을 알고 시작할 수 있습니다.
- **어디서나 읽을 수 있습니다.** 읽기 전용 웹 페이지와 Android 앱으로 어떤 기기에서든 GitHub 저장소에 있는 모든 대화를 볼 수 있습니다.
- **VS Code처럼 생겼습니다.** 흑백의 VS Code 스타일 데스크톱 앱으로, 어두운 테마와 밝은 테마가 있고, 일상적으로 쓰기 좋은 간단 보기와 모든 세부 정보를 보여 주는 고급 보기가 있습니다.

각 도구는 공개 문서가 없는 자체 형식으로 기록을 저장하며, 그 형식은 버전마다 바뀝니다. 그래서 ChatRelay는 여러분의 PC에서 찾은 형식을 확인합니다. 모르는 버전을 발견하면 대화는 계속 보여 주지만, 그 도구에 대해서는 **쓰기를 끄고** 그 이유를 **Settings → AI tools**(설정 → AI 도구)에서 알려 줍니다. 절대 추측하지 않습니다.

## 다운로드 및 설치

### Windows

1. [최신 릴리스](https://github.com/Abh1shxkk/claude-sync-releases/releases/latest)에서 `ChatRelay_<version>_x64-setup.exe`를 다운로드하세요. (v0.5.0까지의 릴리스는 이름이 `ClaudeSync_…`입니다.)
2. 실행하세요. 설치 프로그램에 코드 서명이 되어 있지 않아서 Windows SmartScreen이 "Windows의 PC 보호"라는 메시지를 보여 줄 수 있습니다. **More info → Run anyway**(추가 정보 → 실행)를 클릭하세요.
3. 설치는 한 번만 하면 됩니다. 이후 버전은 자동으로 들어옵니다([업데이트](#업데이트) 참고).

앱은 사용자별로 `%LOCALAPPDATA%\Claude Sync\`에 설치됩니다(폴더는 예전 이름을 유지합니다. [이름 변경에 대하여](#이름-변경에-대하여) 참고). 앱은 시스템 트레이에서 시작합니다. 창을 닫아도 트레이에서 계속 실행되며, 종료하려면 트레이 메뉴의 **Quit**(종료)를 사용하세요.

### Android (뷰어)

같은 릴리스 페이지에서 `ChatRelay_<version>.apk`를 다운로드하여 휴대폰에서 여세요(요청이 나오면 브라우저나 파일 관리자에 "알 수 없는 앱 설치"를 허용하세요). Android 앱은 GitHub 저장소를 보는 **읽기 전용 뷰어**입니다. 휴대폰에는 자체 AI 도구 기록이 없기 때문입니다.

### macOS 및 Linux

Rust 엔진과 앱은 macOS와 Linux에서도 빌드됩니다([소스에서 빌드하기](#소스에서-빌드하기-및-개발) 참고). 하지만 아직 이 운영체제용 설치 프로그램은 게시되지 않았고 테스트도 되지 않았습니다.

### 웹

웹 뷰어는 직접 호스팅하거나(GitHub Pages, Cloudflare Pages, Netlify…) 로컬에서 실행할 수 있는 정적 페이지입니다. [웹 및 휴대폰 뷰어](#웹-및-휴대폰-뷰어)를 참고하세요.

## 처음 설정하기

ChatRelay를 처음 열면 설정 마법사가 다음 단계를 차례로 안내합니다. 명령 팔레트에서 언제든 다시 실행할 수 있습니다(**Ctrl+Shift+P → Run First-time Setup Again**(처음 설정 다시 실행)).

1. **여러분의 기록.** ChatRelay는 Claude Code의 기록을 `%USERPROFILE%\.claude\projects`(또는 `CLAUDE_CONFIG_DIR`에 지정된 폴더)에서, Codex의 기록을 `%USERPROFILE%\.codex`(또는 `CODEX_HOME`)에서 찾습니다. 도구별로 찾은 대화 수를 보여 줍니다.
2. **Claude Code의 30일 삭제.** 기본적으로 Claude Code는 30일보다 오래된 대화를 삭제합니다(`cleanupPeriodDays`). ChatRelay는 이 설정을 보여 주고 늘리도록 제안합니다. 바꾸기 전에 `settings.json`을 백업합니다.
3. **컴퓨터 이름.** 예를 들어 `OFFICE-PC` 또는 `HOME-LAPTOP`입니다. 모든 대화 옆에 표시되므로 어느 PC에서 온 대화인지 알 수 있습니다.
4. **저장소(백엔드).** 폴더(Google Drive, OneDrive, Dropbox, 네트워크 드라이브) 또는 비공개 GitHub 저장소입니다. 다음 섹션을 참고하세요.
5. **Anthropic API 키(선택 사항).** 요약 기능에만 필요합니다. 파일이 아니라 Windows 자격 증명 관리자(OS 키체인)에 저장됩니다.
6. **자동 동기화.** 자동 업로드/다운로드를 켭니다(Claude Code 훅과 백그라운드 타이머).
7. **전체 업로드.** 원하면 기존 기록 전체를 진행률 표시줄과 함께 바로 업로드합니다.

## 기록을 저장할 위치 선택하기 (백엔드)

기록은 **여러분이** 관리하는 곳으로 갑니다. ChatRelay에는 자체 서버가 없습니다.

### 방법 A: 폴더

다른 PC에서도 볼 수 있는 폴더라면 무엇이든 됩니다.

- 데스크톱용 Google Drive, 예: `G:\My Drive\chatrelay`
- OneDrive, 예: `%OneDrive%\chatrelay`
- Dropbox, NAS나 네트워크 공유 폴더, 또는 들고 다니는 USB 드라이브

그곳에는 압축된 사본만 저장됩니다. 실제로 사용 중인 `~/.claude`와 `~/.codex` 폴더는 절대 클라우드 폴더로 옮겨지지 않습니다. 폴더 백엔드는 각 파일의 이전 버전도 보관합니다(**Settings → What to sync → Versions kept (folder backend)**(설정 → 동기화 대상 → 보관할 버전 수(폴더 백엔드)), 기본값 2).

### 방법 B: 비공개 GitHub 저장소

웹이나 휴대폰 뷰어도 쓰고 싶다면 이 방법이 가장 좋습니다.

1. **Sign in with GitHub**(GitHub로 로그인)(권장). ChatRelay가 짧은 코드를 보여 주면, github.com에서 그 코드를 입력하고 승인하세요. ChatRelay GitHub App은 여러분이 선택한 저장소(보통은 기록 저장소 하나)에만 접근하며, 그 내용을 읽고 쓰는 권한만 받습니다. 비밀번호는 저장되지 않고 서버도 거치지 않습니다.
2. 또는 **personal access token**(개인 액세스 토큰)을 붙여 넣으세요(`repo` 범위가 있는 클래식 토큰, 또는 그 저장소 하나에 *Contents: Read and write* 권한이 있는 세분화된 토큰). GitHub CLI로 로그인되어 있다면(`gh auth login`) ChatRelay가 그 토큰을 사용할 수 있습니다.
3. 기존 **비공개** 저장소를 고르거나 **Create private repo**(비공개 저장소 만들기)를 클릭하세요. 대화 기록에는 비공개 코드와 비밀 정보가 들어 있을 수 있으므로 공개 저장소는 거부됩니다.

GitHub에서는 업로드 한 번이 **커밋 한 개**입니다. GitHub가 100 MB를 넘는 단일 파일을 거부하기 때문에, 압축 후 40 MB가 넘는 파일은 자동으로 여러 조각으로 나뉩니다.

토큰은 OS 키체인(서비스 이름 `claude-sync`)에만 저장됩니다.

## 두 번째 PC 설정하기

**PC 1**(이미 기록이 있는 PC)에서:

1. ChatRelay를 설치하고 백엔드를 선택하세요.
2. 업로드하세요. 간단 보기에서 **Upload now**(지금 업로드)를 클릭하거나(또는 설정 마지막 단계의 **Upload everything**(전체 업로드)), 고급 보기에서 프로젝트의 **Push**(푸시)를 클릭합니다. 미리보기에 각 대화와 발견된 비밀 정보가 표시되며, 업로드되는 사본에서 그것들을 가릴지(편집) 선택할 수 있습니다.

**PC 2**에서:

1. ChatRelay를 설치하고 **같은 백엔드**(같은 동기화 폴더 또는 같은 GitHub 저장소)를 선택하세요.
2. 프로젝트 폴더를 PC 2에 두세요(예: `git clone` 사용). 경로는 달라도 됩니다. 예를 들어 `C:\Users\me\shop` 대신 `D:\work\shop`이어도 괜찮습니다.
3. **Bring history to this PC**(이 PC로 기록 가져오기)(간단 보기)를 클릭하거나, **Sync**(동기화) 보기(고급 보기)를 여세요. ChatRelay가 백엔드에 있는 모든 프로젝트와, 각 프로젝트가 이 PC의 어디로 들어갈지를 보여 줍니다.
   - **Git 프로젝트**는 원격 URL로 자동으로 연결됩니다.
   - **그 밖의 프로젝트**: **Import into…**(가져올 위치…) / **Link**(연결)를 클릭하고 로컬 폴더를 한 번 고르세요. 이 연결은 기억됩니다.
4. **드라이 런**을 확인하세요. 어떤 파일이 써지는지, 그리고 모든 경로 변경(예: `×166  C:\Users\me\shop → D:\work\shop`)이 표시됩니다. 그런 다음 확인하세요.
5. 도구에서 대화를 여세요. `claude --resume` 또는 VS Code의 Claude 패널, `codex resume` 또는 Codex 사이드바입니다.

Codex의 경우 **먼저 Codex를 닫으세요**(CLI, VS Code 확장, 데스크톱 앱). ChatRelay는 Codex가 실행 중일 때 Codex 파일에 절대 쓰지 않습니다. 그 대화는 "Codex is running"(Codex 실행 중)이라는 이유로 건너뛰고, 다음 번에 들어옵니다.

두 PC 모두에서 **Auto-sync**(자동 동기화)를 켜 두면, 이 작업을 다시 손으로 할 필요가 없습니다.

## 일상적인 사용

### 간단 보기와 고급 보기

- **간단 보기**(기본값): 상태 점이 붙은 프로젝트 목록, 큰 버튼 두 개(**Upload now** / **Bring history to this PC**), 자동 동기화 스위치, 업데이트 확인이 있습니다.
- **고급 보기**: VS Code와 비슷한 화면 구성으로, 활동 표시줄(Projects **Ctrl+Shift+E**, Sync **Ctrl+Shift+Y**, Summaries, Logs, Backups, Settings), 탭, 상태 표시줄, 그리고 모든 동작이 들어 있는 명령 팔레트(**Ctrl+Shift+P**)가 있습니다.

두 보기는 **Ctrl+Shift+P → Switch to Simple/Advanced View**(간단/고급 보기로 전환)로 바꿀 수 있습니다.

### 상태 점

| 점 | 의미 | 해야 할 일 |
|---|---|---|
| 초록색 | 동기화됨 | 없음 |
| 노란색 / 주황색 | 이 PC의 변경 사항이 아직 업로드되지 않음 | 푸시하거나 자동 동기화를 기다리세요 |
| 빨간색 | 마지막 동기화 실패 | 원인을 보려면 **Logs**(로그)를 여세요 |
| 회색 | 한 번도 동기화되지 않음 | 한 번 푸시하세요 |
| 속이 빈 원 | 아직 프로젝트 식별 정보가 없음(연결되지 않음) | 푸시하거나(연결이 만들어집니다) 다른 PC의 프로젝트에 **Link**(연결)하세요 |

### 여러 도구의 대화

모든 대화에는 어떤 도구인지 알려 주는 작은 배지(**Claude** 또는 **Codex**)가 붙어 있습니다. 둘 이상의 도구를 사용한 프로젝트에는 **필터**(All / Claude Code / Codex)가 표시됩니다. 대화를 열면 전체 기록이 보입니다. 여러분의 메시지, 어시스턴트의 답변, 도구 호출(실행한 명령, 수정한 파일), 그리고 변경된 파일 목록입니다.

### 푸시와 풀

- **Push**(푸시)는 마지막 동기화 이후 바뀐 프로젝트의 대화를 업로드합니다. **Push all**(모두 푸시)은 모든 프로젝트를 처리합니다.
- **Pull**(풀)은 새로운 것을 다운로드합니다. 항상 **드라이 런**으로 시작하여, 쓰게 될 모든 파일과 모든 경로 변경을 보여 줍니다. 확인하기 전까지는 아무것도 쓰지 않습니다.

### 자동 동기화

**Auto-sync**(자동 동기화)가 켜져 있으면:

- **Claude Code**: `~/.claude/settings.json`에 있는 훅이 Claude Code 세션이 **시작될 때**(풀)와 **끝날 때**(푸시) ChatRelay를 실행합니다.
- **Codex**: Codex에는 이런 훅이 없으므로, 데스크톱 앱이 15분마다 확인합니다(실행 20초 후부터 시작). Codex 대화가 바뀐 프로젝트를 업로드하고 새 대화를 다운로드합니다(Codex가 실행 중이면 건너뜁니다).
- 오프라인이어서 실패한 업로드는 대기열에 넣었다가 다시 시도합니다.

자동 동기화는 설정, 트레이 메뉴, 또는 `claude-sync hooks install|uninstall` 명령으로 켜고 끌 수 있습니다.

### 트레이 메뉴

Push now(지금 푸시) · Pull now(지금 풀) · Auto-sync on/off(자동 동기화 켜기/끄기) · Last sync status(마지막 동기화 상태) · Open(열기) · Quit(종료).

### 백업

모든 쓰기 작업 전에는 `~/.claude-sync/backups/<timestamp>-<what>/`에 백업이 만들어집니다. **Backups**(백업)(또는 `claude-sync backups`)를 열어 백업을 확인하고, 하나를 **Restore**(복원)하면 모든 파일이 원래 상태 그대로 돌아갑니다. 복원하면 그 변경으로 새로 생긴 파일도 삭제됩니다.

### 로그

**Logs**(로그)에는 ChatRelay가 한 모든 일이 표시되고, 오류는 강조 표시되며, 오류 보고서를 복사하는 버튼이 있습니다.

## Codex 지원 자세히 보기

각 Codex 대화와 함께 옮겨지는 것:

| 항목 | Codex가 저장하는 곳 | ChatRelay가 하는 일 |
|---|---|---|
| 대화("rollout") | `~/.codex/sessions/YYYY/MM/DD/rollout-<time>-<id>.jsonl` (일부 버전은 압축된 `.jsonl.zst`로 저장) | 복사하고 모든 경로를 다시 씀 |
| 스레드의 인덱스 행 | `~/.codex/state_5.sqlite`, 테이블 `threads` | 대화가 `codex resume`과 사이드바에 나타나도록 추가하거나 업데이트함 |
| 스레드 이름 | `~/.codex/session_index.jsonl` | 추가함 |
| 그 스레드의 Codex 메모리 | `~/.codex/memories_1.sqlite`, 테이블 `stage1_outputs` | 이 PC에 그 스레드의 메모리가 없으면 추가함. 경로를 다시 씀 |
| 그 스레드의 목표 | `~/.codex/goals_1.sqlite`, 테이블 `thread_goals`, `thread_goal_continuation_deferrals` | 이 PC에 그 스레드의 목표가 없으면 추가함 |

알아 두면 좋은 세부 사항:

- ChatRelay가 쓰는 동안에는 **Codex가 닫혀 있어야 합니다.** ChatRelay는 실행 중인 `codex` 프로세스(CLI, VS Code 확장, 데스크톱 앱)를 확인합니다. 백그라운드 동기화 중에는 무언가를 닫으라고 요청하지 않고, 나중에 다시 시도할 뿐입니다.
- **기록 모드가 유지됩니다.** 최신 Codex 버전은 "페이지 나눔" 방식으로 기록을 저장합니다. Codex는 대화를 처음 열 때 대화 파일로부터 페이지 데이터베이스(`thread_history_*.sqlite`)를 다시 만들기 때문에, ChatRelay는 그 데이터베이스에 절대 쓰지 않습니다.
- **스레드에 대한 여러분의 설정은 그대로 유지됩니다.** 업데이트할 때 이 PC의 고정 상태, 사용자 지정 이름, 보관 상태, 계정이 유지됩니다. 다른 PC에만 있는 폴더와 섹션은 비워집니다.
- **계정.** 가져온 스레드는 이 PC에서 가장 많은 스레드를 가진 Codex 계정에 배정됩니다.
- **Windows 경로 접두사.** Windows의 Codex는 작업 폴더를 `\\?\D:\project` 형태로 저장합니다. ChatRelay는 Codex가 이 접두사를 사용하는 PC에서 Windows 경로에만 이 접두사를 붙이며, macOS나 Linux 경로에는 절대 붙이지 않습니다.
- **압축된 대화**(`.jsonl.zst`)도 읽고 업데이트할 수 있습니다. 업데이트하면 파일이 일반 `.jsonl`로 바뀝니다(압축된 원본은 먼저 백업됩니다).
- 다른 PC에 속한 **메모리 관리 정보**(메모리가 얼마나 자주 사용되었는지, 통합 대상으로 선택되었는지)는 복사하지 않습니다.
- **알 수 없는 버전.** Codex 인덱스가 ChatRelay가 모르는 데이터베이스(예: 미래의 `state_6.sqlite`)를 사용하거나, 채울 수 없는 필수 필드를 추가하면 명확한 경고와 함께 Codex에 대한 쓰기가 꺼집니다. 읽기는 계속 가능합니다.

## 요약과 "다른 도구에서 이어서 하기"

> 🔒 **비밀 정보는 AI에 전달되지 않습니다.** 모델에 무엇이든 보내기 전에 ChatRelay는 채팅에서 찾은 키, 토큰, 비밀번호(Anthropic, OpenAI, OpenRouter, GitHub, AWS, Google, Slack, Stripe, Hugging Face, npm, SendGrid, Telegram 봇의 API 키, JWT, 개인 키, `PASSWORD=…` 형식의 줄, URL 안의 비밀번호)를 `[REDACTED:kind]`로 바꿉니다. 이 과정은 항상 실행되며 끌 수 없고, 몇 개를 숨겼는지 화면에 표시됩니다. 코드와 나머지 대화는 그대로 전송되므로, 비공개 코드나 고객 코드에는 데이터를 보관하지 않는 유료 모델을 사용하세요.

**Summaries**(요약)(고급 보기)를 열고 프로젝트를 고른 뒤, 대화(어느 도구의 대화든)와 모델을 선택하고 **Generate handoff**(인계 문서 생성)를 클릭하세요.

- 모델: **Claude Opus 5.5**(기본값), Claude Sonnet 5.5(더 빠르고 저렴함), Claude Haiku 5.5(가장 저렴함), Claude Fable 5.1(가장 성능이 뛰어남). Anthropic API 키가 필요합니다(**Settings → Summaries**(설정 → 요약)).
- 기록은 먼저 압축됩니다. 여러분의 요청, 각 턴에서 어시스턴트의 최종 답변, 그리고 변경된 파일만 남깁니다. 긴 도구 출력과 사고 과정은 제외됩니다. 모든 도구의 대화가 시간 순서로 합쳐지고, 각 대화에 도구 이름이 표시됩니다.
- 긴 기록은 약 10만 토큰 단위로 나누어 요약한 다음 합칩니다.
- 결과에는 다음 섹션이 들어갑니다: 프로젝트 개요, 완료한 일, 주요 결정 사항, 남은 버그 / 알려진 문제, 다음 단계, 수정한 파일.

그런 다음 다음 중 하나를 할 수 있습니다.

- 프로젝트 폴더에 **Save HANDOFF.md**(HANDOFF.md 저장), 또는
- 도구에서 **Continue in…**(…에서 이어서 하기): Claude Code(`CLAUDE.md`), Codex(`AGENTS.md`) 또는 Gemini CLI(`GEMINI.md`)를 선택하세요. 목록에는 이 PC에 설치된 도구가 표시됩니다. ChatRelay는 그 파일에 짧은 "Previous context"(이전 맥락) 섹션(개요, 완료한 일, 다음 단계)을 추가합니다. 다시 실행하면 자신이 만든 섹션만 바꾸고, 파일의 나머지 부분은 건드리지 않습니다.
- 또는 텍스트를 **복사**하세요.

명령줄에서는: `claude-sync summarize --target handoff|claude-md|agents-md|gemini-md|none`.

- 이 페이지는 `api.github.com`과만 통신하며 제3자 스크립트를 불러오지 않습니다.
- 처음 방문할 때 메시지 수를 세기 위해 각 대화를 한 번씩 읽습니다. 결과는 내용 해시 기준으로 캐시됩니다.
- 휴대폰 크기의 화면에서는 하나의 창으로 바뀝니다: 목록 → 프로젝트 → 대화 기록 순서이며, 뒤로 가기 버튼과 하단 바가 있습니다.

## 안전과 개인정보 보호

- **업로드할 때 원본은 절대 수정되지 않습니다.** 업로드는 기록 파일을 읽기만 합니다.
- **도구가 실행 중일 때는 아무것도 쓰지 않습니다**(Codex). Claude Code의 열려 있는 세션(훅을 실행시킨 세션)은 절대 건드리지 않습니다.
- **모든 쓰기 전에 백업합니다.** Claude Code의 `settings.json`, Codex의 데이터베이스(`-wal`, `-shm` 파일 포함)와 `session_index.jsonl`도 포함됩니다.
- **모든 가져오기에 드라이 런이 있습니다.** 무엇이든 실행되기 전에 모든 파일과 모든 경로 변경을 볼 수 있습니다.
- **충돌이 나면 두 버전을 모두 보관하며**, 절대 덮어쓰지 않습니다.
- **비밀 정보 검사.** 업로드하기 전에 ChatRelay는 API 키와 비밀번호를 찾습니다. Anthropic, OpenAI, GitHub, AWS, Google, Slack, Stripe 키, JWT, 개인 키, `.env` 스타일의 `SECRET=…` 줄, URL 안의 자격 증명입니다. 다음 중에서 선택할 수 있습니다: **warn**(경고), **redact**(가리기, 업로드되는 사본에서만 `[REDACTED:kind]`로 바뀜), 또는 **off**(끄기).
- **비밀 정보는 OS 키체인에 보관됩니다.** GitHub 토큰과 Anthropic 키는 절대 파일에 쓰이지 않습니다.
- **로그인 정보는 절대 건드리지 않습니다.** ChatRelay는 Claude Code나 Codex의 로그인 파일(`~/.claude/.credentials.json`, `~/.codex/auth.json`, …)을 읽거나 복사하거나 바꾸지 않습니다. 기록을 동기화해도 로그아웃되지 않습니다. 로그아웃된다면 도구 자체 때문입니다(예: 세션이 만료되었거나 다른 PC에서 다른 계정으로 로그인한 경우).
- **비공개 저장소만 사용합니다.** 공개 GitHub 저장소는 거부됩니다.
- **ChatRelay 서버가 없습니다.** 데이터는 여러분의 PC, 여러분의 폴더 또는 GitHub 사이에서만 오가며, (요약을 만들 때만) Anthropic API로 전송됩니다.

의도적으로 동기화하지 않는 것: `~/.claude/history.jsonl`(모든 프로젝트에 걸친 위쪽 화살표 프롬프트 기록), `~/.claude/file-history/`(되감기 스냅샷), 그리고 모든 자격 증명.

## 명령줄 도구 (CLI)

설치 프로그램은 앱 옆(`%LOCALAPPDATA%\Claude Sync\`)에 `claude-sync.exe`를 둡니다. Claude Code 훅이 실행하는 것이 바로 이 파일입니다. 어디서든 사용하려면 그 폴더를 `PATH`에 추가하세요. 소스에서 실행하려면: `cargo run -p claude-sync-cli -- …`.

```
claude-sync scan [--json]                 List projects & sessions
claude-sync status [--json]               Backend, last sync, hooks, queue, cleanupPeriodDays
claude-sync push [--cwd <dir>] [--all] [--dry-run] [--redact]
claude-sync pull [--cwd <dir>] [--project <id>] [--all] [--dry-run]
claude-sync summarize [--cwd <dir>] [--model <id>] [--target handoff|claude-md|agents-md|gemini-md|none]
claude-sync remote                        List projects stored in the backend
claude-sync link <dir> <projectId>        Link a local folder to a remote project ID (--remove to unlink)
claude-sync config [key] [value]          Show or set config (machineName, backend.folder, backend.github, secretScan, ...)
claude-sync secret set github-token|anthropic-api-key <value>
claude-sync hooks install|uninstall       Add/remove the SessionStart/SessionEnd hooks
claude-sync cleanup-days <n>              Set Claude Code's cleanupPeriodDays (backs up settings.json)
claude-sync backups [restore <id>]        List or restore backups
claude-sync queue                         Retry queued (offline) pushes

Other AI coding tools (provider = claude-code | codex):
claude-sync providers [--json]            Which tools are installed, their version/format, import on/off
claude-sync providers sessions <provider> [--cwd <dir>] [--json]
claude-sync providers show <provider> <id> [--json]      Read a session in the tool-neutral format
claude-sync providers export <provider> <id> --out <file.json.gz>
claude-sync providers import <file.json.gz> --to <dir> [--dry-run]

Flags: --hook (read Claude Code hook JSON from stdin; never fails), --quiet, --json, --verbose
```

종료 코드: `0` 정상, `1` 오류, `2` 푸시 중 충돌 발생(먼저 풀하세요).

환경 변수:

| 변수 | 효과 |
|---|---|
| `CLAUDE_SYNC_HOME` | ChatRelay 자체 데이터 폴더(기본값 `~/.claude-sync`) |
| `CLAUDE_CONFIG_DIR` | Claude Code의 폴더(기본값 `~/.claude`) |
| `CODEX_HOME` | Codex의 폴더(기본값 `~/.codex`) |

## 작동 방식 (기술 정보)

### Claude Code가 기록을 저장하는 곳

| 경로 | 내용 |
|---|---|
| `~/.claude/projects/<encoded-path>/<session-uuid>.jsonl` | 세션당 파일 하나, 줄마다 JSON 객체 하나 |
| `~/.claude/projects/<encoded-path>/<session-uuid>/subagents/*.jsonl` + `*.meta.json` | 서브에이전트 기록("사이드카"로 동기화됨) |
| `~/.claude/projects/<encoded-path>/<session-uuid>/tool-results/*` | 디스크에 저장된 큰 도구 출력(사이드카) |
| `~/.claude/projects/<encoded-path>/memory/` | 프로젝트 자동 메모리(`MEMORY.md` + 메모) |

일반적인 예상과 다른 점들이며, 모두 처리되어 있습니다.

- **드라이브 문자의 대소문자가 클라이언트마다 다릅니다.** VS Code 확장은 `c:\Users\…`(폴더 `c--Users-…`)로 기록하고, CLI는 `C:\Users\…`(폴더 `C--Users-…`)로 기록하며, 한 세션 안에 둘 다 들어 있을 수도 있습니다. Windows에서는 경로를 대소문자 구분 없이 비교합니다.
- **폴더 이름을 정확하게 해독할 수 없습니다.** `C:\Users\me\my project`와 `C:\Users\me\my-project`는 둘 다 `C--Users-me-my-project`로 인코딩됩니다. 실제 경로는 세션에 기록된 `cwd`에서 가져오며, 이름 해독은 표시가 붙은 대체 수단일 뿐입니다.
- **세션이 매우 클 수 있습니다**(이미지/PDF가 포함되면 200 MB 이상). 그래서 모든 것을 스트리밍으로 처리합니다. 검사 결과는 크기와 수정 시간 기준으로 캐시되므로, 다시 검사하는 데 약 100 ms가 걸립니다.
- **어시스턴트의 답변 하나가 여러 줄에 걸쳐 있습니다**(내용 블록마다 한 줄, 같은 `message.id`). 메시지 수를 셀 때 중복을 제거합니다. 제목은 첫 번째 실제 프롬프트에서 가져오며(IDE 래퍼 태그는 제거), Claude Code 자체의 `ai-title`이 그 옆에 표시됩니다.
- **user/assistant 외에도 줄 유형이 많습니다**(`attachment`, `file-history-snapshot`, `queue-operation`, `ai-title`, `last-prompt`, `permission-mode`, …). 알 수 없는 유형과 필드는 그대로 유지됩니다.

### Codex가 기록을 저장하는 곳

[Codex 지원 자세히 보기](#codex-지원-자세히-보기)를 참고하세요. rollout의 각 줄은 `{timestamp, type, payload}`이며, 첫 줄은 세션 ID와 `cwd`가 담긴 `session_meta`입니다. Codex는 세 세대에 걸쳐 다른 방식으로 대화를 저장해 왔습니다(≥0.15x에서는 `event_msg/item_completed` 항목, 그 이전에는 `user_message`/`agent_message` 이벤트, 가장 오래된 버전에서는 일반 `response_item` 메시지). 뷰어는 존재하는 것 중 가장 풍부한 형식을 사용합니다.

### 어댑터

각 AI 도구는 하나의 인터페이스(`ProviderAdapter`) 뒤에 있는 **어댑터**(`crates/core/src/providers/`)입니다. 어댑터는 도구와 그 형식을 감지하고, 프로젝트와 세션을 나열하고, 세션을 도구 중립적인 형태(`UniversalSession`)로 읽고, 손실 없이 내보내고(`SessionBundle`: 원본 파일과 Codex 인덱스 행 같은 도구 메타데이터), 다른 PC에서 가져오고(경로 다시 쓰기, 도구가 실행 중이 아닌지 확인, 백업, 드라이 런), 새 줄을 덧붙입니다. [다른 AI 도구 추가하기](#다른-ai-도구-추가하기-어댑터-가이드)를 참고하세요.

### 프로젝트 식별

같은 프로젝트라도 PC마다 경로가 다르므로, 다음 순서로 식별합니다.

1. **수동 연결**(Link 버튼 / `claude-sync link <dir> <id>`), ChatRelay 설정에 저장됨
2. 정규화된 **git 원격 주소**: `git@github.com:Me/Repo.git`과 `https://github.com/me/repo`는 둘 다 `git:github.com/me/repo`가 됩니다
3. 프로젝트 루트에 있는 UUID가 담긴 **`.claude-sync.json`**. git이 아닌 프로젝트에서 처음 푸시할 때 만들어집니다(이 파일을 커밋하거나, 다른 PC에서 수동으로 연결하세요). "Upload everything"(전체 업로드)과 백그라운드 동기화는 대신 ChatRelay 설정에 연결을 만들기 때문에, 프로젝트 폴더에는 아무것도 쓰지 않습니다.

### 저장소 구조 (폴더 또는 저장소 안)

```
<projectId-slug>/
  manifest.json                          machines, original paths, hashes, timestamps, revision
  <sessionId>.jsonl.gz                   Claude Code session (whole, or its start when deltas exist)
  <sessionId>.d<N>.jsonl.gz              lines appended after that, one blob per push
  <sessionId>.sidecar.json.gz            subagents/ + tool-results/ (if any)
  memory.json.gz                         Claude Code project memory (if any)
  <provider>-<sessionId>.bundle.json.gz  another tool's session (e.g. codex-…): files + metadata
  <provider>-<sessionId>.d<N>.jsonl.gz   lines appended to it later
  .versions/<file>/<timestamp>           previous versions (folder backend)
```

다른 도구의 세션은 manifest의 `providerSessions` 아래에 나열됩니다(키 `<provider>:<id>`). 이전 버전의 앱은 이 목록을 무시하고 그대로 보존합니다.

### 푸시

- 세션은 SHA-256으로 비교하며, 새롭거나 바뀐 세션만 업로드됩니다. 원본은 읽기만 합니다.
- **새 줄만 보냅니다.** AI 도구는 대화 파일에 항상 덧붙이기만 하므로, 세션을 처음 업로드한 뒤에는 푸시할 때 마지막 동기화 이후 추가된 줄만 "델타" 조각으로 저장합니다. 각 조각에는 그것을 푸시한 컴퓨터의 경로가 기록됩니다. 세션 해시는 사슬처럼 연결됩니다(`hash = sha256(previous : sha256(part))`). 조각이 40개가 되면 다음 푸시에서 세션 전체를 다시 업로드합니다. 이 지름길을 쓸 수 없는 경우(파일이 다른 방식으로 바뀌었거나, 충돌이 있거나, 이전 버전의 상태인 경우)에는 파일 전체를 업로드합니다.
- 백엔드에 여러분이 아직 보지 못한 버전이 있고 그 안에 여러분에게 없는 메시지가 들어 있다면, 그 세션의 푸시는 "pull first"(먼저 풀하세요)라는 메시지와 함께 거부되므로 아무것도 잃지 않습니다.
- **오프라인인가요?**(GitHub에 연결할 수 없거나, 클라우드 드라이브가 연결되지 않은 경우.) 푸시는 `~/.claude-sync/queue.json`에 대기열로 저장되고, 다음 실행 때와 데스크톱 앱에서 15분마다 다시 시도됩니다.

### 풀

- 경로는 파싱된 JSON 안에서(문자열 값 **그리고** 객체 키) 다시 쓰기 때문에 JSON 이스케이프 문제가 절대 생기지 않습니다. 처리하는 형식: `C:\…`, `c:/…`, Git-Bash `/c/…`, WSL `/mnt/c/…` 형태의 Windows 경로(대소문자 구분 없음), POSIX 경로(대소문자 구분), `%20`으로 인코딩된 공백을 포함한 `file:///` URL. 운영체제 사이를 옮길 때는 프로젝트 루트 뒤의 구분자가 변환되며, 도구 자체의 홈 폴더(`~/.claude`, `~/.codex`)와 Claude Code의 인코딩된 폴더 이름도 다시 씁니다. `shop-old` 같은 형제 폴더는 절대 건드리지 않습니다.
- **빠른 경로:** 마지막으로 동기화한 상태를 정확히 가진 PC는 빠진 조각만 다운로드해서 덧붙입니다.
- **분기**(대화는 덧붙이기만 하므로, Claude Code는 줄 ID로, 다른 도구는 텍스트 앞부분으로 비교합니다):
  - 원격이 로컬을 포함함 → 업데이트
  - 로컬이 원격을 포함함 → 여러분의 것이 더 최신이므로 유지됨(다음 푸시 때 업로드됨)
  - 둘 다 바뀜 → **충돌**: 여러분의 사본은 그대로 두고, 다른 버전은 **새 ID를 가진 새 대화**로 저장됩니다(Codex: 이름이 "<name> (from <PC>)"). 그러면 둘 다 도구에 나타나고 다른 PC로도 동기화됩니다.

### 자동 동기화 훅 (Claude Code)

"Enable auto-sync"(자동 동기화 켜기)는 다음 내용을 `~/.claude/settings.json`에 병합합니다. 다른 설정과 훅은 유지되며, 먼저 백업이 만들어집니다.

```jsonc
"hooks": {
  "SessionStart": [{ "hooks": [{ "type": "command", "command": "\"…/Claude Sync/claude-sync.exe\" pull --hook --quiet --claude-sync-hook", "timeout": 60 }] }],
  "SessionEnd":   [{ "hooks": [{ "type": "command", "command": "\"…/Claude Sync/claude-sync.exe\" push --hook --quiet --claude-sync-hook", "timeout": 60 }] }]
}
```

- `--hook`은 stdin에서 Claude Code의 훅 JSON(`cwd`, `session_id`)을 읽으며, 없으면 `CLAUDE_PROJECT_DIR`, 그다음에는 작업 디렉터리를 사용합니다. 훅은 **항상 0으로 종료**하므로 세션을 절대 망가뜨리지 않습니다. 오류는 Logs 패널로 갑니다.
- 훅은 앱 옆에 설치된 네이티브 `claude-sync` 실행 파일을 실행합니다. Node.js는 필요 없습니다.
- "Disable auto-sync"(자동 동기화 끄기)는 `claude-sync-hook` 표시가 들어 있는 훅만 제거합니다.

## ChatRelay가 읽고 쓰는 파일

| 위치 | 내용 |
|---|---|
| `~/.claude-sync/config.json` | 컴퓨터 이름과 ID, 백엔드, 연결, 옵션 |
| `~/.claude-sync/state.json` | 세션별 동기화 관리 정보(마지막으로 푸시/풀한 해시와 크기) |
| `~/.claude-sync/backups/` | 시간이 기록된 백업 |
| `~/.claude-sync/logs/claude-sync.log` | JSON-lines 로그(Logs 패널, 복사 가능한 오류 보고서) |
| `~/.claude-sync/queue.json` | 백엔드를 기다리는 푸시 |
| `~/.claude-sync/scan-cache.json` | 검사 캐시(크기, 시간, 제목) |
| OS 키체인, 서비스 `claude-sync` | `github-token`, `anthropic-api-key` |
| `~/.claude/projects/…` | Claude Code 대화(읽기, 풀할 때 쓰기) |
| `~/.claude/settings.json` | 자동 동기화 훅과 `cleanupPeriodDays`에만 사용(먼저 백업) |
| `~/.codex/sessions/…`, `state_5.sqlite`, `session_index.jsonl`, `memories_1.sqlite`, `goals_1.sqlite` | Codex 대화와 그 인덱스(읽기, 풀할 때 Codex가 닫혀 있을 때만 쓰기, 먼저 백업) |
| `<project>/.claude-sync.json` | 프로젝트 화면에서 푸시한 git이 아닌 프로젝트에만 사용 |
| `<project>/HANDOFF.md`, `CLAUDE.md`, `AGENTS.md`, `GEMINI.md` | 요약을 그곳에 저장할 때만 |

## 업데이트

- 데스크톱 앱은 시작할 때, 창을 열 때마다, 1시간마다, 5분 이상 지난 뒤 창으로 돌아올 때, 그리고 **Check for updates**(업데이트 확인)를 클릭할 때(Settings → About, 간단 보기, 또는 명령 팔레트) 새 버전을 확인합니다. 확인하는 동안에는 로딩 표시가 나타납니다.
- 새 버전이 있으면 **A new version is available → Update now**(새 버전이 있습니다 → 지금 업데이트)가 표시됩니다. 앱이 새 버전을 다운로드하고, 서명을 확인한 뒤(앱은 프로젝트 키로 서명된 업데이트만 받아들입니다), 그 자리에 설치하고 다시 시작합니다. 기록과 설정은 유지됩니다.
- Android 앱은 새 APK 링크가 담긴 알림을 보여 줍니다.

## 문제 해결 및 자주 묻는 질문

**SmartScreen이 설치 프로그램을 막아요.** 설치 프로그램에 코드 서명이 되어 있지 않기 때문입니다. **More info → Run anyway**(추가 정보 → 실행)를 클릭하세요.

**프로젝트에 노란색 점이 표시돼요.** 이 PC에 아직 업로드되지 않은 대화가 있다는 뜻입니다. 푸시하거나 자동 동기화를 켜세요.

**다른 PC의 프로젝트가 나타나지 않거나 다른 이름으로 나타나요.** 프로젝트는 git 원격 주소, `.claude-sync.json`, 또는 연결로 짝지어집니다. 폴더 이름이 서로 다르고 git 원격 주소도 없다면, **Link**(연결)(또는 **Import into…**(가져올 위치…))를 한 번 사용해서 올바른 로컬 폴더를 고르세요.

**Codex 대화를 건너뛰었어요: "Codex is running".** Codex CLI, VS Code 확장의 Codex 패널(또는 VS Code), Codex 데스크톱 앱을 닫은 다음 다시 풀하세요. 백그라운드 동기화는 알아서 다시 시도합니다.

**Codex 가져오기가 꺼져 있어요: "Unknown Codex index database" / "new required fields".** 여러분의 Codex가 이 ChatRelay 버전이 아는 것보다 최신입니다. ChatRelay를 업데이트하세요. 대화는 계속 볼 수 있습니다.

**같은 대화가 두 번 보이고, 하나는 "(from OFFICE-PC)"로 끝나요.** 두 PC가 동기화되기 전에 양쪽에서 대화를 이어서 했기 때문입니다. 두 버전 모두 보관됩니다. 필요 없는 쪽을 도구에서 삭제하세요.

**예전 Claude Code 대화가 사라졌어요.** Claude Code는 `cleanupPeriodDays`(기본값 30)보다 오래된 대화를 삭제합니다. 설정에서 이 값을 늘리세요(또는 `claude-sync cleanup-days 3650`). 이미 업로드된 대화는 백엔드에서 다시 풀해 올 수 있습니다.

**동기화 때문에 Claude에서 로그아웃되었나요?** 아니요. ChatRelay는 로그인 파일을 절대 읽거나 쓰지 않습니다. [안전과 개인정보 보호](#안전과-개인정보-보호)를 참고하세요.

**처음 업로드가 느려요.** 첫 업로드는 모든 것을 (압축해서) 보냅니다. 그 뒤로는 새 줄만 보냅니다.

**푸시할 때 "Pull first"(먼저 풀하세요)가 나와요.** 다른 PC가 여러분의 PC에 없는 더 새로운 버전을 업로드했습니다. 풀한 다음 푸시하세요.

**오프라인이에요.** 푸시는 대기열에 들어가 자동으로 다시 시도됩니다. `claude-sync queue`를 실행하면 지금 바로 다시 시도합니다.

**풀한 뒤에 문제가 생겼어요.** **Backups**(백업)를 열고 그 직전에 만들어진 백업을 복원하세요.

**오류는 어디서 볼 수 있나요?** **Logs**(로그) 보기(거기서 오류 보고서를 복사할 수 있습니다), 또는 `~/.claude-sync/logs/claude-sync.log`입니다.

## 소스에서 빌드하기 및 개발

필요한 것: Node.js 20+, Rust(stable), 그리고 Windows에서는 MSVC 툴체인(Visual Studio "C++를 사용한 데스크톱 개발").

```bash
git clone https://github.com/Abh1shxkk/chatrelay.git
cd chatrelay
npm install
npm run tauri:dev      # run the desktop app with hot reload
npm run test:rust      # cargo test --workspace: engine, adapters, push/pull, GitHub backend
npm test               # UI helper tests (vitest)
npm run typecheck      # TypeScript
npm run tauri:build    # installer in target/release/bundle/nsis/
```

프로젝트 구조:

```
crates/core/       Rust engine: scanner, JSONL, path rewriting, sync, backends, hooks, summaries
crates/core/src/providers/   AI tool adapters: claude_code.rs, codex.rs (+ codex_format.rs, browser-safe parsing)
crates/core/src/provider_sync.rs   other tools' sessions in push/pull (bundles, deltas, conflict copies)
crates/core/tests/  integration tests with fixture files (tests/fixtures/codex, tests/fixtures/claude-code)
crates/cli/        the `claude-sync` CLI (also what the Claude Code hooks run)
crates/wasm/       the engine compiled to WebAssembly for the web and phone viewers
src-tauri/         desktop app: window, tray, background sync, the API behind window.claudeSync
src/renderer/      React + TypeScript + Tailwind UI (shared by desktop, web and phone)
src/shared/        TypeScript types and helpers
mobile/            Android / iOS shell around the web version (Tauri)
scripts/           release, CLI staging, WASM build
tests/             vitest tests; tests/web/mock-github.mjs for testing the web version
```

설치된 앱 옆에서 개발용 사본 실행하기: 별도의 식별자와 데이터 폴더를 지정하면 실제 설정을 절대 건드리지 않습니다.

```powershell
$env:TAURI_CONFIG='{"identifier":"com.claudesync.dev","productName":"ChatRelay Dev"}'
$env:CLAUDE_SYNC_HOME='D:\tmp\chatrelay-dev'
npm run tauri:dev
```

### 웹 버전

```bash
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.129   # must match wasm-bindgen in Cargo.lock
npm run web:wasm     # rebuild the WebAssembly engine
npm run web:dev      # http://localhost:5175/web.html
npm run web:build    # static site in out/web/ (host on GitHub Pages, Cloudflare Pages, Netlify…)
```

`node tests/web/mock-github.mjs <folder-backend>`는 폴더 백엔드를 가짜 GitHub API로 제공합니다(개발 빌드 전용: `localStorage['claude-sync-web:apiBase'] = 'http://localhost:5176'`으로 설정하고 토큰 `test-token-123456`을 사용하세요).

### 모바일 앱 (Android, iOS)

**Android**에는 JDK 17, Android SDK(platform 36, build-tools 36, NDK r27), 그리고 Rust Android 타깃(`tauri android init`이 설치해 줍니다)이 필요합니다.

```powershell
$env:JAVA_HOME = "<jdk-17>"; $env:ANDROID_HOME = "<android-sdk>"; $env:NDK_HOME = "$env:ANDROID_HOME\ndk\<version>"
npm run mobile:android:init      # once: generates mobile/gen/android
npm run mobile:android:apk       # debug APK for a phone (arm64)
adb install -r <that apk>
npm run mobile:android:release   # release APK/AAB, signed when CLAUDE_SYNC_KEYSTORE_PROPERTIES is set
```

릴리스 서명은 **저장소 밖에** 보관된 properties 파일을 읽으며, 그 파일 위치는 `CLAUDE_SYNC_KEYSTORE_PROPERTIES`로 지정합니다.

```properties
storeFile=D:/dev/android-keys/claude-sync-release.jks
storePassword=…
keyAlias=claude-sync
keyPassword=…
```

키는 `keytool -genkeypair -keystore claude-sync-release.jks -alias claude-sync -keyalg RSA -keysize 4096 -validity 10000`으로 한 번 만들고 반드시 백업해 두세요. 설치된 앱의 업데이트는 같은 키로 서명되어야 합니다.

**iOS**에는 Xcode가 설치된 Mac과 `rustup target add aarch64-apple-ios aarch64-apple-ios-sim`이 필요합니다.

```bash
npm install && npm run web:wasm
npm run mobile:ios:init
npm run mobile:ios:dev
npm run mobile:ios:build
```

## 다른 AI 도구 추가하기 (어댑터 가이드)

1. **먼저 실제 컴퓨터에서 저장 형식을 확인하세요**: 세션이 저장되는 위치, 줄/레코드 형식, 인덱스 데이터베이스와 그 스키마, 도구가 세션을 나열하는 방법, 경로를 저장하는 방법, 어떤 프로세스가 "실행 중"을 뜻하는지. 이 내용을 어댑터 파일 맨 위에 적어 두세요.
2. `crates/core/src/providers/mod.rs`에 `ProviderId`를 추가하고, `ProviderAdapter`를 구현하는 `providers/<tool>.rs` 파일을 만드세요: `detect`, `list_projects`, `list_sessions`, `read_session`, `export_session`, `import_session`, 그리고 선택적으로 `append_session`, `context_file_name`, `process_names`.
3. 모든 어댑터가 따르는 규칙: 도구가 실행 중이면 쓰기를 거부하고(`ensure_not_running`), 쓰기 전에 모든 파일을 백업하고(`ImportOptions.backups`), `dry_run`을 지키고, `keep_both`를 지키며(갈라진 들어오는 세션을 새 ID로 저장), 인식하지 못하는 형식이 있으면 가져오기를 끕니다(`ProviderStatus`에 경고 표시).
4. 순수한 파싱 코드는 파일 시스템에 접근하지 않는 파일(예: `codex_format.rs`)에 두어 웹 뷰어가 사용할 수 있게 하고, `messages_from_bundle`에 추가하세요.
5. `crates/core/tests/fixtures/<tool>/` 아래에 픽스처 파일을 추가하고 테스트를 작성하세요: 감지, 나열, 읽기, 내보내기 → 두 번째 가상 컴퓨터로 가져오기(경로 다시 쓰기), 업데이트, 로컬이 앞선 경우, 충돌, 실행 중인 프로세스 거부, 알 수 없는 형식.
6. `src/shared/types.ts`(`PROVIDER_LABELS`)에 라벨을 추가하세요. 배지, 필터, 푸시/풀, 요약, 뷰어가 거기서 가져다 씁니다.

## 릴리스 게시하기

설치된 앱은 [Abh1shxkk/claude-sync-releases](https://github.com/Abh1shxkk/claude-sync-releases)의 `latest.json`을 확인합니다.

1. `package.json`, `src-tauri/tauri.conf.json`, `mobile/tauri.conf.json`, `Cargo.toml`의 `version`을 올리세요.
2. `npm run release -- --notes "What changed"`

이 명령은 업데이트 키(`TAURI_SIGNING_PRIVATE_KEY`, 또는 `.password` 파일이 함께 있는 `D:\dev\tauri-keys\claude-sync-updater.key`)로 서명된 Windows 설치 프로그램과 서명된 APK를 빌드하고, `latest.json`을 작성한 다음, 모든 것을 릴리스 `v<version>`으로 업로드합니다. 플래그: `--no-apk`, `--skip-build`, `--dry-run`, `--notes-file <file>`. GitHub 로그인 정보는 `git credential fill`(또는 `GITHUB_TOKEN`)에서 가져옵니다.

업데이트 키는 반드시 백업해 두세요. 앱은 이 키로 서명된 업데이트만 받아들이며, 그 공개 키 부분은 `src-tauri/tauri.conf.json`에 있습니다.

## 알려진 제한 사항

- Windows 설치 프로그램에 코드 서명이 되어 있지 않습니다(SmartScreen 경고).
- Windows만 테스트되었습니다. macOS와 Linux는 빌드는 되지만 게시된 설치 프로그램이 없습니다.
- 두 PC에서 동시에 열려 있는 대화는 실시간으로 병합할 수 없으며, 충돌 사본이 됩니다.
- Codex에는 "세션 종료" 훅이 없으므로, Codex 동기화는 즉시가 아니라 15분마다 실행됩니다.
- 200자보다 긴 경로의 경우 Claude Code의 정확한 폴더 이름 해시 방식이 문서화되어 있지 않습니다. ChatRelay는 세션에 같은 `cwd`가 기록된 기존 폴더를 우선 사용하고, 그런 폴더가 없으면 자체 `-<hash>` 접미사를 사용합니다.
- 웹 및 휴대폰 뷰어는 읽기 전용이며 GitHub 백엔드가 필요합니다.

|---|---|
