**AI コーディングのチャットを、どの PC にも、ある AI ツールから別の AI ツールにも持っていけます。**

ChatRelay は、AI コーディングアシスタント(現在は **Claude Code** と **OpenAI Codex**)のチャット履歴を、お使いのコンピューター間で同期するアプリです。会社の PC で会話を始めて、自宅のノート PC で同じ会話を開くことができます。メッセージもツールの呼び出しも同じままで、ファイルのパスはすべて新しいマシンのパスに書き換えられます。さらに、プロジェクトの履歴の短い要約を、別のツールが読む指示ファイル(`CLAUDE.md`、`AGENTS.md`、`GEMINI.md`)に書き込むこともできるので、作業を別の AI ツールで続けられます。

> **旧名は「Claude Sync」です。** 複数の AI ツールに対応するようになったため、v0.5.1 でプロジェクト名を変更しました。既存のユーザーには何も変わりません。アプリはその場で自動的に更新され、設定と履歴は元の場所(`~/.claude-sync`)に残り、コマンドラインツールの名前も `claude-sync` のままです。また、更新が引き続き動作するように、Windows のインストールフォルダーとスタートメニューの項目は旧名のままです。詳しくは[名前の変更について](#名前の変更について)をご覧ください。

## できること

- **チャット履歴を PC 間で移動します。** Claude Code(ターミナルの CLI と VS Code 拡張機能)と Codex(CLI、VS Code 拡張機能、デスクトップアプリ)のすべての会話を、あなたが所有する保存場所にコピーし、そこから他の PC にコピーします。もう一方の PC では、そのツール自身の履歴一覧に表示されます。`claude --resume`、VS Code の Claude Code パネル、`codex resume`、または Codex のサイドバーです。
- **ファイルのパスを修正します。** プロジェクトが、ある PC では `C:\Users\me\shop`、別の PC では `D:\work\shop`、Linux では `/home/me/shop` になっていることがあります。ChatRelay はチャット内のすべてのパス(作業フォルダー、ツールの入力と出力、ファイルへのリンク、メッセージ本文)を、受け取る側の PC のパスに書き換えます。
- **変更された部分だけを送ります。** 最初のアップロードの後は、会話の新しい行だけが送られます。ファイル全体ではなく、数 KB で済みます。
- **作業を失いません。** アップロード時に元のファイルを編集することはありません。ファイルを変更する前には必ずバックアップを取り、まずプレビュー(ドライラン)を表示します。また、両方の PC で変更された会話を上書きすることはなく、両方を残します。
- **自動で動きます。** 自動同期をオンにすると、Claude Code の会話はセッション終了時にアップロードされ、セッション開始時にダウンロードされます。Codex の会話はバックグラウンドで 15 分ごとにアップロード・ダウンロードされます。
- **要約します。** プロジェクトの全履歴(すべてのツールのもの)を `HANDOFF.md` にまとめます。終わったこと、決めたこと、未解決のバグ、次のステップ、触ったファイルが含まれます。短い版を `CLAUDE.md`、`AGENTS.md`、`GEMINI.md` に入れることもできるので、次のツールは文脈を持った状態で始められます。
- **どこでも読めます。** 読み取り専用の Web ページと Android アプリで、GitHub の保存場所にあるすべての会話を、どの端末からでも見られます。
- **VS Code のような見た目です。** 白黒で VS Code 風のデスクトップアプリです。ダークテーマとライトテーマがあり、普段使い向けのシンプルビューと、すべての詳細が見られる詳細ビューがあります。

## 対応している AI ツール

| ツール | 動作する場所 | チャットの表示 | PC 間の同期 | ツールへの復元 | コンテキストファイル |
|---|---|---|---|---|---|
| **Claude Code** | ターミナルの CLI、VS Code 拡張機能 | ✅ | ✅(自動同期フックを使用) | ✅ `claude --resume`、VS Code の履歴 | `CLAUDE.md` |
| **OpenAI Codex** | Codex CLI、VS Code 拡張機能、Codex デスクトップアプリ | ✅ | ✅(バックグラウンドで 15 分ごと) | ✅ `codex resume`、Codex のサイドバー | `AGENTS.md` |
| Gemini CLI | ターミナル | 予定 | 予定 | 予定 | `GEMINI.md`(要約の書き込み先としてはすでに利用可能) |
| Kiro(IDE と CLI)、Cursor、Antigravity | | 予定 | 予定 | 予定 | |

各ツールは、公開されていない独自の形式で履歴を保存しており、その形式はバージョンによって変わります。そのため ChatRelay は、お使いの PC で見つかった形式を確認します。知らないバージョンを見つけた場合でも会話は表示しますが、そのツールへの**書き込みをオフにし**、その理由を **Settings → AI tools**(設定 → AI ツール)に表示します。推測で動くことはありません。

動作確認済みのバージョン: Claude Code 2.1.x、Codex 0.144〜0.160(インデックスデータベース `state_5.sqlite`、スキーマの移行番号 58)。

## ダウンロードとインストール

### Windows

1. [最新リリース](https://github.com/Abh1shxkk/claude-sync-releases/releases/latest)から `ChatRelay_<version>_x64-setup.exe` をダウンロードします。(v0.5.0 までのリリースは `ClaudeSync_…` という名前です。)
2. それを実行します。インストーラーにはコード署名がないため、Windows SmartScreen が「Windows によって PC が保護されました」と表示することがあります。その場合は **More info → Run anyway**(詳細情報 → 実行)をクリックしてください。
3. インストールは 1 回だけで済みます。以降のバージョンは自動的に届きます([アップデート](#アップデート)をご覧ください)。

アプリはユーザーごとに `%LOCALAPPDATA%\Claude Sync\` にインストールされます(フォルダーは旧名のままです。[名前の変更について](#名前の変更について)をご覧ください)。アプリはシステムトレイで起動します。ウィンドウを閉じてもトレイで動き続けます。停止するには、トレイメニューの **Quit**(終了)を使ってください。

### Android(ビューアー)

同じリリースページから `ChatRelay_<version>.apk` をダウンロードし、スマートフォンで開きます(確認が表示されたら、ブラウザーまたはファイルマネージャーに「不明なアプリのインストール」を許可してください)。Android アプリは GitHub の保存場所を見るための**読み取り専用のビューアー**です。スマートフォン自体には AI ツールの履歴はありません。

### macOS と Linux

Rust エンジンとアプリは macOS と Linux でもビルドできます([ソースからのビルド](#ソースからのビルドと開発)をご覧ください)。ただし、インストーラーはまだ公開されておらず、動作テストもされていません。

### Web

Web ビューアーは静的なページで、自分でホストする(GitHub Pages、Cloudflare Pages、Netlify など)か、ローカルで実行できます。[Web とスマートフォンのビューアー](#web-とスマートフォンのビューアー)をご覧ください。

## 初回セットアップ

ChatRelay を初めて開くと、セットアップウィザードが次の手順を案内します。コマンドパレットからいつでもやり直せます(**Ctrl+Shift+P → Run First-time Setup Again**(初回セットアップを再実行))。

1. **あなたの履歴。** ChatRelay は Claude Code の履歴を `%USERPROFILE%\.claude\projects`(または `CLAUDE_CONFIG_DIR` のフォルダー)から、Codex の履歴を `%USERPROFILE%\.codex`(または `CODEX_HOME`)から見つけます。ツールごとに見つかった会話の数を表示します。
2. **Claude Code の 30 日での削除。** Claude Code は初期設定で、30 日より古い会話を削除します(`cleanupPeriodDays`)。ChatRelay はこれを表示し、日数を増やすことを提案します。変更する前に `settings.json` をバックアップします。
3. **マシン名。** たとえば `OFFICE-PC` や `HOME-LAPTOP` です。すべての会話の横に表示されるので、どの PC から来た会話かが分かります。
4. **保存場所(バックエンド)。** フォルダー(Google Drive、OneDrive、Dropbox、ネットワークドライブ)か、非公開の GitHub リポジトリです。次のセクションをご覧ください。
5. **Anthropic API キー(任意)。** 要約を作るときにだけ必要です。Windows の資格情報マネージャー(OS のキーチェーン)に保存され、ファイルに保存されることはありません。
6. **自動同期。** 自動アップロード・ダウンロードをオンにします(Claude Code のフックとバックグラウンドのタイマー)。
7. **すべてをアップロード。** 必要なら、既存の履歴全体をすぐにアップロードします。進行状況バーが表示されます。

## 履歴の保存先を選ぶ (バックエンド)

履歴は**あなた自身**が管理する場所に送られます。ChatRelay は独自のサーバーを持っていません。

### 方法 A: フォルダー

他の PC からも見えるフォルダーであれば何でも使えます。

- パソコン版 Google ドライブ。例: `G:\My Drive\chatrelay`
- OneDrive。例: `%OneDrive%\chatrelay`
- Dropbox、NAS やネットワーク共有、または持ち歩く USB ドライブ

そこに置かれるのは圧縮したコピーだけです。実際に使われている `~/.claude` や `~/.codex` フォルダーがクラウドのフォルダーに移動されることはありません。フォルダー型のバックエンドでは、各ファイルの以前のバージョンも保存されます(**Settings → What to sync → Versions kept (folder backend)**(設定 → 同期する内容 → 保持するバージョン数(フォルダーバックエンド))、初期値は 2)。

### 方法 B: 非公開の GitHub リポジトリ

Web やスマートフォンのビューアーも使いたい場合は、こちらがおすすめです。

1. **Sign in with GitHub**(GitHub でサインイン)(おすすめ)。ChatRelay が短いコードを表示するので、github.com でそのコードを入力して承認します。ChatRelay の GitHub App がアクセスできるのは、あなたが選んだリポジトリ(通常は履歴用のリポジトリだけ)のみで、その内容の読み取りと書き込みの権限だけを持ちます。パスワードは保存されず、サーバーも関与しません。
2. または **personal access token**(個人用アクセストークン)を貼り付けます(`repo` スコープを持つクラシックトークン、またはそのリポジトリ 1 つに対して *Contents: Read and write* を持つ細粒度トークン)。GitHub CLI でログインしている場合(`gh auth login`)、ChatRelay はそのトークンを使えます。
3. 既存の**非公開**リポジトリを選ぶか、**Create private repo**(非公開リポジトリを作成)をクリックします。チャット履歴には非公開のコードや秘密の情報が含まれることがあるため、公開リポジトリは受け付けません。

GitHub では、1 回のアップロードが **1 つのコミット**になります。GitHub は 100 MB を超える単一ファイルを受け付けないため、40 MB(圧縮後)を超えるファイルは自動的に分割されます。

トークンは OS のキーチェーン(サービス名 `claude-sync`)にだけ保存されます。

## 2台目のPCを設定する

**PC 1**(すでに履歴がある PC)で:

1. ChatRelay をインストールし、バックエンドを選びます。
2. アップロードします。シンプルビューで **Upload now**(今すぐアップロード)をクリックするか(またはセットアップの最後で **Upload everything**(すべてをアップロード))、詳細ビューでプロジェクトの **Push**(プッシュ)をクリックします。プレビューにそれぞれの会話と、見つかった秘密の情報が表示されます。アップロードするコピーの中でそれらを隠す(墨消しする)ことを選べます。

**PC 2** で:

1. ChatRelay をインストールし、**同じバックエンド**(同じ同期フォルダー、または同じ GitHub リポジトリ)を選びます。
2. プロジェクトのフォルダーを PC 2 に置きます(たとえば `git clone` で)。パスは違っていてもかまいません。たとえば `C:\Users\me\shop` ではなく `D:\work\shop` でも大丈夫です。
3. **Bring history to this PC**(この PC に履歴を取り込む)をクリックするか(シンプルビュー)、**Sync**(同期)ビューを開きます(詳細ビュー)。ChatRelay はバックエンドにあるすべてのプロジェクトと、この PC でそれぞれがどこに置かれるかを一覧表示します。
   - **Git のプロジェクト**は、リモート URL によって自動的に対応付けられます。
   - **その他のプロジェクト**: **Import into…**(取り込み先…)/ **Link**(リンク)をクリックし、ローカルのフォルダーを一度選びます。このリンクは記憶されます。
4. **ドライラン**の内容を確認します。どのファイルが書き込まれるか、そしてすべてのパスの変更(たとえば `×166  C:\Users\me\shop → D:\work\shop`)が表示されます。確認したら確定します。
5. ツールで会話を開きます。`claude --resume` または VS Code の Claude パネル、`codex resume` または Codex のサイドバーです。

Codex の場合: **先に Codex を閉じてください**(CLI、VS Code 拡張機能、デスクトップアプリ)。ChatRelay は Codex の実行中に Codex のファイルへ書き込むことはありません。その会話は「Codex is running」(Codex が実行中です)という理由でスキップされ、次回に取り込まれます。

両方の PC で **Auto-sync**(自動同期)をオンにすれば、これらを手作業で行う必要は二度とありません。

## 毎日の使い方

### シンプルビューと詳細ビュー

- **シンプルビュー**(初期設定): 状態を示す点の付いたプロジェクト一覧、2 つの大きなボタン(**Upload now** / **Bring history to this PC**)、自動同期のスイッチ、そして更新の確認があります。
- **詳細ビュー**: VS Code のようなレイアウトで、アクティビティバー(Projects **Ctrl+Shift+E**、Sync **Ctrl+Shift+Y**、Summaries、Logs、Backups、Settings)、タブ、ステータスバー、そしてすべての操作ができるコマンドパレット(**Ctrl+Shift+P**)があります。

切り替えは **Ctrl+Shift+P → Switch to Simple/Advanced View**(シンプル/詳細ビューに切り替え)で行います。

### 状態を示す点

| 点 | 意味 | すること |
|---|---|---|
| 緑 | 同期済み | 何もしなくて大丈夫です |
| 黄 / オレンジ | この PC にまだアップロードされていない変更があります | プッシュするか、自動同期を待ちます |
| 赤 | 前回の同期が失敗しました | **Logs**(ログ)を開いて理由を確認します |
| 灰色 | 一度も同期されていません | 一度プッシュします |
| 中が空の円 | まだプロジェクトの識別情報がありません(リンクされていません) | プッシュする(リンクが作られます)か、もう一方の PC のプロジェクトに **Link** します |

### 複数のツールの会話

すべての会話には、どのツールのものかを示す小さなバッジ(**Claude** または **Codex**)が付いています。複数のツールを使ったプロジェクトでは**フィルター**(All / Claude Code / Codex)が表示されます。会話を開くと、全文が表示されます。あなたのメッセージ、アシスタントの回答、ツールの呼び出し(実行したコマンド、編集したファイル)、そして変更されたファイルの一覧です。

### プッシュとプル

- **Push**(プッシュ)は、前回の同期以降に変更されたプロジェクトの会話をアップロードします。**Push all**(すべてプッシュ)はすべてのプロジェクトに対して行います。
- **Pull**(プル)は新しいものをダウンロードします。必ず**ドライラン**から始まり、書き込む予定のすべてのファイルとすべてのパスの書き換えが一覧表示されます。あなたが確定するまで、何も書き込まれません。

### 自動同期

**Auto-sync** がオンのとき:

- **Claude Code**: `~/.claude/settings.json` に設定されたフックが、Claude Code のセッションの**開始時**(プル)と**終了時**(プッシュ)に ChatRelay を実行します。
- **Codex**: Codex にはこのようなフックがないため、デスクトップアプリが 15 分ごとに確認します(起動から 20 秒後に開始)。Codex の会話が変更されたプロジェクトをアップロードし、新しい会話をダウンロードします(Codex の実行中はスキップされます)。
- オフラインだったために失敗したアップロードは、キューに入れられて再試行されます。

自動同期のオン・オフは、設定、トレイメニュー、または `claude-sync hooks install|uninstall` で切り替えられます。

### トレイメニュー

Push now(今すぐプッシュ)· Pull now(今すぐプル)· Auto-sync on/off(自動同期のオン/オフ)· Last sync status(前回の同期の状態)· Open(開く)· Quit(終了)。

### バックアップ

すべての書き込みの前に、`~/.claude-sync/backups/<timestamp>-<what>/` にバックアップが作られます。**Backups**(バックアップ)を開く(または `claude-sync backups`)とそれらを確認でき、1 つを **Restore**(復元)すると、すべてのファイルが元どおりの状態に戻ります。復元では、その変更によって作られたファイルも削除されます。

### ログ

**Logs** には ChatRelay が行ったことがすべて表示されます。エラーは強調表示され、エラーレポートをコピーするボタンもあります。

## Codex 対応の詳細

Codex の会話ごとに一緒に移動するもの:

| 項目 | Codex が保存している場所 | ChatRelay が行うこと |
|---|---|---|
| 会話(「rollout」) | `~/.codex/sessions/YYYY/MM/DD/rollout-<time>-<id>.jsonl`(バージョンによっては圧縮された `.jsonl.zst` で書き込みます) | コピーし、すべてのパスを書き換えます |
| スレッドのインデックス行 | `~/.codex/state_5.sqlite`、テーブル `threads` | 会話が `codex resume` とサイドバーに表示されるように、追加または更新します |
| スレッドの名前 | `~/.codex/session_index.jsonl` | 追加します |
| そのスレッドの Codex のメモリー | `~/.codex/memories_1.sqlite`、テーブル `stage1_outputs` | この PC にそのスレッドのものがなければ追加します。パスは書き換えます |
| そのスレッドのゴール | `~/.codex/goals_1.sqlite`、テーブル `thread_goals`、`thread_goal_continuation_deferrals` | この PC にそのスレッドのものがなければ追加します |

大切な点:

- ChatRelay が書き込む間は、**Codex を閉じておく必要があります**。ChatRelay は実行中の `codex` プロセス(CLI、VS Code 拡張機能、デスクトップアプリ)がないか確認します。バックグラウンドの同期中に何かを閉じるよう求めることはなく、後でもう一度試すだけです。
- **履歴のモードはそのまま保たれます。** 新しいバージョンの Codex は「ページ分割」形式で履歴を保存します。Codex は、会話を初めて開いたときに会話ファイルからページのデータベース(`thread_history_*.sqlite`)を作り直すので、ChatRelay がそのデータベースに書き込むことはありません。
- **スレッドに対するあなた自身の設定は、あなたのものとして残ります。** 更新時には、この PC でのピン留めの状態、独自の名前、アーカイブの状態、アカウントが保持されます。もう一方の PC にしか存在しないフォルダーやセクションは解除されます。
- **アカウント。** 取り込まれたスレッドは、この PC で最も多くのスレッドを所有している Codex アカウントに割り当てられます。
- **Windows のパスの接頭辞。** Windows の Codex は作業フォルダーを `\\?\D:\project` の形で保存します。ChatRelay はこの接頭辞を、Codex がこれを使っている PC 上の Windows のパスにだけ付け、macOS や Linux のパスには決して付けません。
- **圧縮された会話**(`.jsonl.zst`)も読み取りと更新ができます。更新時には、ファイルは通常の `.jsonl` に置き換えられます(圧縮された元のファイルは先にバックアップされます)。
- もう一方の PC に属する**メモリーの管理情報**(メモリーが何回使われたか、統合の対象に選ばれたかどうか)はコピーされません。
- **知らないバージョン。** Codex のインデックスが ChatRelay の知らないデータベース(たとえば将来の `state_6.sqlite`)を使っている場合や、ChatRelay が埋められない必須項目が追加された場合は、Codex への書き込みはオフになり、分かりやすい警告が表示されます。読み取りは引き続きできます。

## 要約と別のツールでの続行

> 🔒 **秘密情報は AI に届きません。** モデルに何かを送る前に、ChatRelay はチャット内で見つかったキー・トークン・パスワード(Anthropic、OpenAI、OpenRouter、GitHub、AWS、Google、Slack、Stripe、Hugging Face、npm、SendGrid、Telegram ボットの API キー、JWT、秘密鍵、`PASSWORD=…` 形式の行、URL 内のパスワード)を `[REDACTED:kind]` に置き換えます。これは常に行われ、オフにはできません。隠した数は画面に表示されます。コードや会話のほかの部分は送信されるため、非公開のコードや顧客のコードには、データを保持しない有料モデルを選んでください。

**Summaries**(要約)を開き(詳細ビュー)、プロジェクトを選び、会話(どのツールのものでも可)とモデルにチェックを入れて、**Generate handoff**(引き継ぎを生成)をクリックします。

- モデル: **Claude Opus 5.5**(初期設定)、Claude Sonnet 5.5(より速く、より安い)、Claude Haiku 5.5(最も安い)、Claude Fable 5.1(最も高性能)。Anthropic API キーが必要です(**Settings → Summaries**(設定 → 要約))。
- 履歴はまず凝縮されます。残るのは、あなたの依頼、各ターンでのアシスタントの最終回答、変更されたファイルです。長いツールの出力や思考の過程は除かれます。すべてのツールの会話が時系列順にまとめられ、それぞれのツール名が付けられます。
- 長い履歴は約 10 万トークンずつに分けて要約され、その後でまとめられます。
- 結果には次のセクションがあります: プロジェクトの概要、終わったこと、主な決定事項、未解決のバグ / 既知の問題、次のステップ、触ったファイル。

その後、次のことができます:

- プロジェクトフォルダーに **Save HANDOFF.md**(HANDOFF.md を保存)する、または
- **Continue in…**(…で続ける)でツールを選ぶ: Claude Code(`CLAUDE.md`)、Codex(`AGENTS.md`)、Gemini CLI(`GEMINI.md`)から選びます。一覧には、この PC にインストールされているツールが表示されます。ChatRelay はそのファイルに短い「Previous context」(これまでの文脈)セクション(概要、終わったこと、次のステップ)を追加します。もう一度実行すると、置き換えられるのは自分のセクションだけで、ファイルの他の部分には手を付けません。
- または、テキストを **copy**(コピー)します。

コマンドラインからは: `claude-sync summarize --target handoff|claude-md|agents-md|gemini-md|none`。

## Web とスマートフォンのビューアー

**🌐 オンライン Web ビューアー:** <https://abh1shxkk.github.io/claude-sync-web/>

アプリの読み取り専用版で、**GitHub** バックエンドにある履歴を、どのブラウザーからでも、また Android アプリからでも開けます。プロジェクト、すべてのツールの会話、そして会話の全文が見られます。WebAssembly にコンパイルされた同じ Rust エンジンを使っているので、デスクトップアプリとまったく同じ内容が表示されます。アップロード、ダウンロード、自動同期、要約は、ローカルの履歴フォルダーが必要なため、デスクトップアプリでのみ行えます。

- GitHub でサインインするか、リポジトリ名と、**そのリポジトリだけに限定し、Contents: Read-only の権限を持つ細粒度トークン**でサインインします。
- トークンはそのブラウザーの中にだけ保存されます(「remember」(記憶する)にチェックを入れた場合は localStorage、そうでなければ sessionStorage)。
- このページが通信するのは `api.github.com` だけで、第三者のスクリプトは読み込みません。
- 初回の訪問時には、メッセージ数を数えるために各会話を 1 回ずつ読み込みます。結果は内容のハッシュによってキャッシュされます。
- スマートフォンの大きさの画面では、レイアウトが 1 画面ずつの表示(一覧 → プロジェクト → 会話の全文)に切り替わり、戻るボタンと下部のバーが付きます。

## 安全性とプライバシー

- **アップロード時に元のファイルが変更されることはありません。** アップロードでは履歴ファイルを読み取るだけです。
- **ツールの実行中は何も書き込みません**(Codex)。Claude Code の開いているセッション(フックを起動したセッション)に触れることはありません。
- **すべての書き込みの前にバックアップを取ります。** Claude Code の `settings.json`、Codex のデータベース(その `-wal` と `-shm` ファイルを含む)、`session_index.jsonl` も対象です。
- **すべての取り込みでドライランを行います。** 何かが起きる前に、すべてのファイルとすべてのパスの書き換えを確認できます。
- **競合したときは両方のバージョンを残します。** 上書きは決してしません。
- **秘密情報のスキャン。** アップロードの前に、ChatRelay は API キーやパスワードを探します。対象は、Anthropic、OpenAI、GitHub、AWS、Google、Slack、Stripe のキー、JWT、秘密鍵、`.env` 形式の `SECRET=…` の行、URL に含まれる認証情報です。**warn**(警告)、**redact**(墨消し。アップロードするコピーの中だけで `[REDACTED:kind]` に置き換えます)、**off**(オフ)から選べます。
- **秘密の情報は OS のキーチェーンに保存されます。** GitHub のトークンと Anthropic のキーがファイルに書き込まれることはありません。
- **ログイン情報には一切触れません。** ChatRelay は Claude Code や Codex のログイン用ファイル(`~/.claude/.credentials.json`、`~/.codex/auth.json` など)を読み取ったり、コピーしたり、変更したりしません。履歴を同期してもログアウトされることはありません。もしログアウトされた場合、それはツール自体が原因です(たとえば、セッションの有効期限切れや、別の PC で別のアカウントにサインインしたことなど)。
- **非公開の保存場所だけを使います。** 公開の GitHub リポジトリは受け付けません。
- **ChatRelay のサーバーはありません。** データが行き来するのは、あなたの PC 同士、あなたのフォルダーまたは GitHub、そして(要約を作るときだけ)Anthropic API の間だけです。

意図的に同期しないもの: `~/.claude/history.jsonl`(すべてのプロジェクトにまたがる、上矢印キーで呼び出すプロンプト履歴)、`~/.claude/file-history/`(巻き戻し用のスナップショット)、そしてすべての認証情報。

## コマンドラインツール (CLI)

インストーラーは `claude-sync.exe` をアプリと同じ場所(`%LOCALAPPDATA%\Claude Sync\`)に置きます。Claude Code のフックが実行するのはこのファイルです。どこからでも使えるようにするには、そのフォルダーを `PATH` に追加してください。ソースから使う場合: `cargo run -p claude-sync-cli -- …`。

```
claude-sync scan [--json]                 List projects & sessions
claude-sync status [--json]               Backend, last sync, hooks, queue, cleanupPeriodDays
claude-sync push [--cwd <dir>] [--all] [--dry-run] [--redact]
claude-sync pull [--cwd <dir>] [--project <id>] [--all] [--dry-run]
claude-sync summarize [--cwd <dir>] [--model <id>] [--target handoff|claude-md|agents-md|gemini-md|none]
claude-sync remote                        List projects stored in the backend
claude-sync link <dir> <projectId>        Link a local folder to a remote project ID (--remove to unlink)
claude-sync config [key] [value]          Show or set config (machineName, backend.folder, backend.github, secretScan, ...)
claude-sync secret set github-token|anthropic-api-key <value>
claude-sync hooks install|uninstall       Add/remove the SessionStart/SessionEnd hooks
claude-sync cleanup-days <n>              Set Claude Code's cleanupPeriodDays (backs up settings.json)
claude-sync backups [restore <id>]        List or restore backups
claude-sync queue                         Retry queued (offline) pushes

Other AI coding tools (provider = claude-code | codex):
claude-sync providers [--json]            Which tools are installed, their version/format, import on/off
claude-sync providers sessions <provider> [--cwd <dir>] [--json]
claude-sync providers show <provider> <id> [--json]      Read a session in the tool-neutral format
claude-sync providers export <provider> <id> --out <file.json.gz>
claude-sync providers import <file.json.gz> --to <dir> [--dry-run]

Flags: --hook (read Claude Code hook JSON from stdin; never fails), --quiet, --json, --verbose
```

終了コード: `0` 成功、`1` エラー、`2` プッシュで競合が発生(先にプルしてください)。

環境変数:

| 変数 | 効果 |
|---|---|
| `CLAUDE_SYNC_HOME` | ChatRelay 自身のデータフォルダー(初期値 `~/.claude-sync`) |
| `CLAUDE_CONFIG_DIR` | Claude Code のフォルダー(初期値 `~/.claude`) |
| `CODEX_HOME` | Codex のフォルダー(初期値 `~/.codex`) |
| `ANTHROPIC_API_KEY` | キーチェーンにキーが保存されていないときに、要約で使われます |
| `GITHUB_TOKEN` | リリース用スクリプトが使います |

## 仕組み (技術的な説明)

### Claude Code が履歴を保存する場所

| パス | 内容 |
|---|---|
| `~/.claude/projects/<encoded-path>/<session-uuid>.jsonl` | セッションごとに 1 ファイル、1 行に 1 つの JSON オブジェクト |
| `~/.claude/projects/<encoded-path>/<session-uuid>/subagents/*.jsonl` + `*.meta.json` | サブエージェントの会話記録(「サイドカー」として同期されます) |
| `~/.claude/projects/<encoded-path>/<session-uuid>/tool-results/*` | ディスクに保存された大きなツールの出力(サイドカー) |
| `~/.claude/projects/<encoded-path>/memory/` | プロジェクトの自動メモリー(`MEMORY.md` + メモ) |

よくある想定とは異なる点(すべて対応済み):

- **ドライブ文字の大文字・小文字がクライアントによって異なります。** VS Code 拡張機能は `c:\Users\…`(フォルダーは `c--Users-…`)と記録し、CLI は `C:\Users\…`(フォルダーは `C--Users-…`)と記録します。1 つのセッションに両方が含まれることもあります。Windows では、パスは大文字・小文字を区別せずに比較されます。
- **フォルダー名は確実には元に戻せません。** `C:\Users\me\my project` と `C:\Users\me\my-project` は、どちらも `C--Users-me-my-project` に変換されます。本当のパスはセッションに記録された `cwd` から取得します。名前を元に戻す方法は、目印を付けた予備の手段としてのみ使います。
- **セッションはとても大きくなることがあります**(画像や PDF が埋め込まれると 200 MB 以上)。そのため、すべてストリーム処理で扱います。スキャン結果はサイズと更新日時でキャッシュされるので、再スキャンは約 100 ミリ秒で終わります。
- **アシスタントの 1 つの返答が複数行にまたがります**(コンテンツブロックごとに 1 行で、`message.id` は同じです)。メッセージ数を数えるときは、これらの重複を除きます。タイトルは最初の本当のプロンプトから取ります(IDE のラッパータグは取り除きます)。Claude Code 自身の `ai-title` はその横に表示されます。
- **ユーザー/アシスタント以外にも多くの種類の行があります**(`attachment`、`file-history-snapshot`、`queue-operation`、`ai-title`、`last-prompt`、`permission-mode` など)。知らない種類や項目は、そのまま手を付けずに残します。

### Codex が履歴を保存する場所

[Codex 対応の詳細](#codex-対応の詳細)をご覧ください。rollout の各行は `{timestamp, type, payload}` の形で、最初の行はセッション ID と `cwd` を持つ `session_meta` です。Codex はこれまでに 3 世代の形式で会話を書き込んできました(0.15x 以降では `event_msg/item_completed` の項目、それ以前は `user_message`/`agent_message` のイベント、最も古いものは単純な `response_item` のメッセージ)。ビューアーは、その中で最も情報の多いものを使います。

### アダプター

それぞれの AI ツールは、1 つの共通インターフェース(`ProviderAdapter`)の背後にある**アダプター**(`crates/core/src/providers/`)です。アダプターは、ツールとその形式の検出、プロジェクトとセッションの一覧表示、セッションをツールに依存しない形(`UniversalSession`)で読み込むこと、情報を失わずにエクスポートすること(`SessionBundle`: 元のファイルと、Codex のインデックス行などのツールのメタデータ)、別の PC での取り込み(パスの書き換え、ツールが実行中でないかの確認、バックアップ、ドライラン)、そして新しい行の追記を行います。[別の AI ツールを追加する](#別の-ai-ツールを追加する-アダプターガイド)をご覧ください。

### プロジェクトの識別

同じプロジェクトでも PC ごとにパスが異なるため、次の順番で識別します:

1. **手動のリンク**(Link ボタン / `claude-sync link <dir> <id>`)。ChatRelay の設定に保存されます
2. 正規化した **git のリモート**。`git@github.com:Me/Repo.git` と `https://github.com/me/repo` は、どちらも `git:github.com/me/repo` になります
3. プロジェクトのルートにある、UUID を含む **`.claude-sync.json`**。git を使っていないプロジェクトで最初にプッシュしたときに作られます(これをコミットするか、もう一方の PC で手動でリンクしてください)。「Upload everything」とバックグラウンドの同期では、代わりに ChatRelay の設定にリンクが作られるので、プロジェクトのフォルダーには何も書き込まれません。

### 保存場所の構成(フォルダーまたはリポジトリ内)

```
<projectId-slug>/
  manifest.json                          machines, original paths, hashes, timestamps, revision
  <sessionId>.jsonl.gz                   Claude Code session (whole, or its start when deltas exist)
  <sessionId>.d<N>.jsonl.gz              lines appended after that, one blob per push
  <sessionId>.sidecar.json.gz            subagents/ + tool-results/ (if any)
  memory.json.gz                         Claude Code project memory (if any)
  <provider>-<sessionId>.bundle.json.gz  another tool's session (e.g. codex-…): files + metadata
  <provider>-<sessionId>.d<N>.jsonl.gz   lines appended to it later
  .versions/<file>/<timestamp>           previous versions (folder backend)
```

他のツールのセッションは、マニフェストの `providerSessions` の下に一覧として記録されます(キーは `<provider>:<id>`)。古いバージョンのアプリはこの一覧を無視し、そのまま残します。

### プッシュ

- セッションは SHA-256 で比較され、新しいものや変更されたものだけがアップロードされます。元のファイルは読み取るだけです。
- **新しい行だけを送ります。** AI ツールは会話ファイルに追記しかしないため、セッションを最初にアップロードした後は、前回の同期以降に追加された行だけを「差分(delta)」の部分として保存します。各部分には、それをプッシュしたマシンのパスが記録されます。セッションのハッシュは連鎖しています(`hash = sha256(previous : sha256(part))`)。部分が 40 個になると、次のプッシュではセッション全体をもう一度アップロードします。この近道が使えない場合(ファイルが別の方法で変更された、競合がある、古いバージョンの状態が残っている)は、ファイル全体がアップロードされます。
- バックエンドに、あなたがまだ見ていない、あなたの持っていないメッセージを含むバージョンがある場合、そのセッションのプッシュは「pull first」(先にプルしてください)として拒否されます。そのため何も失われません。
- **オフラインの場合は?**(GitHub に接続できない、クラウドドライブがマウントされていない。)プッシュは `~/.claude-sync/queue.json` のキューに入れられ、次回の実行時と、デスクトップアプリによって 15 分ごとに再試行されます。

### プル

- パスの書き換えは、解析した JSON の中で行います(文字列の値**と**オブジェクトのキー)。そのため JSON のエスケープが問題になることはありません。扱える形式: `C:\…`、`c:/…`、Git-Bash の `/c/…`、WSL の `/mnt/c/…` の形の Windows パス(大文字・小文字を区別しない)、POSIX のパス(大文字・小文字を区別する)、`%20` でエンコードされた空白を含む `file:///` の URL。OS をまたいで移動するときは、プロジェクトのルートより後ろの区切り文字が変換されます。ツール自身のホームフォルダー(`~/.claude`、`~/.codex`)と、Claude Code のエンコードされたフォルダー名も書き換えます。`shop-old` のような隣のフォルダーに触れることはありません。
- **高速な経路:** 前回同期したときとまったく同じ内容を持っている PC は、足りない部分だけをダウンロードして追記します。
- **分岐**(会話は追記のみで、Claude Code では行の ID、他のツールではテキストの先頭部分で比較します):
  - リモートがローカルを含んでいる → 更新します
  - ローカルがリモートを含んでいる → あなたの方が新しいので、そのまま残します(次のプッシュでアップロードされます)
  - 両方が変更されている → **競合**: あなたのコピーはそのまま残り、もう一方のバージョンは**新しい ID を持つ新しい会話**として保存されます(Codex では「<name> (from <PC>)」という名前になります)。その後、両方がツールに表示され、他の PC にも同期されます。

### 自動同期のフック(Claude Code)

「Enable auto-sync」(自動同期を有効にする)は、次の内容を `~/.claude/settings.json` に統合します。あなたの他の設定やフックはそのまま残り、先にバックアップが作られます:

```jsonc
"hooks": {
  "SessionStart": [{ "hooks": [{ "type": "command", "command": "\"…/Claude Sync/claude-sync.exe\" pull --hook --quiet --claude-sync-hook", "timeout": 60 }] }],
  "SessionEnd":   [{ "hooks": [{ "type": "command", "command": "\"…/Claude Sync/claude-sync.exe\" push --hook --quiet --claude-sync-hook", "timeout": 60 }] }]
}
```

- `--hook` は Claude Code のフック JSON(`cwd`、`session_id`)を標準入力から読み取ります。読み取れない場合は `CLAUDE_PROJECT_DIR`、さらに作業ディレクトリを使います。フックは**常に終了コード 0 で終わる**ので、セッションを壊すことはありません。エラーはログパネルに記録されます。
- フックは、アプリと同じ場所にインストールされたネイティブの `claude-sync` 実行ファイルを実行します。Node.js は必要ありません。
- 「Disable auto-sync」(自動同期を無効にする)は、`claude-sync-hook` という目印を含むフックだけを削除します。

## アップデート

- デスクトップアプリは、起動時、ウィンドウを開くたび、1 時間ごと、5 分以上たってからウィンドウに戻ったとき、そして **Check for updates**(更新を確認)をクリックしたとき(Settings → About、シンプルビュー、またはコマンドパレット)に、新しいバージョンがあるか確認します。確認中はスピナーが表示されます。
- 新しいバージョンがあると、**A new version is available → Update now**(新しいバージョンがあります → 今すぐ更新)と表示されます。アプリはそれをダウンロードし、署名を検証し(アプリはプロジェクトの鍵で署名された更新しか受け付けません)、その場でインストールして再起動します。履歴と設定はそのまま残ります。
- Android アプリでは、新しい APK へのリンク付きのお知らせが表示されます。

## トラブルシューティングとよくある質問

**SmartScreen がインストーラーをブロックします。** インストーラーにはコード署名がありません。**More info → Run anyway** をクリックしてください。

**プロジェクトに黄色の点が表示されます。** この PC に、まだアップロードされていない会話があります。プッシュするか、自動同期をオンにしてください。

**もう一方の PC のプロジェクトが表示されません / 別の名前で表示されます。** プロジェクトは、git のリモート、`.claude-sync.json`、またはリンクによって対応付けられます。フォルダー名が異なり、git のリモートもない場合は、**Link**(または **Import into…**)を一度使って、正しいローカルフォルダーを選んでください。

**Codex の会話がスキップされました:「Codex is running」。** Codex CLI、VS Code 拡張機能の Codex パネル(または VS Code)、Codex デスクトップアプリを閉じてから、もう一度プルしてください。バックグラウンドの同期は自動的に再試行します。

**Codex の取り込みがオフになっています:「Unknown Codex index database」/「new required fields」。** お使いの Codex が、この ChatRelay のバージョンが知っているものより新しいためです。ChatRelay を更新してください。会話は引き続き表示されます。

**同じ会話が 2 つ表示され、1 つは「(from OFFICE-PC)」で終わっています。** 同期される前に、両方の PC でその会話が続けられたためです。両方のバージョンが残されています。不要な方をツールの中で削除してください。

**古い Claude Code の会話が消えました。** Claude Code は `cleanupPeriodDays`(初期値 30)より古い会話を削除します。設定で日数を増やしてください(または `claude-sync cleanup-days 3650`)。すでにアップロード済みの会話は、バックエンドからプルして取り戻せます。

**同期したせいで Claude からログアウトされましたか?** いいえ。ChatRelay はログイン用のファイルを読み書きすることはありません。[安全性とプライバシー](#安全性とプライバシー)をご覧ください。

**初回のアップロードが遅いです。** 初回のアップロードでは、すべて(圧縮したもの)を送ります。その後は新しい行だけが送られます。

**プッシュすると「Pull first」と表示されます。** 別の PC が、あなたの PC にはない新しいバージョンをアップロードしています。プルしてから、プッシュしてください。

**オフラインです。** プッシュはキューに入れられ、自動的に再試行されます。`claude-sync queue` を実行すると、すぐに再試行します。

**プルした後に何かおかしくなりました。** **Backups** を開き、その直前に作られたバックアップを復元してください。

**エラーはどこで確認できますか?** **Logs** ビュー(そこからエラーレポートをコピーできます)、または `~/.claude-sync/logs/claude-sync.log` です。

## ソースからのビルドと開発

必要なもの: Node.js 20 以上、Rust(stable)、そして Windows では MSVC ツールチェーン(Visual Studio の「C++ によるデスクトップ開発」)。

```bash
git clone https://github.com/Abh1shxkk/chatrelay.git
cd chatrelay
npm install
npm run tauri:dev      # run the desktop app with hot reload
npm run test:rust      # cargo test --workspace: engine, adapters, push/pull, GitHub backend
npm test               # UI helper tests (vitest)
npm run typecheck      # TypeScript
npm run tauri:build    # installer in target/release/bundle/nsis/
```

プロジェクトの構成:

```
crates/core/       Rust engine: scanner, JSONL, path rewriting, sync, backends, hooks, summaries
crates/core/src/providers/   AI tool adapters: claude_code.rs, codex.rs (+ codex_format.rs, browser-safe parsing)
crates/core/src/provider_sync.rs   other tools' sessions in push/pull (bundles, deltas, conflict copies)
crates/core/tests/  integration tests with fixture files (tests/fixtures/codex, tests/fixtures/claude-code)
crates/cli/        the `claude-sync` CLI (also what the Claude Code hooks run)
crates/wasm/       the engine compiled to WebAssembly for the web and phone viewers
src-tauri/         desktop app: window, tray, background sync, the API behind window.claudeSync
src/renderer/      React + TypeScript + Tailwind UI (shared by desktop, web and phone)
src/shared/        TypeScript types and helpers
mobile/            Android / iOS shell around the web version (Tauri)
scripts/           release, CLI staging, WASM build
tests/             vitest tests; tests/web/mock-github.mjs for testing the web version
```

インストール済みのアプリと並べて開発版を動かす場合は、別の識別子とデータフォルダーを設定してください。そうすれば、実際の設定に触れることはありません:

```powershell
$env:TAURI_CONFIG='{"identifier":"com.claudesync.dev","productName":"ChatRelay Dev"}'
$env:CLAUDE_SYNC_HOME='D:\tmp\chatrelay-dev'
npm run tauri:dev
```

### モバイルアプリ(Android、iOS)

## 別の AI ツールを追加する (アダプターガイド)

1. **まず実際のマシンで保存形式を確認してください**: セッションがどこにあるか、行/レコードの形式、インデックスデータベースがあればそのスキーマ、ツールがセッションをどう一覧表示するか、パスをどう保存するか、どのプロセスがあれば「実行中」とみなすか。これらをアダプターファイルの先頭に書き留めておきます。
2. `crates/core/src/providers/mod.rs` に `ProviderId` を追加し、`ProviderAdapter` を実装するファイル `providers/<tool>.rs` を作ります: `detect`、`list_projects`、`list_sessions`、`read_session`、`export_session`、`import_session`、必要に応じて `append_session`、`context_file_name`、`process_names`。
3. すべてのアダプターが守るルール: ツールの実行中は書き込みを拒否する(`ensure_not_running`)、書き込む前にすべてのファイルをバックアップする(`ImportOptions.backups`)、`dry_run` に従う、`keep_both` に従う(分岐した受信セッションを新しい ID で保存する)、そして認識できない形式があれば取り込みをオフにする(`ProviderStatus` に警告を出す)。
4. 純粋な解析処理は、ファイルシステムにアクセスしないファイル(`codex_format.rs` のようなもの)に置き、Web ビューアーから使えるようにします。そして `messages_from_bundle` に追加します。
5. `crates/core/tests/fixtures/<tool>/` にフィクスチャファイルを追加し、テストを書きます: 検出、一覧表示、読み込み、エクスポート → 2 台目の仮想マシンへの取り込み(パスが書き換えられること)、更新、ローカルが先行している場合、競合、実行中のプロセスによる拒否、未知の形式。
6. `src/shared/types.ts`(`PROVIDER_LABELS`)にラベルを追加します。バッジ、フィルター、プッシュ/プル、要約、ビューアーは、そこから自動的に反映されます。

## リリースの公開

インストール済みのアプリは、[Abh1shxkk/claude-sync-releases](https://github.com/Abh1shxkk/claude-sync-releases) にある `latest.json` を確認します。

1. `package.json`、`src-tauri/tauri.conf.json`、`mobile/tauri.conf.json`、`Cargo.toml` の `version` を上げます。
2. `npm run release -- --notes "What changed"`

これにより、アップデーター用の鍵(`TAURI_SIGNING_PRIVATE_KEY`、または `D:\dev\tauri-keys\claude-sync-updater.key` とその `.password` ファイル)で署名された Windows インストーラーと、署名済みの APK がビルドされ、`latest.json` が書き出され、すべてがリリース `v<version>` としてアップロードされます。フラグ: `--no-apk`、`--skip-build`、`--dry-run`、`--notes-file <file>`。GitHub のログイン情報は `git credential fill`(または `GITHUB_TOKEN`)から取得します。

アップデーター用の鍵は必ずバックアップしておいてください。アプリはこの鍵で署名された更新しか受け付けません。鍵の公開側は `src-tauri/tauri.conf.json` にあります。

## 既知の制限

- Windows のインストーラーにはコード署名がありません(SmartScreen の警告が出ます)。
- テストしているのは Windows だけです。macOS と Linux はビルドできますが、インストーラーは公開されていません。
- 2 台の PC で同時に開いている会話は、リアルタイムでは統合できません。競合のコピーになります。
- Codex には「セッション終了」のフックがないため、Codex の同期はすぐには行われず、15 分ごとに行われます。
- 200 文字を超えるパスについては、Claude Code のフォルダー名のハッシュの正確な仕様が公開されていません。ChatRelay は、セッションに同じ `cwd` が記録されている既存のフォルダーを優先し、それがなければ独自の `-<hash>` という接尾辞を使います。
- Web とスマートフォンのビューアーは読み取り専用で、GitHub バックエンドが必要です。

| そのままにしたもの | 理由 |
|---|---|
| インストールフォルダーとスタートメニューの項目「Claude Sync」 | Windows はこれによってインストール済みのアプリを識別します。変更すると、更新されずに 2 つ目のコピーがインストールされてしまいます |
| アプリの識別子 `com.claudesync.app` / `com.claudesync.mobile` | 更新と Android でのインストールがこれに依存しています |
| `~/.claude-sync/` データフォルダー、`CLAUDE_SYNC_HOME` | あなたの設定、同期の状態、バックアップ |
| `claude-sync` CLI | Claude Code のフックがパスでこれを呼び出します |
| `.claude-sync.json` プロジェクトファイル、`claude-sync-hook` という目印 | 既存のプロジェクトとフックが引き続き動作します |
| リリース用リポジトリ `claude-sync-releases` | インストール済みのアプリはここから更新をダウンロードします |
| GitHub App「claude-sync-abh1shxkk」 | 既存のサインインが引き続き動作します |
