**Take your AI coding chats to any PC, and from one AI tool to another.**

ChatRelay syncs the chat history of AI coding assistants (**Claude Code** and **OpenAI Codex** today) between your computers. Start a conversation on your office PC, then open the same conversation on your home laptop: same messages, same tool calls, with every file path changed to the new machine's paths. It also writes a short summary of a project's history into the instructions file another tool reads (`CLAUDE.md`, `AGENTS.md`, `GEMINI.md`), so you can continue the work in a different AI tool.

## What it does

- **Moves chat history between PCs.** Every conversation from Claude Code (terminal CLI and VS Code extension) and Codex (CLI, VS Code extension and desktop app) is copied to a storage place you own, and from there to your other PCs. On the other PC it appears in the tool's own history list: `claude --resume`, the Claude Code panel in VS Code, `codex resume`, or the Codex sidebar.
- **Fixes file paths.** Your project might be `C:\Users\me\shop` on one PC and `D:\work\shop` on another, or `/home/me/shop` on Linux. ChatRelay rewrites every path inside the chat (working folder, tool inputs and outputs, file links, message text) to the path on the receiving PC.
- **Only sends what changed.** After the first upload, only the new lines of a conversation travel: a few KB instead of the whole file.
- **Never loses work.** It never edits your originals when uploading. It backs up every file before it changes it, shows a preview (dry run) first, and never overwrites a conversation that changed on both PCs: it keeps both.
- **Works by itself.** With auto-sync on, Claude Code conversations are uploaded when a session ends and downloaded when a session starts. Codex conversations are uploaded and downloaded every 15 minutes in the background.
- **Summarizes.** It turns a project's whole history (from every tool) into a `HANDOFF.md`: what's done, decisions, open bugs, next steps, files touched. It can also put a short version into `CLAUDE.md`, `AGENTS.md` or `GEMINI.md`, so the next tool starts with the context.
- **Read anywhere.** A read-only web page and an Android app show all your conversations from the GitHub storage, on any device.
- **Looks like VS Code.** Black-and-white, VS Code-style desktop app, with dark and light themes, a simple view for everyday use and an advanced view with every detail.

## Supported AI tools

| Tool | Where it runs | View chats | Sync between PCs | Restore into the tool | Context file |
|---|---|---|---|---|---|
| **Claude Code** | Terminal CLI, VS Code extension | ✅ | ✅ (with auto-sync hooks) | ✅ `claude --resume`, VS Code history | `CLAUDE.md` |
| **OpenAI Codex** | Codex CLI, VS Code extension, Codex desktop app | ✅ | ✅ (background, every 15 min) | ✅ `codex resume`, Codex sidebar | `AGENTS.md` |
| Gemini CLI | Terminal | planned | planned | planned | `GEMINI.md` (summary target already available) |
| Kiro (IDE and CLI), Cursor, Antigravity | | planned | planned | planned | |

Each tool keeps its history in its own undocumented format, and those formats change between versions. So ChatRelay checks the format it finds on your PC. If it sees a version it doesn't know, it still shows the conversations, but **turns off writing** for that tool and tells you why in **Settings → AI tools**. It never guesses.

Verified versions: Claude Code 2.1.x; Codex 0.144 to 0.160 (index database `state_5.sqlite`, schema migration 58).

## Download and install

### Windows

1. Download `ChatRelay_<version>_x64-setup.exe` from the [latest release](https://github.com/Abh1shxkk/claude-sync-releases/releases/latest). (Releases up to v0.5.0 are named `ClaudeSync_…`.)
2. Run it. The installer is not code-signed, so Windows SmartScreen may say "Windows protected your PC": click **More info → Run anyway**.
3. You only install once. Later versions arrive by themselves (see [Updates](#updates)).

The app installs per user in `%LOCALAPPDATA%\Claude Sync\` (the folder keeps its old name; see [About the rename](#about-the-rename)). It starts in the system tray. Closing the window keeps it running there; use **Quit** in the tray menu to stop it.

### Android (viewer)

Download `ChatRelay_<version>.apk` from the same release page and open it on your phone (allow "install unknown apps" for your browser or file manager when asked). The Android app is a **read-only viewer** of your GitHub storage; a phone has no AI tool history of its own.

### macOS and Linux

The Rust engine and the app build on macOS and Linux (see [Building from source](#building-from-source-and-development)), but no installers are published for them yet and they haven't been tested.

### Web

The web viewer is a static page you can host yourself (GitHub Pages, Cloudflare Pages, Netlify…) or run locally. See [Web and phone viewer](#web-and-phone-viewer).

## First-time setup

When ChatRelay opens for the first time, a setup wizard walks you through these steps. You can run it again any time from the command palette (**Ctrl+Shift+P → Run First-time Setup Again**).

1. **Your history.** ChatRelay finds Claude Code's history in `%USERPROFILE%\.claude\projects` (or the folder in `CLAUDE_CONFIG_DIR`) and Codex's in `%USERPROFILE%\.codex` (or `CODEX_HOME`). It shows how many conversations it found per tool.
2. **Claude Code's 30-day deletion.** By default Claude Code deletes conversations older than 30 days (`cleanupPeriodDays`). ChatRelay shows this and offers to raise it. It backs up `settings.json` before changing it.
3. **Machine name.** For example `OFFICE-PC` or `HOME-LAPTOP`. It is shown next to every conversation, so you know which PC it came from.
4. **Storage (backend).** A folder (Google Drive, OneDrive, Dropbox, network drive) or a private GitHub repository. See the next section.
5. **Anthropic API key (optional).** Only needed for summaries. It is stored in the Windows Credential Manager (OS keychain), never in a file.
6. **Auto-sync.** Turns on automatic upload/download (Claude Code hooks plus the background timer).
7. **Upload everything.** Optionally uploads your whole existing history right away, with a progress bar.

## Choosing where your history is stored (backend)

Your history goes to a place **you** control. ChatRelay has no server of its own.

### Option A: a folder

Any folder that your other PCs can also see:

- Google Drive for desktop, e.g. `G:\My Drive\chatrelay`
- OneDrive, e.g. `%OneDrive%\chatrelay`
- Dropbox, a NAS or network share, or a USB drive you carry

Only compressed copies go there. Your live `~/.claude` and `~/.codex` folders are never moved into a cloud folder. The folder backend also keeps the previous versions of each file (**Settings → What to sync → Versions kept (folder backend)**, default 2).

### Option B: a private GitHub repository

Best if you also want the web or phone viewer.

1. **Sign in with GitHub** (recommended). ChatRelay shows a short code; you enter it on github.com and approve. The ChatRelay GitHub App only gets access to the repositories you choose (normally just your history repository), with permission to read and write their contents. No password is stored, and no server is involved.
2. Or paste a **personal access token** (classic token with `repo` scope, or a fine-grained token with *Contents: Read and write* on that one repo). If you are logged in with the GitHub CLI (`gh auth login`), ChatRelay can use that token.
3. Pick an existing **private** repository or click **Create private repo**. Public repositories are refused, because chat history can contain private code and secrets.

On GitHub, each upload is **one commit**. Files bigger than 40 MB (compressed) are split into parts automatically, because GitHub refuses single files over 100 MB.

The token lives only in the OS keychain (service `claude-sync`).

## Setting up your second PC

On **PC 1** (the one that already has the history):

1. Install ChatRelay and choose a backend.
2. Upload: click **Upload now** in the Simple view (or **Upload everything** at the end of setup), or **Push** on a project in the Advanced view. A preview shows each conversation and any secrets found; you can choose to hide (redact) them in the uploaded copy.

On **PC 2**:

1. Install ChatRelay and choose **the same backend** (the same synced folder, or the same GitHub repo).
2. Put the project folder on PC 2 (for example with `git clone`). The path may differ, for example `D:\work\shop` instead of `C:\Users\me\shop`.
3. Click **Bring history to this PC** (Simple view), or open the **Sync** view (Advanced view). ChatRelay lists every project in the backend and where it would go on this PC:
   - **Git projects** are matched automatically by their remote URL.
   - **Other projects**: click **Import into…** / **Link** and pick the local folder once. The link is remembered.
4. Check the **dry run**: which files will be written and every path change (for example `×166  C:\Users\me\shop → D:\work\shop`). Then confirm.
5. Open the conversation in the tool: `claude --resume` or the VS Code Claude panel; `codex resume` or the Codex sidebar.

For Codex: **close Codex first** (CLI, VS Code extension and desktop app). ChatRelay never writes to Codex's files while it is running; that conversation is skipped with the reason "Codex is running", and comes in the next time.

Turn on **Auto-sync** on both PCs and you don't need to do any of this by hand again.

## Everyday use

### Simple view and Advanced view

- **Simple view** (default): your projects with a status dot, two big buttons (**Upload now** / **Bring history to this PC**), the auto-sync switch and the update check.
- **Advanced view**: a VS Code-like layout with an activity bar (Projects **Ctrl+Shift+E**, Sync **Ctrl+Shift+Y**, Summaries, Logs, Backups, Settings), tabs, a status bar and a command palette (**Ctrl+Shift+P**) with every action.

Switch between them with **Ctrl+Shift+P → Switch to Simple/Advanced View**.

### Status dots

| Dot | Meaning | What to do |
|---|---|---|
| Green | Synced | Nothing |
| Yellow / orange | Changes on this PC not uploaded yet | Push, or wait for auto-sync |
| Red | Last sync failed | Open **Logs** for the reason |
| Grey | Never synced | Push it once |
| Hollow circle | No project identity yet (not linked) | Push it (a link is created) or **Link** it to the project from the other PC |

### Conversations from several tools

Every conversation has a small badge with its tool (**Claude** or **Codex**). Projects where you used more than one tool show a **filter** (All / Claude Code / Codex). Opening a conversation shows the full transcript: your messages, the assistant's answers, tool calls (commands run, files edited) and the list of changed files.

### Push and pull

- **Push** uploads the conversations of a project that changed since the last sync. **Push all** does every project.
- **Pull** downloads what's new. It always starts with a **dry run** that lists every file it would write and every path rewrite. Nothing is written until you confirm.

### Auto-sync

When **Auto-sync** is on:

- **Claude Code**: hooks in `~/.claude/settings.json` run ChatRelay when a Claude Code session **starts** (pull) and **ends** (push).
- **Codex**: Codex has no such hook, so the desktop app checks every 15 minutes (starting 20 seconds after launch). It uploads projects whose Codex conversations changed and downloads new ones (skipped while Codex is running).
- Uploads that failed because you were offline are queued and retried.

You can turn auto-sync on or off in Settings, in the tray menu, or with `claude-sync hooks install|uninstall`.

### Tray menu

Push now · Pull now · Auto-sync on/off · Last sync status · Open · Quit.

### Backups

Every write is preceded by a backup in `~/.claude-sync/backups/<timestamp>-<what>/`. Open **Backups** (or `claude-sync backups`) to see them, and **Restore** one to put every file back exactly as it was. A restore also removes files that the change had created.

### Logs

**Logs** shows everything ChatRelay did, with errors highlighted, and a button that copies an error report.

## Codex support in detail

What travels with each Codex conversation:

| Item | Where Codex keeps it | What ChatRelay does |
|---|---|---|
| The conversation ("rollout") | `~/.codex/sessions/YYYY/MM/DD/rollout-<time>-<id>.jsonl` (some versions write `.jsonl.zst`, compressed) | Copied, every path rewritten |
| The thread's index row | `~/.codex/state_5.sqlite`, table `threads` | Added or updated so the conversation appears in `codex resume` and the sidebar |
| The thread's name | `~/.codex/session_index.jsonl` | Added |
| Codex memory for that thread | `~/.codex/memories_1.sqlite`, table `stage1_outputs` | Added if this PC has none for that thread; paths rewritten |
| Goals of that thread | `~/.codex/goals_1.sqlite`, tables `thread_goals`, `thread_goal_continuation_deferrals` | Added if this PC has none for that thread |

Details that matter:

- **Codex must be closed** while ChatRelay writes. ChatRelay checks for running `codex` processes (CLI, VS Code extension, desktop app). It does not ask you to close anything during background sync; it just tries again later.
- **History mode is kept.** Newer Codex versions store "paginated" history; Codex rebuilds its page database (`thread_history_*.sqlite`) from the conversation file the first time you open it, so ChatRelay never writes that database.
- **Your own settings for a thread stay yours.** On update, this PC's pinned state, custom name, archive state and account are kept. Folders and sections that only exist on the other PC are cleared.
- **Account.** An imported thread is assigned to the Codex account that owns most threads on this PC.
- **Windows path prefix.** Codex on Windows stores working folders as `\\?\D:\project`. ChatRelay adds that prefix only to Windows paths on a PC whose Codex uses it, and never to macOS or Linux paths.
- **Compressed conversations** (`.jsonl.zst`) can be read and updated. On update the file is replaced by a plain `.jsonl` (the compressed original is backed up first).
- **Memory bookkeeping** that belongs to the other PC (how often a memory was used, whether it was picked for consolidation) is not copied.
- **Unknown versions.** If Codex's index uses a database ChatRelay doesn't know (for example a future `state_6.sqlite`), or adds a required field it can't fill, writing is turned off for Codex with a clear warning. Reading still works.

## Summaries and "Continue in another tool"

> 🔒 **Secrets never reach the AI.** Before anything is sent to the model, ChatRelay replaces keys, tokens and passwords found in the chats (API keys for Anthropic, OpenAI, OpenRouter, GitHub, AWS, Google, Slack, Stripe, Hugging Face, npm, SendGrid, Telegram bots; JWTs; private keys; `PASSWORD=…`-style lines; passwords inside URLs) with `[REDACTED:kind]`. This always happens and can't be turned off; the screen shows how many were hidden. Your code and the rest of the conversation are still sent, so for private or client code prefer a paid model whose provider doesn't keep data.

Open **Summaries** (Advanced view), pick a project, tick the conversations (from any tool) and a model, then click **Generate handoff**.

- Models: **Claude Opus 5.5** (default), Claude Sonnet 5.5 (faster, cheaper), Claude Haiku 5.5 (cheapest), Claude Fable 5.1 (most capable). You need an Anthropic API key (**Settings → Summaries**).
- The history is condensed first: your requests, the assistant's final answer of each turn, and the files changed. Long tool output and thinking are dropped. Conversations from all tools are merged in time order and labelled with their tool.
- Long histories are summarized in ~100k-token parts and then merged.
- The result has these sections: Project overview, What's done, Key decisions, Open bugs / known issues, Next steps, Files touched.

Then you can:

- **Save HANDOFF.md** in the project folder, or
- **Continue in…** a tool: choose Claude Code (`CLAUDE.md`), Codex (`AGENTS.md`) or Gemini CLI (`GEMINI.md`). The list shows the tools installed on this PC. ChatRelay adds a short "Previous context" section (overview, what's done, next steps) to that file. Running it again replaces only its own section; the rest of the file is untouched.
- Or **copy** the text.

From the command line: `claude-sync summarize --target handoff|claude-md|agents-md|gemini-md|none`.

## Web and phone viewer

**🌐 Live web viewer:** <https://abh1shxkk.github.io/claude-sync-web/>

A read-only version of the app that opens the history in your **GitHub** backend from any browser or from the Android app: projects, conversations from every tool, and full transcripts. It uses the same Rust engine compiled to WebAssembly, so it shows exactly what the desktop app shows. Uploading, downloading, auto-sync and summaries stay in the desktop app, because they need the local history folders.

- Sign in with GitHub, or with your repo name and a **fine-grained token limited to that repo with Contents: Read-only**.
- The token is kept only in that browser (localStorage if you tick "remember", otherwise sessionStorage).
- The page only talks to `api.github.com` and loads no third-party scripts.
- The first visit reads each conversation once to count messages; results are cached by content hash.
- On phone-sized screens the layout switches to a single pane: list → project → transcript, with a back button and a bottom bar.

## Safety and privacy

- **Originals are never modified on upload.** Uploading only reads your history files.
- **Nothing is written while the tool is running** (Codex). Claude Code's open session (the one that triggered the hook) is never touched.
- **Backup before every write**, including Claude Code's `settings.json`, Codex's databases (with their `-wal` and `-shm` files) and `session_index.jsonl`.
- **Dry run for every import.** You see every file and every path rewrite before anything happens.
- **Both versions are kept on conflict**, never overwritten.
- **Secret scan.** Before uploading, ChatRelay looks for API keys and passwords: Anthropic, OpenAI, GitHub, AWS, Google, Slack and Stripe keys, JWTs, private keys, `.env`-style `SECRET=…` lines, and credentials inside URLs. You choose: **warn**, **redact** (replaced with `[REDACTED:kind]` in the uploaded copy only), or **off**.
- **Secrets stay in the OS keychain.** Your GitHub token and Anthropic key are never written to a file.
- **Your logins are never touched.** ChatRelay does not read, copy or change Claude Code's or Codex's login files (`~/.claude/.credentials.json`, `~/.codex/auth.json`, …). Syncing history cannot log you out. If you get logged out, it comes from the tool itself (for example an expired session or signing in with another account on another PC).
- **Private storage only.** Public GitHub repositories are refused.
- **No ChatRelay server.** Data only goes between your PCs, your folder or GitHub, and (only when you make a summary) the Anthropic API.

Not synced, by design: `~/.claude/history.jsonl` (your up-arrow prompt history across all projects), `~/.claude/file-history/` (rewind snapshots), and all credentials.

## How it works (technical)

### Where Claude Code keeps history

| Path | What |
|---|---|
| `~/.claude/projects/<encoded-path>/<session-uuid>.jsonl` | One file per session, one JSON object per line |
| `~/.claude/projects/<encoded-path>/<session-uuid>/subagents/*.jsonl` + `*.meta.json` | Subagent transcripts (synced as a "sidecar") |
| `~/.claude/projects/<encoded-path>/<session-uuid>/tool-results/*` | Large tool outputs saved to disk (sidecar) |
| `~/.claude/projects/<encoded-path>/memory/` | Project auto-memory (`MEMORY.md` + notes) |

Things that differ from the usual assumptions, all handled:

- **Drive-letter case differs by client.** The VS Code extension records `c:\Users\…` (folder `c--Users-…`), the CLI records `C:\Users\…` (folder `C--Users-…`), and one session can contain both. On Windows, paths are compared case-insensitively.
- **Folder names can't be decoded reliably.** `C:\Users\me\my project` and `C:\Users\me\my-project` both encode to `C--Users-me-my-project`. The real path comes from the `cwd` recorded in the sessions; decoding the name is only a labelled fallback.
- **Sessions can be huge** (200+ MB with embedded images/PDFs), so everything is streamed. Scan results are cached by size and modification time, so a rescan takes about 100 ms.
- **One assistant reply spans several lines** (one per content block, same `message.id`); message counts de-duplicate them. Titles come from the first real prompt (IDE wrapper tags stripped); Claude Code's own `ai-title` is shown next to it.
- **Many line types besides user/assistant** (`attachment`, `file-history-snapshot`, `queue-operation`, `ai-title`, `last-prompt`, `permission-mode`, …). Unknown types and fields are kept untouched.

### Where Codex keeps history

See [Codex support in detail](#codex-support-in-detail). Each line of a rollout is `{timestamp, type, payload}`; the first is `session_meta` with the session id and `cwd`. Codex has written conversations in three generations (`event_msg/item_completed` items in ≥0.15x, `user_message`/`agent_message` events earlier, plain `response_item` messages in the oldest); the viewer uses the richest one present.

### Adapters

Each AI tool is an **adapter** (`crates/core/src/providers/`) behind one interface (`ProviderAdapter`): detect the tool and its format, list projects and sessions, read a session into a tool-neutral shape (`UniversalSession`), export it losslessly (`SessionBundle`: the original files plus tool metadata such as the Codex index row), import it on another PC (rewrite paths, check the tool isn't running, back up, dry run), and append new lines. See [Adding another AI tool](#adding-another-ai-tool-adapter-guide).

### Project identity

The same project has a different path on each PC, so it is identified by, in order:

1. A **manual link** (Link button / `claude-sync link <dir> <id>`), stored in ChatRelay's config
2. The **git remote**, normalized: `git@github.com:Me/Repo.git` and `https://github.com/me/repo` both become `git:github.com/me/repo`
3. A **`.claude-sync.json`** in the project root holding a UUID, created on first push for non-git projects (commit it, or link manually on the other PC). "Upload everything" and background sync create a link in ChatRelay's config instead, so nothing is written into your project folders.

### Storage layout (in the folder or repo)

```
<projectId-slug>/
  manifest.json                          machines, original paths, hashes, timestamps, revision
  <sessionId>.jsonl.gz                   Claude Code session (whole, or its start when deltas exist)
  <sessionId>.d<N>.jsonl.gz              lines appended after that, one blob per push
  <sessionId>.sidecar.json.gz            subagents/ + tool-results/ (if any)
  memory.json.gz                         Claude Code project memory (if any)
  <provider>-<sessionId>.bundle.json.gz  another tool's session (e.g. codex-…): files + metadata
  <provider>-<sessionId>.d<N>.jsonl.gz   lines appended to it later
  .versions/<file>/<timestamp>           previous versions (folder backend)
```

Other tools' sessions are listed under `providerSessions` in the manifest (key `<provider>:<id>`). Older versions of the app ignore that list and keep it intact.

### Push

- Sessions are compared by SHA-256; only new or changed ones are uploaded. Originals are only ever read.
- **Only new lines are sent.** AI tools only ever append to a conversation file, so after a session's first upload a push stores just the lines added since the last sync as a "delta" part. Each part records the paths of the machine that pushed it. Session hashes are chained (`hash = sha256(previous : sha256(part))`). After 40 parts the next push uploads the whole session again. When the shortcut doesn't apply (the file changed some other way, a conflict, state from an older version) the whole file is uploaded.
- If the backend has a version you haven't seen that contains messages you don't have, that session's push is refused with "pull first", so nothing is lost.
- **Offline?** (GitHub unreachable, the cloud drive not mounted.) The push is queued in `~/.claude-sync/queue.json` and retried on the next run and every 15 minutes by the desktop app.

### Pull

- Paths are rewritten inside parsed JSON (string values **and** object keys), so JSON escaping is never a problem. Forms handled: Windows paths as `C:\…`, `c:/…`, Git-Bash `/c/…` and WSL `/mnt/c/…` (case-insensitive); POSIX paths (case-sensitive); `file:///` URLs including `%20`-encoded spaces; separators after the project root are converted when moving between operating systems; the tool's own home folder (`~/.claude`, `~/.codex`) and Claude Code's encoded folder name are rewritten too. Sibling folders such as `shop-old` are never touched.
- **Fast path:** a PC that has exactly what it last synced downloads only the missing parts and appends them.
- **Divergence** (conversations are append-only, compared by line ids for Claude Code and by text prefix for other tools):
  - remote contains local → update
  - local contains remote → yours is newer and is kept (uploaded on the next push)
  - both changed → **conflict**: your copy stays as it is, and the other version is saved as a **new conversation with a new id** (Codex: named "<name> (from <PC>)"). Both then appear in the tool and sync to your other PCs.

### Auto-sync hooks (Claude Code)

"Enable auto-sync" merges this into `~/.claude/settings.json`; your other settings and hooks are kept, and a backup is made first:

```jsonc
"hooks": {
  "SessionStart": [{ "hooks": [{ "type": "command", "command": "\"…/Claude Sync/claude-sync.exe\" pull --hook --quiet --claude-sync-hook", "timeout": 60 }] }],
  "SessionEnd":   [{ "hooks": [{ "type": "command", "command": "\"…/Claude Sync/claude-sync.exe\" push --hook --quiet --claude-sync-hook", "timeout": 60 }] }]
}
```

- `--hook` reads Claude Code's hook JSON from stdin (`cwd`, `session_id`), falling back to `CLAUDE_PROJECT_DIR` and then the working directory. Hooks **always exit 0**, so they can never break a session; errors go to the Logs panel.
- The hook runs the native `claude-sync` executable installed next to the app. No Node.js needed.
- "Disable auto-sync" removes only the hooks containing the `claude-sync-hook` marker.

## Updates

- The desktop app checks for a new version when it starts, every time its window is opened, every hour, when you come back to its window after 5 minutes or more, and when you click **Check for updates** (Settings → About, the Simple view, or the command palette). It shows a spinner while checking.
- When one is available you see **A new version is available → Update now**. The app downloads it, verifies its signature (apps only accept updates signed with the project's key), installs it in place and restarts. History and settings are kept.
- The Android app shows a notice with a link to the new APK.

## Troubleshooting and FAQ

**SmartScreen blocks the installer.** The installer isn't code-signed. Click **More info → Run anyway**.

**A project shows a yellow dot.** It has conversations on this PC that aren't uploaded yet. Push it, or turn on auto-sync.

**A project from my other PC doesn't appear / appears under a different name.** Projects are matched by git remote, a `.claude-sync.json`, or a link. If the folders have different names and no git remote, use **Link** (or **Import into…**) once and pick the right local folder.

**A Codex conversation was skipped: "Codex is running".** Close the Codex CLI, the VS Code extension's Codex panel (or VS Code) and the Codex desktop app, then pull again. Background sync retries by itself.

**Codex import is off: "Unknown Codex index database" / "new required fields".** Your Codex is newer than this ChatRelay version knows. Update ChatRelay. Your conversations are still visible.

**I see a conversation twice, one ending with "(from OFFICE-PC)".** It was continued on both PCs before they synced. Both versions are kept; delete the one you don't need in the tool.

**My old Claude Code conversations disappeared.** Claude Code deletes conversations older than `cleanupPeriodDays` (default 30). Raise it in Settings (or `claude-sync cleanup-days 3650`). Already-uploaded conversations can be pulled back from the backend.

**Did syncing log me out of Claude?** No. ChatRelay never reads or writes login files. See [Safety and privacy](#safety-and-privacy).

**Upload is slow the first time.** The first upload sends everything (compressed). After that only new lines are sent.

**"Pull first" when pushing.** Another PC uploaded a newer version that yours doesn't contain. Pull, then push.

**Offline.** Pushes are queued and retried automatically; `claude-sync queue` retries now.

**Something went wrong after a pull.** Open **Backups** and restore the backup made just before it.

**Where do I find errors?** The **Logs** view (copy an error report from there), or `~/.claude-sync/logs/claude-sync.log`.

## Adding another AI tool (adapter guide)

1. **Verify the storage format on a real machine first**: where sessions live, the line/record format, any index database and its schema, how the tool lists sessions, how it stores paths, which processes mean "running". Write it down at the top of the adapter file.
2. Add a `ProviderId` in `crates/core/src/providers/mod.rs` and a file `providers/<tool>.rs` implementing `ProviderAdapter`: `detect`, `list_projects`, `list_sessions`, `read_session`, `export_session`, `import_session`, optionally `append_session`, `context_file_name`, `process_names`.
3. Rules every adapter follows: refuse to write while the tool runs (`ensure_not_running`), back up every file before writing (`ImportOptions.backups`), honour `dry_run`, honour `keep_both` (save a diverged incoming session under a new id), and turn import off (with a warning in `ProviderStatus`) on any format it doesn't recognise.
4. Put pure parsing in a file without file-system access (like `codex_format.rs`) so the web viewer can use it, and add it to `messages_from_bundle`.
5. Add fixture files under `crates/core/tests/fixtures/<tool>/` and tests: detect, list, read, export → import on a second fake machine (paths rewritten), update, local-ahead, conflict, running-process refusal, unknown format.
6. Add the label in `src/shared/types.ts` (`PROVIDER_LABELS`). Badges, filters, push/pull, summaries and the viewer pick it up from there.

## Publishing a release

Installed apps check `latest.json` on [Abh1shxkk/claude-sync-releases](https://github.com/Abh1shxkk/claude-sync-releases).

1. Bump `version` in `package.json`, `src-tauri/tauri.conf.json`, `mobile/tauri.conf.json` and `Cargo.toml`.
2. `npm run release -- --notes "What changed"`

That builds the Windows installer signed with the updater key (`TAURI_SIGNING_PRIVATE_KEY`, or `D:\dev\tauri-keys\claude-sync-updater.key` with its `.password` file) and the signed APK, writes `latest.json` and uploads everything as release `v<version>`. Flags: `--no-apk`, `--skip-build`, `--dry-run`, `--notes-file <file>`. The GitHub login comes from `git credential fill` (or `GITHUB_TOKEN`).

Keep the updater key backed up. Apps only accept updates signed with it; its public half is in `src-tauri/tauri.conf.json`.

## Known limitations

- The Windows installer is not code-signed (SmartScreen warning).
- Only Windows is tested. macOS and Linux build but have no published installers.
- A conversation open on two PCs at the same time can't be merged live; it becomes a conflict copy.
- Codex has no "session ended" hook, so Codex sync runs every 15 minutes rather than instantly.
- For paths longer than 200 characters Claude Code's exact folder-name hash isn't documented; ChatRelay prefers an existing folder whose sessions record the same `cwd`, and otherwise uses its own `-<hash>` suffix.
- The web and phone viewers are read-only and need the GitHub backend.

## About the rename

ChatRelay was called **Claude Sync** until v0.5.0. To keep existing installs updating and nothing lost, these internal names did **not** change:

| Kept | Why |
|---|---|
| Install folder and Start-menu entry "Claude Sync" | Windows identifies the installed app by it; changing it would install a second copy instead of updating |
| App identifier `com.claudesync.app` / `com.claudesync.mobile` | Updates and Android installs depend on it |
| `~/.claude-sync/` data folder, `CLAUDE_SYNC_HOME` | Your settings, sync state and backups |
| `claude-sync` CLI | Claude Code hooks call it by path |
| `.claude-sync.json` project files, `claude-sync-hook` marker | Existing projects and hooks keep working |
| Releases repo `claude-sync-releases` | Installed apps download updates from it |
| GitHub App "claude-sync-abh1shxkk" | Existing sign-ins keep working |
