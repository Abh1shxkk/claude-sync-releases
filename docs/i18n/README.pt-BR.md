**Leve suas conversas de programação com IA para qualquer PC, e de uma ferramenta de IA para outra.**

O ChatRelay sincroniza o histórico de conversas dos assistentes de programação com IA (hoje, **Claude Code** e **OpenAI Codex**) entre os seus computadores. Comece uma conversa no PC do escritório e depois abra a mesma conversa no notebook de casa: as mesmas mensagens, as mesmas chamadas de ferramentas, com cada caminho de arquivo trocado pelos caminhos da nova máquina. Ele também escreve um resumo curto do histórico de um projeto no arquivo de instruções que outra ferramenta lê (`CLAUDE.md`, `AGENTS.md`, `GEMINI.md`), para que você possa continuar o trabalho em outra ferramenta de IA.

## O que ele faz

- **Leva o histórico de conversas entre PCs.** Cada conversa do Claude Code (CLI no terminal e extensão do VS Code) e do Codex (CLI, extensão do VS Code e app de desktop) é copiada para um local de armazenamento que pertence a você e, de lá, para os seus outros PCs. No outro PC ela aparece na própria lista de histórico da ferramenta: `claude --resume`, o painel do Claude Code no VS Code, `codex resume` ou a barra lateral do Codex.
- **Corrige os caminhos de arquivo.** Seu projeto pode estar em `C:\Users\me\shop` em um PC e em `D:\work\shop` em outro, ou em `/home/me/shop` no Linux. O ChatRelay reescreve cada caminho dentro da conversa (pasta de trabalho, entradas e saídas das ferramentas, links para arquivos, texto das mensagens) para o caminho do PC que recebe.
- **Envia só o que mudou.** Depois do primeiro envio, só as linhas novas de uma conversa viajam: alguns KB em vez do arquivo inteiro.
- **Nunca perde trabalho.** Ele nunca altera seus originais ao enviar. Faz backup de cada arquivo antes de alterá-lo, mostra antes uma prévia (simulação, "dry run") e nunca sobrescreve uma conversa que mudou nos dois PCs: ele guarda as duas.
- **Funciona sozinho.** Com a sincronização automática ligada, as conversas do Claude Code são enviadas quando uma sessão termina e baixadas quando uma sessão começa. As conversas do Codex são enviadas e baixadas a cada 15 minutos, em segundo plano.
- **Faz resumos.** Ele transforma todo o histórico de um projeto (de todas as ferramentas) em um `HANDOFF.md`: o que já foi feito, decisões, bugs em aberto, próximos passos, arquivos alterados. Também pode colocar uma versão curta em `CLAUDE.md`, `AGENTS.md` ou `GEMINI.md`, para que a próxima ferramenta já comece com o contexto.
- **Leia em qualquer lugar.** Uma página web somente leitura e um app Android mostram todas as suas conversas guardadas no GitHub, em qualquer dispositivo.
- **Parece o VS Code.** App de desktop em preto e branco, no estilo do VS Code, com temas escuro e claro, uma visão simples para o dia a dia e uma visão avançada com todos os detalhes.

## Ferramentas de IA suportadas

| Ferramenta | Onde roda | Ver conversas | Sincronizar entre PCs | Restaurar na ferramenta | Arquivo de contexto |
|---|---|---|---|---|---|
| **Claude Code** | CLI no terminal, extensão do VS Code | ✅ | ✅ (com hooks de sincronização automática) | ✅ `claude --resume`, histórico do VS Code | `CLAUDE.md` |
| **OpenAI Codex** | Codex CLI, extensão do VS Code, app de desktop do Codex | ✅ | ✅ (em segundo plano, a cada 15 min) | ✅ `codex resume`, barra lateral do Codex | `AGENTS.md` |
| Gemini CLI | Terminal | planejado | planejado | planejado | `GEMINI.md` (já disponível como destino de resumo) |
| Kiro (IDE e CLI), Cursor, Antigravity | | planejado | planejado | planejado | |

Cada ferramenta guarda seu histórico em um formato próprio, sem documentação, e esses formatos mudam de uma versão para outra. Por isso o ChatRelay verifica o formato que encontra no seu PC. Se ele vê uma versão que não conhece, continua mostrando as conversas, mas **desliga a gravação** para aquela ferramenta e explica o motivo em **Settings → AI tools** (Configurações → Ferramentas de IA). Ele nunca tenta adivinhar.

Versões verificadas: Claude Code 2.1.x; Codex 0.144 a 0.160 (banco de dados de índice `state_5.sqlite`, migração de esquema 58).

## Download e instalação

### Windows

1. Baixe `ChatRelay_<version>_x64-setup.exe` da [versão mais recente](https://github.com/Abh1shxkk/claude-sync-releases/releases/latest). (As versões até a v0.5.0 se chamam `ClaudeSync_…`.)
2. Execute o arquivo. O instalador não tem assinatura de código, então o Windows SmartScreen pode dizer "O Windows protegeu o computador": clique em **More info → Run anyway** (Mais informações → Executar assim mesmo).
3. Você só instala uma vez. As versões seguintes chegam sozinhas (veja [Atualizações](#atualizações)).

O app é instalado por usuário em `%LOCALAPPDATA%\Claude Sync\` (a pasta mantém o nome antigo; veja [Sobre a mudança de nome](#sobre-a-mudança-de-nome)). Ele inicia na bandeja do sistema. Fechar a janela o mantém rodando lá; use **Quit** (Sair) no menu da bandeja para encerrá-lo.

### Android (visualizador)

Baixe `ChatRelay_<version>.apk` da mesma página de versões e abra no seu celular (permita "instalar apps desconhecidos" para o navegador ou gerenciador de arquivos quando for pedido). O app Android é um **visualizador somente leitura** do seu armazenamento no GitHub; o celular não tem histórico próprio de ferramentas de IA.

### macOS e Linux

O motor em Rust e o app compilam no macOS e no Linux (veja [Compilando a partir do código-fonte](#compilando-a-partir-do-código-fonte-e-desenvolvimento)), mas ainda não há instaladores publicados para eles e eles ainda não foram testados.

### Web

O visualizador web é uma página estática que você mesmo pode hospedar (GitHub Pages, Cloudflare Pages, Netlify…) ou rodar localmente. Veja [Visualizador web e no celular](#visualizador-web-e-no-celular).

## Configuração inicial

Quando o ChatRelay abre pela primeira vez, um assistente de configuração conduz você por estes passos. Você pode rodá-lo de novo quando quiser pela paleta de comandos (**Ctrl+Shift+P → Run First-time Setup Again**, ou seja, rodar a configuração inicial de novo).

1. **Seu histórico.** O ChatRelay encontra o histórico do Claude Code em `%USERPROFILE%\.claude\projects` (ou na pasta indicada em `CLAUDE_CONFIG_DIR`) e o do Codex em `%USERPROFILE%\.codex` (ou `CODEX_HOME`). Ele mostra quantas conversas encontrou para cada ferramenta.
2. **A exclusão de 30 dias do Claude Code.** Por padrão, o Claude Code apaga conversas com mais de 30 dias (`cleanupPeriodDays`). O ChatRelay mostra isso e oferece aumentar esse prazo. Ele faz backup do `settings.json` antes de alterá-lo.
3. **Nome da máquina.** Por exemplo `OFFICE-PC` ou `HOME-LAPTOP`. Ele aparece ao lado de cada conversa, para você saber de qual PC ela veio.
4. **Armazenamento (backend).** Uma pasta (Google Drive, OneDrive, Dropbox, unidade de rede) ou um repositório privado no GitHub. Veja a próxima seção.
5. **Chave de API da Anthropic (opcional).** Só é necessária para os resumos. Ela fica guardada no Gerenciador de Credenciais do Windows (o chaveiro do sistema), nunca em um arquivo.
6. **Sincronização automática.** Liga o envio/download automático (hooks do Claude Code mais o temporizador em segundo plano).
7. **Enviar tudo.** Se você quiser, envia na hora todo o seu histórico existente, com uma barra de progresso.

## Escolhendo onde seu histórico fica guardado (backend)

Seu histórico vai para um lugar que **você** controla. O ChatRelay não tem servidor próprio.

### Opção A: uma pasta

Qualquer pasta que seus outros PCs também consigam ver:

- Google Drive para desktop, por exemplo `G:\My Drive\chatrelay`
- OneDrive, por exemplo `%OneDrive%\chatrelay`
- Dropbox, um NAS ou compartilhamento de rede, ou um pen drive que você leva com você

Só vão para lá cópias compactadas. Suas pastas em uso `~/.claude` e `~/.codex` nunca são movidas para uma pasta na nuvem. O backend de pasta também guarda as versões anteriores de cada arquivo (**Settings → What to sync → Versions kept (folder backend)**, ou seja, Configurações → O que sincronizar → Versões guardadas (backend de pasta); o padrão é 2).

### Opção B: um repositório privado no GitHub

A melhor opção se você também quiser o visualizador web ou no celular.

1. **Sign in with GitHub** (Entrar com o GitHub) (recomendado). O ChatRelay mostra um código curto; você digita esse código no github.com e aprova. O GitHub App do ChatRelay só recebe acesso aos repositórios que você escolher (normalmente só o repositório do seu histórico), com permissão para ler e gravar o conteúdo deles. Nenhuma senha é guardada e nenhum servidor participa.
2. Ou cole um **personal access token** (token de acesso pessoal): um token clássico com escopo `repo`, ou um token granular (fine-grained) com *Contents: Read and write* (Conteúdo: leitura e gravação) só nesse repositório. Se você estiver conectado com o GitHub CLI (`gh auth login`), o ChatRelay pode usar esse token.
3. Escolha um repositório **privado** existente ou clique em **Create private repo** (Criar repositório privado). Repositórios públicos são recusados, porque o histórico de conversas pode conter código privado e segredos.

No GitHub, cada envio é **um commit**. Arquivos maiores que 40 MB (compactados) são divididos em partes automaticamente, porque o GitHub recusa arquivos individuais acima de 100 MB.

O token fica guardado só no chaveiro do sistema (serviço `claude-sync`).

## Configurando seu segundo PC

No **PC 1** (aquele que já tem o histórico):

1. Instale o ChatRelay e escolha um backend.
2. Envie: clique em **Upload now** (Enviar agora) na visão Simples (ou em **Upload everything** (Enviar tudo) no fim da configuração), ou em **Push** (Enviar) em um projeto na visão Avançada. Uma prévia mostra cada conversa e qualquer segredo encontrado; você pode escolher esconder (redigir) esses segredos na cópia enviada.

No **PC 2**:

1. Instale o ChatRelay e escolha **o mesmo backend** (a mesma pasta sincronizada ou o mesmo repositório no GitHub).
2. Coloque a pasta do projeto no PC 2 (por exemplo com `git clone`). O caminho pode ser diferente, por exemplo `D:\work\shop` em vez de `C:\Users\me\shop`.
3. Clique em **Bring history to this PC** (Trazer o histórico para este PC) na visão Simples, ou abra a visão **Sync** (Sincronizar) na visão Avançada. O ChatRelay lista cada projeto que está no backend e para onde ele iria neste PC:
   - **Projetos git** são associados automaticamente pela URL do repositório remoto.
   - **Outros projetos**: clique em **Import into…** (Importar para…) / **Link** (Vincular) e escolha a pasta local uma vez. O vínculo fica guardado.
4. Confira a **simulação (dry run)**: quais arquivos serão gravados e cada troca de caminho (por exemplo `×166  C:\Users\me\shop → D:\work\shop`). Depois confirme.
5. Abra a conversa na ferramenta: `claude --resume` ou o painel do Claude no VS Code; `codex resume` ou a barra lateral do Codex.

Para o Codex: **feche o Codex antes** (CLI, extensão do VS Code e app de desktop). O ChatRelay nunca grava nos arquivos do Codex enquanto ele está rodando; aquela conversa é pulada com o motivo "Codex is running" (o Codex está rodando) e entra na próxima vez.

Ligue o **Auto-sync** (sincronização automática) nos dois PCs e você não vai precisar fazer nada disso à mão de novo.

## Uso no dia a dia

### Visão Simples e visão Avançada

- **Simple view** (visão Simples, o padrão): seus projetos com uma bolinha de status, dois botões grandes (**Upload now** / **Bring history to this PC**), o botão de sincronização automática e a verificação de atualizações.
- **Advanced view** (visão Avançada): um layout parecido com o VS Code, com uma barra de atividades (Projects **Ctrl+Shift+E**, Sync **Ctrl+Shift+Y**, Summaries, Logs, Backups, Settings — ou seja, Projetos, Sincronizar, Resumos, Registros, Backups, Configurações), abas, uma barra de status e uma paleta de comandos (**Ctrl+Shift+P**) com todas as ações.

Alterne entre elas com **Ctrl+Shift+P → Switch to Simple/Advanced View** (mudar para a visão Simples/Avançada).

### Bolinhas de status

| Bolinha | Significado | O que fazer |
|---|---|---|
| Verde | Sincronizado | Nada |
| Amarela / laranja | Há mudanças neste PC que ainda não foram enviadas | Envie (Push) ou espere a sincronização automática |
| Vermelha | A última sincronização falhou | Abra **Logs** (Registros) para ver o motivo |
| Cinza | Nunca sincronizado | Envie (Push) uma vez |
| Círculo vazado | Ainda sem identidade de projeto (não vinculado) | Envie (Push) (um vínculo é criado) ou use **Link** para vinculá-lo ao projeto do outro PC |

### Conversas de várias ferramentas

Cada conversa tem uma pequena etiqueta com a sua ferramenta (**Claude** ou **Codex**). Projetos em que você usou mais de uma ferramenta mostram um **filtro** (All / Claude Code / Codex, ou seja, Todas / Claude Code / Codex). Abrir uma conversa mostra a transcrição completa: suas mensagens, as respostas do assistente, as chamadas de ferramentas (comandos executados, arquivos editados) e a lista de arquivos alterados.

### Push e pull (enviar e baixar)

- **Push** envia as conversas de um projeto que mudaram desde a última sincronização. **Push all** (Enviar tudo) faz isso para todos os projetos.
- **Pull** baixa o que há de novo. Ele sempre começa com uma **simulação (dry run)** que lista cada arquivo que seria gravado e cada caminho que seria reescrito. Nada é gravado até você confirmar.

### Sincronização automática

Quando o **Auto-sync** está ligado:

- **Claude Code**: hooks em `~/.claude/settings.json` executam o ChatRelay quando uma sessão do Claude Code **começa** (pull) e **termina** (push).
- **Codex**: o Codex não tem esse tipo de hook, então o app de desktop verifica a cada 15 minutos (começando 20 segundos depois de abrir). Ele envia os projetos cujas conversas do Codex mudaram e baixa as novas (isso é pulado enquanto o Codex está rodando).
- Envios que falharam porque você estava sem internet ficam em uma fila e são tentados de novo.

Você pode ligar ou desligar a sincronização automática nas Configurações, no menu da bandeja ou com `claude-sync hooks install|uninstall`.

### Menu da bandeja

Push now · Pull now · Auto-sync on/off · Last sync status · Open · Quit (Enviar agora · Baixar agora · Sincronização automática ligada/desligada · Status da última sincronização · Abrir · Sair).

### Backups

Toda gravação é precedida por um backup em `~/.claude-sync/backups/<timestamp>-<what>/`. Abra **Backups** (ou `claude-sync backups`) para vê-los e use **Restore** (Restaurar) em um deles para colocar cada arquivo de volta exatamente como estava. Uma restauração também remove arquivos que a mudança tinha criado.

### Registros (Logs)

**Logs** mostra tudo o que o ChatRelay fez, com os erros destacados, e um botão que copia um relatório de erro.

## Suporte ao Codex em detalhes

O que viaja junto com cada conversa do Codex:

| Item | Onde o Codex guarda | O que o ChatRelay faz |
|---|---|---|
| A conversa ("rollout") | `~/.codex/sessions/YYYY/MM/DD/rollout-<time>-<id>.jsonl` (algumas versões gravam `.jsonl.zst`, compactado) | Copiada, com cada caminho reescrito |
| A linha de índice da conversa (thread) | `~/.codex/state_5.sqlite`, tabela `threads` | Adicionada ou atualizada para que a conversa apareça em `codex resume` e na barra lateral |
| O nome da conversa | `~/.codex/session_index.jsonl` | Adicionado |
| A memória do Codex para aquela conversa | `~/.codex/memories_1.sqlite`, tabela `stage1_outputs` | Adicionada se este PC não tiver nenhuma para aquela conversa; caminhos reescritos |
| Os objetivos (goals) daquela conversa | `~/.codex/goals_1.sqlite`, tabelas `thread_goals`, `thread_goal_continuation_deferrals` | Adicionados se este PC não tiver nenhum para aquela conversa |

Detalhes que importam:

- **O Codex precisa estar fechado** enquanto o ChatRelay grava. O ChatRelay verifica se há processos `codex` rodando (CLI, extensão do VS Code, app de desktop). Ele não pede para você fechar nada durante a sincronização em segundo plano; apenas tenta de novo mais tarde.
- **O modo de histórico é mantido.** Versões mais novas do Codex guardam o histórico "paginado"; o Codex reconstrói seu banco de dados de páginas (`thread_history_*.sqlite`) a partir do arquivo da conversa na primeira vez que você a abre, então o ChatRelay nunca grava nesse banco de dados.
- **Suas próprias configurações de uma conversa continuam suas.** Ao atualizar, ficam mantidos o estado de fixada, o nome personalizado, o estado de arquivada e a conta deste PC. Pastas e seções que só existem no outro PC são limpas.
- **Conta.** Uma conversa importada é atribuída à conta do Codex que é dona da maioria das conversas neste PC.
- **Prefixo de caminho do Windows.** O Codex no Windows guarda as pastas de trabalho como `\\?\D:\project`. O ChatRelay adiciona esse prefixo só a caminhos do Windows, em um PC cujo Codex o utiliza, e nunca a caminhos do macOS ou do Linux.
- **Conversas compactadas** (`.jsonl.zst`) podem ser lidas e atualizadas. Ao atualizar, o arquivo é substituído por um `.jsonl` comum (antes é feito backup do original compactado).
- **Os controles internos da memória** que pertencem ao outro PC (quantas vezes uma memória foi usada, se ela foi escolhida para consolidação) não são copiados.
- **Versões desconhecidas.** Se o índice do Codex usa um banco de dados que o ChatRelay não conhece (por exemplo, um futuro `state_6.sqlite`), ou adiciona um campo obrigatório que ele não consegue preencher, a gravação é desligada para o Codex com um aviso claro. A leitura continua funcionando.

## Resumos e "Continuar em outra ferramenta"

> 🔒 **Segredos nunca chegam à IA.** Antes de enviar qualquer coisa ao modelo, o ChatRelay substitui chaves, tokens e senhas encontrados nos chats (chaves de API da Anthropic, OpenAI, OpenRouter, GitHub, AWS, Google, Slack, Stripe, Hugging Face, npm, SendGrid, bots do Telegram; JWTs; chaves privadas; linhas no estilo `PASSWORD=…`; senhas dentro de URLs) por `[REDACTED:kind]`. Isso sempre acontece e não pode ser desligado; a tela mostra quantos foram ocultados. Seu código e o resto da conversa ainda são enviados, então para código privado ou de clientes prefira um modelo pago cujo provedor não guarde dados.

Abra **Summaries** (Resumos) na visão Avançada, escolha um projeto, marque as conversas (de qualquer ferramenta) e um modelo e clique em **Generate handoff** (Gerar passagem de trabalho).

- Modelos: **Claude Opus 5.5** (padrão), Claude Sonnet 5.5 (mais rápido, mais barato), Claude Haiku 5.5 (o mais barato), Claude Fable 5.1 (o mais capaz). Você precisa de uma chave de API da Anthropic (**Settings → Summaries**, ou seja, Configurações → Resumos).
- Primeiro o histórico é condensado: seus pedidos, a resposta final do assistente em cada rodada e os arquivos alterados. Saídas longas de ferramentas e o raciocínio interno são descartados. As conversas de todas as ferramentas são juntadas em ordem cronológica e identificadas com a sua ferramenta.
- Históricos longos são resumidos em partes de cerca de 100 mil tokens, que depois são juntadas.
- O resultado tem estas seções: Visão geral do projeto, O que já foi feito, Decisões principais, Bugs em aberto / problemas conhecidos, Próximos passos, Arquivos alterados.

Depois você pode:

- **Save HANDOFF.md** (Salvar HANDOFF.md) na pasta do projeto, ou
- **Continue in…** (Continuar em…) uma ferramenta: escolha Claude Code (`CLAUDE.md`), Codex (`AGENTS.md`) ou Gemini CLI (`GEMINI.md`). A lista mostra as ferramentas instaladas neste PC. O ChatRelay adiciona a esse arquivo uma seção curta "Previous context" (contexto anterior) com visão geral, o que já foi feito e próximos passos. Rodar de novo substitui só a sua própria seção; o resto do arquivo não é tocado.
- Ou **copiar** o texto.

Pela linha de comando: `claude-sync summarize --target handoff|claude-md|agents-md|gemini-md|none`.

## Segurança e privacidade

- **Os originais nunca são alterados no envio.** Enviar apenas lê seus arquivos de histórico.
- **Nada é gravado enquanto a ferramenta está rodando** (Codex). A sessão aberta do Claude Code (aquela que disparou o hook) nunca é tocada.
- **Backup antes de cada gravação**, incluindo o `settings.json` do Claude Code, os bancos de dados do Codex (com seus arquivos `-wal` e `-shm`) e o `session_index.jsonl`.
- **Simulação (dry run) em cada importação.** Você vê cada arquivo e cada caminho reescrito antes de qualquer coisa acontecer.
- **As duas versões são mantidas em caso de conflito**, nunca sobrescritas.
- **Busca de segredos.** Antes de enviar, o ChatRelay procura chaves de API e senhas: chaves da Anthropic, OpenAI, GitHub, AWS, Google, Slack e Stripe, JWTs, chaves privadas, linhas no estilo `.env` como `SECRET=…` e credenciais dentro de URLs. Você escolhe: **warn** (avisar), **redact** (redigir: substituído por `[REDACTED:kind]` apenas na cópia enviada) ou **off** (desligado).
- **Os segredos ficam no chaveiro do sistema.** Seu token do GitHub e sua chave da Anthropic nunca são gravados em um arquivo.
- **Seus logins nunca são tocados.** O ChatRelay não lê, não copia e não altera os arquivos de login do Claude Code ou do Codex (`~/.claude/.credentials.json`, `~/.codex/auth.json`, …). Sincronizar o histórico não tem como desconectar você. Se você for desconectado, isso vem da própria ferramenta (por exemplo, uma sessão expirada ou um login com outra conta em outro PC).
- **Só armazenamento privado.** Repositórios públicos no GitHub são recusados.
- **Nenhum servidor do ChatRelay.** Os dados só circulam entre os seus PCs, a sua pasta ou o GitHub e (só quando você gera um resumo) a API da Anthropic.

Não são sincronizados, de propósito: `~/.claude/history.jsonl` (seu histórico de prompts da seta para cima, de todos os projetos), `~/.claude/file-history/` (instantâneos para voltar atrás, "rewind") e todas as credenciais.

## Como funciona (técnico)

### Onde o Claude Code guarda o histórico

| Caminho | O que é |
|---|---|
| `~/.claude/projects/<encoded-path>/<session-uuid>.jsonl` | Um arquivo por sessão, um objeto JSON por linha |
| `~/.claude/projects/<encoded-path>/<session-uuid>/subagents/*.jsonl` + `*.meta.json` | Transcrições de subagentes (sincronizadas como "sidecar", um arquivo complementar) |
| `~/.claude/projects/<encoded-path>/<session-uuid>/tool-results/*` | Saídas grandes de ferramentas salvas em disco (sidecar) |
| `~/.claude/projects/<encoded-path>/memory/` | Memória automática do projeto (`MEMORY.md` + anotações) |

Coisas que são diferentes do que normalmente se imagina, todas tratadas:

- **A letra da unidade muda de maiúscula para minúscula conforme o cliente.** A extensão do VS Code registra `c:\Users\…` (pasta `c--Users-…`), a CLI registra `C:\Users\…` (pasta `C--Users-…`), e uma mesma sessão pode conter as duas formas. No Windows, os caminhos são comparados sem diferenciar maiúsculas de minúsculas.
- **Os nomes das pastas não podem ser decodificados com segurança.** `C:\Users\me\my project` e `C:\Users\me\my-project` viram, os dois, `C--Users-me-my-project`. O caminho real vem do `cwd` registrado nas sessões; decodificar o nome é só uma alternativa de reserva, sinalizada como tal.
- **As sessões podem ser enormes** (mais de 200 MB com imagens/PDFs embutidos), então tudo é lido em fluxo contínuo (streaming). Os resultados da varredura ficam em cache por tamanho e data de modificação, então uma nova varredura leva cerca de 100 ms.
- **Uma resposta do assistente ocupa várias linhas** (uma por bloco de conteúdo, com o mesmo `message.id`); a contagem de mensagens elimina essas duplicatas. Os títulos vêm do primeiro prompt de verdade (sem as tags de invólucro da IDE); o `ai-title` do próprio Claude Code é mostrado ao lado.
- **Muitos tipos de linha além de user/assistant** (`attachment`, `file-history-snapshot`, `queue-operation`, `ai-title`, `last-prompt`, `permission-mode`, …). Tipos e campos desconhecidos são mantidos intactos.

### Onde o Codex guarda o histórico

Veja [Suporte ao Codex em detalhes](#suporte-ao-codex-em-detalhes). Cada linha de um rollout é `{timestamp, type, payload}`; a primeira é `session_meta`, com o id da sessão e o `cwd`. O Codex já gravou conversas em três gerações de formato (itens `event_msg/item_completed` nas versões ≥0.15x, eventos `user_message`/`agent_message` antes disso, e mensagens `response_item` simples nas mais antigas); o visualizador usa a mais completa que estiver presente.

### Adaptadores

Cada ferramenta de IA é um **adaptador** (`crates/core/src/providers/`) por trás de uma única interface (`ProviderAdapter`): detectar a ferramenta e seu formato, listar projetos e sessões, ler uma sessão em um formato neutro, independente de ferramenta (`UniversalSession`), exportá-la sem perdas (`SessionBundle`: os arquivos originais mais os metadados da ferramenta, como a linha de índice do Codex), importá-la em outro PC (reescrever caminhos, verificar que a ferramenta não está rodando, fazer backup, simulação) e acrescentar linhas novas. Veja [Adicionando outra ferramenta de IA](#adicionando-outra-ferramenta-de-ia-guia-de-adaptadores).

### Identidade do projeto

O mesmo projeto tem um caminho diferente em cada PC, então ele é identificado, nesta ordem, por:

1. Um **vínculo manual** (botão Link / `claude-sync link <dir> <id>`), guardado na configuração do ChatRelay
2. O **repositório remoto do git**, normalizado: `git@github.com:Me/Repo.git` e `https://github.com/me/repo` viram, os dois, `git:github.com/me/repo`
3. Um **`.claude-sync.json`** na raiz do projeto contendo um UUID, criado no primeiro push para projetos que não usam git (faça commit dele, ou vincule manualmente no outro PC). "Upload everything" (Enviar tudo) e a sincronização em segundo plano criam, em vez disso, um vínculo na configuração do ChatRelay, para que nada seja gravado nas pastas dos seus projetos.

### Organização do armazenamento (na pasta ou no repositório)

```
<projectId-slug>/
  manifest.json                          machines, original paths, hashes, timestamps, revision
  <sessionId>.jsonl.gz                   Claude Code session (whole, or its start when deltas exist)
  <sessionId>.d<N>.jsonl.gz              lines appended after that, one blob per push
  <sessionId>.sidecar.json.gz            subagents/ + tool-results/ (if any)
  memory.json.gz                         Claude Code project memory (if any)
  <provider>-<sessionId>.bundle.json.gz  another tool's session (e.g. codex-…): files + metadata
  <provider>-<sessionId>.d<N>.jsonl.gz   lines appended to it later
  .versions/<file>/<timestamp>           previous versions (folder backend)
```

As sessões de outras ferramentas são listadas em `providerSessions` no manifesto (chave `<provider>:<id>`). Versões mais antigas do app ignoram essa lista e a mantêm intacta.

### Push (envio)

- As sessões são comparadas por SHA-256; só as novas ou alteradas são enviadas. Os originais só são lidos, nunca alterados.
- **Só as linhas novas são enviadas.** As ferramentas de IA só acrescentam conteúdo ao fim de um arquivo de conversa, então, depois do primeiro envio de uma sessão, um push guarda apenas as linhas adicionadas desde a última sincronização, como uma parte "delta". Cada parte registra os caminhos da máquina que a enviou. Os hashes das sessões são encadeados (`hash = sha256(previous : sha256(part))`). Depois de 40 partes, o próximo push envia a sessão inteira de novo. Quando esse atalho não se aplica (o arquivo mudou de outra forma, há um conflito, o estado veio de uma versão mais antiga), o arquivo inteiro é enviado.
- Se o backend tem uma versão que você ainda não viu e que contém mensagens que você não tem, o push daquela sessão é recusado com "pull first" (faça pull antes), para que nada se perca.
- **Sem internet?** (GitHub inacessível, unidade de nuvem não montada.) O push vai para a fila em `~/.claude-sync/queue.json` e é tentado de novo na próxima execução e a cada 15 minutos pelo app de desktop.

### Pull (download)

- Os caminhos são reescritos dentro do JSON já interpretado (valores de texto **e** chaves de objeto), então o escape de caracteres do JSON nunca é um problema. Formas tratadas: caminhos do Windows como `C:\…`, `c:/…`, `/c/…` do Git-Bash e `/mnt/c/…` do WSL (sem diferenciar maiúsculas de minúsculas); caminhos POSIX (diferenciando maiúsculas de minúsculas); URLs `file:///`, incluindo espaços codificados como `%20`; os separadores depois da raiz do projeto são convertidos ao passar de um sistema operacional para outro; a própria pasta pessoal da ferramenta (`~/.claude`, `~/.codex`) e o nome de pasta codificado do Claude Code também são reescritos. Pastas vizinhas como `shop-old` nunca são tocadas.
- **Caminho rápido:** um PC que tem exatamente o que sincronizou da última vez baixa só as partes que faltam e as acrescenta ao fim.
- **Divergência** (as conversas só crescem no fim; são comparadas pelos ids das linhas no Claude Code e pelo início do texto nas outras ferramentas):
  - o remoto contém o local → atualizar
  - o local contém o remoto → a sua versão é mais nova e é mantida (enviada no próximo push)
  - os dois mudaram → **conflito**: a sua cópia fica como está, e a outra versão é salva como uma **nova conversa com um novo id** (Codex: com o nome "<name> (from <PC>)"). As duas passam a aparecer na ferramenta e são sincronizadas com os seus outros PCs.

### Hooks de sincronização automática (Claude Code)

"Enable auto-sync" (Ativar sincronização automática) junta isto ao `~/.claude/settings.json`; suas outras configurações e hooks são mantidos, e um backup é feito antes:

```jsonc
"hooks": {
  "SessionStart": [{ "hooks": [{ "type": "command", "command": "\"…/Claude Sync/claude-sync.exe\" pull --hook --quiet --claude-sync-hook", "timeout": 60 }] }],
  "SessionEnd":   [{ "hooks": [{ "type": "command", "command": "\"…/Claude Sync/claude-sync.exe\" push --hook --quiet --claude-sync-hook", "timeout": 60 }] }]
}
```

- `--hook` lê o JSON de hook do Claude Code pela entrada padrão (stdin) (`cwd`, `session_id`); se não houver, usa `CLAUDE_PROJECT_DIR` e, por último, a pasta de trabalho atual. Os hooks **sempre terminam com código 0**, então nunca conseguem quebrar uma sessão; os erros vão para o painel Logs.
- O hook executa o programa nativo `claude-sync` instalado ao lado do app. Não é preciso Node.js.
- "Disable auto-sync" (Desativar sincronização automática) remove apenas os hooks que contêm o marcador `claude-sync-hook`.

## Atualizações

- O app de desktop verifica se há uma versão nova quando inicia, toda vez que a janela é aberta, a cada hora, quando você volta para a janela depois de 5 minutos ou mais e quando você clica em **Check for updates** (Verificar atualizações) (em Settings → About, na visão Simples ou na paleta de comandos). Ele mostra um indicador girando enquanto verifica.
- Quando há uma disponível, você vê **A new version is available → Update now** (Uma nova versão está disponível → Atualizar agora). O app baixa a versão, verifica a assinatura dela (os apps só aceitam atualizações assinadas com a chave do projeto), instala no mesmo lugar e reinicia. O histórico e as configurações são mantidos.
- O app Android mostra um aviso com um link para o novo APK.

## Solução de problemas e perguntas frequentes

**O SmartScreen bloqueia o instalador.** O instalador não tem assinatura de código. Clique em **More info → Run anyway** (Mais informações → Executar assim mesmo).

**Um projeto mostra uma bolinha amarela.** Ele tem conversas neste PC que ainda não foram enviadas. Faça o push, ou ligue a sincronização automática.

**Um projeto do meu outro PC não aparece / aparece com outro nome.** Os projetos são associados pelo repositório remoto do git, por um `.claude-sync.json` ou por um vínculo. Se as pastas têm nomes diferentes e não há repositório remoto do git, use **Link** (ou **Import into…**) uma vez e escolha a pasta local certa.

**Uma conversa do Codex foi pulada: "Codex is running".** Feche o Codex CLI, o painel do Codex na extensão do VS Code (ou o próprio VS Code) e o app de desktop do Codex, e depois faça o pull de novo. A sincronização em segundo plano tenta de novo sozinha.

**A importação do Codex está desligada: "Unknown Codex index database" / "new required fields".** (Banco de dados de índice do Codex desconhecido / novos campos obrigatórios.) Seu Codex é mais novo do que esta versão do ChatRelay conhece. Atualize o ChatRelay. Suas conversas continuam visíveis.

**Estou vendo uma conversa duas vezes, uma terminando com "(from OFFICE-PC)".** Ela foi continuada nos dois PCs antes de eles sincronizarem. As duas versões são mantidas; apague na ferramenta aquela de que você não precisa.

**Minhas conversas antigas do Claude Code sumiram.** O Claude Code apaga conversas mais antigas que `cleanupPeriodDays` (padrão 30). Aumente esse valor nas Configurações (ou com `claude-sync cleanup-days 3650`). Conversas que já foram enviadas podem ser trazidas de volta do backend com pull.

**A sincronização me desconectou do Claude?** Não. O ChatRelay nunca lê nem grava arquivos de login. Veja [Segurança e privacidade](#segurança-e-privacidade).

**O envio é lento na primeira vez.** O primeiro envio manda tudo (compactado). Depois disso, só as linhas novas são enviadas.

**"Pull first" ao fazer push.** Outro PC enviou uma versão mais nova que a sua não contém. Faça o pull e depois o push.

**Sem internet.** Os pushes vão para a fila e são tentados de novo automaticamente; `claude-sync queue` tenta de novo na hora.

**Algo deu errado depois de um pull.** Abra **Backups** e restaure o backup feito logo antes dele.

**Onde encontro os erros?** Na visão **Logs** (copie um relatório de erro de lá), ou em `~/.claude-sync/logs/claude-sync.log`.

## Compilando a partir do código-fonte e desenvolvimento

Requisitos: Node.js 20+, Rust (stable) e, no Windows, o conjunto de ferramentas MSVC (Visual Studio "Desktop development with C++", ou seja, desenvolvimento para desktop com C++).

```bash
git clone https://github.com/Abh1shxkk/chatrelay.git
cd chatrelay
npm install
npm run tauri:dev      # run the desktop app with hot reload
npm run test:rust      # cargo test --workspace: engine, adapters, push/pull, GitHub backend
npm test               # UI helper tests (vitest)
npm run typecheck      # TypeScript
npm run tauri:build    # installer in target/release/bundle/nsis/
```

Organização do projeto:

```
crates/core/       Rust engine: scanner, JSONL, path rewriting, sync, backends, hooks, summaries
crates/core/src/providers/   AI tool adapters: claude_code.rs, codex.rs (+ codex_format.rs, browser-safe parsing)
crates/core/src/provider_sync.rs   other tools' sessions in push/pull (bundles, deltas, conflict copies)
crates/core/tests/  integration tests with fixture files (tests/fixtures/codex, tests/fixtures/claude-code)
crates/cli/        the `claude-sync` CLI (also what the Claude Code hooks run)
crates/wasm/       the engine compiled to WebAssembly for the web and phone viewers
src-tauri/         desktop app: window, tray, background sync, the API behind window.claudeSync
src/renderer/      React + TypeScript + Tailwind UI (shared by desktop, web and phone)
src/shared/        TypeScript types and helpers
mobile/            Android / iOS shell around the web version (Tauri)
scripts/           release, CLI staging, WASM build
tests/             vitest tests; tests/web/mock-github.mjs for testing the web version
```

Para rodar uma cópia de desenvolvimento ao lado de uma instalada: defina um identificador e uma pasta de dados separados, para que ela nunca mexa nas suas configurações reais:

```powershell
$env:TAURI_CONFIG='{"identifier":"com.claudesync.dev","productName":"ChatRelay Dev"}'
$env:CLAUDE_SYNC_HOME='D:\tmp\chatrelay-dev'
npm run tauri:dev
```

### Versão web

```bash
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.129   # must match wasm-bindgen in Cargo.lock
npm run web:wasm     # rebuild the WebAssembly engine
npm run web:dev      # http://localhost:5175/web.html
npm run web:build    # static site in out/web/ (host on GitHub Pages, Cloudflare Pages, Netlify…)
```

`node tests/web/mock-github.mjs <folder-backend>` serve um backend de pasta como se fosse uma API do GitHub falsa (só em builds de desenvolvimento: defina `localStorage['claude-sync-web:apiBase'] = 'http://localhost:5176'` e use o token `test-token-123456`).

### App para celular (Android, iOS)

O **Android** precisa do JDK 17, do Android SDK (plataforma 36, build-tools 36, NDK r27) e dos alvos Android do Rust (o `tauri android init` instala esses alvos):

```powershell
$env:JAVA_HOME = "<jdk-17>"; $env:ANDROID_HOME = "<android-sdk>"; $env:NDK_HOME = "$env:ANDROID_HOME\ndk\<version>"
npm run mobile:android:init      # once: generates mobile/gen/android
npm run mobile:android:apk       # debug APK for a phone (arm64)
adb install -r <that apk>
npm run mobile:android:release   # release APK/AAB, signed when CLAUDE_SYNC_KEYSTORE_PROPERTIES is set
```

A assinatura das versões de publicação lê um arquivo de propriedades guardado **fora do repositório**, indicado por `CLAUDE_SYNC_KEYSTORE_PROPERTIES`:

```properties
storeFile=D:/dev/android-keys/claude-sync-release.jks
storePassword=…
keyAlias=claude-sync
keyPassword=…
```

Crie a chave uma única vez com `keytool -genkeypair -keystore claude-sync-release.jks -alias claude-sync -keyalg RSA -keysize 4096 -validity 10000` e faça backup dela: as atualizações de um app instalado precisam ser assinadas com a mesma chave.

O **iOS** precisa de um Mac com Xcode e de `rustup target add aarch64-apple-ios aarch64-apple-ios-sim`:

```bash
npm install && npm run web:wasm
npm run mobile:ios:init
npm run mobile:ios:dev
npm run mobile:ios:build
```

## Adicionando outra ferramenta de IA (guia de adaptadores)

1. **Primeiro, verifique o formato de armazenamento em uma máquina de verdade**: onde as sessões ficam, o formato das linhas/registros, qualquer banco de dados de índice e seu esquema, como a ferramenta lista as sessões, como ela guarda os caminhos, quais processos indicam que ela está "rodando". Anote tudo isso no topo do arquivo do adaptador.
2. Adicione um `ProviderId` em `crates/core/src/providers/mod.rs` e um arquivo `providers/<tool>.rs` que implemente `ProviderAdapter`: `detect`, `list_projects`, `list_sessions`, `read_session`, `export_session`, `import_session` e, opcionalmente, `append_session`, `context_file_name`, `process_names`.
3. Regras que todo adaptador segue: recusar gravar enquanto a ferramenta está rodando (`ensure_not_running`), fazer backup de cada arquivo antes de gravar (`ImportOptions.backups`), respeitar `dry_run`, respeitar `keep_both` (salvar uma sessão recebida que divergiu com um novo id) e desligar a importação (com um aviso em `ProviderStatus`) diante de qualquer formato que não reconheça.
4. Coloque a interpretação pura dos dados em um arquivo sem acesso ao sistema de arquivos (como `codex_format.rs`), para que o visualizador web possa usá-la, e adicione-a em `messages_from_bundle`.
5. Adicione arquivos de exemplo (fixtures) em `crates/core/tests/fixtures/<tool>/` e testes: detectar, listar, ler, exportar → importar em uma segunda máquina simulada (caminhos reescritos), atualização, local à frente, conflito, recusa com processo rodando, formato desconhecido.
6. Adicione o rótulo em `src/shared/types.ts` (`PROVIDER_LABELS`). Etiquetas, filtros, push/pull, resumos e o visualizador passam a usá-lo a partir dali.

## Publicando uma versão

Os apps instalados verificam o `latest.json` em [Abh1shxkk/claude-sync-releases](https://github.com/Abh1shxkk/claude-sync-releases).

1. Aumente a `version` em `package.json`, `src-tauri/tauri.conf.json`, `mobile/tauri.conf.json` e `Cargo.toml`.
2. `npm run release -- --notes "What changed"`

Isso gera o instalador do Windows assinado com a chave do atualizador (`TAURI_SIGNING_PRIVATE_KEY`, ou `D:\dev\tauri-keys\claude-sync-updater.key` com seu arquivo `.password`) e o APK assinado, grava o `latest.json` e envia tudo como a versão `v<version>`. Opções: `--no-apk`, `--skip-build`, `--dry-run`, `--notes-file <file>`. O login no GitHub vem de `git credential fill` (ou de `GITHUB_TOKEN`).

Mantenha um backup da chave do atualizador. Os apps só aceitam atualizações assinadas com ela; a metade pública dela está em `src-tauri/tauri.conf.json`.

## Limitações conhecidas

- O instalador do Windows não tem assinatura de código (aviso do SmartScreen).
- Só o Windows foi testado. macOS e Linux compilam, mas não têm instaladores publicados.
- Uma conversa aberta em dois PCs ao mesmo tempo não pode ser mesclada ao vivo; ela vira uma cópia de conflito.
- O Codex não tem um hook de "sessão terminada", então a sincronização do Codex roda a cada 15 minutos, e não na hora.
- Para caminhos com mais de 200 caracteres, o hash exato que o Claude Code usa no nome da pasta não está documentado; o ChatRelay dá preferência a uma pasta existente cujas sessões registrem o mesmo `cwd` e, se não houver, usa seu próprio sufixo `-<hash>`.
- Os visualizadores web e no celular são somente leitura e precisam do backend no GitHub.

## Sobre a mudança de nome

O ChatRelay se chamava **Claude Sync** até a v0.5.0. Para que as instalações existentes continuem recebendo atualizações e nada se perca, estes nomes internos **não** mudaram:

| Mantido | Por quê |
|---|---|
| Pasta de instalação e atalho do menu Iniciar "Claude Sync" | O Windows identifica o app instalado por eles; mudá-los instalaria uma segunda cópia em vez de atualizar |
| Identificador do app `com.claudesync.app` / `com.claudesync.mobile` | As atualizações e as instalações no Android dependem dele |
| Pasta de dados `~/.claude-sync/`, `CLAUDE_SYNC_HOME` | Suas configurações, o estado da sincronização e os backups |
| CLI `claude-sync` | Os hooks do Claude Code o chamam pelo caminho |
| Arquivos de projeto `.claude-sync.json`, marcador `claude-sync-hook` | Projetos e hooks existentes continuam funcionando |
| Repositório de versões `claude-sync-releases` | Os apps instalados baixam as atualizações dele |
| GitHub App "claude-sync-abh1shxkk" | Os logins existentes continuam funcionando |
