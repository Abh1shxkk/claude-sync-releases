**Lleva tus chats de programación con IA a cualquier PC, y de una herramienta de IA a otra.**

ChatRelay sincroniza el historial de chats de los asistentes de programación con IA (hoy, **Claude Code** y **OpenAI Codex**) entre tus computadoras. Empieza una conversación en la PC de la oficina y luego abre esa misma conversación en tu laptop de casa: los mismos mensajes, las mismas llamadas a herramientas, con cada ruta de archivo cambiada a las rutas de la nueva máquina. También escribe un resumen corto del historial de un proyecto en el archivo de instrucciones que lee otra herramienta (`CLAUDE.md`, `AGENTS.md`, `GEMINI.md`), para que puedas seguir el trabajo en otra herramienta de IA.

## Qué hace

- **Mueve el historial de chats entre PCs.** Cada conversación de Claude Code (CLI de terminal y extensión de VS Code) y de Codex (CLI, extensión de VS Code y app de escritorio) se copia a un lugar de almacenamiento que es tuyo, y de ahí a tus otras PCs. En la otra PC aparece en la propia lista de historial de la herramienta: `claude --resume`, el panel de Claude Code en VS Code, `codex resume` o la barra lateral de Codex.
- **Corrige las rutas de archivos.** Tu proyecto puede estar en `C:\Users\me\shop` en una PC y en `D:\work\shop` en otra, o en `/home/me/shop` en Linux. ChatRelay reescribe cada ruta dentro del chat (carpeta de trabajo, entradas y salidas de herramientas, enlaces a archivos, texto de los mensajes) con la ruta de la PC que lo recibe.
- **Solo envía lo que cambió.** Después de la primera subida, solo viajan las líneas nuevas de una conversación: unos pocos KB en lugar del archivo completo.
- **Nunca pierde tu trabajo.** Nunca modifica tus originales al subir. Hace una copia de seguridad de cada archivo antes de cambiarlo, primero muestra una vista previa (simulación, o "dry run") y nunca sobrescribe una conversación que cambió en las dos PCs: conserva las dos.
- **Funciona solo.** Con la sincronización automática activada, las conversaciones de Claude Code se suben cuando termina una sesión y se descargan cuando empieza una. Las conversaciones de Codex se suben y descargan cada 15 minutos en segundo plano.
- **Hace resúmenes.** Convierte todo el historial de un proyecto (de todas las herramientas) en un `HANDOFF.md`: lo que está hecho, las decisiones, los errores pendientes, los próximos pasos y los archivos modificados. También puede poner una versión corta en `CLAUDE.md`, `AGENTS.md` o `GEMINI.md`, para que la siguiente herramienta empiece con el contexto.
- **Léelo donde sea.** Una página web de solo lectura y una app de Android muestran todas tus conversaciones desde el almacenamiento en GitHub, en cualquier dispositivo.
- **Se parece a VS Code.** App de escritorio en blanco y negro al estilo de VS Code, con temas oscuro y claro, una vista simple para el uso diario y una vista avanzada con todos los detalles.

## Herramientas de IA compatibles

| Herramienta | Dónde se ejecuta | Ver chats | Sincronizar entre PCs | Restaurar en la herramienta | Archivo de contexto |
|---|---|---|---|---|---|
| **Claude Code** | CLI de terminal, extensión de VS Code | ✅ | ✅ (con hooks de sincronización automática) | ✅ `claude --resume`, historial de VS Code | `CLAUDE.md` |
| **OpenAI Codex** | Codex CLI, extensión de VS Code, app de escritorio de Codex | ✅ | ✅ (en segundo plano, cada 15 min) | ✅ `codex resume`, barra lateral de Codex | `AGENTS.md` |
| Gemini CLI | Terminal | planeado | planeado | planeado | `GEMINI.md` (ya disponible como destino de resúmenes) |
| Kiro (IDE y CLI), Cursor, Antigravity | | planeado | planeado | planeado | |

Cada herramienta guarda su historial en su propio formato no documentado, y esos formatos cambian entre versiones. Por eso ChatRelay revisa el formato que encuentra en tu PC. Si ve una versión que no conoce, igual muestra las conversaciones, pero **desactiva la escritura** para esa herramienta y te explica el motivo en **Settings → AI tools** (Configuración → Herramientas de IA). Nunca adivina.

Versiones verificadas: Claude Code 2.1.x; Codex 0.144 a 0.160 (base de datos de índice `state_5.sqlite`, migración de esquema 58).

## Descarga e instalación

### Windows

1. Descarga `ChatRelay_<version>_x64-setup.exe` desde la [última versión](https://github.com/Abh1shxkk/claude-sync-releases/releases/latest). (Las versiones hasta la v0.5.0 se llaman `ClaudeSync_…`.)
2. Ejecútalo. El instalador no tiene firma de código, así que Windows SmartScreen puede decir "Windows protected your PC" (Windows protegió tu PC): haz clic en **More info → Run anyway** (Más información → Ejecutar de todas formas).
3. Solo instalas una vez. Las versiones posteriores llegan solas (consulta [Actualizaciones](#actualizaciones)).

La app se instala por usuario en `%LOCALAPPDATA%\Claude Sync\` (la carpeta conserva su nombre anterior; consulta [Sobre el cambio de nombre](#sobre-el-cambio-de-nombre)). Arranca en la bandeja del sistema. Si cierras la ventana, sigue funcionando ahí; usa **Quit** (Salir) en el menú de la bandeja para detenerla.

### Android (visor)

Descarga `ChatRelay_<version>.apk` desde la misma página de versiones y ábrelo en tu teléfono (cuando te lo pida, permite "instalar apps desconocidas" para tu navegador o administrador de archivos). La app de Android es un **visor de solo lectura** de tu almacenamiento en GitHub; un teléfono no tiene historial propio de herramientas de IA.

### macOS y Linux

El motor en Rust y la app se compilan en macOS y Linux (consulta [Compilar desde el código fuente](#compilar-desde-el-código-fuente-y-desarrollo)), pero todavía no se publican instaladores para ellos y no se han probado.

### Web

El visor web es una página estática que puedes alojar tú mismo (GitHub Pages, Cloudflare Pages, Netlify…) o ejecutar en tu computadora. Consulta [Visor web y para teléfono](#visor-web-y-para-teléfono).

## Configuración inicial

La primera vez que se abre ChatRelay, un asistente de configuración te guía por estos pasos. Puedes volver a ejecutarlo cuando quieras desde la paleta de comandos (**Ctrl+Shift+P → Run First-time Setup Again** (Volver a ejecutar la configuración inicial)).

1. **Tu historial.** ChatRelay encuentra el historial de Claude Code en `%USERPROFILE%\.claude\projects` (o en la carpeta de `CLAUDE_CONFIG_DIR`) y el de Codex en `%USERPROFILE%\.codex` (o `CODEX_HOME`). Muestra cuántas conversaciones encontró por herramienta.
2. **El borrado a los 30 días de Claude Code.** Por defecto, Claude Code borra las conversaciones de más de 30 días (`cleanupPeriodDays`). ChatRelay te lo muestra y te ofrece aumentar ese plazo. Hace una copia de seguridad de `settings.json` antes de cambiarlo.
3. **Nombre de la máquina.** Por ejemplo `OFFICE-PC` o `HOME-LAPTOP`. Se muestra junto a cada conversación, para que sepas de qué PC vino.
4. **Almacenamiento (backend).** Una carpeta (Google Drive, OneDrive, Dropbox, unidad de red) o un repositorio privado de GitHub. Consulta la siguiente sección.
5. **Clave de API de Anthropic (opcional).** Solo se necesita para los resúmenes. Se guarda en el Administrador de credenciales de Windows (el llavero del sistema operativo), nunca en un archivo.
6. **Sincronización automática.** Activa la subida y descarga automáticas (los hooks de Claude Code más el temporizador en segundo plano).
7. **Subir todo.** Opcionalmente sube todo tu historial existente de inmediato, con una barra de progreso.

## Elegir dónde se guarda tu historial (backend)

Tu historial va a un lugar que controlas **tú**. ChatRelay no tiene servidor propio.

### Opción A: una carpeta

Cualquier carpeta que tus otras PCs también puedan ver:

- Google Drive para escritorio, por ejemplo `G:\My Drive\chatrelay`
- OneDrive, por ejemplo `%OneDrive%\chatrelay`
- Dropbox, un NAS o carpeta compartida en red, o una memoria USB que lleves contigo

Ahí solo van copias comprimidas. Tus carpetas activas `~/.claude` y `~/.codex` nunca se mueven a una carpeta en la nube. El backend de carpeta también guarda las versiones anteriores de cada archivo (**Settings → What to sync → Versions kept (folder backend)** (Configuración → Qué sincronizar → Versiones guardadas (backend de carpeta)), por defecto 2).

### Opción B: un repositorio privado de GitHub

Es lo mejor si también quieres el visor web o para teléfono.

1. **Sign in with GitHub** (Iniciar sesión con GitHub) (recomendado). ChatRelay muestra un código corto; lo ingresas en github.com y lo apruebas. La GitHub App de ChatRelay solo obtiene acceso a los repositorios que eliges (normalmente solo tu repositorio de historial), con permiso para leer y escribir su contenido. No se guarda ninguna contraseña y no interviene ningún servidor.
2. O pega un **token de acceso personal** (token clásico con el alcance `repo`, o un token de granularidad fina con *Contents: Read and write* en ese único repositorio). Si iniciaste sesión con GitHub CLI (`gh auth login`), ChatRelay puede usar ese token.
3. Elige un repositorio **privado** existente o haz clic en **Create private repo** (Crear repositorio privado). Los repositorios públicos se rechazan, porque el historial de chats puede contener código privado y secretos.

En GitHub, cada subida es **un commit**. Los archivos de más de 40 MB (comprimidos) se dividen en partes automáticamente, porque GitHub rechaza archivos individuales de más de 100 MB.

El token vive solo en el llavero del sistema operativo (servicio `claude-sync`).

## Configurar tu segunda PC

En la **PC 1** (la que ya tiene el historial):

1. Instala ChatRelay y elige un backend.
2. Sube: haz clic en **Upload now** (Subir ahora) en la vista simple (o en **Upload everything** (Subir todo) al final de la configuración), o en **Push** (Enviar) en un proyecto en la vista avanzada. Una vista previa muestra cada conversación y cualquier secreto encontrado; puedes elegir ocultarlos (redactarlos) en la copia que se sube.

En la **PC 2**:

1. Instala ChatRelay y elige **el mismo backend** (la misma carpeta sincronizada o el mismo repositorio de GitHub).
2. Pon la carpeta del proyecto en la PC 2 (por ejemplo con `git clone`). La ruta puede ser distinta, por ejemplo `D:\work\shop` en lugar de `C:\Users\me\shop`.
3. Haz clic en **Bring history to this PC** (Traer el historial a esta PC) (vista simple), o abre la vista **Sync** (Sincronizar) (vista avanzada). ChatRelay lista cada proyecto del backend y a dónde iría en esta PC:
   - Los **proyectos Git** se emparejan automáticamente por su URL remota.
   - **Otros proyectos**: haz clic en **Import into…** (Importar en…) / **Link** (Vincular) y elige la carpeta local una vez. El vínculo se recuerda.
4. Revisa la **simulación (dry run)**: qué archivos se van a escribir y cada cambio de ruta (por ejemplo `×166  C:\Users\me\shop → D:\work\shop`). Luego confirma.
5. Abre la conversación en la herramienta: `claude --resume` o el panel de Claude en VS Code; `codex resume` o la barra lateral de Codex.

Para Codex: **cierra Codex primero** (CLI, extensión de VS Code y app de escritorio). ChatRelay nunca escribe en los archivos de Codex mientras está abierto; esa conversación se omite con el motivo "Codex is running" (Codex se está ejecutando) y llega la próxima vez.

Activa **Auto-sync** (Sincronización automática) en las dos PCs y no vuelves a tener que hacer nada de esto a mano.

## Uso diario

### Vista simple y vista avanzada

- **Simple view** (Vista simple) (por defecto): tus proyectos con un punto de estado, dos botones grandes (**Upload now** / **Bring history to this PC**), el interruptor de sincronización automática y la búsqueda de actualizaciones.
- **Advanced view** (Vista avanzada): una disposición tipo VS Code con barra de actividad (Projects **Ctrl+Shift+E**, Sync **Ctrl+Shift+Y**, Summaries, Logs, Backups, Settings), pestañas, barra de estado y una paleta de comandos (**Ctrl+Shift+P**) con todas las acciones.

Cambia entre ellas con **Ctrl+Shift+P → Switch to Simple/Advanced View** (Cambiar a vista simple/avanzada).

### Puntos de estado

| Punto | Significado | Qué hacer |
|---|---|---|
| Verde | Sincronizado | Nada |
| Amarillo / naranja | Hay cambios en esta PC que todavía no se subieron | Haz push, o espera la sincronización automática |
| Rojo | La última sincronización falló | Abre **Logs** (Registros) para ver el motivo |
| Gris | Nunca se sincronizó | Haz push una vez |
| Círculo vacío | Todavía no tiene identidad de proyecto (no está vinculado) | Haz push (se crea un vínculo) o usa **Link** para vincularlo al proyecto de la otra PC |

### Conversaciones de varias herramientas

Cada conversación tiene una pequeña etiqueta con su herramienta (**Claude** o **Codex**). Los proyectos donde usaste más de una herramienta muestran un **filtro** (All / Claude Code / Codex). Al abrir una conversación ves la transcripción completa: tus mensajes, las respuestas del asistente, las llamadas a herramientas (comandos ejecutados, archivos editados) y la lista de archivos modificados.

### Push y pull

- **Push** (Enviar) sube las conversaciones de un proyecto que cambiaron desde la última sincronización. **Push all** (Enviar todo) lo hace con todos los proyectos.
- **Pull** (Traer) descarga lo nuevo. Siempre empieza con una **simulación (dry run)** que lista cada archivo que escribiría y cada ruta que reescribiría. No se escribe nada hasta que confirmas.

### Sincronización automática

Cuando **Auto-sync** está activado:

- **Claude Code**: unos hooks en `~/.claude/settings.json` ejecutan ChatRelay cuando una sesión de Claude Code **empieza** (pull) y **termina** (push).
- **Codex**: Codex no tiene un hook así, por lo que la app de escritorio revisa cada 15 minutos (empezando 20 segundos después de abrirse). Sube los proyectos cuyas conversaciones de Codex cambiaron y descarga las nuevas (se omite mientras Codex está abierto).
- Las subidas que fallaron porque no tenías conexión quedan en cola y se reintentan.

Puedes activar o desactivar la sincronización automática en Settings, en el menú de la bandeja o con `claude-sync hooks install|uninstall`.

### Menú de la bandeja

Push now · Pull now · Auto-sync on/off · Last sync status · Open · Quit (Enviar ahora · Traer ahora · Sincronización automática sí/no · Estado de la última sincronización · Abrir · Salir).

### Copias de seguridad

Antes de cada escritura se hace una copia de seguridad en `~/.claude-sync/backups/<timestamp>-<what>/`. Abre **Backups** (Copias de seguridad) (o `claude-sync backups`) para verlas, y usa **Restore** (Restaurar) en una para dejar cada archivo exactamente como estaba. Una restauración también elimina los archivos que el cambio había creado.

### Registros

**Logs** (Registros) muestra todo lo que hizo ChatRelay, con los errores resaltados, y un botón que copia un informe de errores.

## Soporte de Codex en detalle

Lo que viaja con cada conversación de Codex:

| Elemento | Dónde lo guarda Codex | Qué hace ChatRelay |
|---|---|---|
| La conversación ("rollout") | `~/.codex/sessions/YYYY/MM/DD/rollout-<time>-<id>.jsonl` (algunas versiones escriben `.jsonl.zst`, comprimido) | La copia, con cada ruta reescrita |
| La fila de índice del hilo | `~/.codex/state_5.sqlite`, tabla `threads` | La agrega o actualiza para que la conversación aparezca en `codex resume` y en la barra lateral |
| El nombre del hilo | `~/.codex/session_index.jsonl` | Lo agrega |
| La memoria de Codex para ese hilo | `~/.codex/memories_1.sqlite`, tabla `stage1_outputs` | La agrega si esta PC no tiene ninguna para ese hilo; rutas reescritas |
| Los objetivos de ese hilo | `~/.codex/goals_1.sqlite`, tablas `thread_goals`, `thread_goal_continuation_deferrals` | Los agrega si esta PC no tiene ninguno para ese hilo |

Detalles importantes:

- **Codex debe estar cerrado** mientras ChatRelay escribe. ChatRelay busca procesos `codex` en ejecución (CLI, extensión de VS Code, app de escritorio). No te pide cerrar nada durante la sincronización en segundo plano; simplemente vuelve a intentarlo más tarde.
- **Se respeta el modo de historial.** Las versiones más nuevas de Codex guardan el historial "paginado"; Codex reconstruye su base de datos de páginas (`thread_history_*.sqlite`) a partir del archivo de la conversación la primera vez que la abres, así que ChatRelay nunca escribe esa base de datos.
- **Tu propia configuración de un hilo sigue siendo tuya.** Al actualizar, se conservan el estado de fijado, el nombre personalizado, el estado de archivado y la cuenta de esta PC. Las carpetas y secciones que solo existen en la otra PC se borran.
- **Cuenta.** Un hilo importado se asigna a la cuenta de Codex dueña de la mayoría de los hilos en esta PC.
- **Prefijo de rutas de Windows.** Codex en Windows guarda las carpetas de trabajo como `\\?\D:\project`. ChatRelay agrega ese prefijo solo a rutas de Windows en una PC cuyo Codex lo use, y nunca a rutas de macOS o Linux.
- **Las conversaciones comprimidas** (`.jsonl.zst`) se pueden leer y actualizar. Al actualizar, el archivo se reemplaza por un `.jsonl` normal (antes se hace una copia de seguridad del original comprimido).
- **Los datos de control de la memoria** que pertenecen a la otra PC (cuántas veces se usó una memoria, si se eligió para consolidación) no se copian.
- **Versiones desconocidas.** Si el índice de Codex usa una base de datos que ChatRelay no conoce (por ejemplo un futuro `state_6.sqlite`), o agrega un campo obligatorio que no puede llenar, la escritura se desactiva para Codex con una advertencia clara. La lectura sigue funcionando.

## Resúmenes y "Continuar en otra herramienta"

> 🔒 **Los secretos nunca llegan a la IA.** Antes de enviar nada al modelo, ChatRelay reemplaza las claves, tokens y contraseñas que encuentra en los chats (claves de API de Anthropic, OpenAI, OpenRouter, GitHub, AWS, Google, Slack, Stripe, Hugging Face, npm, SendGrid, bots de Telegram; JWT; claves privadas; líneas tipo `PASSWORD=…`; contraseñas dentro de URLs) por `[REDACTED:kind]`. Esto ocurre siempre y no se puede desactivar; la pantalla muestra cuántos se ocultaron. Tu código y el resto de la conversación sí se envían, así que para código privado o de clientes usa mejor un modelo de pago cuyo proveedor no guarde datos.

Abre **Summaries** (Resúmenes) (vista avanzada), elige un proyecto, marca las conversaciones (de cualquier herramienta) y un modelo, y luego haz clic en **Generate handoff** (Generar traspaso).

- Modelos: **Claude Opus 5.5** (por defecto), Claude Sonnet 5.5 (más rápido, más barato), Claude Haiku 5.5 (el más barato), Claude Fable 5.1 (el más capaz). Necesitas una clave de API de Anthropic (**Settings → Summaries** (Configuración → Resúmenes)).
- Primero se condensa el historial: tus pedidos, la respuesta final del asistente en cada turno y los archivos modificados. Las salidas largas de herramientas y el razonamiento interno se descartan. Las conversaciones de todas las herramientas se unen en orden cronológico y se etiquetan con su herramienta.
- Los historiales largos se resumen en partes de ~100k tokens y luego se combinan.
- El resultado tiene estas secciones: Project overview, What's done, Key decisions, Open bugs / known issues, Next steps, Files touched (Resumen del proyecto, Lo que está hecho, Decisiones clave, Errores pendientes / problemas conocidos, Próximos pasos, Archivos modificados).

Después puedes:

- **Save HANDOFF.md** (Guardar HANDOFF.md) en la carpeta del proyecto, o
- **Continue in…** (Continuar en…) una herramienta: elige Claude Code (`CLAUDE.md`), Codex (`AGENTS.md`) o Gemini CLI (`GEMINI.md`). La lista muestra las herramientas instaladas en esta PC. ChatRelay agrega a ese archivo una sección corta "Previous context" (Contexto anterior) (resumen, lo que está hecho, próximos pasos). Si lo vuelves a ejecutar, solo reemplaza su propia sección; el resto del archivo no se toca.
- O **copiar** el texto.

Desde la línea de comandos: `claude-sync summarize --target handoff|claude-md|agents-md|gemini-md|none`.

## Seguridad y privacidad

- **Los originales nunca se modifican al subir.** Subir solo lee tus archivos de historial.
- **No se escribe nada mientras la herramienta está abierta** (Codex). La sesión abierta de Claude Code (la que activó el hook) nunca se toca.
- **Copia de seguridad antes de cada escritura**, incluidos el `settings.json` de Claude Code, las bases de datos de Codex (con sus archivos `-wal` y `-shm`) y `session_index.jsonl`.
- **Simulación (dry run) en cada importación.** Ves cada archivo y cada reescritura de ruta antes de que pase algo.
- **Ante un conflicto se conservan las dos versiones**, nunca se sobrescriben.
- **Búsqueda de secretos.** Antes de subir, ChatRelay busca claves de API y contraseñas: claves de Anthropic, OpenAI, GitHub, AWS, Google, Slack y Stripe, JWTs, claves privadas, líneas al estilo `.env` como `SECRET=…`, y credenciales dentro de URLs. Tú eliges: **warn** (avisar), **redact** (ocultar: se reemplazan por `[REDACTED:kind]` solo en la copia subida) u **off** (desactivado).
- **Los secretos se quedan en el llavero del sistema operativo.** Tu token de GitHub y tu clave de Anthropic nunca se escriben en un archivo.
- **Tus inicios de sesión nunca se tocan.** ChatRelay no lee, copia ni cambia los archivos de inicio de sesión de Claude Code ni de Codex (`~/.claude/.credentials.json`, `~/.codex/auth.json`, …). Sincronizar el historial no puede cerrar tu sesión. Si se cierra tu sesión, eso viene de la propia herramienta (por ejemplo, una sesión vencida o haber iniciado sesión con otra cuenta en otra PC).
- **Solo almacenamiento privado.** Los repositorios públicos de GitHub se rechazan.
- **No hay servidor de ChatRelay.** Los datos solo van entre tus PCs, tu carpeta o GitHub, y (solo cuando haces un resumen) la API de Anthropic.

No se sincroniza, a propósito: `~/.claude/history.jsonl` (tu historial de prompts con la flecha hacia arriba en todos los proyectos), `~/.claude/file-history/` (instantáneas para retroceder) y ninguna credencial.

## Cómo funciona (técnico)

### Dónde guarda Claude Code el historial

| Ruta | Qué es |
|---|---|
| `~/.claude/projects/<encoded-path>/<session-uuid>.jsonl` | Un archivo por sesión, un objeto JSON por línea |
| `~/.claude/projects/<encoded-path>/<session-uuid>/subagents/*.jsonl` + `*.meta.json` | Transcripciones de subagentes (se sincronizan como "sidecar", un archivo complementario) |
| `~/.claude/projects/<encoded-path>/<session-uuid>/tool-results/*` | Salidas grandes de herramientas guardadas en disco (sidecar) |
| `~/.claude/projects/<encoded-path>/memory/` | Memoria automática del proyecto (`MEMORY.md` + notas) |

Cosas que no son como uno supondría, y que se manejan todas:

- **Las mayúsculas/minúsculas de la letra de unidad dependen del cliente.** La extensión de VS Code registra `c:\Users\…` (carpeta `c--Users-…`), la CLI registra `C:\Users\…` (carpeta `C--Users-…`), y una misma sesión puede contener ambas. En Windows, las rutas se comparan sin distinguir mayúsculas de minúsculas.
- **Los nombres de carpeta no se pueden decodificar de forma confiable.** `C:\Users\me\my project` y `C:\Users\me\my-project` se codifican ambos como `C--Users-me-my-project`. La ruta real sale del `cwd` registrado en las sesiones; decodificar el nombre es solo un último recurso, y se marca como tal.
- **Las sesiones pueden ser enormes** (más de 200 MB con imágenes o PDFs incrustados), así que todo se procesa en flujo (streaming). Los resultados del escaneo se guardan en caché según el tamaño y la fecha de modificación, así que volver a escanear tarda unos 100 ms.
- **Una respuesta del asistente ocupa varias líneas** (una por bloque de contenido, con el mismo `message.id`); el conteo de mensajes elimina esos duplicados. Los títulos salen del primer prompt real (sin las etiquetas que agrega el IDE); el `ai-title` propio de Claude Code se muestra al lado.
- **Hay muchos tipos de línea además de user/assistant** (`attachment`, `file-history-snapshot`, `queue-operation`, `ai-title`, `last-prompt`, `permission-mode`, …). Los tipos y campos desconocidos se conservan sin cambios.

### Dónde guarda Codex el historial

Consulta [Soporte de Codex en detalle](#soporte-de-codex-en-detalle). Cada línea de un rollout es `{timestamp, type, payload}`; la primera es `session_meta`, con el id de la sesión y el `cwd`. Codex ha escrito las conversaciones en tres generaciones (elementos `event_msg/item_completed` en ≥0.15x, eventos `user_message`/`agent_message` antes, y mensajes `response_item` simples en las más antiguas); el visor usa la más completa que encuentre.

### Adaptadores

Cada herramienta de IA es un **adaptador** (`crates/core/src/providers/`) detrás de una sola interfaz (`ProviderAdapter`): detectar la herramienta y su formato, listar proyectos y sesiones, leer una sesión en una forma neutral respecto a la herramienta (`UniversalSession`), exportarla sin pérdidas (`SessionBundle`: los archivos originales más los metadatos de la herramienta, como la fila de índice de Codex), importarla en otra PC (reescribir rutas, comprobar que la herramienta no esté abierta, hacer copia de seguridad, simulación) y agregar líneas nuevas. Consulta [Agregar otra herramienta de IA](#agregar-otra-herramienta-de-ia-guía-de-adaptadores).

### Identidad del proyecto

El mismo proyecto tiene una ruta distinta en cada PC, así que se identifica, en este orden, por:

1. Un **vínculo manual** (botón Link / `claude-sync link <dir> <id>`), guardado en la configuración de ChatRelay
2. El **remoto de git**, normalizado: `git@github.com:Me/Repo.git` y `https://github.com/me/repo` se convierten ambos en `git:github.com/me/repo`
3. Un **`.claude-sync.json`** en la raíz del proyecto que contiene un UUID, creado en el primer push para proyectos que no usan git (haz commit de ese archivo, o vincúlalo a mano en la otra PC). "Upload everything" (Subir todo) y la sincronización en segundo plano crean en cambio un vínculo en la configuración de ChatRelay, así que no se escribe nada en las carpetas de tus proyectos.

### Estructura del almacenamiento (en la carpeta o el repositorio)

```
<projectId-slug>/
  manifest.json                          machines, original paths, hashes, timestamps, revision
  <sessionId>.jsonl.gz                   Claude Code session (whole, or its start when deltas exist)
  <sessionId>.d<N>.jsonl.gz              lines appended after that, one blob per push
  <sessionId>.sidecar.json.gz            subagents/ + tool-results/ (if any)
  memory.json.gz                         Claude Code project memory (if any)
  <provider>-<sessionId>.bundle.json.gz  another tool's session (e.g. codex-…): files + metadata
  <provider>-<sessionId>.d<N>.jsonl.gz   lines appended to it later
  .versions/<file>/<timestamp>           previous versions (folder backend)
```

Las sesiones de otras herramientas se listan en `providerSessions` dentro del manifiesto (clave `<provider>:<id>`). Las versiones anteriores de la app ignoran esa lista y la dejan intacta.

### Push

- Las sesiones se comparan por SHA-256; solo se suben las nuevas o modificadas. Los originales solo se leen, nunca se modifican.
- **Solo se envían las líneas nuevas.** Las herramientas de IA siempre agregan al final de un archivo de conversación, así que, después de la primera subida de una sesión, un push guarda solo las líneas agregadas desde la última sincronización como una parte "delta". Cada parte registra las rutas de la máquina que la subió. Los hashes de las sesiones se encadenan (`hash = sha256(previous : sha256(part))`). Después de 40 partes, el siguiente push vuelve a subir la sesión completa. Cuando este atajo no sirve (el archivo cambió de otra manera, hay un conflicto, el estado viene de una versión anterior) se sube el archivo completo.
- Si el backend tiene una versión que no has visto y que contiene mensajes que tú no tienes, el push de esa sesión se rechaza con "pull first" (haz pull primero), así no se pierde nada.
- **¿Sin conexión?** (GitHub no responde, la unidad en la nube no está montada.) El push queda en cola en `~/.claude-sync/queue.json` y se reintenta en la siguiente ejecución y cada 15 minutos desde la app de escritorio.

### Pull

- Las rutas se reescriben dentro del JSON ya interpretado (valores de texto **y** claves de objetos), así que el escape de caracteres de JSON nunca es un problema. Formas que se manejan: rutas de Windows como `C:\…`, `c:/…`, `/c/…` de Git-Bash y `/mnt/c/…` de WSL (sin distinguir mayúsculas); rutas POSIX (distinguiendo mayúsculas); URLs `file:///`, incluidos los espacios codificados como `%20`; los separadores después de la raíz del proyecto se convierten al pasar de un sistema operativo a otro; también se reescriben la carpeta propia de la herramienta (`~/.claude`, `~/.codex`) y el nombre de carpeta codificado de Claude Code. Las carpetas vecinas como `shop-old` nunca se tocan.
- **Camino rápido:** una PC que tiene exactamente lo que sincronizó la última vez descarga solo las partes que faltan y las agrega al final.
- **Divergencia** (las conversaciones solo crecen al final; se comparan por los ids de línea en Claude Code y por el prefijo de texto en otras herramientas):
  - el remoto contiene al local → se actualiza
  - el local contiene al remoto → el tuyo es más nuevo y se conserva (se sube en el siguiente push)
  - los dos cambiaron → **conflicto**: tu copia queda como está y la otra versión se guarda como una **conversación nueva con un id nuevo** (Codex: con el nombre "<name> (from <PC>)"). Después, las dos aparecen en la herramienta y se sincronizan con tus otras PCs.

### Hooks de sincronización automática (Claude Code)

"Enable auto-sync" (Activar la sincronización automática) combina esto con `~/.claude/settings.json`; tus otras opciones y hooks se conservan, y antes se hace una copia de seguridad:

```jsonc
"hooks": {
  "SessionStart": [{ "hooks": [{ "type": "command", "command": "\"…/Claude Sync/claude-sync.exe\" pull --hook --quiet --claude-sync-hook", "timeout": 60 }] }],
  "SessionEnd":   [{ "hooks": [{ "type": "command", "command": "\"…/Claude Sync/claude-sync.exe\" push --hook --quiet --claude-sync-hook", "timeout": 60 }] }]
}
```

- `--hook` lee el JSON del hook de Claude Code desde stdin (`cwd`, `session_id`); si no lo hay, usa `CLAUDE_PROJECT_DIR` y después la carpeta de trabajo. Los hooks **siempre terminan con código 0**, así que nunca pueden romper una sesión; los errores van al panel de registros (Logs).
- El hook ejecuta el programa nativo `claude-sync` instalado junto a la app. No se necesita Node.js.
- "Disable auto-sync" (Desactivar la sincronización automática) quita solo los hooks que contienen la marca `claude-sync-hook`.

## Actualizaciones

- La app de escritorio busca una versión nueva al iniciar, cada vez que se abre su ventana, cada hora, cuando vuelves a su ventana tras 5 minutos o más y cuando haces clic en **Check for updates** (Buscar actualizaciones) (Settings → About, la vista simple o la paleta de comandos). Mientras busca, muestra un indicador de carga.
- Cuando hay una disponible, ves **A new version is available → Update now** (Hay una versión nueva disponible → Actualizar ahora). La app la descarga, verifica su firma (las apps solo aceptan actualizaciones firmadas con la clave del proyecto), la instala en el mismo lugar y se reinicia. El historial y la configuración se conservan.
- La app de Android muestra un aviso con un enlace al nuevo APK.

## Solución de problemas y preguntas frecuentes

**SmartScreen bloquea el instalador.** El instalador no tiene firma de código. Haz clic en **More info → Run anyway** (Más información → Ejecutar de todas formas).

**Un proyecto muestra un punto amarillo.** Tiene conversaciones en esta PC que todavía no se subieron. Haz push o activa la sincronización automática.

**Un proyecto de mi otra PC no aparece / aparece con otro nombre.** Los proyectos se emparejan por el remoto de git, por un `.claude-sync.json` o por un vínculo. Si las carpetas tienen nombres distintos y no hay remoto de git, usa **Link** (o **Import into…**) una vez y elige la carpeta local correcta.

**Se omitió una conversación de Codex: "Codex is running".** Cierra Codex CLI, el panel de Codex de la extensión de VS Code (o VS Code) y la app de escritorio de Codex, y vuelve a hacer pull. La sincronización en segundo plano lo reintenta sola.

**La importación de Codex está desactivada: "Unknown Codex index database" / "new required fields"** (Base de datos de índice de Codex desconocida / campos obligatorios nuevos). Tu Codex es más nuevo de lo que conoce esta versión de ChatRelay. Actualiza ChatRelay. Tus conversaciones se siguen viendo.

**Veo una conversación dos veces, una termina en "(from OFFICE-PC)".** Se continuó en las dos PCs antes de que se sincronizaran. Se conservan las dos versiones; borra en la herramienta la que no necesites.

**Desaparecieron mis conversaciones viejas de Claude Code.** Claude Code borra las conversaciones de más de `cleanupPeriodDays` días (por defecto 30). Aumenta ese valor en Settings (o con `claude-sync cleanup-days 3650`). Las conversaciones que ya se subieron se pueden recuperar del backend con pull.

**¿Sincronizar cerró mi sesión de Claude?** No. ChatRelay nunca lee ni escribe archivos de inicio de sesión. Consulta [Seguridad y privacidad](#seguridad-y-privacidad).

**La primera subida es lenta.** La primera subida envía todo (comprimido). Después solo se envían las líneas nuevas.

**"Pull first" al hacer push.** Otra PC subió una versión más nueva que la tuya no contiene. Haz pull y luego push.

**Sin conexión.** Los pushes quedan en cola y se reintentan automáticamente; `claude-sync queue` los reintenta en ese momento.

**Algo salió mal después de un pull.** Abre **Backups** (Copias de seguridad) y restaura la copia hecha justo antes.

**¿Dónde encuentro los errores?** En la vista **Logs** (Registros) (desde ahí puedes copiar un informe de errores), o en `~/.claude-sync/logs/claude-sync.log`.

## Compilar desde el código fuente y desarrollo

Requisitos: Node.js 20+, Rust (estable) y, en Windows, el conjunto de herramientas MSVC (la carga de trabajo "Desktop development with C++" de Visual Studio).

```bash
git clone https://github.com/Abh1shxkk/chatrelay.git
cd chatrelay
npm install
npm run tauri:dev      # run the desktop app with hot reload
npm run test:rust      # cargo test --workspace: engine, adapters, push/pull, GitHub backend
npm test               # UI helper tests (vitest)
npm run typecheck      # TypeScript
npm run tauri:build    # installer in target/release/bundle/nsis/
```

Estructura del proyecto:

```
crates/core/       Rust engine: scanner, JSONL, path rewriting, sync, backends, hooks, summaries
crates/core/src/providers/   AI tool adapters: claude_code.rs, codex.rs (+ codex_format.rs, browser-safe parsing)
crates/core/src/provider_sync.rs   other tools' sessions in push/pull (bundles, deltas, conflict copies)
crates/core/tests/  integration tests with fixture files (tests/fixtures/codex, tests/fixtures/claude-code)
crates/cli/        the `claude-sync` CLI (also what the Claude Code hooks run)
crates/wasm/       the engine compiled to WebAssembly for the web and phone viewers
src-tauri/         desktop app: window, tray, background sync, the API behind window.claudeSync
src/renderer/      React + TypeScript + Tailwind UI (shared by desktop, web and phone)
src/shared/        TypeScript types and helpers
mobile/            Android / iOS shell around the web version (Tauri)
scripts/           release, CLI staging, WASM build
tests/             vitest tests; tests/web/mock-github.mjs for testing the web version
```

Para ejecutar una copia de desarrollo junto a una instalada: define un identificador y una carpeta de datos separados, para que nunca toque tu configuración real:

```powershell
$env:TAURI_CONFIG='{"identifier":"com.claudesync.dev","productName":"ChatRelay Dev"}'
$env:CLAUDE_SYNC_HOME='D:\tmp\chatrelay-dev'
npm run tauri:dev
```

### Versión web

```bash
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.129   # must match wasm-bindgen in Cargo.lock
npm run web:wasm     # rebuild the WebAssembly engine
npm run web:dev      # http://localhost:5175/web.html
npm run web:build    # static site in out/web/ (host on GitHub Pages, Cloudflare Pages, Netlify…)
```

`node tests/web/mock-github.mjs <folder-backend>` sirve un backend de carpeta como si fuera una API de GitHub falsa (solo en compilaciones de desarrollo: define `localStorage['claude-sync-web:apiBase'] = 'http://localhost:5176'` y usa el token `test-token-123456`).

### App móvil (Android, iOS)

**Android** necesita JDK 17, el Android SDK (plataforma 36, build-tools 36, NDK r27) y los targets de Rust para Android (`tauri android init` los instala):

```powershell
$env:JAVA_HOME = "<jdk-17>"; $env:ANDROID_HOME = "<android-sdk>"; $env:NDK_HOME = "$env:ANDROID_HOME\ndk\<version>"
npm run mobile:android:init      # once: generates mobile/gen/android
npm run mobile:android:apk       # debug APK for a phone (arm64)
adb install -r <that apk>
npm run mobile:android:release   # release APK/AAB, signed when CLAUDE_SYNC_KEYSTORE_PROPERTIES is set
```

La firma de las versiones publicadas lee un archivo de propiedades guardado **fuera del repositorio**, indicado por `CLAUDE_SYNC_KEYSTORE_PROPERTIES`:

```properties
storeFile=D:/dev/android-keys/claude-sync-release.jks
storePassword=…
keyAlias=claude-sync
keyPassword=…
```

Crea la clave una sola vez con `keytool -genkeypair -keystore claude-sync-release.jks -alias claude-sync -keyalg RSA -keysize 4096 -validity 10000` y haz una copia de seguridad: las actualizaciones de una app ya instalada deben firmarse con la misma clave.

**iOS** necesita una Mac con Xcode y `rustup target add aarch64-apple-ios aarch64-apple-ios-sim`:

```bash
npm install && npm run web:wasm
npm run mobile:ios:init
npm run mobile:ios:dev
npm run mobile:ios:build
```

## Agregar otra herramienta de IA (guía de adaptadores)

1. **Primero verifica el formato de almacenamiento en una máquina real**: dónde viven las sesiones, el formato de las líneas o registros, cualquier base de datos de índice y su esquema, cómo lista la herramienta las sesiones, cómo guarda las rutas y qué procesos significan que está "en ejecución". Anótalo al inicio del archivo del adaptador.
2. Agrega un `ProviderId` en `crates/core/src/providers/mod.rs` y un archivo `providers/<tool>.rs` que implemente `ProviderAdapter`: `detect`, `list_projects`, `list_sessions`, `read_session`, `export_session`, `import_session` y, opcionalmente, `append_session`, `context_file_name`, `process_names`.
3. Reglas que sigue todo adaptador: negarse a escribir mientras la herramienta está abierta (`ensure_not_running`), hacer copia de seguridad de cada archivo antes de escribir (`ImportOptions.backups`), respetar `dry_run`, respetar `keep_both` (guardar una sesión entrante que divergió con un id nuevo) y desactivar la importación (con una advertencia en `ProviderStatus`) ante cualquier formato que no reconozca.
4. Pon el análisis puro (parsing) en un archivo sin acceso al sistema de archivos (como `codex_format.rs`) para que el visor web pueda usarlo, y agrégalo a `messages_from_bundle`.
5. Agrega archivos de prueba (fixtures) en `crates/core/tests/fixtures/<tool>/` y pruebas para: detectar, listar, leer, exportar → importar en una segunda máquina simulada (con rutas reescritas), actualizar, local adelantado, conflicto, rechazo con el proceso en ejecución y formato desconocido.
6. Agrega la etiqueta en `src/shared/types.ts` (`PROVIDER_LABELS`). Las etiquetas visuales, los filtros, push/pull, los resúmenes y el visor la toman de ahí.

## Publicar una versión

Las apps instaladas revisan `latest.json` en [Abh1shxkk/claude-sync-releases](https://github.com/Abh1shxkk/claude-sync-releases).

1. Sube el número de `version` en `package.json`, `src-tauri/tauri.conf.json`, `mobile/tauri.conf.json` y `Cargo.toml`.
2. `npm run release -- --notes "What changed"`

Eso compila el instalador de Windows firmado con la clave del actualizador (`TAURI_SIGNING_PRIVATE_KEY`, o `D:\dev\tauri-keys\claude-sync-updater.key` con su archivo `.password`) y el APK firmado, escribe `latest.json` y sube todo como la versión `v<version>`. Opciones: `--no-apk`, `--skip-build`, `--dry-run`, `--notes-file <file>`. El inicio de sesión en GitHub sale de `git credential fill` (o de `GITHUB_TOKEN`).

Guarda una copia de seguridad de la clave del actualizador. Las apps solo aceptan actualizaciones firmadas con ella; su mitad pública está en `src-tauri/tauri.conf.json`.

## Limitaciones conocidas

- El instalador de Windows no tiene firma de código (aviso de SmartScreen).
- Solo se prueba en Windows. macOS y Linux compilan, pero no tienen instaladores publicados.
- Una conversación abierta en dos PCs al mismo tiempo no se puede combinar en vivo; se convierte en una copia por conflicto.
- Codex no tiene un hook de "sesión terminada", así que la sincronización de Codex se ejecuta cada 15 minutos y no al instante.
- Para rutas de más de 200 caracteres, el hash exacto que usa Claude Code en el nombre de carpeta no está documentado; ChatRelay prefiere una carpeta existente cuyas sesiones registren el mismo `cwd` y, si no la hay, usa su propio sufijo `-<hash>`.
- Los visores web y para teléfono son de solo lectura y necesitan el backend de GitHub.

## Sobre el cambio de nombre

ChatRelay se llamaba **Claude Sync** hasta la v0.5.0. Para que las instalaciones existentes se sigan actualizando y no se pierda nada, estos nombres internos **no** cambiaron:

| Se conserva | Por qué |
|---|---|
| Carpeta de instalación y entrada del menú Inicio "Claude Sync" | Windows identifica la app instalada por ese nombre; cambiarlo instalaría una segunda copia en lugar de actualizar |
| Identificador de la app `com.claudesync.app` / `com.claudesync.mobile` | Las actualizaciones y las instalaciones en Android dependen de él |
| Carpeta de datos `~/.claude-sync/`, `CLAUDE_SYNC_HOME` | Tu configuración, el estado de sincronización y las copias de seguridad |
| CLI `claude-sync` | Los hooks de Claude Code la llaman por su ruta |
| Archivos de proyecto `.claude-sync.json`, marca `claude-sync-hook` | Los proyectos y hooks existentes siguen funcionando |
| Repositorio de versiones `claude-sync-releases` | Las apps instaladas descargan las actualizaciones desde ahí |
| GitHub App "claude-sync-abh1shxkk" | Los inicios de sesión existentes siguen funcionando |
